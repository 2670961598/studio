## 一、审查范围与方法

**范围**：57-60 四份文档。58 引用了 55 的六岗位类型，故在核对 58 的类型映射时，
以 55 的六类型定义为参照；55/56 本身不在本次审查范围。

**方法**：只做管理逻辑审查，不做技术审查。具体六条：

1. **概念自洽**：同一词在同一层是否同义；有没有循环定义、类别错误、把比喻当定义。
2. **划分正确**：每一层的分类是否互斥且穷尽（MECE）；父类与子类是否一致。
3. **权责闭环**：每个「权」是否有对应的问责（forum/证据/制裁）；每个「责」是否有人承接；
   有没有无主的裁量。
4. **制衡有效**：不相容职务是否分离；制衡者是否也被制衡；例外/默认/超时是否有规则；
   会不会死锁。
5. **跨文档一致**：同一概念、同一计数、同一映射、同一「独立性」定义是否一致。
6. **可被人使用**：一个公司作者/制作人能否据此设计岗位、裁决冲突、审计执行；
   还是只能读出「原则上很重要」。

**不评价**：怎么实现、用什么系统、成本、性能、模型能力、组织规模能撑多大。
这些属于技术/工程审查，不在本文。

## 二、总体判断：骨架是对的，接缝是硬的

### 2.1 四份文档的关系

```
57 权责原子（谁可以做什么、向谁交代）
        ↓
58 岗位组合（哪些原子可以拼成一个岗位、怎么拼）
        ↓
59 制衡结构（这些岗位如何互相制约、制衡者如何被制约）
        ↓
60 员工模型（一个 agent 作为员工，需要什么、能做什么、如何被控制）
```

这个顺序是**正确的**，而且比常见的「先画组织架构图、再补职责」要扎实：
先有原子，再有组合，再有制衡，最后才是员工。四份文档合起来，确实构成了一套
「权责体系」的骨架，不是零散概念的堆叠。

### 2.2 四份文档各自最强的地方

**57 最强的是「分解」**：
- 用霍菲尔德四型把「权」拆开，指出「作为/要求/变更/豁免」不是一回事；
- 三条公理（权责可结算、权可授责不可授、原子性四判据）有理论根基；
- 九族 74 原子 + 24 条禁配，是一份可以拿来当「控制库」的清单；
- 「剩余裁量默认归顶点」避免了「制度没写就没人管」的漏洞。

**58 最强的是「组合」**：
- 「岗位 = 权责原子的合法组合 + 参数」这个定义，比「岗位说明书」更接近本质；
- 「规模不增减原则，只增减持有者」是一个很干净的规模观；
- 12 条规模不变量 + 外化铁律（执行可外化，验收/追责/终止不可外化）有实操价值。

**59 最强的是「失效模式」**：
- 五链分离把「一张单子」的生命周期拆成提案/审议/执行/验收/审计，方向对；
- 15 个历史失败模式不是装饰，每一条都能对应到一条防线；
- 「衡量制衡看否决是否真的发生，不看机构是否还在」这句话，是整套文档里最锋利的一句；
- 保留事项 + 成本红线，说明作者知道「制衡不是越多越好」。

**60 最强的是「本体四分」**：
- 把「agent」拆成岗位/任职者/执行体/会话，直接回答了四个最容易混的问题：
  记忆属于谁、凭证发给谁、绩效算谁、越权追谁；
- 「仪器不是员工」（G0 不占工号）是一个重要的边界；
- 「控制 = 权责 ∩ 能力 ∩ 凭证」虽然是个比喻，但方向是对的：
  该有、能做、本次拿到，三者收缩即收缩。

### 2.3 但接缝处有硬伤

四份文档各自看，都有说服力；合起来看，出现了三类接缝问题：

1. **同一件事，两份文档给出相反规则**（57 允许的，59 禁止；57 禁止的，58 采用）。
2. **同一层分类，两份文档用两套坐标**（58 的六类型 vs 60 的 G0-G6；57 的四型 vs 60 的十三面）。
3. **同一个概念，在不同文档里定义不同**（「独立性」「责」「执行体」）。

这些不是文字瑕疵，是**逻辑冲突**：照着文档去设计岗位/裁决争议时，会出现
「按 57 合法、按 58 非法」「按 57 允许、按 59 禁止」的情况。下面逐条列。

## 三、划分正确性：四份文档分别看

### 3.1 57 的划分：九族 74 原子

**结论：族级划分基本正确，原子级有两处硬伤，权/责维度不完整。**

| 检查项 | 结果 | 说明 |
|---|---|---|
| 九族是否互斥 | 大体互斥 | A 决策/B 资源/C 执行/D 验证/E 人事/F 信息/G 风险/H 元规则/I 协作，边界清楚 |
| 74 原子是否穷尽 | 大体穷尽 | 但「义务」没有独立族；D1/D4/I7 是复合控制，不是原子 |
| 原子是否可独立授予 | 部分 | A3 终裁、A10 剩余裁量、H5 除名等是「主权型」权力，不能按普通原子独立授予 |
| 原子是否可独立追责 | 部分 | D1/D2/D4 的 forum/证据/制裁往往共享，独立性不足 |
| 是否存在无主裁量 | 形式上有兜底 | A10 兜底，但 A10 本身无边界、无期限、无额度，变成「主权者的空白支票」 |
| 权型四分是否够用 | **不够** | 霍菲尔德四型是「权」的分类，不是「权责」的分类；「义务」没有位置 |

**具体问题**：
- 57-§〇 自己说「复核/审计/双人原则不是原子」，但 57-§二 把 D1 复核、D4 审计、
  I7 双人控制列为原子。这是同一份文档内部的直接矛盾。
- 57-§〇 说「组合封闭：任意子集组合仍构成合法岗位」，但 57-§三/§四 又有禁配表。
  如果任意子集都合法，禁配表就没有意义；如果禁配表有效，「任意子集」就不成立。
- 57 的「责」是 forum/证据/制裁，本质是**事后问责**；但 58/60 讲的「义务」是
  **事前的必须做**。两者都叫「责」，混在一起，导致「岗位=权责组合」实际上只是
  「权利 + 问责」，缺了「义务」这一半。

### 3.2 58 的划分：六类型 / 21 个范式

**结论：类型划分不正确，范式库与禁配表冲突，覆盖不完备。**

| 检查项 | 结果 | 说明 |
|---|---|---|
| 六类型是否 MECE | **否** | 审计/法务/安全/财务/人事等范式，放不进六类的「必有原子」 |
| 范式是否都合法 | **否** | 部长 A1+A2、宰相 A5+A6、人事 E3+E4 等，直接违反 57 禁配表 |
| 原子是否都有承接 | **否** | E5/E6/E8、H4/H5、I3/I5/I8/I9、C3、D3/D9、F3/F4/F6/F7/F8、G4、B6/B7/B13 等，未在范式库中出现 |
| 规模变形是否自洽 | 部分 | 「监事可无」与 59 的审计链冲突；「外部锚」与「验收/追责/终止不可外化」边界不清 |
| 计数是否一致 | **否** | 文档说「20 个 archetype」，实际列出 21 个 |

**具体问题**：
- `govern`（治理岗）的「必有原子」写的是「D1 或 D2 + A4」。但审计负责人（D4+D6+F1）、
  法务合规（G2+G3+A4+B5）、安全岗（C4+B3+G3+D8）、财务负责人（B2+B3+B12+F2）、
  风控（G1+B3+D5+A4）都不满足「D1 或 D2 + A4」。这不是个别漏项，是六类型本身的
  分类维度不对：它按「职能」分，但「必有原子」按「控制点」写，两者不是一套坐标。
- `platform`（平台岗）在六类型里有，但范式库里没有真正的「平台岗」；
  `coordinate`（协调岗）与 `execute`（执行岗）的边界，在「部长」这个范式上被打破了
  （部长既有 A1/A2，又有 C2/E1/E3）。
- 21 个范式里，至少 3 个直接违反 57 的禁配表；还有 1 个（巡检）与 55 的 P-8 冲突。
  这说明 58 在写范式时，没有把 57-§四 当作硬约束逐条校验。

### 3.3 59 的划分：四族 / 五链 / 十五失败模式

**结论：五链是「工单生命周期」的划分，不是「74 原子」的划分；作为制衡骨架不完整。**

| 检查项 | 结果 | 说明 |
|---|---|---|
| 四族（信息/激励/认知/规范）是否 MECE | 大体成立 | 是四种「失灵来源」，不是四类岗位；可以接受 |
| 五链是否覆盖全部权责 | **否** | 只覆盖一张工单的提案/审议/执行/验收/审计；A3 终裁、C2 派工、A5/A6 议程、B/E/F/H/I 族大量原子不在链上 |
| 五链是否与 57 一致 | **否** | 57 明确允许 A1+C1、A2+D5、D8+C1；59 说「任何两链不得同一执行体/上下文/模型实例」 |
| 五链是否内部一致 | **否** | §二 是绝对分离，§六 又说只在「高相关×不可逆×自动检出力弱」时硬分离；两条规则打架 |
| 十五失败模式是否对应防线 | 大体对应 | 但部分病理是「人类政治」类比，AI 组织需要转译 |

**具体问题**：
- 五链把 A10（剩余裁量）放进「提案链」，但 A10 是决策权，不是提议权；
  它应该和 A3 一起放在「审议/决定链」，而不是提案链。
- 五链没有 A3（终裁）。如果 A3 不在任何链上，那么「最后拍板」这个人不受五链约束，
  这是五链模型最大的洞。
- 五链没有「协调链」：C2 派工、A5 议程、A6 召集、D7 异议受理，都不在五链里。
  这些权力恰恰是最容易形成「内朝/信息垄断」的地方。
- 五链没有覆盖 B（资源）、E（人事）、F（信息）、H（元规则）、I（协作）族。
  如果五链自称是「框架的制衡骨架」，那它只覆盖了骨架的一条肋骨。
- 59-§二 的「任何两链不得同一执行体/上下文/模型实例」与 57-§三.8 的
  「只在三条件同时成立处做硬分离」是两条相反的规则。前者是绝对禁令，后者是成本红线。

### 3.4 60 的划分：四层本体 / 十三面 / G0-G6

**结论：四分方向正确，但执行体与会话没有真正切开；十三面不是最小闭集；G 带与六类型/1-9 级未对齐。**

| 检查项 | 结果 | 说明 |
|---|---|---|
| 四分本体是否正交 | **部分** | 岗位/任职者清楚；执行体与会话重叠（都定义为「一次出工」） |
| 十三面是否 MECE | **否** | 任务含预算/时限，资源面也含预算/时限；上下文含教训，记忆面也含经验；沟通含反馈，反馈面单列；边界是权责/凭证的子集 |
| G0-G6 是否与 1-9 级一致 | **部分** | G1≈1-2、G2≈3-4、G3≈5、G4≈6、G5≈7-8、G6≈9；G0 不在 1-9；映射是「建议」不是定义 |
| G 带与六类型是否一致 | **未定义** | 六类型是横向职能，G 带是纵向能力；文档没有给出「类型×带」的矩阵 |
| G6 与 58 的「宰相」是否同一角色 | **未定义** | 58 有「宰相/协调总长」，60 有「G5 协调/宰相级」和「G6 幕僚长」；三者关系不清 |

**具体问题**：
- 执行体：文档说「一次出工实际运转的 执行环境（宿主+模型）」，持久性「会话级」；
  会话：「一次出工：任务书+上下文+工位+凭证」，持久性「单任务」。两者都叫「一次出工」，
  实际上是一个东西的两个侧面（手段 vs 场合），不是两层独立实体。
- 十三面：任务面自己就包含「预算帽+时限」，资源面又列「预算+节奏窗」；
  上下文面包含「教训」，记忆面又列「经验」；沟通面包含「汇报/求助」，反馈面又列
  「复核意见/打回理由」。这些是重叠，不是「互为必要条件」。文档说「任一缺失不可由
  其他面补」，但没有证明；例子只能说明重要，不能说明独立。
- G6：既是「对接制作人的唯一日常接口」，又掌握收件箱排序（事实上的议程设置），
  但没有 A5 议程/ F1 知情 的正式原子。这是「隐性权力没有对应原子」，违反 57 的
  「不存在无主的裁量」。
- G6 与 59 的审计链冲突：59 说审计「直报制作人」，60 说 G6 是「唯一日常接口」。
  如果审计也要经过 G6，审计独立性失效；如果审计可以直报，G6 就不是「唯一」。
  这是硬冲突，不是措辞问题。

## 四、硬冲突与硬缺口（必须先修，否则不能二审）

> 判定标准：两份文档对同一件事给出相反规则，或同一份文档内部自相矛盾，
> 或基础分类错误导致下游无法判定；照着文档做会出现「合法/非法」两可。

### H1 · 57 的「原子」定义与原子表自相矛盾

**原文**：
- 57-§〇：「『复核』『审计』『双人原则』不是原子，是『计量 + 否决 + 豁免』的组合。
  把它们当原子，权限表会爆炸且无法解释为什么能被绕过。」
- 57-§二：D1 复核、D4 独立审计、I7 双人控制，全部列为原子。

**问题**：这是同一份文档的直接矛盾。如果 D1/D4/I7 是原子，那么「复核/审计/双人原则
不是原子」这句话就是错的；如果它们不是原子，那么原子表就不该把它们列进去。

**为什么是硬冲突**：整个 58 的岗位组合、59 的五链、60 的 G3 都建立在
「D1/D2/D4 是原子」这个前提上。如果前提被推翻，下游全部要改。

**建议**：
- 二选一：
  (a) 承认它们是「控制型原子」，并说明它们为何通过原子性四判据；
  (b) 把它们降为「组合模式」，在原子表外单列，岗位只持有其组成原子
      （计量、否决、豁免、复核动作）。
- 无论选哪种，都要同步修改 58/59/60 的引用，不能只改 57。

### H2 · 57 的「组合封闭」与禁配表互斥

**原文**：57-§〇：「组合封闭——任意子集组合仍构成合法岗位，且不存在无主的裁量。」

**问题**：57-§三/§四 有 24 条禁配。如果「任意子集」都合法，禁配表就没有约束力；
如果禁配表有效，就不是「任意子集」。

**为什么是硬冲突**：这关系到「岗位合法性」的判定。一个公司作者按「任意子集」组合，
会得到非法岗位；按禁配表组合，又不符合「任意子集」的公理。

**建议**：把「组合封闭」改为：
> **任一合法岗位的子集仍合法（遗传性）；但并非任意原子子集都合法——合法性由
> 组合规则与禁配表共同判定。**
这样既保留「子集不放大权力」的直觉，又不与禁配表打架。

### H3 · 59 的「五链绝对分离」与 57 的「允许合并」直接冲突

**原文**：
- 57-§三：「允许且应当合并的组合：A1+C1（提议者执行）、A2+D5（批准+监控）、
  D8+C1（一线叫停自己）。」
- 59-§二：「任何一张工单/一次变更，其生命周期由五条链分段持有，**任何两链不得由
  同一执行体、同一上下文、同一模型实例同时持有**。」

**问题**：A1 在提案链、C1 在执行链；A2 在审议链、D5 在审计链；D8 在验收链、C1 在执行链。
这三组都是 57 明确允许的，59 却全部禁止。同一岗位在 57 合法、在 59 非法。

**为什么是硬冲突**：这不是「原则 vs 例外」的措辞问题，而是两条规则的方向相反。
照着 59 做，57 的「允许合并」全部作废；照着 57 做，59 的五链全部破。

**建议**：
- 把五链分离分成**硬分离/软分离/补偿控制**三档；
- 硬分离只用于「错误相关性高 × 后果不可逆 × 自动检出力弱」的场景（57-§三.8 已给出判据）；
- A1+C1 这类低风险合并，允许但要求「同事项的验收/审计仍由他岗承担」；
- 在 59-§二 明确写「本条的绝对分离仅适用于高风险变更；其余按 57-§三.8 的判据」。
- 同时修正 59-§二 与 59-§六 的内部矛盾（绝对规则 vs 成本红线）。

### H4 · 58 的多个范式直接违反 57 的禁配表

**原文/位置**：
- 58-§3.2「部长」：A1 提案 + A2 部门内批准（限额）——57 禁配 #1「A1 ⊥ A2（同事项）」。
- 58-§3.1「宰相」：A5 议程 + A6 召集——57 禁配 #4「A5 ⊥ A6」。
- 58-§3.3「人事岗」：E3 考核 + E4 薪酬——57 禁配 #20「E3 ⊥ E5 ⊥ E4 三权同人」。
- 58-§3.3「安全岗」：C4「特权治理（非使用）」——57 的 C4 是「特权访问（使用）」，
  「治理」不是 C4，属于把原子改名后使用。
- 58-§3.2「巡检岗」：D5 + D8 + I2——55-P-8 规定 `watch` 只许「只读+告警」，
  D8/I2 是变更权，不是只读+告警。

**问题**：这些不是边角案例，是范式库里的核心岗位。一个公司作者照着 58 建岗，
会直接建出 57 判定为非法的岗位。

**为什么是硬冲突**：58 自己说「组合不合法=这个岗位不存在」「禁配表硬约束」，
但它的范式库自己违反了禁配表。

**建议**：
- 对每个范式增加一列「同事项限制」：A1 与 A2 可以同岗，但不得同事项；
  A5 与 A6 可以同岗，但必须有「议程/主持分离」的补偿控制（或明确 #4 是软规则）；
- 人事岗的 E3/E4 如果只是「程序持有」，就不能写成持有 E3/E4；应新增
  「程序持有 vs 决定持有」的区分，或改用「E3 组织/E4 执行」这类子权限；
- 安全岗的 C4 要么改为 C5/D5，要么新增「特权治理」原子；
- 巡检岗的 D8/I2 要么承认 `watch` 可以叫停/把关（修改 55-P-8），要么从范式里删除。
- 在 58 末尾加一张「21 范式 × 24 禁配」的核对表，逐格打勾；这是二审的硬门槛。

### H5 · 60 的「G6 唯一日常接口」与 59 的「审计直报制作人」冲突

**原文**：
- 58-§3.1 审计负责人：「双线汇报（功能→制作人、行政→宰相）。」
- 59-§二 审计链：「不参与设计与运营；**直报制作人**；只读、限时、限范围；豁免权。」
- 60-§三 G6：「**对接制作人的唯一日常接口**」；「全景上下文+制作人收件箱
  （待批/异常/预算/人事按『需要你出手』排序）」。

**问题**：三条线不一致。58 说审计「功能→制作人、行政→宰相」；59 说「直报制作人」；
60 说 G6 是「唯一日常接口」。如果 G6 是唯一接口，审计、异议、辩护、不信任票都必须
经过 G6；G6 可以过滤、排序、延迟，审计独立性失效。如果审计可以直报，G6 就不是「唯一」。
同理，57 的 D7 异议受理、I3 独立辩护、I8 不信任票，都需要「不被过滤的直达通道」。

**为什么是硬冲突**：这不是「接口设计」问题，是治理结构问题。一个掌握信息入口的人，
即使没有名义上的终裁权，也可以决定「什么能被看到」，这就是 59 自己列出的
「内朝」「信息垄断」病理。

**建议**：
- 把「唯一日常接口」改为「**唯一日常经营接口**」，并明确列出**直通例外**：
  审计（D4）、异议/申诉（D7）、独立辩护（I3）、不信任票/退出（I8）、紧急叫停（D8）。
- 这些直通通道必须留痕、可审计，G6 不得过滤/延迟；G6 的收件箱排序权应显式定义为
  A5 议程权（或明确它只是「排序建议」，不改变可见性）。
- 在 59 的失败模式里补一条「幕僚长/信息入口垄断」，并给出对应防线。

### H6 · 60 的「十三面互为必要条件/最小闭集」没有被证明，且存在重叠

**原文**：60-§二：「十三面互为必要条件的证明=任一缺失导致的失效模式不可由其他面补。」
「十三面是自洽的最小闭集。」

**问题**：
- 任务面已包含「预算帽+时限」，资源面又列「预算+节奏窗」——重叠。
- 上下文面包含「教训」，记忆面又列「经验」——重叠。
- 沟通面包含「汇报/求助」，反馈面又列「复核意见/打回理由」——重叠。
- 边界面（不许碰清单）本质是权责/凭证的否定面，不是独立维度。
- 工具面与技能面高度相关：技能往往要求工具，工具没有技能也用不好。

**为什么是硬冲突**：如果十三面不是最小闭集，那么「缺任何一面，干活不闭合」的
强断言就不成立；下游用它做「上岗检查表」时，会重复检查/漏检。

**建议**：
- 把十三面分成两层：
  * **主维度**（不可再分）：身份、任务、授权/边界、资源、信息/上下文、工具/技能、
    证据、反馈、沟通；
  * **派生要求**（由主维度推出）：记忆（上下文+时间）、边界（授权+凭证）、
    工位（资源+隔离）等。
- 或者保留十三面作为「检查清单」，但删掉「最小闭集」「互为必要条件」的强断言，
  改为「一张覆盖清单，允许重叠，不宣称最小」。
- 如果坚持「最小闭集」，必须给出反例检验：逐面删除，证明不能被其他面补；
  目前文档只给了「缺了会怎样」的例子，没有证明「不可替代」。

### H7 · 57 的「权/责」模型缺「义务」，F2 的权型标注错误

**原文**：
- 57-§一 四型：作为权、要求权、变更权、豁免权。
- 57-F2「报告义务」：权型=「要求」。
- 57-§〇：「责的三件套=forum/证据/制裁」。

**问题**：
- 霍菲尔德四型是「权」的分类；「义务」是「要求权」的对应项（claim ↔ duty），
  不是「要求权」本身。F2 是「报告义务」，却标成「要求」，这是权型错误。
- 「责的三件套」是**事后问责**（向谁交代、凭什么、交代不清怎样），不是
  **事前义务**（必须做什么、什么时候做、做到什么程度）。
- 57 的原子表里，C1 执行、F2 报告是「必须做」的义务，但它们的权型被写成
  「作为/要求」，没有「义务」这一型。结果：**「岗位=权责组合」实际上只有
  「权利 + 问责」，缺了「义务」这一半。**

**为什么是硬冲突**：58/60 反复讲「岗位欠什么」「义务面」「SLA」，但 57 的原子表
没有给「义务」一个正式位置。下游只能把义务塞进「责」或「任务」，导致同一概念
三种叫法，无法统一判定。

**建议**：
- 在 57-§一 增加第五型「**义务（duty）**」，或把表头改成「权型 / 义务型」两列；
- 重新标注 F2、C1、C6、D1、D2、D4、E3、F5 等「必须做」的原子；
- 把「责的三件套」改名为「**问责三件套**」，与「义务」分开；
- 增加一个「义务原子」小表：对象、触发、截止、验收、违约后果；
- 这样 58/60 的「obligations」才有上位定义，不会各写各的。

## 五、重要问题（应修，但不一定阻塞二审）

### I1 · 57 的 A3 与 A2 边界不清，导致「终裁者」过度集中

**现象**：
- 57-§三.1：「任何一类决策，全公司只有一个 A3 持有者。」
- 58「制作人」：A3 全域终裁；「部长」：A2 部门内批准（限额）。
- 60 G4 部长：A2 限额内批准；G6 幕僚长：无终裁。

**问题**：如果 A3 是「全域终裁」，那么部长只有 A2，没有 A3；部门内的争议、例外、
冲突，最终都要到制作人。这叫「一亩地经营权」，但没有「一亩地终裁权」。
另一方面，如果 A3 可以按决策类别分设（如预算 A3、人事 A3），那么「全域终裁」
就不成立。文档没有回答这个二选一。

**建议**：明确写：
- A2 = 常规批准（限额内，可重复）；
- A3 = 终裁（只用于规则冲突、例外、跨部门争议、不可逆事项）；
- A3 可以按「决策类别」分设，但每一类只能有一个 A3；
- 制作人保留「跨类别的最终仲裁」，不代替每一类的 A3。
这样既保留「一事一裁」，又不会把所有事都推到制作人。

### I2 · A7/A9/A10/A4 的「决定机制」缺口

**现象**：
- A7 搁置：「到期自动通过或自动失效」——谁定默认？如果 A7 持有者可以选默认，
  他就能把「搁置」变成「隐性批准」或「隐性否决」。
- A9 例外豁免：「同一例外重复 N 次→强制走制度修订」——谁计数、谁触发？
  如果豁免持有者自己计数，就不会触发。
- A10 剩余裁量：「默认归顶点；每次行使落账」——没有范围/期限/额度，
  是一张空白支票；与 57 自己的「限额参数化」规则不一致。
- A4 否决：「必须给理由与整改条件」——但没有「否决次数上限/复核/推翻」机制；
  一个否决者可以无限期阻断。

**建议**：
- A7 的默认语义由 H1/H2（规则所有者）设定，不由 A7 持有者设定；A7 只能延迟，
  不能决定结果；延迟必须落账。
- A9 的计数与触发由独立于豁免持有者的角色（D4/D9）承担；触发后强制 H1。
- A10 加「范围/期限/理由/事后审计」；把它定义为「宪法性保留」，不是日常权力。
- A4 加「否决后 N 次必须复核/合议/升级」；防止永久阻断。

### I3 · 58 的六类型与范式库不是一套坐标

**现象**：
- 六类型按「职能」分（执行/协调/治理/平台/情报/巡检）；
- 范式库按「岗位」分（部长/会计/出纳/法务/风控/安全/人事/规范委员会…）；
- 六类型的「必有原子」与范式的「原子组合」对不上（审计/法务/安全/财务/人事）。

**问题**：读者无法判断「会计」属于哪一类、「法务」属于哪一类、「部长」是协调还是执行。
类型与范式的关系没有定义，导致「新类型只能在组合不进六类时增设」这条规则无法执行。

**建议**：
- 把「类型」定义为**主族**（primary family），允许一个岗位有「主类型 + 副类型」；
- 或者把六类型改成「岗位族」，范式库按族分组，每族列「必有/可选/禁止」；
- 增加一张「类型 × 范式」矩阵，标出每个范式的主类型；无法归类的，新增类型或明确
  「混合型」。
- 特别处理：审计、法务、安全、财务、人事，这五个是「治理/资源/人事」的交叉，
  不应该硬塞进 `govern`。

### I4 · 58 的范式库覆盖不完备：大量原子无岗位承接

**现象**（抽样）：
- E5 晋升、E6 处分、E8 回避审查：没有明确持有者；
- H4 转授权、H5 除名：没有明确持有者；
- I3 独立辩护、I5 更正、I8 不信任票、I9 同侪晋升：没有明确持有者；
- C3 发布上线、D3 认证签章、D9 指标定义、G4 应急指挥：没有明确持有者；
- F3 披露、F4 保密、F6 对外代表、F7 对外发言、F8 诉讼和解：没有明确持有者；
- B6 采购下单、B7 验收收货、B13 用印：没有明确持有者。

**问题**：58 自称「公司模板的零件盒」，但零件盒里缺件。一个公司作者按 21 个范式
建公司，会发现很多原子没人持有，只能临时发明岗位；这又绕开了禁配表。

**建议**：
- 增加一张「74 原子 × 持有范式」覆盖矩阵；每个原子至少有一个「主持有者」，
  或者显式标注「默认不启用/外化/由制作人保留」。
- 对「保留/外化」的原子，写明问责归属（不能因为没岗位就不问责）。
- 这张矩阵是 58 二审的硬门槛，比再写 10 个范式更有用。

### I5 · 制作人「无禁配」与「制衡者也被制衡」冲突

**现象**：
- 58「制作人」：「无禁配（终裁者）；但受章程与判据约束——终裁者的制衡在 59-§四。」
- 59-§四 是「保留事项」，列的是制作人**保留哪些权**，不是**限制制作人**。
- 59-§〇 又说「制衡者必须也被制衡」。

**问题**：制作人是唯一一个「没有禁配」的角色，可以同时提议、批准、终裁、保管、
记录、审计（如果他愿意）。「终裁者的制衡在 59-§四」这句话不成立：保留事项是权力，
不是约束。真正能约束制作人的，只有章程、判据、外部审计、公开、退出机制，但文档
没有把这些写成可执行的约束。

**建议**：
- 明确「终裁者不免于自利型禁配」：至少 A1⊥A2（同事项）、B9⊥B10⊥B11、E4 自定薪酬、
  C1⊥D4 自审，这四类对制作人同样适用；
- 如果制作人必须自兼（小公司），则用「外部锚」：外部审计、公示、事后复盘、
  独立顾问、退出权；
- 增加「制作人干预日志」：非保留事项的干预必须说明理由、落账、可被审计；
- 59-§四 改名「制作人保留权力」；另加一节「制作人约束」。
- 这是「自治理」能否成立的关键：如果顶点不受约束，组织就还是「人治 + 流程装饰」。

### I6 · 59 的五链不完整：A3、协调链、资源/人事/信息/元规则链缺失

**现象**：
- 五链：提案/审议/执行/验收/审计。
- A3 终裁不在任何链；C2 派工、A5 议程、A6 召集、D7 异议不在任何链；
  B/E/F/H/I 族大量原子不在链上。

**问题**：五链只覆盖「一张工单的生命周期」，不是「组织的制衡骨架」。如果把它当
完整骨架，会漏掉最关键的「谁决定、谁协调、谁管钱/人/信息/规则」。

**建议**：
- 明确五链的适用范围：「仅覆盖工单/变更的生命周期；资源、人事、信息、元规则、
  协作另有横切制衡」。
- 增加「协调链」：C2/A5/A6/D7，明确与提案/审议/执行/验收/审计的接口；
- 增加一张「族 × 链」矩阵：A/B/C/D/E/F/G/H/I 每一族的主链/辅链/跨链；
- 把 A3 放入「审议/决定链」，A10 从「提案链」移到「决定链」；
- 这样五链才是「骨架」，不是「一条肋骨」。

### I7 · 59 把「框架/组件」当成没有岗位的行动者

**现象**：
- 59-§二 执行链：「无权改状态（状态推进归框架）」；
- 59-§二 横切纪律：「事件/台账由独立于执行链的组件写入」。

**问题**：在一个纯管理模型里，「框架」「组件」不是行动者。谁对「状态推进」负责？
谁对「记录」负责？如果不指名岗位/原子，就是「无主裁量」，违反 57-§〇 的
「不存在无主的裁量」。

**建议**：
- 把「状态推进」指派给一个具名岗位/原子（如 C2 派工、或新增「案件管理」原子）；
- 把「记录」指派给 B10 记录岗/会计，并写明其 forum/证据/制裁；
- 如果确实由「制度/规则」自动推进，也要写明「规则所有者」和「异常时的人工兜底」；
- 不要用「框架」代替「谁负责」。

### I8 · 59 的制衡指标需要基线与分层，不能一刀切

**现象**：
- 「否决率长期=0 → 橡皮图章」「批准延迟≈0 → 秒批」「复核分歧率恒=0 → 同源复核实锤」。
- 这些阈值没有按风险等级/事项类型分层。

**问题**：
- AI 的审阅速度可以很快；延迟≈0 不一定是橡皮图章，可能是事项简单/规则明确。
- 否决率=0 可能是提案质量高，也可能是审议链被绕过；单看比率无法判断。
- 复核分歧率=0 可能是同源，也可能是复核标准非常明确；需要看复核的**证据覆盖**
  和**反例抽样**，不能只看分歧率。

**建议**：
- 每个指标按「风险等级 × 事项类型」设基线；
- 配「反指标」：否决率配周期时延/返工率；延迟配复核深度/证据覆盖；分歧率配
  抽样复核/事后事故率；
- 增加「否决是否被推翻」「复核是否改变了结论」这类**效果指标**，不只看数量；
- 对 AI 场景，少用「人类审批延迟」作为唯一代理，多用「独立证据数/反例覆盖」。

### I9 · 60 的执行体/会话未切开，G 带与六类型/1-9 未对齐

**现象**：
- 执行体：「一次出工实际运转的 执行环境（宿主+模型）」，持久性「会话级」；
- 会话：「一次出工：任务书+上下文+工位+凭证」，持久性「单任务」。
- G0-G6 与 1-9 的映射是「建议」，没有定义边界；G 带与六类型没有矩阵；
- G5「协调/宰相级」与 G6「幕僚长」和 58「宰相/协调总长」三者关系不清。

**问题**：执行体与会话都定义为「一次出工」，读者无法判断「换执行体」和「换会话」
是不是同一件事；G 带是纵向能力，六类型是横向职能，两者没有交叉表，岗位设计时
会出现「G4 部长」与「govern 岗」谁优先的困惑。

**建议**：
- 把「执行体」定义为「可复用的执行能力（宿主+模型+工具面）」，把「会话」定义为
  「一次具体的出工」；执行体可以跨会话复用，会话不能跨执行体；
- 或者合并为「出工」一层，另设「能力面」作为属性，不强行四分。
- 增加「六类型 × G0-G6」矩阵，标出每个格子的典型岗位/权限；
- 明确 G6 与 58 宰相的关系：是同一岗位的两个名字，还是两个岗位（幕僚长 vs 协调总长）；
- 如果 G6 是新岗位，补进 58 的范式库；如果是同一岗位，统一命名。

### I10 · 「独立性」的定义在四份文档里不一致

**四套定义**：
- 57-E8：「同模型/同上下文/同数据源/同上级指标=关联」；
- 58-§五：「不同模型/不同上下文/不同数据源/不同时间/不同指标」；
- 59-§二：「不同上下文/工具/时点/外部事实」；
- 60-G3：「不同模型/不同上下文/不同数据源」。

**问题**：同一概念四种口径。读者无法判断「不同时间」算不算独立、「不同工具」
算不算独立、「不同上级指标」算不算关联。这直接影响 D1/D2/D4 的合法性判定。

**建议**：
- 定义一张「独立性剖面」：
  * 模型、上下文、数据源、工具链、时点、指标口径、上级汇报线；
  * 每个维度标「同/异」，并给出「最小独立组合」（如 D1 至少模型+上下文不同）；
- 57/58/59/60 全部引用这一张表，不再各写一套；
- 明确「不同时间」是弱独立，「不同模型+不同数据源」是强独立；不要把所有维度等价。

### I11 · 「AI 无恶意」的前提与 59 的「激励残留」不一致

**现象**：
- 57 前提：「组织成员是 AI——不存在骗与恶性竞争；制衡的对象是错误相关性、
  质量失守、权限渐变。」
- 59-§一：「激励论大幅放松但不归零（奖励黑客与目标漂移是自利的功能等价物）。」

**问题**：57 说「不存在骗」，59 说「自利的功能等价物仍在」。这不是措辞差异，
是前提冲突。如果 AI 会奖励黑客/目标漂移/被外部诱导，那么「防恶降级为审计」就不够；
如果 AI 真的无恶意，59 的「激励论不归零」就没有对象。

**建议**：
- 把前提改为：「**不以人类恶意为主要设计假设；但保留最低限度的防欺骗、防合谋、
  防奖励黑客层**。」
- 区分「恶意（intent）」与「错位（misalignment）」：AI 可以无恶意但目标错位；
  错位需要用激励/指标/审计来治，不是用「信任」来治。
- 把人类操作者、外部合作方、供应链也纳入威胁模型：他们可以有恶意；
  「AI 无恶意」不等于「系统无恶意」。
- 这与开源/外部公司包的现实直接相关；如果不修，整套防恶降级会在真实场景里
  变成「假设性安全」。

### I12 · 「权可授，责不可授」与分布式运营责任没有调和

**现象**：
- 57-公理二：「权可授，责不可授；授权人仍对结果负责。」
- 60-§一：「越权追谁：会话 → 任职者 → 岗位 → 授权链 → 制作人。」

**问题**：如果责任不可授，那么所有责任最终都回到制作人；中间岗位只有「操作责任」，
没有「管理责任」。这会导致两种极端：要么制作人成为唯一责任主体（组织无法自治），
要么中间岗位的「责」只是名义上的（问责链形同虚设）。

**建议**：
- 区分三层责任：
  * **运营责任**（这件事谁做、谁负责交付）——归任职者/岗位；
  * **管理责任**（这个岗位/部门是否被正确设计、监督、纠偏）——归上级/部长；
  * **最终责任**（组织对外的最终承诺）——归制作人。
- 「责不可授」应表述为「最终责任不可转移」，而不是「所有运营责任都归授权人」。
- 在 57/60 里写明三层责任的归属、证据、申诉路径；否则「责不可授」会被误读为
  「中层无责」。

### I13 · 问责三件套缺标准：forum/证据/制裁没有统一模板

**现象**：
- 57 每个原子都有「责」，但写法不一：有的写「计入绩效」，有的写「可被推翻」，
  有的写「事故」，有的写「复盘」。
- 没有统一的 forum 类型（制作人/委员会/审计/同行/外部）、证据等级、制裁档位。

**问题**：同一份「总表」，问责口径不统一，读者无法比较不同原子的责任强度；
也无法判断「这个岗位被问责时，到底谁来判、凭什么判、判到什么程度」。

**建议**：
- 定义 forum 类型：制作人、委员会、审计、同行、外部锚；
- 定义证据等级：自述/记录/第三方复核/可复算；
- 定义制裁档位：提醒/记录/降档/停派/撤职/除名；
- 每个原子填「forum 类型 + 最低证据等级 + 制裁范围」；
- 这张表比「责的三件套」一句话更有用。

### I14 · 「岗位=权责组合」与 `mandate`/`interfaces` 的关系未定义

**现象**：
- 58 的岗位模型：`atoms + params + interfaces + holder`；`mandate` 在 55 的字段里；
- 58 说 `interfaces` 是「57 原子的关系面投影」；
- 但没有说 `mandate` 是原子的摘要，还是独立文本。

**问题**：如果 `mandate` 是独立文本，它可以与原子组合冲突（写着「负责质量」，
但原子里没有 D1/D2）；如果它是原子的摘要，就不应该单独手写。`interfaces` 同理：
如果是投影，为什么还要单独配置？如果是独立配置，如何防止与原子冲突？

**建议**：
- 明确 `mandate` = 原子组合的人读摘要（派生，不独立授权）；如要写额外职责，
  必须映射到原子，否则视为「未授权职责」；
- `interfaces` = 原子关系的投影（派生），或明确「接口可以独立配置，但必须与
  原子兼容」；加一致性校验；
- 这样「岗位=权责组合」才是真的组合，不是「组合 + 一段自由文本」。

### I15 · 60 的「记忆属于任职者」只解决了归属，没解决转岗/离岗/接替

**现象**：
- 60-§一：「记忆属于任职者（工号），不属于会话，也不属于执行体。」
- 58-§六 退役清单：「凭证/派单边/订阅/在途单/外部连接」，没有「记忆」。

**问题**：如果记忆属于任职者，那么：
- 任职者转岗，记忆跟着人走还是留在原岗位？
- 任职者离岗/退役，记忆归档、删除、还是可被继任者读取？
- 任职者换执行体/模型，记忆是否保留？保留哪些？
- 团队/项目级记忆，属于谁？谁可以读、谁可以删？

文档只回答了「属于谁」，没有回答「之后怎么办」。在 AI 组织里，记忆是经验资产；
没有生命周期，就会出现「人走记忆丢」或「记忆被错误继承」两种极端。

**建议**：
- 定义三类记忆：个人记忆（随任职者）、岗位记忆（随岗位，供继任者）、
  组织记忆（公司级，公开/受控）；
- 定义转岗/离岗/接替时的处理：哪些随人、哪些留岗、哪些归档、哪些删除；
- 定义读取/修改/删除权限，以及「记忆继承」的审批；
- 把记忆生命周期写进 58 的岗位生命周期与 60 的 13 面，而不是只写「属于任职者」。

### I16 · 60 的绩效归任职者，但模型版本是解释变量：缺少归因方法

**现象**：
- 60-§一：「绩效算任职者；执行体的模型版本是绩效的解释变量——同工号换模型后的
  表现差异必须可分离，否则考核失真。」

**问题**：这句话提出了正确的问题，但没有给方法。如果同一个任职者换了模型，
绩效变化多少算人的、多少算模型的？如果没有配对任务/对照设计，考核会把模型升级
算成人的功劳，或把模型降级算成人的过错。

**建议**：
- 定义「绩效归因」的最小方法：同任务配对、模型版本分层、前后对照、人工校准；
- 明确「个人绩效」与「模型/执行体影响」分开报告；
- 对高风险岗位，要求跨模型复核/抽样，避免「模型红利」被误读为「人的能力」；
- 这也是 60 的 G 带晋升/降档的证据基础；没有归因，升降级不可信。

### I17 · 58 的「外部锚」只有名词，没有定义

**现象**：
- 58-§四 规模不变量第 12 条：「外部锚（内部无法分离时：执行可外化，验收/追责/终止
  必留内部）」；
- 规模表：「法务/审计：全外包」；
- 但没有定义「外部锚」是谁、凭什么资格、对谁负责、如何保密/回避。

**问题**：「外部锚」是一个关键控制，却只有名词。实际操作中会退化为「找个朋友签字」
或「外包即免责」。这不是制衡，是责任转移。

**建议**：
- 定义外部锚的类型：外部审计、独立董事/顾问、客户/监管方、行业认证机构；
- 定义资格、独立性、利益冲突、保密、报告路径、责任边界；
- 明确「外部锚提供意见/证据，不替组织承担最终责任」；
- 外部锚的选用/更换/付费由谁决定，不能由被审方自己定。

### I18 · 58 的「部长」是一个权力闭环，存在「藩镇」风险

**现象**：
- 58-§3.2 部长：A1 提案、A2 部门内批准（限额）、C2 部门派工、E1 提名、E3 初考。
- 57 禁配 #1 只禁「A1 ⊥ A2（同事项）」；#18 只禁「E1 ⊥ E2（同人同岗）」；
  #20 只禁「E3 ⊥ E5 ⊥ E4 三权同人」。没有一条禁「A2 + C2 + E1 + E3」的组合。

**问题**：部长可以提议、批准、派工、提名、初考，形成一个自我强化的闭环：
- 提自己熟悉的方案 → 自己批 → 派给自己提名的人 → 自己初考；
- 即使有限额，限额只限制单笔，不限制「方向」；
- 这就是 59 自己列出的「藩镇」病理：每次兼职都合理，总和是独立王国。

**建议**：
- 加一条「权力集中度」检查：同一岗位不得同时持有「提案+批准+派工+提名+初考」
  五项；至少拆出 E1（提名）或 E3（初考），或引入外部/跨部门校准；
- 对部门内的高风险事项，要求 D1/D2 来自部门外；
- 给部长加「限额+任期+轮岗+审计」四件套，而不是只加限额；
- 把「部长」拆成「业务部长」与「人事部长」两种范式，或明确部长不持 E3 终评。
- 这与 59 的失败模式 #3（藩镇）直接对应，应在 58 的范式库里显式设防。
