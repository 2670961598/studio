## 三、设计原则（逐条对文档，冲突即停）

1. **目录即 API、公司目录=唯一事实源**（docs/04-§二）：平台侧（Taiga/Matrix）不新增
   组织语义，只是目录的投影镜像（docs/21A-§2.2 同款声明）。
2. **单向同步**：目录 → 平台，永不做反向回写；平台 id 按名解析、绝不落盘进目录
   （docs/03 N11 口径）。对账发现漂移→修平台侧或 ESCALATE，不从平台拉回目录。
3. **daemon 唯一写入者**（docs/04-§二/§九）：公司目录的每一次人事写=daemon 单点代写，
   挂单据号进 commit message（git 历史=组织变迁史）。
4. **人事变动必挂单、append-only**（docs/01-C1-06）：生效即写 personnel_events，
   无单号拒绝——旁路变更的挂单语义见 §五.四。
5. **幂等基线**：平台资源先 GET 按名找、找到即 diff-复用（docs/30-§6 幂等基线；
   docs/32-§八「重名 400 → 幂等必须 GET-first」实测）。同步器两跑同结果。
6. **值只增不删**（N5）——唯一显式例外=Taiga 出厂状态集退役（§十.二 A3，走决策点 D3）。
7. **契约不随便动**（AGENTS.md 纪律 2）：不加事件名、不动七相位（docs/17-§2 冻结）、
   不动 GATEWAY_ACTIONS（留位给批示流，docs/49 缓办口径）。
8. **fail-closed 不静默**：未映射/未知态/同步失败一律显式报错或 ESCALATE 落账
   （与 fieldmap/unknown-state 既有纪律同族）。

## 四、总体架构

### 4.1 一图（数据流）

```
┌──────────────── 入口三路（终将合一） ────────────────┐
│ ①直改目录（git/制作人手改）  ②网页编辑面草稿→批示（C1-05/07，另单）  ③MCP hr.* 动作词（docs/49 留位，缓办） │
└──────────────────────┬─────────────────────────┘
                       ▼ 所有写最终=daemon 单点写公司目录（git commit 挂单号）
        公司目录（唯一事实源）departments/**/people/<工号>.md
                       │ ①stat/mtime 指纹（每拍，稳定窗 500ms）
                       ▼
        L1 热重载 reloadNow（已落地）──读→校验→信任闸→指纹→apply→SCHEMA_EVOLVE(RELOAD;)
                       │ apply 段（拍边界）
                       ▼
   ┌─ peopleDiff 分类器（新，纯函数）：前后快照 PersonRef 逐字段比对 ─┐
   │  文件级 stat diff 粗定位（hot-reload 已有）+ 快照级细分类        │
   └──────────────────────┬───────────────────────────┘
                          ▼
     personnel_events（append-only，挂单号）+ people 镜像 syncCompany
                          ▼
     hr_sync_log 任务队列（store v7 拟稿）——每拍「落账/心跳」相位尾消化 N 条（docs/17-§2）
        ├─▶ TaigaSync：membership 邀请令牌建号（docs/30-§6④）→ 角色绑定 → 调整/移除
        ├─▶ MatrixSync：shared-secret 建号（docs/21A-§2.3）→ 房间 invite → power_levels
        └─▶ 失败：幂等重试 → 3 连击 ESCALATE（断路器形状借用，docs/17-§6）→ 对账岗兜底
```

### 4.2 三入口一内核

`HrSyncPort`（拟落 `packages/core`，port 形状）：

```ts
interface HrSyncPort {
  /** 全量 onboard（幂等，--dry-run/--rollback 对齐 docs/03 N10-N12） */
  onboard(snapshot: CompanySnapshot, opts: { dryRun?: boolean }): Promise<OnboardReport>
  /** 增量同步：消化 peopleDiff（热重载 apply 段与 CLI 共用） */
  sync(diff: PeopleDiff): Promise<SyncReport>
}
```

- 入口①（热重载，本刀）：serve apply 段调用（§九）。
- 入口②（编辑面，后续单）：草稿→批示→生效时 daemon 写目录→热重载照常触发，同管线。
- 入口③（MCP 经营面，docs/49 定位=调岗/频率/成本的经营操作面）：动作词走
  GATEWAY_ACTIONS 契约批示流扩展，执行体=同一 HrSyncPort 内核——**本刀只留此接口位，
  不实现动作词**（docs/49「MCP 定位澄清与缓办」落档口径②③）。

### 4.3 与 DEV-43 类型系统的边界

类型流（workflows/types、typeInbox、initialState 解析序「显式 > typeInbox[type] >
states[0] > 平台默认」——docs/18-§2.1.1、docs/51 W-1..W-9）是**单据状态机**面；人事

## 五、人事变动事件化

### 5.1 分类器（peopleDiff，纯函数，可单测）

输入=前后两份 CompanySnapshot（serve 侧 apply 段在替换持有者**之前**可同时拿到）；
辅助输入=文件级 StatDiff（hot-reload 已产）做粗定位与审计留痕。

主键=工号（C1-02：工号=文件名=永不变主键）。PersonRef 字段集
（id/name/login/level/dept/role/reports_to/skills/status/executor…）逐一比对：

| 快照事实 | 事件 type | prev/next | 备注 |
|---|---|---|---|
| 新 id 出现，people 表无此工号 | 入 | prev=∅ next=level/dept | |
| 新 id 出现，people 表有且 status∈{retired,paused} | 复 | prev=旧 status next=active | 退/停复职；目录文件新增+档案在库 |
| id 消失 | 退 | prev=level/dept/status next=∅ | 与 status=retired 语义区分见 5.3 |
| level ↑ / ↓ | 升 / 降 | prev/next=level 数字 | |
| dept 变 | 调 | prev/next=dept path | |
| status active→paused / paused→active | 停 / 复 | prev/next=status | |
| name/role/skills 等描述类变更 | 调 | prev/next=该字段 | 复合变动拆多条（records.ts 拟稿口径） |
| 仅正文（六节 Markdown）变更 | 不产事件 | — | 只 RELOAD，不进人事流（自述段手编是合法日常） |

校验器已有悬空引用/孤儿档案双检（docs/04-§九），分类器以快照为准、不信文件名。

### 5.2 落账序（apply 段内，全部幂等可重入）

```
1. ensureAiwsTree（已有，先行——人事变树变）
2. peopleDiff = diffPeople(prevSnapshot, next)          ← 新
3. 对每条变动：
   a. 挂单号解析（§5.4）→ 无单则先补开「人事对账单」（决策点 D7）
   b. appendPersonnelEvent（append-only，同 id 幂等）    ← 新接线
   c. hr_sync_log.enqueue(person, kind, platform×2)      ← 新
4. syncCompany(next)（people/departments 镜像落库）      ← 新接线（启动期也接一次）
5. seedJobs/removeMissingJobs（已有）
6. 持有者替换 + engine.applyCompanyUpdate（已有）
7. SCHEMA_EVOLVE(RELOAD;) note 增 people 变动段（+入/退/调… 计数） ← 扩 note
```

失败面沿用热重载既有分类：apply 内抛错=RELOAD_APPLY_FAILED 保持旧配置整批重试
（步骤 3 幂等保证重入安全）；平台侧 IO 失败**不在 apply 内同步做**——只入队，由
hr-sync 相位尾异步消化（决策点 D1），避免平台抖动拖死热重载。

### 5.3 退 vs 停的语义约定

- **停（paused）**：档案在目录、status=paused。不派新单（分类器产停事件；引擎侧
  resolvePerson 是否跳过 paused 属引擎后续微调，本设计标注需求：派工择人应过滤
  status≠active，拟随本刀实现切片 S3 一并落，防「停职仍在接单」漂移）。
- **退（retired/文件删除）**：目录除名。.AIWS 归档（已有）、Taiga membership 移除、
  Matrix 房间 kick（D4）、在途单处置（D5）。
- 「档案文件删除但 status 仍 active」=目录不一致——校验器孤儿侧已拦；反之
  status=retired 文件仍在=合法「留档退休」，只产退事件一次（幂等键防重）。

### 5.4 挂单语义（C1-06「无单号拒绝」与旁路现实的调和）

正常流=人事单先行：编辑面/MCP/制作人令 → 开 HR 单 → 批 → daemon 代写目录（commit
message 挂单号，docs/04-§二）→ 热重载触发 → 事件挂该单号。
旁路流=直改目录（制作人手改/git 操作）：无单号。**daemon 自动补开「人事对账单」**
（断路器「自动开 bug 单」同款先例，docs/17-§6；type 用系统保留词 `task` 或拟
`hr-recon` 类型——走 DEV-43 类型声明，零代码）→ personnel_events.ticket=补开单号，
评论留 diff 摘要。C1-06 不破：事件恒有单号，只是单号后补。取舍见决策点 D7。

### 5.5 台账 events 承载（拟稿，D2）

personnel_events 是权威事件账本；面板事件流（:8787）的可见性经 events 表搭桥：
**ORG_UPGRADE + note 前缀 `HRSYNC;`**（对齐 RELOAD; 先例——25 枚举冻结不加名；
ORG_UPGRADE 语义=组织升级，cutover.ts:61 已自评待勘定，本设计给它在「组织变更族」
下的第二用途，正式归批随契约批次批示）。零值 tokens 桶，与 RELOAD 事件同形。

## 六、Taiga 联动面

### 6.1 账号/成员（onboard ④，docs/30-§6④ 实测修正版）

```
① admin 换 token（POST /api/v1/auth——daemon 已持 admin 凭据，daemon.yaml taigaAuth）
② POST /api/v1/memberships {project, username: <login>, role: <等级角色>, is_admin: false}
   → 邀请 token 不在 API 响应，落 console 邮件日志（docker logs <taiga>）
③ 抓取 token（日志正则定位邀请 URL——worker-p2 实证此路通，docs/32-§二④）
④ POST /api/v1/auth/register {type:"private", token, accepted_terms:true, …账号字段}
   → 201 = 建号+绑成员一次完成（POST /users 405 不存在——已证伪）
```

- **关注册态前置**：`ENABLE_PUBLIC_REGISTER/关注册` 下匿名均拒、此路通（docs/32 实测
  口径，生产 daemon.yaml 环境即此形态）。
- **幂等**：GET /memberships?project 按用户名找，已有即 diff-复用（角色变了只 PATCH）；
  建号后重跑=跳过。token 抓取失败→hr_sync_log 重试（日志轮转/时序是脆弱面，§十三）。
- **body 细节待真机复核**（register 的 username/password/full_name 逐字段形状）归
  切片 S0 探针单（读面先行，docs/30-§7 纪律）。

### 6.2 角色权限（onboard ⑤ + 运行期）

- onboard 建「等级锚点角色集」：L3/L2/L1 → Taiga 项目角色（映射表进 provision 配置
  拟稿，具体角色名/权限数组以 `/tmp/taiga-probe/roles-probe-co.json` 快照为底，值走
  切片 S0 定版）。guards.install 收窄闸（modify_{entity} 剥离）已落地不动——
  **角色权限数组=onboard/guards 面；成员挂哪个角色=人事同步面**，两不越界。
- 运行期：升/降级 → PATCH /memberships/{id} {role}（无 version 语义，实测
  docs/32-§八）；调部门不改 Taiga 角色（部门语义在自定义属性 dept 维，建单字段面
  已映射——docs/25-§3.2 v1.6），只联动 Matrix 部门房间（§七）。
- 退 → DELETE /memberships/{id}（在途单处置前置，D5）。

### 6.3 不做什么

不动 roles permissions 数组（guards 面）；不写转换矩阵进 Taiga（无双真源——框架
guard 全责，docs/30-§6 守闸补偿）；不做 Taiga 侧组织树（Taiga 无部门模型，dept 是
单据字段维）。

### 7.2 账号（shared-secret registration，docs/21A-§2.3 拍板）

```
GET  /_synapse/admin/v1/register           → {nonce}
mac  = HMAC-SHA1(shared_secret, nonce\0user\0password\0(not admin)\0(0|1))
POST /_synapse/admin/v1/register {nonce, username, password, admin:false, mac}
PUT  /_matrix/client/v3/profile/<mxid>/displayname   → 工号原文（大写）
```

- **localpart=工号小写**（MXID 语法禁大写——docs/21A-§2.2）：`AGENT-1`→`@agent-1:…`；
  displayname=工号原文，@唤醒解析按大写工号词（21A 既有口径）。
- **账号=身份锚+权限位，不是登录通道**：员工 agent 不上线，消息代发/收取全走 gateway
  bot 管理账号（21A-§2.2「网关 bot 一个管理账号」）。因此 join 非必须、invite 即足够；
  密码 daemon 随机生成落 daemon_kv（rootDir 本机盘、非 git 仓——密钥永不入库，
  21A-§4.2 口径；取舍 D6）。

### 7.3 房间与权限（power_levels）

## 九、与 L1 热重载的衔接（people 热改后自动触发同步）

### 9.1 挂点（唯一正确位）

`serve.ts` 热重载 apply 回调（§五.2 落账序）。关键约束：

- **prev 快照在替换前取**（`companyState.snapshot` 持有者赋值前）。
- **apply 内不做平台 IO**（只分类+落账+入队）——平台抖动不得拖死热重载
  （RELOAD_APPLY_FAILED 会连累配置回滚，代价不对称）。
- 手动 reload 通道（control/reload.request.json）与自动指纹共享同一 apply——
  两触发面天然同管线，无需另挂。

### 9.2 执行模型（D1 推荐：相位尾异步队列）

主循环七相位冻结（docs/17-§2：采集→state-diff→派发→收割→合并→回收→落账/心跳），
**不加第八相位**。hr-sync 执行体挂在**「落账/心跳」相位尾**：每拍从 hr_sync_log 取
pending ≤ N 条（`maxHrSyncPerTick` 可配，类比 maxActionsPerTick），逐条幂等执行。

- 不占泳道租约/在途上限（泳道=单据并发闸；人事同步非单据流，不与工位抢闸）。
- 失败重试+同(工号,平台,操作)错误签名 3 连击→ESCALATE+冷却（断路器形状借用，
  docs/17-§6；不自动开 bug 单——对账岗兜底即可，避免事件风暴）。
- 断电恢复：applying 态超时（一拍上限时间戳）→重置 pending 重入（幂等保证安全）。
- 启动期：daemon 起来先跑一次 syncCompany 对账（镜像与目录一致化）+清 hr_sync_log
  积压（启动全量对账与采集相位同族语义，docs/17-§2「启动全量对账」）。

### 9.3 与 .AIWS 的顺序保证

ensureAiwsTree 在 apply 段先行（已有）；平台同步（异步）延后于树——树是本地幂等
快操作，平台是远端慢操作，先后由 apply→相位尾自然保证，无需跨拍锁。

## 十、「新建单默认落出厂态 New unmapped」根治

### 10.1 根因链（三环）

1. Taiga 项目复制出厂模板带全套英文出厂状态集（New/Ready/…）；公司五态由
   provision **追加**（GET-first 只增不删，fields.ts:147-153）——出厂态全数留存。
2. Taiga 建单默认落项目级 `default_us_status`（出厂=New）——项目默认值面实证：
   taiga-front `default-values.jade`（`project.default_us_status` 等，
   ADMIN > Default Values 可改，即 `PATCH /api/v1/projects/{id}` 可写）。
3. New ∉ 五态表 stateFlow → state-diff 未知态 NOOP（引擎纪律「状态权威在平台侧、
   不猜不动」——serve.ts:1120 同款）→ 单据卡死，等人救（DEV-26..39 实证）。

既有缓解只盖住**走适配器且 fields 配了 states** 的建单（issues.create 初态解析序+
落位补一次 transition，issues.ts:168-180）；暴露面=平台 UI 手建单、第三方直调 API、
历史存量、未配 states 的项目。

### 10.2 方案 A：onboard 替换出厂状态集（治根，推荐主刀）

| 步 | 操作 | 端点/落位 | 幂等 |
|---|---|---|---|
| A1 默认态重指 | 把 default_us_status/default_task_status/default_issue_status（及 epic，如有）指到公司收件态（五态=新单；DEV-43 类型流=各 typeInbox 收件态，按 entity 档案分实体指） | PATCH /api/v1/projects/{id}（形状待 S0 真机复核） | 读现值 diff，已指即跳过 |
| A2 存量归化 | 扫描 state∈出厂集的单 → 逐单 transition 到收件态（fix-new-state.ts 语义收编进 onboard，按类型选收件态） | 既有 issues.transition | 已在目标态不重放 |
| A3 出厂态退役 | 引用清零后 DELETE出厂状态（先落状态集快照进 var/ 入档——roles 快照同款先例）；**N5「值只增不删」的显式例外**，走 D3 决策；保守替代 A3'=保留出厂态+未知态哨报警 | DELETE /api/v1/{entity}-statuses/{id}（前置条件待 S0：无引用才可删） | 引用未清零→跳过+报告 |
| A4 未知态哨 | daemon 采集相位：单据 state∉声明状态集 → ESCALATE（note=UNKNOWN_STATE，不 NOOP 沉默）+对账巡逻岗周期核「项目状态集−(公司声明集∪已知外来态白名单)=∅」（C1-08 看门狗口径；白名单=org-config `yt.known_foreign_states`，127-C 州表卫生——已知外来态降 FOREIGN_KNOWN 观察级，白名单吞不掉未声明新漂移） | engine 采集面 + S7 巡逻岗 | 每单每态一次（防刷屏比对位） |

A1 落地后，「显式 > typeInbox[type] > states[0] > 平台默认」解析序的末位兜底本身
变成映射态——**任何路径**（UI/API/适配器/未来实体）建单都落公司声明集内，DEV-43
多实体档案面同享。A2 清存量，A4 防回归（新实体/新类型/旁路建单）。

### 10.3 方案 B：建单显式初始态（治已建路径，辅助）

- B1（已在）：适配器初态解析序+落位补 transition——保持不动；A1 后其兜底链全安全。
- B2（收编）：放单脚本手工 transition 惯例（put-ticket*.ts）收进 CLI 建单命令——
  `studio-next` 建单恒带 initialState（显式位优先），脚本不再各自兜底。

### 10.4 推荐

**A1+A2+A4 必做**（治根+清存量+防回归），A3/A3' 走 D3 拍板（删 vs 保留+哨兵），
B2 顺手工程卫生。两方案非二选一——票面「or」实为组合：onboard 替换出厂状态集为主，
建单显式初始态为辅。

### 10.5 实现补记（studio-dev-95 落地定版，2026-10-20）

S0 真机源码复核结论（docs/32-§九）与四步落位：

  成功 204 无体。快照先行入档 `<rootDir>/var/`（roles 快照同款先例），persistSnapshot

- **A4 落位**：引擎**采集相位（相位 1）尾**执行（非另立 S7 巡逻岗进程面）：单级哨

## 十一、数据模型（store migration v7 拟稿）

```sql
CREATE TABLE hr_sync_log (
  id TEXT PRIMARY KEY,            -- ULID（appendEvent 同族生成口径）
  ts INTEGER NOT NULL,
  company TEXT NOT NULL,
  person_id TEXT NOT NULL,        -- 工号（people 表 FK 语义，不硬约束）
  kind TEXT NOT NULL,             -- 入/调/升/降/停/复/退（personnel_events type 同值域）
  platform TEXT NOT NULL,         -- 'taiga' | 'matrix' | 'ledger'
  op_key TEXT NOT NULL,           -- 幂等键：person+kind+字段维度（同键 done 即跳过）
  ticket TEXT NOT NULL,           -- 挂单号（personnel_events 同源）
  status TEXT NOT NULL DEFAULT 'pending',  -- pending|applying|done|failed
  attempts INTEGER NOT NULL DEFAULT 0,
  last_error TEXT,
  updated INTEGER NOT NULL
);
-- applying 断电恢复：updated 超一拍上限 → 重置 pending（幂等重入）
-- append-only 不加触发器（status 机流转合法——与 personnel_events 语义不同：这是任务队列不是账本）
```

台账事件（events 表）：ORG_UPGRADE + note 前缀 `HRSYNC;`（D2）；personnel_events
表：权威账本（§五）。三账各司其职：personnel_events=人事事实账（append-only）、
hr_sync_log=同步任务账（可流转）、events=面板可见性桥。
