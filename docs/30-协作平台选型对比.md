# 30 · 协作平台选型对比（自托管 FlowPlatform 候选实查）

> 2026-10-16 ｜ 调研工兵出品。任务：为「一家公司 = 一个项目」的多公司 AI 框架选**默认自托管协作平台**（FlowPlatform 端口的非 YouTrack 实现，见 `docs/23-协作平台解耦.md` §一）。
> 方法：全部结论经 WebSearch/WebFetch 对官方文档、官方 changelog、GitHub issue 实查（2026-10 现状），每条关键事实带来源 URL；未查证处一律标「待实测」。旧系统（WeTrack/在用 YouTrack）零接触，只引用其教训（`docs/03-YouTrack-对接方案.md` §三 N3：全局字段互相污染；§一：无 webhook、角色权限 API 只读、免费版 10 用户封顶）。
> 引用依据：`docs/23`（FlowPlatform 七能力端口）、`docs/03`（YouTrack 能力矩阵与 N1-N12 建模）、`docs/17-整体技术设计.md`（架构分层）。

## 0. 摘要与结论（一句话版）

- **推荐：Taiga**。唯一同时满足「管理面全 API 可写 + 状态集/角色/自定义字段全部项目级 + 自托管无配额 + 轻量（实测 ~1.5 GB RAM）」的候选——「一条命令 onboard 一家公司」可 100% API 化。短板：无平台侧状态转换 guard（角色×转换矩阵），第二道闸退化为「项目角色写权限收窄 + 框架第一道闸」。
- **次选：Plane**。states 项目级且 API 全 CRUD、隔离模型正确、API 活跃（v2 迭代中）；但自定义字段 provisioning 与 KB（Pages）两处 API 缺口（issue #8654 / #7319 均 OPEN）、容器多且 8 GB 内存起步、自托管版本路由与文档有出入（#9484）。列入观察名单，待 v2 API 补齐后重评。
- **不推荐为默认**：OpenProject（statuses/types 系统级全局 + 管理面 API 只读——两条硬标准双 ❌，恰是 WeTrack/YouTrack 教训复刻）；Redmine（管理面 GET-only 实锤）；GitLab CE / Gitea（无状态机/无字段，语义不合）；Tuleap（guards 能力全场唯一满分，但 x86_64 部署面 + 模板导入式 API，工程成本高，列为特例备选）。

## 3. 逐平台事实卡

### 3.1 Taiga —— 推荐

**许可证/配额现状**：taiga-back 与 taiga-docker 仓库为 **MPL-2.0**（[taiga-docker README](https://github.com/taigaio/taiga-docker)："Every code patch accepted in Taiga codebase is licensed under MPL 2.0"；[LICENSE FAQ](https://community.taiga.io/t/whats-taigas-open-source-license/138)：数年前从 AGPL-3.0 迁至 MPL-2.0）。注意 **taiga-front 仓库 README 声明 AGPL-3.0**（[taiga-front](https://github.com/taigaio/taiga-front/blob/main/README.md)）——双仓许可证不同，自托管不分发修改则无实际影响。**2024 后的「许可变动」实为商业变动**：2025-10-15 官宣 SaaS 恢复付费档（存量 SaaS 用户 2026-01-01 前须选档/缩项目/转自托管），官方明确「**Self hosted instances are not affected**」（[Paid plans are coming back to Taiga](https://community.taiga.io/t/paid-plans-are-coming-back-to-taiga/8534)）。自托管**无用户数/项目数限制**（官方社区答：「for self-hosted instances, there are currently no limits (for number of projects or members)」，[Team member limit?](https://community.taiga.io/t/team-member-limit/1386)）。

| 标准 | 判定 | 证据 |
|---|---|---|
| C1 API 完整度 | ✅ | 官方文档原话：「**Taiga has a complete REST API (the one used by the web app)**」——前端只吃公开 API（[docs.taiga.io](https://docs.taiga.io/)）。[API 参考](https://docs.taiga.io/api.html) 实查：projects / memberships / **roles** / **userstory-statuses / task-statuses / issue-statuses / epic-statuses** / severities / priorities / types / **四类 custom attributes 及其 values** / **webhooks（含 POST /test 与 log resend）** / wiki pages —— 全部 **POST 创建 + PUT/PATCH 更新**，状态类另有 bulk_update_order |
| C1 唯一缺口：建用户 | ⚠️ 待实测 | 无独立 admin 建-用户端点；用户创建走注册端点 `POST /api/v1/users`（[Creating a user from command line](https://community.taiga.io/t/creating-a-user-from-command-line/1491)）。注册开关 `PUBLIC_REGISTER_ENABLED` 默认关，后端须设 `"True"`、前端 `"true"`（大小写敏感，[taiga-docker README](https://github.com/taigaio/taiga-docker/blob/main/README.md)、[setup-production](https://docs.taiga.io/setup-production.html)）。**开关关闭时 admin token 能否调注册端点 = 待实测（onboard 关键前置）** |
| C2 项目级隔离 | ✅ | 状态集/角色/自定义属性在 API 上全部按 `?project=` 作用域（[API 参考](https://docs.taiga.io/api.html)：statuses、roles、custom-attributes 端点均为项目资源）。一家公司=一个项目，新公司不改旧公司任何枚举——**正面解决 N3 的 YouTrack 全局 bundle 污染问题** |
| C3 无配额 | ✅ | 同上（[community](https://community.taiga.io/t/team-member-limit/1386)） |
| C4 docker | ⚠️→✅ | 官方 compose 服务：taiga-back / taiga-front / taiga-events / taiga-async / taiga-protected / taiga-gateway(nginx) + PostgreSQL + RabbitMQ（[taiga-docker](https://github.com/taigaio/taiga-docker)），单口 9000。实测内存：4 GB 机器上全栈约 **1.5 GB**（2025-09 用户报告 [Self-hosting lightweight installation](https://community.taiga.io/t/self-hosting-lightweight-installation/8503)）。**ARM64**：官方称「Taiga works perfectly on ARM64 because it is the architecture we use for our SaaS」（[community](https://community.taiga.io/t/installing-and-hosting-taiga-on-arm64-based-machine/622)），但 Docker Hub 预编译镜像 arm64 manifest **待实测**；不行则按 2025-11 社区指南源码构建（[Docker Setup on ARM](https://community.taiga.io/t/docker-setup-on-arm/8580)） |
| C5 流程与权限 | ⚠️ | 角色是**项目级**且可 API 创建（roles POST，携带 permissions 数组，[API 参考](https://docs.taiga.io/api.html)）——可做到「本公司角色只在本项目存在」。但**无 per-transition 转换 guard**：任何有编辑权限的角色可把单据置为任意状态，角色权限粒度止于 view/add/modify/delete 级。字段级权限无 |
| C6 活动/webhook | ✅ | webhook 项目级 CRUD + 测试端点（[API 参考](https://docs.taiga.io/api.html)）。活动历史按实体：`GET /api/v1/history/{userstory|issue|task|wikipage}/{id}`（注意实体名单数，[API 参考](https://docs.taiga.io/api.html)）。**无全局时间线/epoch 游标（YouTrack activities 那种）——增量轮询需「列实体→逐个拉 history」或以 webhook 为主**，量级代价待实测 |

**FlowPlatform 映射小结**：issues ✅（US/task/issue 三实体天然映射需求/缺陷/提案三单型）；comments ✅；fields ✅（custom attributes + values 全 API）；kb ✅（wiki API）；activity ⚠️（webhook 主 + history 辅）；links ⚠️（epic→US→task 从属链明确，横向 relates 待实测）；guards ⚠️（角色收窄可 API 化，转换矩阵平台侧无，框架闸兜底）。

### 3.2 Plane —— 次选（观察名单）

**许可证/配额现状**：**AGPL-3.0** 开源（[plane.so/open-source](https://plane.so/open-source)；社区讨论 [Potential future restrictions on the self-hosted version](https://github.com/orgs/makeplane/discussions/1266)）。自托管 Community Edition 无用户配额，单命令 compose 安装。

| 标准 | 判定 | 证据 |
|---|---|---|
| C1 API 完整度 | ⚠️ | REST API 180+ 端点、文档齐全（[developers.plane.so](https://developers.plane.so)，2026-10 仍在更新）。**两处硬缺口**：① 自定义字段（custom properties）无 CRUD 文档端点，work-items API 响应也不回传其值——特性请求 [issue #8654](https://github.com/makeplane/plane/issues/8654) **仍 OPEN**（2026 评论：仅 `GET /work-items/{id}/properties/` 有未文档化支持）；② KB（Pages）创建/编辑 API 缺失——[issue #7319](https://github.com/makeplane/plane/issues/7319) **仍 OPEN**。另有自托管 v1.3.1 实际路由与文档不一致的 bug（[issue #9484](https://github.com/makeplane/plane/issues/9484)，open） |
| C2 项目级隔离 | ✅ | states 为项目作用域且全 CRUD：`/api/v1/workspaces/{slug}/projects/{project_id}/states/` GET/POST/PATCH/DELETE（[Plane States API](https://apis.io/apis/plane-so/plane-so-states-api)）；custom properties 对象内嵌 project/workspace 标识，属项目级（[API 参考 issue-types/properties](https://developers.plane.so/api-reference/issue-types/properties/overview)） |
| C3 无配额 | ✅ | CE 自托管无配额（[plane.so/open-source](https://plane.so/open-source)） |
| C4 docker | ⚠️ | 官方要求：**2 vCPU / 最低 4 GB、生产建议 8 GB**，端口 80/5672 等（[docker-compose 自托管文档](https://developers.plane.so/self-hosting/methods/docker-compose)）；官方页另有 4C/8G/50GB 建议（[plane.so/self-hosted](https://plane.so/self-hosted)）。容器清单长（web/space/admin/api/proxy/worker/beat/migrator + redis/rabbitmq/minio/postgres，约 10+）。相对 Mac mini 现有负载偏重 |
| C5 流程权限 | ❌ | 无按角色的状态转换矩阵；states 自由流转（文档与 issue 区均无该能力记载）。字段级权限无 |
| C6 活动/webhook | ✅ | work item activities API（append-only 审计流，[work-item-activities](https://developers.plane.so/api-reference/v2/work-item-activities/overview)）+ webhook（[developers.plane.so](https://developers.plane.so)） |

**FlowPlatform 映射小结**：issues/comments/activity/links ✅；states provision ✅；fields ⚠️（值可写否都存疑，#8654）；kb ❌（#7319）；guards ❌。

### 3.3 OpenProject —— 落选（教训复刻）

**许可证/配额现状**：CE 为 GPLv3、**无用户数限制**（[Community edition](https://www.openproject.org/community-edition)；[FAQ](https://www.openproject.org/docs/faq)）。EE（付费 add-on）锁 SSO/2FA/密码策略/多级自定义字段等（[pricing](https://www.openproject.org/pricing)）。

| 标准 | 判定 | 证据 |
|---|---|---|
| C1 API 完整度 | ⚠️ | API v3 业务面完整（work packages 全 CRUD、wiki pages、memberships、activities 等，[API 文档](https://www.openproject.org/docs/api/)）。**管理面只读**：statuses 仅 GET（[statuses 端点](https://www.openproject.org/docs/api/endpoints/statuses)）、types 仅 GET（[types](https://www.openproject.org/docs/api/endpoints/types)）、custom fields 仅 GET（[custom-fields](https://www.openproject.org/docs/api/endpoints/custom-fields)；社区确认定义不可 API 编辑，字段**值**可随 work package 写入）；**workflow 转换配置无任何 API**。建项目可 API，建状态集/改字典=UI 手工 |
| C2 项目级隔离 | ❌ | statuses/types 由系统管理员**全局定义**，项目只能选用不能自建（[Manage work package status](https://www.openproject.org/docs/user-guide/work-packages/work-package-status/)）——与 WeTrack/YouTrack 全局污染教训同构 |
| C3 无配额 | ✅ | 同上 |
| C4 docker | ✅ | 单容器（all-in-one）部署；官方最低 **4096 MB RAM / 20 GB 盘**（[System requirements](https://www.openproject.org/docs/installation-and-operations/system-requirements)），社区实测稳态 ~1.5 GB（[Reddit](https://www.reddit.com/r/openproject/comments/13cfuhn/installing_through_docker_compose_with_problem)） |
| C5 流程权限 | ⚠️ | 有 workflow（role×type 转换矩阵）模型，但只能 UI 配置、无 API |
| C6 活动/webhook | ✅ | Activities API 端点组（[API 文档](https://www.openproject.org/docs/api/)）；webhook 属 CE 核心功能（[API and webhooks](https://www.openproject.org/docs/system-admin-guide/api-and-webhooks)），非 EE 专属 |

**判定**：C1（管理面）+ C2 双硬伤直接命中我们最高权重两条，排除为默认平台。若未来只需「单字典多公司共用」的形态可复评。

### 3.4 Redmine —— 落选（判断获验证）

**许可证/配额现状**：GPL-2.0，自托管无配额。

| 标准 | 判定 | 证据 |
|---|---|---|
| C1 API 完整度 | ❌ | 官方 REST API 索引（[rest_api](https://www.redmine.org/projects/redmine/wiki/rest_api)）下逐页实查：**Trackers 仅 `GET /trackers`**（[Rest_Trackers](https://www.redmine.org/projects/redmine/wiki/Rest_Trackers)）；**Issue Statuses 仅 GET**（[Rest_IssueStatuses](https://www.redmine.org/projects/redmine/wiki/Rest_IssueStatuses)）；**Custom Fields 仅 GET（且需 admin）**（[Rest_CustomFields](https://www.redmine.org/projects/redmine/wiki/Rest_CustomFields)）；**workflow 转换配置零 API**。用户/项目/成员/issue 可写——管理面恰好是我们最需要的部分不可写。第三方 [redmine_extended_api 插件](https://github.com/jcatrysse/redmine_extended_api) 可解锁，但引入插件依赖即偏离「默认平台零补丁」 |
| C2 项目级隔离 | ❌ | trackers/statuses/workflow/roles 均站点级全局（各 wiki 页「Returns the list of all」全实例语义）；自定义字段全局定义。多公司=共享一套字典，互相污染 |
| C3 无配额 | ✅ | GPL-2.0 |
| C4 docker | ✅ | 单容器（bitnami 等），量级轻 |
| C5 流程权限 | ⚠️ | workflow 按 role×tracker 可配转换 + 字段按状态必填/只读（[Feature #21639](https://www.redmine.org/issues/21639) 语境）——模型存在但 UI-only |
| C6 活动/webhook | ⚠️→✅ | 2026 年大更新：**Redmine 7.0 原生 webhook**（HMAC-SHA256 签名，feature #29664 落地；7.0.1 加 webhook 管理页）（[Changelog 7.0](https://www.redmine.org/projects/redmine/wiki/Changelog_7_0)、[发布公告](https://www.redmine.org/news/161)）；此前仅 Atom 活动 feed + 插件（[suer/redmine_webhook](https://github.com/suer/redmine_webhook)） |

**判定**：「statuses/trackers/workflow 只读」的预判**验证成立**；叠加全局模型，排除。

### 3.5 GitLab CE —— 落选（确认）

| 标准 | 判定 | 证据 |
|---|---|---|
| C1 | ⚠️ | API 面广（项目/用户/成员/issue CRUD/label/milestone）。issue 无传统自定义字段；work items custom fields 文档现挂 Free/Premium/Ultimate 全档，但自管 Free 档需管理员开 `namespace_level_work_items` feature flag（[docs.gitlab.com custom fields](https://docs.gitlab.com/user/work_items/custom_fields)）——可用性待实测 |

| C3 | ✅ | CE 自管无用户数限制 |
| C4 | ❌ | 官方最低要求已抬到 **8 GB RAM**（内存受限环境）（[installation requirements](https://docs.gitlab.com/install/requirements)）——Mac mini 上与现有服务共存不现实 |
| C6 | ✅ | events API + webhook 成熟 |

**判定**：确认「issue 无自定义字段/无强制状态机」；资源量级再补一刀。排除。

### 3.6 Gitea —— 落选（确认）

| 标准 | 判定 | 证据 |
|---|---|---|
| C1/C5 | ❌ | 无状态机（open/closed）、无自定义字段，labels 是唯一分类机制；v1.19+ scoped labels 模拟状态（[Gitea Blog: labels & projects](https://blog.gitea.com/introducing-new-features-of-labels-and-projects)）；无转换权限矩阵 |

**判定**：作代码托管配件合格，作 FlowPlatform 主体语义不合。排除。

### 3.7 Tuleap —— 特例备选（guards 全场唯一满分）

| 标准 | 判定 | 证据 |
|---|---|---|
| C1 | ⚠️ | REST API 面大（[API Explorer](https://tuleap.net/api/explorer)），但 tracker 创建非细粒度 CRUD，走 **XML/JSON 模板导入**（[tracker 导入格式（含 workflow 与 permissions 节点）](https://docs.tuleap.com/administration-guide/projects-management/export-import/import-format/trackers.html)；[SO: create tracker via REST](https://stackoverflow.com/questions/52260271/)）——onboard 需维护模板工件 |
| C2 | ✅ | tracker（含字段/状态/权限）为项目级资产 |
| C3 | ✅ | GPLv2，CE 无配额 |

## 4. FlowPlatform 七能力 × 平台 实现难度映射

> 端口定义见 `docs/23` §一。难度：低=直连 API；中=需组合/妥协；高=缺 API 需绕道或预置。

| 能力 | Taiga | Plane | OpenProject | Redmine | Tuleap |
|---|---|---|---|---|---|
| issues | **低**（三实体三单型） | 低 | 低 | 低 | 中（tracker 模板先行） |
| comments | **低** | 低 | 低 | 低 | 中 |
| fields（schema+provision） | **低**（custom attributes CRUD + values PUT） | **高**（provision 无 API，#8654 OPEN） | 高（定义只读→全局字典一次 UI 预置，值可写） | 高（定义 GET-only） | 中（模板内定义） |
| kb | **低**（wiki API） | **高**（Pages 无建/编 API，#7319 OPEN） | 低（wiki pages） | 低（wiki API） | 中 |
| activity（since/cursor） | 中（无全局游标：webhook 主拉 + `history/{entity}/{id}` 辅；量级**待实测**） | **低**（activities API） | 低（activities API） | 中（journals include + atom；7.0 起有 webhook） | 待实测 |
| links | 中（epic→US→task 从属明确；横向 relates **待实测**） | 低（relations/dependencies） | 低（relations） | 低（issue relations） | 中（artifact links） |
| guards（install/uninstall） | **中**（角色+权限数组可 API 装/卸（roles CRUD），但无转换矩阵→「闸」降级为写权限收窄 + 框架第一道闸兜底） | 高（无模型） | 高（有模型无 API） | 高（有模型无 API） | **低-中**（transition×用户组 + Freeze fields 随模板导入，唯一原生「闸」） |

**guards 专节结论**（C5 的裁决）：

- 平台侧「角色×状态转换矩阵」**可经 API 配置的只有 Tuleap**（模板导入式，[workflow 文档](https://docs.tuleap.com/user-guide/trackers/administration/configuration/workflow.html)），代价是 x86_64 部署面 + 模板工件维护。
- Redmine / OpenProject 有该模型但 **UI-only**（[Redmine workflow 无 API](https://www.redmine.org/projects/redmine/wiki/rest_api)、[OpenProject 无 workflow API](https://www.openproject.org/docs/api/)）——若选它们，guard 变成「一次性 UI 安装手册」，违背 N6「guard 由 ticket-types.yaml 同源生成、禁手改」的双真源防线。
- Taiga / Plane / GitLab / Gitea 连模型都没有。**选 Taiga 即接受：第二道闸收窄为「项目角色写权限」（可 API 全自动）+ 框架侧第一道闸全责**——与 `docs/03` §二分工表「平台扛状态迁移 guard」一项相比是能力回退，需在实现单中明示该取舍。

## 5. 推荐与次选（理由链）

### 推荐：Taiga

1. **C1 满分是唯一解**：候选中唯一「建项目/建角色/建状态集/建自定义字段/配 webhook 全部官方 API 可写」（[API 参考](https://docs.taiga.io/api.html)），且官方确认 web 前端就吃这套公开 API——**凡界面上能干的事 API 都能干**（[docs.taiga.io](https://docs.taiga.io/)）。这正是「多公司自动 onboard」的命门；OpenProject/Redmine 倒在这里，GitLab/Gitea 倒在模型本身。
2. **C2 满分**：状态集/角色/自定义字段全项目级，「公司=项目」隔离干净，正面修复 YouTrack N3 全局污染教训。
3. **C3/C4 达标**：自托管无配额（[community](https://community.taiga.io/t/team-member-limit/1386)）；9 服务但实测 ~1.5 GB（[社区实测](https://community.taiga.io/t/self-hosting-lightweight-installation/8503)），Mac mini 可并跑。风险点（arm64 镜像 manifest、注册端点行为）已列待实测，均有社区先例可循。
4. **许可证稳定**：MPL-2.0（back），2025 商业化仅涉 SaaS、明文不动自托管（[官宣](https://community.taiga.io/t/paid-plans-are-coming-back-to-taiga/8534)）。
5. **代价（明示）**：无平台侧转换 guard、无全局活动游标。前者以「角色写权限收窄 + 框架闸」补偿（角色本身可 API 全自动安装，guard 精神保住一半：**谁能在本公司动手**可编程，**谁能转哪个状态**不行）；后者以 webhook 为主信道 + history 逐实体补偿。两者都不阻塞 onboard 全 API 化。

### 次选：Plane（观察名单，暂不施工）

1. C2 正确（states 项目级 CRUD 实锤）+ API 文档活跃（2026-10 仍在更）+ v2 API 演进中。
2. 两处 FlowPlatform 硬缺口（fields provisioning #8654、kb #7319 均 OPEN）+ 自托管路由漂移（#9484）+ 8 GB 档资源——**当前不满足 C1，但其缺口是「还没写」而非「模型没有」**，半年内复评一次性价比高。
3. 不选 OpenProject 为次选的原因：其短板是**架构性的**（全局字典 + 管理面只读），修不了。

## 6. 「多公司自动 onboard 全 API 化」在 Taiga 上的走法

> 对齐 `docs/03` §三 N10-N12（onboard 脚手架、id 按名解析绝不落盘、幂等+dry-run+回滚）。以下全部端点见 [API 参考](https://docs.taiga.io/api.html)。

```
studio-next platform onboard <company>          # 幂等；--dry-run / --rollback
├─ ① POST /api/v1/auth                     admin 换 token
├─ ② 模板层（一次性）：POST /api/v1/project-templates   公司模板（状态集/角色/CF 固化进模板）
│     或每公司显式：POST userstory-statuses|task-statuses|issue-statuses?project=X
├─ ③ POST /api/v1/projects（选模板复制）    公司=项目；短名=公司代号
├─ ④ 成员：POST /api/v1/memberships（admin 邀请）→ POST /api/v1/auth/register
│          {type:"private", token, accepted_terms:true} → 建号+绑成员一次完成
│          【2026-10-18 实测修正，见 docs/32：POST /users 405 不存在；邀请 token
│          不在 API 响应，落 console 邮件日志；关注册态此路通、匿名均拒】
├─ ⑤ POST /api/v1/roles?project=X          公司角色（等级锚点角色集）
├─ ⑥ POST /api/v1/{entity}-custom-attributes  工号/attempt/验收命令等字段
│          【2026-10-19 选B 定案（docs/25-§3.2 v1.6）：lane/level 两维=onboard 统一约定的
│           自定义属性映射（所有平台同形状）——本步一并建同名属性，适配器同形状翻译，
│           未映射显式报错】
├─ ⑦ POST /api/v1/webhooks（project 级）→ POST …/webhooks/{id}/test  验证回环
├─ ⑧ POST /api/v1/wiki                     KB 根页
└─ ⑨ 回写公司目录：platform 项目短名/实体映射（N11：id 不落盘，按名解析）
```

- **幂等基线**：全部资源先 GET 按名找、找到即 diff-复用（N5 精神：值只增不删，旧的置档）。
- **守闸补偿**：⑤ 安装的角色权限数组即「写权限收窄闸」；转换矩阵由框架 guard（statemachine 渲染）全责，禁止在平台侧手配（无双真源风险——平台侧本来也没有）。
- **活动同步**：⑦ 的 webhook 为主（实测 HMAC-SHA1 签名投递，docs/32 §三；**私网部署须 `WEBHOOKS_ALLOW_PRIVATE_ADDRESS=True`**）；轮询兜底用 `GET /api/v1/history/{entity}/{id}`（实测变更 diff 结构化在录，docs/32 §四）。
