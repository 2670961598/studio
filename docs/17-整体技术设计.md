## 1. 架构总览（组件与数据流）

```
制作人 ──批示/口味──→ YouTrack ←──wkey 网关（署名注入/动作词校验）──┐
   │                                                              │
   │            ┌──────────── daemon（唯一写入者）───────────────┐ │
   │            │ 调度表 → 唤起六源 → 主循环七相位 → 收割/合并/回收 │ │
   │            │      ↕ company 包（目录校验/报表/定时岗源）      │ │
   │            │      ↕ prompt 包（L0-L5→AGENTS.md/任务书）      │ │
   │            │      ↕ store 包（SQLite 台账，唯一写口）        │ │
   │            │      ↕ adapters（四原语→dsh/claude/codex/kimi） │ │
   │            └──────────────────────────────────────────────┘ │
   │                            │ spawn/kill（execa 进程组）      │
   │                     worker（一单一命）→ REPORT/闸门/证据      │
   ▼                                                              │
:8787 监控  :8788 对外API（默认局域网）  :8789 概览 /<slug>/        │
公司 git 目录（daemon 代写） ◄─────────────────────────────────────┘
```

三事实源不变：YouTrack=流程+工作知识｜公司 git 目录=组织人事｜SQLite=可重建投影台账。
文件产物（REPORT/stream/证据）落盘，库里只存路径+哈希。

## 2. daemon 内部设计

**主循环（相位机，每拍幂等）**：`采集 → state-diff → 派发 → 收割 → 合并 → 回收 → 落账/心跳`
- 采集：YouTrack 活动流增量（`start` epoch-ms 游标 + 最后活动 id 去重双保险）；启动全量对账
- state-diff：纯函数 `decide(state, level, type, lane_lease) → action`，golden trace 可回放
- 并发三闸：泳道租约（锁名不含 pid，TTL+续租+死主回收）/ 每拍上限 / 全局在途上限
- 同一 tick 内单只一单至多一动作；tick 返回结构化 actions 落账

**调度表（jobs 表，SQLite 持久化）**：
`{job_id, company, dept, cron, role, level, model_tier, budget_cap, payload, next_run_at, last_run_at, status}`
- 定时岗全部来自公司目录配置（D9）；启动时扫 `next_run_at <= now` 的槽位补跑（coalesce 成一次）
- 表达式解析用 croner；补跑/错过语义自己实现（APScheduler 语义无现成库）

**生命周期**：supervisor（launchd/看护脚本）拉 daemon；`/api/health` 心跳；
升级=进化管线候选制品，切权后 supervisor 重启加载。

## 5. 唤起与装配管线（prompt 包）

```
intent（六源之一）→ 装配器：
  L0 框架（config-home/prompts/） → L1 公司（<company>/prompts/） → L2 组织（部门 config+org-config）
  → L3 个人（departments/<部门>/people/<工号>.md 事实段摘要） → L4 项目（任务书+冻结验收+同类教训 top-k）（勘误 2026-10-17：实形为 departments/<部门>/people/<工号>.md——04-§二）
  → L5 工具（executor 能力声明+插件 manifest）
→ AGENTS.md（用户级通道优先；claude<2.1.277 回退 append-system-prompt-file）
→ 任务书（首次版/续跑版两模板；续跑版含前情摘要=上次 summary.json）
→ 分层指纹 W-<fwk>/co.<rev>/org.<rev>/p.<工号>.<rev>/t.<单号>.<att>/ex.<adapter>@<ver> 记账
```
裁剪优先级（超长时）：永不裁=红线/证据契约/验收口径/署名；先裁 L3 做过的事（留最近 N 单+画像数字）。
网页可编辑内容=不可信输入（引用块包裹+剥离命令形态行+记事件）。

## 6. 执行与收割（adapters 包）

四原语实现差异全在适配器内：
| executor | launch | stream | result_stats | kill |
|---|---|---|---|---|
| dsh | `dsh --profile headless --json`（锁版本） | NDJSON（step_end 带 usage） | tokens 有，**成本无价目表折算** | SIGTERM 可杀；成功判定=turn_end.completed+输出非空（非退出码） |
| claude | `claude -p --output-format stream-json --max-budget-usd` | stream-json result 事件 | 原生 cost/tokens/duration | killpg TERM→KILL |
| codex | `codex exec --json` | turn.completed.usage | tokens 有，成本折算 | 同上 |
| kimi | `kimi -p --output-format stream-json` | stdout JSONL；**usage 读 session wire.jsonl** | tokens 有，成本折算 | 同上（`-p` 与 yolo/auto/plan 互斥） |

收割成功契约（四要件）：终态事件 completed + 输出非空 + REPORT 落盘 + 闸门 exit=0。
REPORT 旁落 `summary.json` sidecar（结论/改动文件/打回理由）供续跑前情摘要。
断路器：同(单号,错误签名)连击 3 → 停重派+回首批位+自动开 bug 单+面板标记。
**半开重试（DEV-46 修订 2026-10-20，studio-dev-78 实证后）**：「停重派」=冷却窗（拟稿
30min，`breakerCooldownMs` 可配）内停——窗过放行**一次**半开试探派发（DISPATCH note 携
`breaker=half-open-probe` 锚）：试探成功=复位（成功信号，走 GATE_PASS 面），试探失败=回
全开续冷却（熔断时刻刷新，bug 单不重开）。熔断不再是死锁终态——复位唯一路径不再是
「被压制期间的成功信号」（结构性不可达）。熔断期间不吊销 ticket 的 wkey（吊销令试探
重签的 key 出生即死；终局吊销唯一收口=CLOSE）。

## 7. 网关与协作协议（yt 包 + gateway）

- **写入全收口**：agent 对 YouTrack 的一切写入经 wkey 网关；wkey 按单签发、关单吊销
  （关单即吊销，杜绝归档后仍有效）；scope/TTL/nonce；fail-closed
- **署名自动注入** `[公司·部门·岗位·级别]`；**动作词结构化**（枚举+zod，解析失败 fail-closed；
  中文自由批示由 LLM 回退解析——制作人中文习惯保留）
- 控制面自身也过网关（写路径全部收口，不留绕过通道）
- 读面分级：Full/Focused/Blind（验证岗 Blind，防生成者上下文污染）

## 8. 三端口服务（panel/api 包）

- **:8787 监控**：jobs/runs/workers（实时流 SSE）/事件流/断路器与漂移告警/成本趋势（全部读 SQLite）
- **:8789 概览**：`/<slug>/` 路由；tab=概览/组织/人事/财务/项目/报表/编辑中心；
  编辑中心=人事变动草稿→三档批示（D2）→daemon 单点写回
- **:8788 对外 API**：默认局域网（D4）；信息端点（company/org/people/projects/issues/finance/reports/docs）
  + 触发端点（requests/explore/tasks/intel，只落单不派工，幂等键+派单人锚）+ `/v1/agent-card`（org-config 生成，带版本/有效期）+ SSE 订阅；凭证三档（D5 全公开=信息面不限，触发面仍需凭证）

## 9. 错误分类（契约枚举，两级）

`类别×子因`：GATE_FAIL（验收红/超时/环境）· WORKER_DEAD（wall/budget/心跳/僵尸）· QA_BACK ·
STALL · NO_LANE · DISPATCH_FAIL（脏树/锁占/预查拦）· MERGE_CONFLICT · LLM_FAIL（超时/解析）·
CONFIG_INVALID · EVOLVE_REJECT · EXTERNAL_REJECT。每类带处置语义（重试/退审/开单/熔断）。

## 10. 健壮性机制（实现位置）

心跳事件（store）｜报错升级电路（core：同单同错误 N 连击→自动 bug 单）｜漂移看门狗（company 包：
config↔代码能力↔未提交改动三方比对）｜崩溃注入五点（contract 包测试集）｜短时令牌（gateway）｜
不可逆操作同步阻断（独立进程：删数据/改权限/对外发信/动钱）｜SQLite 快照+季度重建演习（store）。

## 11. 安全模型

凭证三档（公开/伙伴/签名，库存哈希+last4）｜出站白名单+密钥扫描+SSRF 黑名单（127.0.0.1 等）｜
网页可编辑内容按不可信输入隔离｜探针集物理隔离（一次性人工基建：专户持有题目，daemon 只持 id+期望哈希）｜
审计：外部调用全落 events，台账 rolling hash。

## 12. 规模与性能（9 级前瞻）

9 级公司数千工号：people/departments 走 SQLite 索引而非扫目录；ticket_mirror 分页+增量；
概览页服务端聚合（不强前端渲染整树）；活动流增量游标分摊；YouTrack 字段每公司自建（D12）防 bundle 膨胀。
