## 0. 一句话与差异表

**v2 = 状态是唯一控制面。** 制作人只做一件事：在 YouTrack 板上拖单子。批注降级为纯上下文（写给 agent 看的，不再是命令）。daemon 轮询活动流，发现「制作人拖的状态变化」→ 执行对应动作。

| | v1（现状） | v2（本方案） |
|---|---|---|
| 控制面 | 评论指令（approve-plan/kill…） | **状态拖拽** |
| 批示解析 | LLM 岛逐条解析评论（C9/C10/C11 温床，每 tick 烧钱） | **整岛删除**。活动流 author=opengames 即批示，零解析、零成本 |
| 人工触点 | 2~5 次评论指令 | **1 次拖拽**（轻装轨全程） |
| 状态合法性 | daemon 自律（statemachine.py） | **平台强制**：YouTrack state-machine workflow，越表迁移在手工/命令/API 三层全禁 |
| 验收字段冻结 | 靠自觉 | workflow on-change 规则平台级冻结 |
| QA | 独立 cron（5 天只跑 5 次，半停摆） | 内联收割链（已验证可用）+ 加测强制落证据 |
| 证据 | 35/37 空日志、恒真命令可过闸 | 空日志=无效证据、恒真命令进黑名单、加测必落盘 |

平台实测支撑（2026-09-20 核实）：活动流 `activities` 带 `author.login` 与字段变更明细，天然区分「制作人拖的」与「daemon 改的」；state bundle `PM3 流程态` 已跨项目共享；增量轮询（`updated: {date} .. *` + `activities?start=` 水位）实测可用。**注意：当前实例一块 Agile 板都没有**（`/api/agiles` 为空）——「拖拽驱动」的第一块板要随本方案建。

## 1. 设计原则（修订版三铁律 → 五律）

1. **状态外置**：一切进行态在 YouTrack/文件，daemon 崩溃重启无损接手。
2. **机器断言**：完成只认落盘证据；**空证据 = 无证据**（v2 新增）。
3. **状态驱动**：状态迁移是唯一控制面；评论是上下文，不是命令。
4. **一人一公司**：全工作室只有一个制作人。每个设计都为「最少人工触点」优化——没有多审批人、没有@团队、没有需要第二个人才能推进的环节。
5. **两级承包**：一单一 worker 一命；大需求拆 Epic 上板，不搞 agent 套 agent。

## 2. 核心模型：状态即控制面

### 2.1 两类状态（v2 最重要的一张表）

| 类别 | 含义 | 谁能迁出 |
|---|---|---|
| **人工闸口态（H 态）** | 单停在这里 = 在等你 | **只有 opengames**（拖走即批示） |
| **agent 工作态（A 态）** | daemon/agent 正在推进 | daemon 按规则自动迁移 |
| **终态** | 已关闭 / 已取消 | 任何人不可迁出（复活走「重新打开」评论约定） |
| **停泊态** | 草稿 / 挂起 | 双向自由 |

### 2.2 状态全集（8 通用 + 专用）

**交付族通用态**：`草稿 → 待批准(H) → 已批准 → 开发中 → 测试中 → 验收中 → 已关闭 / 已取消`

- **待批准（H）**：daemon 已补齐方案摘要 + 冻结 DoD + 冻结验收命令，贴一条「待批要点」评论，然后停。**你的全部工作就是看一眼、拖到已批准。**
- **已批准（A，瞬时）**：daemon 校验冻结字段 → 建分支 → 派 worker → 立即转入开发中。它存在的意义是给你的拖拽一个落点。
- **开发中（A）**：worker 施工；心跳字段 + 进度评论。
- **测试中（A）**：收割 + run-gate + QA 复跑 + 加测（全部落证据）。
- **验收中（S 轨=A / H 轨=H）**：轻装轨 daemon 终验+合并+自动关单；重保轨停在这里等你。
- **已关闭**：证据链齐全（gate/QA/merge 三件套非空）。

**重保轨（H 轨）插入的额外 H 态**：`方案待审`（待批准之前）、`代码待审`（开发中之后）、`验收中` 本身为 H。即：草稿 → 方案待审(H) → 待批准(H) → 已批准 → 开发中 → 代码待审(H) → 测试中 → 验收中(H) → 已关闭。你 3~4 个触点。

**专用流**：
- **战役单（长期）**：`研究中 ⇄ 运行中 → 已结案`。带巡逻节奏字段，产出子单进交付流。**不进交付状态机**。
- **情报单**：`草稿 → 研究中 → 已归档`（拖出草稿即转正）。
- **提案单（内部改进）**：`草稿 → 待批准(H) → 交付流`。
- **故障单**：`触发 → 止血中 → 待复盘(H) → 已关闭`。

### 2.3 拖拽语义矩阵（daemon 的行为定义）

| 你的动作 | daemon 的解释 | 行为 |
|---|---|---|
| 前拖（顺流，可跨格） | **批准沿途所有 H 闸口** | 补齐冻结字段（缺则按模板生成）、立即派工或继续推进；日报记录「跳级批准」 |
| 回拖（逆流） | **返工** | attempt+1；你最近一条评论作为返工意见原样注入 worker 任务书；无评论则用 QA/闸门失败原因 |
| 任意态 → 已取消 | **kill** | 停 worker（SIGTERM 进程组）、stash 隔离、释放锁、归档证据 |
| 任意态 → 挂起/草稿 | **park** | 当前 worker 跑到下一个检查点停止；不派新工 |
| A 态中途你加了评论（不换状态） | **上下文** | 下轮 worker/QA 动作时原样注入；不打断在跑 worker |
| 非常规跳态（如 草稿→测试中） | ⚖️ 决策点 A4：默认「接受并自适应」——daemon 推导缺省步骤自动补齐并记录 | |

**关键简化**：v1 的 `_directives` / `parse_directive` / `DIRECTIVE_ALIASES` / reviewed_ask 批示链**全部删除**。控制面零 LLM、零解析歧义、零评论轮询成本。LLM 岛只保留三个纯文本生成用途：DoD 草案、QA 加测草案、Epic 拆解草案——全部是「生成后冻结、人可改」的草稿角色，且输出过消毒器。

### 2.4 daemon 如何认出「你拖的」

实测机制（两段式轮询，每 10 分钟）：
1. `query=project: X updated: <上次水位> .. * sort by: updated` 拿候选单；
2. 对候选单 `activities?categories=CustomFieldCategory&start=<水位>` 拿状态变更明细，`author.login == "opengames"` 的才是你的拖拽；agent-* 作者的是 daemon 自己的回声，跳过。
水位持久化在 kernel/state/poll-watermark.json，崩溃后按水位重放，不漏不重（迁移幂等：目标态已是目标值则跳过动作只留痕）。

## 3. 编制与权限

### 3.1 账号矩阵（⚖️ 决策点 C1）

| 账号 | 角色 | v2 职责 | 板面权限（目标态） |
|---|---|---|---|
| opengames | 制作人（你） | 拖拽、批注、预算 | 全部 |
| agent-8 | daemon 主账号 | 状态迁移、派工、收割、记账、KB 转正 | 全部（daemon 自律：不碰 H 态的迁出） |
| agent-4 | 验收 | 测试中状态的复跑与加测、落证据 | 全部（daemon 自律：只在 测试中 活动） |
| agent-dev | 工人 | 施工、REPORT、心跳、KB 草稿 | **只读 + 评论 + 心跳字段**（现状已达标） |
| agent-6 / artist / inspector / scout | 休眠 | ⚖️ C1 决定启用与否 | 只读 + 评论 |

### 3.2 平台级护栏（v2 新增，实测可行）

权限实测结论：YouTrack **无字段级权限**（UPDATE_ISSUE 是总开关），所以「工人改不了状态」必须用 workflow 补位：

1. **state-machine 规则**（每项目 attach）：合法迁移表按 §2.2 定义，**未定义迁移三层全禁**（手工/命令/API 都拦）——你在板上都不可能拖出非法路径，agent 更不可能。
2. **迁移 guard（JS Editor）**：H 态的迁出迁移上加 guard：`ctx.currentUser.login == "opengames"` 否则拒绝。效果：**agent 账号在 API 层物理改不动 H 态**，daemon bug 也拦得住。
3. **字段冻结规则**（on-change）：`验收命令`/`期望输出哈希` 一旦非空，仅 agent-8 在 `草稿/待批准` 态可改；其他任何修改（包括你手滑）自动回写并评论提示。
4. daemon 自律保留为第二层（双保险，不冲突）。

### 3.3 令牌纪律

沿用现状（分账号 token、600 权限、worker 环境变量注入）+ 两条收紧：
- worker 任务书不再教 worker 自读 token 直调 API（撤销 STUDIO-13 引入的越权指引）；KB 草稿改为**写本地文件，daemon 代发**。
- youtrack.json 删除明文 password 字段（token 已够用）。

## 4. daemon 架构 v2

### 4.1 模块变化

```
保留（修复后）：config / yt / locks / gates / workers / metrics / runs / web / supervise
重写：          orchestrator → stateengine（状态diff引擎，替代批示解析）
删除：          llm.parse_directive / DIRECTIVE_ALIASES / 批示位置语义计数
瘦身：          llm.py 只留 dod_gen / extra_test_gen / epic_split（草稿向）
新增：          workflow 安装器（建/更新 state-machine 与冻结规则）
              budget.py（预算闸，接线现有 events 成本）
              inbox.py（驾驶舱「待你处理」聚合）
```

### 4.2 tick 流程（每 10 分钟，每项目）

1. tick 锁 → 水位增量拉取（§2.4）
2. **你的拖拽优先处理**：按 §2.3 语义矩阵执行（kill/park/返工/批准推进）
3. A 态推进：待派工→派工（lane 锁+预算闸+attempt<3）；在飞→心跳巡检（看 stream mtime + 板面心跳双信号）；待收割→run-gate+QA 内联链
4. H 态停留清单更新 → inbox
5. 记账（接线 duration_ms、成本）→ 释放锁+心跳
6. 异常即停：连续失败 ≥2 → 停派 + inbox 置顶 + macOS 通知（⚖️ G2）

### 4.3 证据硬化（针对审计「空心化」发现，全部为强制规则）

- 证据日志 0 字节 → 该证据**视为无效**，等同 GATE_FAIL 处理；
- 验收命令黑名单：`test -e /dev/null`、`true`、`echo ok` 等恒真模式在 dod_gen 输出与建单校验两处拦截；
- QA 加测：命令+输出**必须**写入 `*-qa-*` 证据（现在只记 note）；加测生成失败 → 退回开发中，**不得放行**；
- 证据 commit 必须 == REPORT 声明 tip（sync-merge 产生的偏差要在证据里双记录）；
- 文档类单的「文档门」：验收命令必须是真实检查（文件存在+非空+字数下限+链接可达），由模板生成，不允许恒真命令。

### 4.4 预算闸（⚖️ F1）

- 每件单实时成本从 claude stream 的 usage/cost 字段记账（现状已有数据，未接线）；
- 软停：日/月超线 → 停新派工，在跑单跑完；inbox+日报提示；
- 硬停：超线 150% → 连收割也停，只留巡检；
- 预算配置就是 kernel/budget.json，你随时改，daemon 每分钟热读。

### 4.5 安全面（内网档，⚖️ F2）

- 网络层：保持 0.0.0.0（你的内网裁定），不投入；
- **AI 层约束不省**（防的是模型失控不是黑客）：worker 固定 `--model`、加 `--disallowedTools`（禁WebFetch/写入YouTrack类）、wall-clock 超时（如 45 分钟）；消毒器修 N2（解释器首词不适用引号豁免）+ N3（白名单命令路径限仓内）；
- gates 超时 TypeError（N1）等 4 个 P0 修复前置（见 §9 分期）。

## 5. 知识库

- **载体**：YouTrack Articles 唯一真源（STUDIO-13 迁移已完成，31 篇健康）；仓内只留生成过程中的草稿。
- **结构**：`全局`（宪章/编制/手册）+ `项目/{PID}/`（每项目自动建根：README、决策记录、教训、接口文档）。
- **写入纪律**：worker 过程产物 → 本地文件 → daemon 以 agent-8 代发到 `项目/{PID}/草稿/`，PM tick 巡检转正；教训类 Article 在关单时由收割链自动摘要追加到 `教训/{单号}.md`（从 REPORT 提取，不烧 LLM）。
- **阅读权**：所有 agent 全库可读（worker 任务书自动注入「同类历史教训」——现状已有此机制，保留）。

## 6. 多项目 onboarding

一条命令（⚖️ E1）：`studio onboard <PID> --template unity|web|generic --dir <path>`

自动完成：YouTrack 项目（短名=PID=目录）→ 字段模板 attach（共享 bundle 复用）→ state-machine workflow attach → 流程板+里程碑板创建 → KB 根 Article → lane 注册（plugin.json：base_branch、验收模板、轨道默认、并发上限）→ cron/泳道接入 daemon。

你侧的操作只剩：建好 git 仓目录，跑一条命令，在板上建第一张单。

## 7. 驾驶舱与你的收件箱

## 9. 实施分期（每期有验收判据）

- **P0 先行修复**（与 v2 无关，1 天内）：gates 超时 TypeError（N1）、/api/schema 500、消毒器 N2/N3、studio-worker 三约束。判据：88 测试全绿且**套件零真实 LLM 调用**（conftest 打桩 C10）。
