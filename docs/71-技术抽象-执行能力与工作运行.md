## 〇、能力连接工作的总原则

任职者通过出工承担责任，执行能力是出工可调用的条件。模型、agent loop、插件、CLI、
沙箱和远程服务都不是天然员工，也不是权源。任何能力必须先被正确表达，才能讨论匹配；
必须被独立认定，才能形成资格；必须进入执行计划，才能说明本次如何履职；必须有本次授权，
才允许产生相应行动；最后还要由工作证据和验收判断实际结果。

本章不要求某种模型或 CLI 具备所有能力。不能暂停、不能恢复、不能热更、不能读取某平台，
都可以是真实限制；禁止的是把限制隐藏起来，或用降低验收、扩大授权来制造“兼容”。

**能力、工具与任职者不能互相顶替。** `Instrument Binding`（模型、agent loop、CLI、插件、
技能包、验证器、隔离器与远程服务的绑定）只是能力的组成与挂载方式，不是任职者，也不是
权源；它不承担匿名任职责任，也不因被安装、被加载或被写进提示词而取得资格或授权。因此本
卷把能力状态逐级拆开，并把“本次已授权”与“运行时实际生效”分成两个必须分别举证的状态：
前者回答有没有权这样用，后者回答运行时暴露的东西是否真是锁定计划里的那套。

## 一、能力描述、资格与实际可用

### 1.1 能力的组成而非单个执行器名称

`Capability Descriptor` 描述一个可识别的能力供给，至少能表达：

| 维度 | 要回答的问题 |
|---|---|
| 中立能力与类型 | 提供理解、判断、行动、工具、知识、隔离还是验证能力？ |
| 实现与来源 | 哪个发布者的哪个包/服务、版本、内容摘要、来源与许可？ |
| 宿主与绑定 | 需要哪类 agent loop、CLI、协议、运行时和绑定特性？ |
| 依赖与冲突 | 还需要什么，和什么不能共存，如何锁定完整解析结果？ |
| 输入输出与配置 | 接受什么、产生什么、配置语义与已知限制是什么？ |
| 副作用请求 | 请求哪些读、写、网络、平台、秘密和资源访问？这里只是请求，不是授权 |
| 生命周期 | 如何启动、观察、暂停、恢复、停止、交接、更新、退役；哪些明确不支持？ |
| 观测与成本 | 能提供哪些真实事件、用量、成本和健康信号，盲区在哪里？ |
| 证据与已知不能 | 声明由谁作出、用何证据、在何范围有效、什么情况下失效？ |

能力类型可以包含模型、agent loop、工具插件、技能/知识、验证器和隔离器。逐项落到执行面时，
它们是 `Instrument Binding`——把某宿主、某路径、某协议与某版本绑起来的技术绑定；绑定只是
能力的组成与调用方式，**不是任职者**：

- 绑定没有独立人格、没有任职关系、不承担匿名任职责任，也不能自证资格或授权（`69-§2.3`）；
- 装上一个绑定不产生员工，换一个绑定也不换员工（§2.3）；
- 绑定失效是能力问题，责任仍落在任职者、岗位与治理位置，不能把后果归给“工具自己”。

中立能力名与宿主实现名分开，才能表达“同一需求由 DSH 插件、另一 CLI 工具或外部服务分别
实现”，也才能明确替代后的损失面。

### 1.2 从声明到实际生效不能合并

供给、安装（落位）、来源与完整性核验、加载、授权与运行时生效是不同环节，各有自己的证据与
失败方式。合并其中任意两项，都会让“文件在那儿”冒充“能用”“有权用”或“真在用”。
加载/挂载本身是执行行为，须先取得能力激活批准与部署供给确认；这与后文针对具体工作和出工的本次授权分属
两个层面，表格顺序不表示可以未经授权先加载再补批。

| 状态 | 含义 | 不能推出 |
|---|---|---|
| **已声明** | 某来源声称有能力或公司提出需求 | 声明真实、兼容、可信 |
| **已解析** | 依赖和版本找到满足全部约束的候选 | 已取得内容、可运行、获准使用 |
| **已供给** | 能从某来源取得发布物（包、镜像、服务地址） | 内容完整、来源可信、许可允许 |
| **已安装/已落位** | 内容被复制或指向受控位置（如隔离插件根）并有登记 | 来源与完整性已核验、宿主已承认、可加载 |
| **来源与完整性已核验** | 发布者、内容摘要、许可与传递依赖被独立核对一致 | 内容安全、宿主兼容、适合本岗位 |
| **已加载** | 宿主承认并初始化了该能力 | 功能正确、无副作用、当前仍可用 |
| **已探测** | 在指定环境与范围观察到实际行为 | 在所有任务/版本/时间均有效 |
| **已认定资格** | 独立认定位置承认某任职者在范围内可使用它履职 | 本次授权、当前可用、所有任务资格 |
| **已纳入执行计划** | 本次出工锁定具体能力组合、边界、替代方案与已知不能 | 该计划已获批准、运行时会照此暴露 |
| **已授权（待生效）** | 本次权源允许在范围内使用该计划 | 已经运行、已经加载、验收通过 |
| **已按计划生效** | 运行时实际暴露的能力与锁定计划一致，且有可核验证据 | 授权仍有效、工作完成、外部价值成立 |
| **授权撤回/到期** | 权源已按规则撤回、到期、被禁配或改由他人 | 运行时已停止暴露、已发生副作用消失 |
| **运行时偏离** | 实际暴露与锁定计划不一致（缺失、降权、额外能力、版本或来源不符） | 偏离无害、可用事后追认合法化 |

远程服务可能没有“安装”阶段，纯声明能力可能没有“加载”阶段；应记为不适用并给出理由，
不能为了统一流程虚构安装日志。任一必需环节无法证明时，按范围限制、补证、替换或拒绝处理。

三个失败面必须各有处置，不能用“反正批过了”或“反正装上了”掩盖：

| 失败面 | 判定 | 合法处置 |
|---|---|---|
| **已授权未生效** | 有权，但运行时没有按计划暴露 | 先查加载、配置、绑定与宿主承认；能补则补证生效，不能补则缩范围、换能力或暂停；不得把未生效状态记为有效履职，但实际消耗和已发生动作仍须如实入账 |
| **已生效但授权撤回/到期** | 运行时还在暴露，权源已收回或已到期 | 立即停止新动作、撤销运行时访问、围栏旧写入，清点在途影响与迟到副作用；不得以“已经跑起来了”主张延续授权 |
| **运行时偏离锁定计划** | 缺失、降权、额外能力、版本/来源不符 | 立即降级或暂停；额外能力按未授权处理并隔离；偏离出授权范围时须重走开工五门，不能事后追认 |

“已授权”与“已按计划生效”之间还有一层常见混淆：授权写在配置里、加载发生在宿主里、暴露
发生在运行时，三处的证据不能互相顶替。没有运行时暴露证据时，只能记“已授权未生效”。

### 1.3 能力需求与资格认定

工作先提出需求剖面，岗位提供持续能力需求，任职者/提供方提交能力声明和证据，独立认定位置
作出资格结论。资格至少含范围、期限、条件、认定者、证据、复审与失效规则。

- 属性匹配只生成候选，不是资格认定；部门相同不证明每名成员都能使用某插件。
- 职级高不自动具备能力，模型贵不自动有资格，安装成功也不自动有资格。
- 能力提供方不能单独认证自己，也不能认证自己的独立性。
- 无能力、证据不足或成本不可接受时，必须明示缺口，允许缩范围、替换、补能力、外部能力、
  拒绝或停止；不能用降标冒充完成。
- 外部能力需要合法委托、信息边界与结果核验；外包不转移公司的责任。

### 1.4 依赖解析、权限与秘密差分

依赖解析以能力需求和所有适用约束求兼容交集，不以“最新版”或第一条命中掩盖冲突。
同名不同来源、同版本不同摘要、宿主 ABI/协议不兼容、循环依赖和权限冲突都要显式报告。
锁定结果包括传递依赖与绑定版本，不能只锁顶层名称。

每次变更的差分至少六类，缺一类就不能宣称“已核对”：

| 差分面 | 要回答 |
|---|---|
| 能力增删 | 新增/删除了哪些中立能力，替代损失面是什么 |
| 版本与来源 | 发布者、版本、内容摘要、许可、传递依赖是否变化 |
| 权限变化 | 读、写、网络、平台、资源、宿主钩子与生命周期的请求增减 |
| 秘密类别与逻辑引用 | 需要哪些**类别的**秘密、引用哪一个逻辑凭据（不是值，也不是本机路径）、用途与知悉范围如何变化 |
| 知悉与数据边界 | 可读数据范围、上下文注入范围、保留与出站约束如何变化 |
| 宿主与成本 | 宿主要求、绑定版本、资源与费用影响，以及受影响工作清单 |

约束：

- 新增权限不随普通版本升级自动获批；**新增或扩大秘密类别/引用同样不是版本批准的附带
  效果**，须另经激活批准与部署供给确认（§3.4、`70-§3.6/§5.2`）。
- 减少权限也不能因此被用来降低原验收口径。
- 无法求出兼容解时，不安装“差不多”的版本，不静默忽略必要依赖。
- 变更链的段名与次序以 `72-§5.1` 为唯一主答：**实质分类 → 验证授权 → 独立验证 →
  激活批准 → 受控生效 → 后验**。本节只补两处事实：**验证授权**回答“允许对什么范围、用
  什么判据做验证”；**激活批准**回答“是否允许生效、以何方式生效、允许取得哪些秘密引用”。
  两门不得互相代替：验证通过不等于获准生效，获准生效也不能倒推验证成立。

## 二、任职、出工与出工段

### 2.1 六面交集才能形成正常履职

| 面 | 开工前引用的对象 | 缺失时 |
|---|---|---|
| 身份 | 稳定任职者与实际可归因主体 | 不能匿名开工 |
| 任职关系 | 有权源、范围、期限、接受和交接的任命/兼任/代理/替补 | 不因“已经在做”倒推关系 |
| 职级接口 | 若岗位要求，则引用当时职级与任免决定；无要求记不适用 | 不能用模型档或资格补职级 |
| 能力资格 | 覆盖岗位/任务范围的有效认定 | 补认定、限范围、替换或拒绝 |
| 执行配置 | 本次锁定的能力、依赖、限制、已知不能 | 明示不足，不得先运行再补 |
| 本次授权 | 工作范围内的授权及全部任职/出工的禁配检查 | 申请、回避、转呈或拒绝 |

这六面只说明任职侧条件，不能替代§四的任务侧开工五门。账号、显示名、进程、会话与模型
都是绑定信息，不是任职身份。平台签名应能回到实际任职与调用关系，而不是给工具匿名归属。

### 2.2 出工与出工段

`Engagement` 表示某任职者在特定工作与期间实际履职；`Execution Segment` 表示其中执行配置、
授权与交接边界稳定的一段。一个出工可以有多个段，段之间不换员工身份。

每段至少关联：任职关系、工作/合同版本、执行计划、授权与禁配结论、关键输入快照、
**决定依据**（当时依据的口径、证据、请示与取舍理由）、开始/结束与停顿、行动回执、
产物/证据、未决事项和已知不能。记录目的是重建权源、决定依据和后果，不是强迫宿主暴露或
虚构内部思维过程；宿主无法保留内部推理时，只记录可核验的决定依据与后果，不编造推理
（`72-§2.4`）。

段边界包括实质能力配置变化、授权变化、交接、暂停与恢复。普通重试是否新段由绑定规则说明，
但每次重试都不能重置工作身份、禁配、资源累计或失败次数。历史配置保留当时版本，不能被
最新员工档案或最新插件清单覆盖。

**出工记忆的接口。** 出工段记录同时是 `Engagement Memory` 的形成面：归属随工作及其责任
关系，不随任职者，也不随 executor、CLI 或会话。本卷只定义四个接口——

- **形成**：只从本工作的事实形成（受理与合同、开工判断、执行与变更、验收与异议、失败
  复盘、代价账），每条标来源、置信与未决部分；传闻、未验证推断和他工作的结论不得直写。
- **使用**：限本工作及其责任关系内的判断与交接；跨工作复用须先按“方法沉淀”检验并标明
  适用范围与失效条件；不得替代验收证据，也不得直接用于绩效归因（绩效归 65/72）。
- **交接**：随工作与责任承接移交，须接收确认；新任者读到的是未结事项、决定依据、承诺
  与边界，不是把前任经验当成自己的事实。
- **结清**：随工作归档保留、按决定清除、或经确认转为岗位/组织记忆，三路未完成不得宣称
  结清（`67-§十`）。

访问、继承、修正、清除的授权与争议不属本卷：出工记忆归 `66-§9.4` 的组织治理位置，个人
记忆处置归 `70-§3.4`，四层记忆的分层处置与访问审计见 `72-§3.1/§3.3`。**个人记忆不随
executor 配置或会话复制**：换 CLI、换框架、离岗或调岗时四层记忆分别处置，不能打包成
“员工文件夹一并复制”，也不能用恢复出厂式删除或丢弃索引冒充合法结清。

### 2.3 更换 agent loop、模型或插件

1. **触发与保全**：识别退化、不可用、成本、资格到期、轮换或外部变化，保存可靠状态与未决项。
2. **影响评估**：判断对任务、信息、权限、承诺、证据、资格和在途副作用的影响。
3. **交接与互斥**：尽量在安全边界暂停或完成当前段，接收者核验交接；必要时围栏旧执行写入。
4. **资格处置**：实质变化先重认，非实质变化按规则登记；不能用“都是小版本”跳过实质评估。
5. **新段或新出工**：锁定新执行计划，重新核验任务五门，再按恢复决定继续。
6. **后验**：比较新旧能力表现、任务结果和副作用，任职者/组织绩效不得直接归因给配置红利。

更换与交接必须同时交代四件事：**身份**不变（`Holder Identity` 同一）；**历史**留在原主体
名下，不被新配置或新档案覆盖；**承诺**逐项交代承接（含未完结的 `Obligation Instance`），
接收者未确认不得声称无损；**资格**按实质/非实质分别处置，过期即失效，不得默认延续。
围栏旧写入是技术手段（`Fencing Token`／`Epoch`），它不等于 `Activation Generation`，也不
等于业务批准（`69-§3.3`）：围栏生效只说明旧写者被拒，不说明新配置已获授权。

更换执行能力不换任职身份；换任职者则须新的接受与交接，前任历史不转给继任者。恢复同一个
executor session 不等于恢复同一出工；不同 CLI 也不能靠复制一段对话就声称无损续跑。

### 2.4 不支持时的诚实路径

- 不能暂停：在可中断边界停止新动作，形成交接材料后结束段，而不是假装原地冻结。
- 不能恢复：按当前证据重建新段，标明可能缺失与重复副作用；先对账再重试。
- 不能快照：只保存外部可核验输入、行动、结果与未决事项，不伪造宿主内部状态。
- 不能取消：限制新动作、撤销可用凭据并隔离写入，持续观察迟到副作用。
- 不能替换：暂停、改派、寻求外部能力或终止，不得为了持续运行而降低授权或验收。

取消一个进程不是撤销外部后果，杀掉 worker 也不是工作结清。正常更新不得杀活 worker；
故障与紧急处置按预设叫停/止损权限执行并留证，不借“热更”扩大处置权。

## 三、DSH 依赖清单与更新语义

### 3.1 当前能力的抽象边界

本抽象承认现有 `dependencies.yaml` 是可继承的依赖解析基础，但拒绝把库函数存在写成全链实现。
以下约束是当前能力缺口的语义边界，**代码事实、调用点与行号统一由 `73-§1.2` 维护**，本卷不再
复制一份现状清单：

- 属性绑定只产生能力需求候选，不是资格、授权或秘密供给。按人计算的启用投影必须与真实执行
  计划对账；落盘一个启用集不等于它已被任何人使用。
- 安装/落位、宿主挂载、加载、实际可用、资格认定、本次授权和运行时生效必须分别证明。
  当前的安装形态校验不等于来源真实性、完整性或内容安全已经验证。
- 生成 overlay 不等于挂载。挂载须由宿主命令显式声明；未挂载时，注入不发生。
- daemon 的公司配置 L1 重载不等于插件运行期接线，不证明重读了依赖语义或调用了插件同步函数。
- 指纹只说明声明或启用投影发生变化，不是依赖内容寻址、来源证明或安全证明。
- 启用集收缩不卸载，退役、撤销、清理与在途处置仍是缺口；登记被替换不等于历史被保留。
- 提示词中的插件清单只是文本，不能证明插件已安装、已加载或已认定资格；宿主版本可探测也
  只证明一个绑定事实。
- 仓内已有适配器与模型档选择，不证明通用 agent loop 切换。切换语义是目标抽象，须真实探针验证。

本卷只保留这些抽象约束与后续 H0a–H4 的级别定义、闭合判据，不把当前实现写成目标能力。
具体事实修正以 73 为唯一现状基线，本文不修改现有清单，也不宣称目标兼容层已经存在。

### 3.2 目标能力依赖的三个层次

| 层 | 管什么 | 典型对象 |
|---|---|---|
| **中立需求层** | 岗位/任务需要什么能力、边界和验证 | 能力需求、资格要求、可接受替代、权限上限 |
| **宿主绑定层** | DSH 或其他宿主如何提供该能力 | DSH 插件引用、宿主版本范围、patch/生命周期能力 |
| **部署解析层** | 本机从哪里取得、安装到何处、实际可用什么 | 信任源、内容锁、隔离根、实际挂载和探测结果 |

旧 `dependencies@1` 可通过兼容绑定转成宿主层输入，但转换必须保留“dsh-only”和未表达项。
不能因为另一框架读得懂 `name/version` 就宣称它能提供同一能力。旧包内 `plugins/` 应先被
提取、识别为独立能力包并单独授权，不能作为纯配置公司包的一部分继续获得导入例外。

### 3.3 “热更”必须分级

“热更”不是一个级别。安装、挂载、声明可见、新出工备战、段间替换与宿主内原地替换各有不同
的前提与证据：

| 级别 | 实际语义 | 可否声称 |
|---|---|---|
| **H0a 已安装/已落位** | 内容已复制进受控位置并登记；宿主未加载、未承认 | 只称“已安装/已供给”，**绝不称静态装载** |
| **H0b 宿主已挂载并承认** | 经能力激活批准与部署供给确认挂载，宿主承认该内容，且至少一次可用性探测通过 | 可称“静态装载”（启动前挂载，运行中不变）；仅挂载回执不等于可用 |
| **H1 配置可观察** | 控制进程无需重启即可看到新声明（声明文件、启用投影） | 只称“配置热重载/L1 声明可见” |
| **H2 新出工备战** | 新能力已完成独立验证并获激活批准，可供给新出工；在途工作钉旧版 | 可称受控上线，不称在途热替换；**版本批准不新增权限，也不授权新增秘密** |
| **H3 段间替换** | 当前段安全结束或暂停并交接，新段使用新能力 | 可称段间受控替换 |
| **H4 宿主内原地更新** | 宿主在不破坏当前语义的前提下原子替换并验证 | 只有宿主实证（探针记录）才能称运行期热插拔 |

当前 daemon 的 L1 只到“声明可见”（事实锚点见 `73-§1.2`「daemon L1 重载」）：重走装载、快照与 jobs，
不重读 `dependencies.yaml` 的插件语义，也不调 `syncCompanyPlugins`。daemon 的 L1 不等于插件运行期
接线；H0a 的落位结果也不会因为一次公司配置重载就变成 H0b。

默认目标是 H2/H3：在途工作保留锁定计划，新出工使用已批准新版；通过结束段、交接和新段
完成替换。H4 是可选宿主能力，不是公司理论前提，也不是“热更”一词可以含糊带过的承诺。

闭合判据逐级独立，缺一项就只能按较低级别记录：

| 级别 | 闭合必须同时具备 |
|---|---|
| **H0a** | 内容落在受控位置、登记可查、安装日志可读，并明确记录“宿主未承认” |
| **H0b** | 来源与完整性核验通过 + 能力激活批准与部署供给确认覆盖挂载 + 宿主命令含实际加载参数（如 `--patch`）与宿主承认 + 至少一次可用性探测通过；仅有挂载回执不算可用 |
| **H1** | 声明变更在控制面可见且指纹可核对；不得据此声称插件已换、资格已变 |
| **H2** | 独立验证 + 激活批准 + 权限差分 + 秘密类别/引用差分与部署供给确认 + 新出工可用且旧出工仍钉旧版 |
| **H3** | 段结束/暂停与交接确认 + 新段锁定新计划 + 旧段围栏写入 + 在途副作用对账 |
| **H4** | 宿主侧原子替换证据 + 替换前后语义与行为探测 + 回滚路径演练 |

### 3.4 更新生命周期

段名与次序以 `72-§5.1` 为唯一主答；本卷只补能力与秘密面的事实：

```text
候选依赖与供给 → 实质分类 → 验证授权 → 独立验证 → 激活批准 → 受控生效 → 后验观察
→ 停止 / 恢复 / 修复 → 凭据轮换与吊销 → 旧版本退役与清理
```

“凭据轮换与吊销、旧版本退役与清理”是后验之后的链后义务，不扩充 `72-§5.1` 的主答链；
其权源、范围、证据与完成判据仍须逐项保留，不能用一句“后验”代替。

- **实质分类**：判断是否实质改变能力、权限、秘密类别/引用、适用范围或宿主绑定；不得用
  “只是依赖升级”“只是小版本”“只是 prompt”降级（`72-§5.1`）。
- **验证授权**：允许对什么范围、用什么判据做验证；它不包含生效许可。
- **独立验证**：解析结果、来源、完整性、宿主兼容、权限差分、秘密差分与探针；结论要写明
  范围、判据、失败项与盲区。
- **激活批准**：独立于验证的另一道门（能力语境称“能力激活批准”）；决定是否生效、以 H2/H3/H4
  中哪种方式生效，以及是否允许：（a）在哪些环境以静态挂载/加载方式生效（H0b）；
  （b）在哪些环境、为哪些工作、以何目的、多长期限取得哪些秘密引用。H0b 不是越过这道门的既有安装事实。
- **受控生效**：按批准范围只对新出工或指定段生效，在途按原计划冻结；新旧执行计划按公司、
  工作、出工段和宿主隔离，不能只按插件名共用可变目录。
- **后验观察**：实际暴露是否等于计划、权限与秘密是否真的按批准收口、成本与副作用是否变化。

秘密与凭据的专门约束：

- 每次变更列出**秘密类别**（不是值）与**逻辑引用**（引用键，不是路径，也不是值）的新增、
  删除、范围扩大与知悉变化；秘密值不进清单、指纹、日志、证据或提示词。
- **部署供给确认是独立的资源供给决定与回执**：部署责任者按 `Authority Requirement` 与
  `Access Policy` 决定是否提供宿主、秘密与运行条件（`70-§3.6/§5.2`）。它不是公司授权，
  不扩大公司权源，也不要求部署必须配合；公司激活批准不自动产生供给，部署供给确认也不替代公司批准。
- **轮换与吊销**：凭据须能按发布者、包、版本或用途限定，过期、吊销、回滚与密钥更替各有显
  式状态。吊销后要验证运行时确实拿不到（撤销句柄、停止注入、围栏旧凭据），而不是只在清单
  里删一行；迟到的旧凭据使用与残留副本属于后验对账范围。
- 只读内容缓存可以共享，但不因此共享可写注册表、权限或运行时状态。
- 移除依赖先停止新分配并处理在途，之后吊销运行时访问、停用和清理；不得只从清单删除。
- 回滚是新的变更决定，须检查安全、兼容与在途影响；安全撤销可能需要立即停止新版本，
  不能为了等待常规窗口继续扩大损害。已发生副作用不随回滚消失。
- 更新失败保留可用旧版的条件是旧版仍合法、安全、兼容；否则暂停相关工作而非盲目恢复。

### 3.5 能力供应链不是公司自我授权

能力包代码及其安装/初始化钩子均属于执行行为，须单独审查、隔离和授权。签名与来源证明
只证明来源链，不证明内容安全；包描述的工具说明同样可能漂移。至少验证发布者、内容锁、
宿主兼容、权限差异、依赖差异和实际探针，再按事项风险决定能否激活。

缺失依赖可以允许只读导入和显示损失面，但受影响的工作不能默认开工。其他 executor 若不支持
DSH 插件，必须提供替代能力并通过相应资格/开工判断，或在公司/工作能力说明中明示不能。

## 四、从意图到合法工作

### 4.1 入口只产生意图，不自动产生承诺

外部 API、IM、定时源、平台活动、内部发现和既有义务都可以形成 `Intent Envelope`。入口须保留
原始内容、来源、接收时间、身份映射、完整性/真实性状态、受理责任位置与时限。

受理结果至少有接受、附条件接受、暂缓、拒绝、转呈。暂缓必须有期限或复审条件；来源未核验
不能使用；没有合法入口的指令不能因在提示词里出现就覆盖任务合同。通知发送、平台建单、
消息已读或工具 `completed` 均不等于受理、承诺或验收。

### 4.2 工作类型先于工作模板

工作主类型严格取 `67-§一` 的六类，主类型唯一；复合工作须声明主类型，并说明复合部分各自
的验收如何合并，不能以“都做一点”回避口径。

| 类型 | 何时成立 | 主要结果面 | 不能用哪种“完成”冒充 |
|---|---|---|---|
| **创造** | 需要形成此前不存在的产物或状态 | 产物 + 状态结果 | 只运行工具，产物齐全而状态未变 |
| **维持** | 需要使某状态在界内持续 | 状态结果 + 过程 | 无新文件就声称没有工作，或以动作充数 |
| **探索** | 目标不可事前完全指定 | 学习交付 + 边界 | 事后把偶然产物追认为原目标 |
| **调查** | 需要确立事实、原因或责任线索 | 事实链 | 把单一自述当事实，结论超出证据 |
| **回收** | 需要撤回、归还、退役或复原 | 状态结果 + 残留 | 只停机或只删除就称结清（撤而不清） |
| **清算** | 需要了结义务并完成承接 | 结清状态 | 宣布完成但无人承接 |

**回收与清算必须是两类**：前者的主验收对象是残留完整性与无残留，后者是承接确认与未决
清单。合并会把“东西清干净了”误当“责任有人接了”，也会让“有人接了”掩盖残留。

**拒绝/避免/暂缓/撤回不是工作主类型**，它们是无产物结果形态（`67-§九`）：值守、维护、
避免、拒绝、暂缓、撤回各有自己的验收对象与证据结构（例如避免类须有事前风险条件、期间
监测与事后独立复盘三段）。**拒绝仍是受理结果的取值之一**（接受、附条件接受、暂缓、拒绝、
转呈），受理阶段就要留痕并告知替代路径。这类结果可以验收，但**不得为它们新造工作主类型**，
也不得把它们塞进“维持”来绕过各自的证据要求。

工作类型决定证据和评价重点，不决定员工职级或固定 executor。探索须事前写边界、学习交付、
停止条件和事后独立评价；维持须写观察窗口、状态判据、异常/反事实证据及资源成本。

### 4.3 任务合同是不可覆盖的版本链

任务合同至少引用：

- 原始意图与合法来源，及受理决定；
- 具体承诺（若存在）及相对方/承诺授权，内部任务不得冒称对外承诺；
- 验收口径及其定义/验收位置、风险与可逆性分类；
- 工作、验收、记录、协调等责任位置及具名实例；
- 时限、复审点、到期语义、暂停/叫停/恢复与强制出口；
- 资源、信息、能力需求、知悉边界和部署限制；
- 协作/交接、证据、异常、结清与重开规则。

合同成立后冻结修订。任何范围、时限、口径或相对方权利变化进入变更链，不直接编辑旧版本。
方法、顺序和工具选择可以在授权内自主，不需要把每个动作变成审批；但方法自主不改变承诺、
边界、证据和报告义务。

### 4.4 开工五门与任职侧检查并行

| 门 | 必须引用 | 缺失的合法出口 |
|---|---|---|
| 权 | 本次授权、父链、范围/期限、累计禁配 | 申请、回避、转呈或拒绝 |
| 能力 | 资格、执行计划、当前探测与已知不能 | 补、换、外援、缩范围、拒绝 |
| 资源 | 真实可用额度、预留、时间和注意力 | 补充、协商变更、拒绝；不能透支 |
| 信息 | 必需输入、来源、时效和知悉许可 | 请求、暂缓；严格例外才可带假设开工 |
| 禁止 | 禁止/保留清单、未覆盖处置和例外状态 | 停止、请求决定或拒绝 |

承接者作出并记录开工判断，但各门判据和争议位置不由承接者单方控制。结论只有可开工、
附条件开工、不可开工；附条件必须含责任者与到期处置。范围、资源、能力、关键信息或禁止
变化时重新判断。未覆盖的新事项默认保留，而不是“没人禁止即可做”。

信息假设开工只适用于非关键缺失、低风险且经有权位置允许的情形，须写假设、验证和到期处置。
中高风险、不可逆且影响重大或显著影响相关方权利时，不得以“先做看看”代替信息。

### 4.5 派工、领取和共同工作

派工携带合同及开工条件，被派方可接受、附条件接受或拒绝；派工者必须处理拒绝，不能让
“已派出无人接”无限悬置。领取需资格、容量和禁配检查；领取不是改变承诺主体。

共同工作指定唯一协调责任者用于口径、证据和外部表述，但共同责任仍按约定和实际控制分配。
请求输入、评审、授权、移交、接力、会签、异议和裁决都须有时限与未响应语义。未响应不是同意，
未确认不是移交，交接也不是验收。

共有成果能否按份划分、共同责任如何承担、多主冲突的优先关系与共同终裁，属 66（R1/R15）；
本卷只提供共同工作的事实：谁决定了什么、谁掌握信息与资源、谁有能力止损、谁做过什么承诺。

## 五、工作状态、异常、验收与恢复

### 5.1 工作状态与判断结果分开

可采用 67 的状态语义：受理中、待开工、进行中、暂停、待验收、返工、已接受、已拒绝、
已终止、已结清；具体存储状态名由绑定档案映射，不能要求每家平台使用同一显示文案。

- 每次迁移有权源/依据、预期版本、时间、实际主体和回执。
- 工作状态不能由 executor 的 `turn_end` 直接覆盖；执行完成只是收割输入。
- 接受、附条件接受、拒绝、依授权终止是验收判断，不是简单的布尔完成位。
- 已接受不等于已结清，已拒绝/已终止也不等于责任已消失。
- 重开由独立位置按新证据标准受理，追加关联记录并限定影响范围；不能无痕改写原终态。
- 平台不支持某状态/字段时必须报告语义损失，不能把返工映射成完成，也不能用评论伪造结构化决定。

### 5.2 风险、验收与生效时序

风险与可逆性由不受交付方控制的独立位置分类。分类权、分类争议与终裁属 66（R31 的主答
仍是 66）；本节只规定按档执行的技术时序，不搬权责。二者存疑、分类争议、无独立分类或
不可逆且影响重大时按高档。

| 风险档 | 判定 | 验收与生效 |
|---|---|---|
| 低 | 低风险 + 可逆 + 不涉不可放弃权利 | 自检 + 可复核证据 + **事后独立审计（不可省略）**；可先生效；日常低风险对外事项保留相对方验收与异议 |
| 中 | 外部影响超出低档但可逆，或不可逆但不重大 | 独立验收；在生效前或事前约定的复审点完成 |
| 高 | 高风险、不可逆且重大，或显著影响相关方权利 | 高风险与不可逆重大者**生效前**独立验收；显著影响相关方权利者按事前规则在生效前或约定复审点 |
| 未分类/存疑 | 无独立分类、分类争议、口径无法判定 | 一律按高档，不能因工具无法分类就降级 |

低档可以先生效，但事后独立审计不是可选项；省掉它，低档就退化成“自评通过”。**唯一允许在
生效前独立验收缺口下先行的情形，是 63-§6.1 的紧急止损路由**（§5.5），且只允许最小保全与
止损，不追认原高风险动作，也不能延长为常态。

自检、多个同源 agent 的一致意见和测试通过都不能自动代替独立验收。验收结论必须写明范围、
依据、判断者、时点、独立性和异议位置。价值与外部承诺兑现另行评价，不能由“验收通过”直接推出。
验收通过也不等于外部损害不存在：收益能否抵销第三方损害、损害是否不可补偿、是否需要停止与
救济，属 66 的认定（R19）；本卷只提供外部影响、受影响方与代价的事实（观察面见 72-§四）。

### 5.3 变更分流

非承诺任务要件由变更决定位置批准；验收口径由口径定义位置主导，验收位置参与可验收性确认。
具体承诺内容、降标、退出或相对方权利变化必须走承诺授权者与相对方程序。同一变更兼有
两类时先完成承诺程序，再处理其他要件。派工、执行或插件都不能自行批准。

变更是否构成实质、受益方能否自行降级、争议由谁终裁，属 66（R8/R24）；本节只写工作层的
分流与在途处置，不重排治理程序。

中途指令只是变更请求，不自动覆盖旧合同。未批准前按原合同继续；触及禁止或高风险时先暂停。
双方各引一版时按版本与生效记录对账，不能让“最新消息”自动获胜。

### 5.4 异常、返工与强制出口

**异常的定义取 `63-§6.1`**：实际或潜在状态偏离事前口径、**缺少可比口径**、**口径本身失效**、
来源真实性存疑、多个局部合规累积成整体不可接受，以及**缓慢漂移**；单次未越线不免除。
三个技术义务随之而来：每个责任位置必须发现、接收或转交与其信息范围相关的异常；异常必须
落成 `Exception Record`（对象、判定依据、当时口径、影响范围、发现者、接收者）；无人认领的
异常按既有升级链进入最终责任位置，**不得归给“框架”**。发现义务只要求合理注意与可检验的
监测，不要求全知；隐瞒与应发现而未发现必须区分。

**口径缺失或失效不能被“按高档”永久糊住。** 缺可比口径、口径冲突或口径本身失效时，进入
口径变更或元治理（`63-§6.3`、`70-§3.6`）：先暂停受影响决定、保全事实、具名受理，再产生
新口径；新口径同样要经验证授权与激活批准。以“未分类按高档”长期行驶，会把元治理问题拖成
常态例外，也会让真实口径缺陷永远没有主人。

| 异常 | 合法技术处置 | 期限/复审与终局 |
|---|---|---|
| 偏差 | 按事前口径分级，规则内校正、返工或停止；规则外偏差不得自行放宽口径 | 限期校正；逾期升级为变更或终止 |
| 超时/无响应 | 按到期语义升级、暂停、变更或终止；不默认同意或续期 | 到期即升级；无复审条件者不得续期 |
| 资源耗尽 | 停止超限消耗，预留/结算对账；暂停并申请，或**依法缩小范围**（须走变更）；不静默透支 | 补充、缩范围、终止三者之一 |
| 能力失效 | 保全、交接、重认、替换、降级或终止；**高风险动作先停**；不降标 | 换能力走 §2.3；无替代则缩范围或终止 |
| 来源存疑 | 暂停使用并核验，失败则拒绝、撤销或终止；保留影响范围；暂缓须有复审期限 | 复审期限到点必有结论 |
| 执行结果不明 | 先查询回执和外部副作用，再决定重试/接管；不盲目重放 | 对账完成前不得结清 |
| 外部事件 | 重新受理或变更合同；不得用旧口径评价新情况 | 新旧口径切换点必须记录 |
| 验收/独立性争议 | 保持待验收或暂停，换独立位置或重审；不由交付方终裁 | 移交 66 的争议位置，有处理时限 |
| 协作/多主冲突 | 暂缓冲突新承诺，提交预定终裁；不私选同级一方；**工作进入暂停并计时** | 暂停计时到期升级，不无限等待 |
| 平台/存储离线 | 按权威档案只读、暂缓或授权降级；不擅自提升镜像为权威 | 降级须有授权与恢复条件 |
| 局部合规整体透支 | 合并资源与趋势，升级整体资源责任者和最终责任位置 | 汇总责任者按周期复审 |

每类异常都要有期限或复审条件与明确终局（校正、返工、变更、终止或退出异常）；没有终局的
异常状态本身就是异常，按升级链处理。

返工记录原因、范围、次数与期限（原因至少归类为口径、能力、信息、协作或外部变化）；暂停/
叫停记录决定者、范围、保全义务、复审/恢复条件。达到事前阈值必须变更合同、更换能力、终止
或上报。升级链尽头必须有具名接收者、处理时限或复审条件和再升级去向；“等待框架处理”不是
合法终态。

### 5.5 叫停、恢复与紧急止损

常态叫停只在预设范围由有权位置发起，阻止继续影响但不代替终局。恢复是新的决定，要求条件
已满足的证据、按风险的恢复程序、后续验收和暂停期影响处置；不能由被叫停交付方静默恢复。
恢复档位与 66-§5.2.1 的设置任命一致：

| 风险档 | 恢复程序 | 时点 |
|---|---|---|
| 低 | 自检 + 可复核证据 + **事后独立审计** | 可先恢复，事后审计不得省略 |
| 中 | 独立恢复决定 | 生效前或事前约定的复审点 |
| 高 / 不可逆且影响重大 | 独立恢复决定 | 生效前 |
| 未分类/存疑 | 按高档 | 同高档 |

**恢复位置不受交付方控制。** 恢复决定不能由被叫停工作的交付方单独作出，也不能由同一被
叫停主体兼任决定与复核。恢复决定要给依据、范围、恢复条件与记录，且不构成对既往违规的
追认。静默恢复（无决定、无记录地继续）视为违规，暂停期间的动作不能因后来成功获得追溯授权。

**紧急止损的特别路由**（`63-§6.1`）：禁止事项仍禁止，保留事项仍须备用决定程序。

- **保留事项**：事前指定备用决定者；备用决定者不可达且延迟将造成更大不可逆损害时，现场
  责任主体才能在预设紧急边界内采取最小必要保全/止损，并立即留证、通知、接受事后独立复核。
  保留事项的实体决定权仍按备用决定者程序取得，不因现场先行而转移。
- **高风险或不可逆动作**：独立验收确实无法及时获得时，也只能按预设紧急边界先行**保全与
  止损**（冻结、隔离、撤回访问、留存证据），不能借“来不及验收”完成原动作。
- **先行不等于后续批准**：该先行不构成对恢复的批准，也不追认原高风险动作；恢复仍是新的
  决定，仍按上表分档，且要另行取得相应的恢复决定。
- **无预设紧急边界时**，只能采取不进入禁止或保留权限的保全与升级行动；升级本身也须有时限。

### 5.6 终止、结清与跨公司工作

终止须处理在途产物、资源、承诺、相对方通知、证据、未决责任和后续影响。合法终止可以是
拒绝越界、停止无价值工作或避免损害，不能为了“保持成功率”而排除失败记录。使命不可行或
合同无法继续时，本卷只提供工作事实：无法履约的事实、代价账、在途承诺与残留处置；重新
协商、依法变更使命或终止是 66 的决定（R21），本卷不替代。

跨公司交付使用各方事先同意的联合合同/协议，明确对外最终责任、实际控制、联合验收、
共享信息、争议与退出。内部状态全绿不替代联合验收；无法约定责任时不得作出联合承诺。

## 六、协作平台、工作目录与 CLI

### 6.1 协作平台是语义绑定，不是理论前提

协作端口需要承载意图、工作、状态/字段、评论/知识、关联、活动游标和平台回执。平台是权威
还是镜像，由 69-§三的权威登记逐事实域声明；更换产品时，不能只换 URL，必须核对语义与历史。

| 能力 | 替换时必须检查 |
|---|---|
| 身份映射 | 平台账号如何回到任职/外部主体，代理与伪造如何识别 |
| 工作语义 | 类型、状态、合同版本、承诺、验收和结清是否有无损承载 |
| 写入收口 | 谁能写、如何授权、能否防绕过、平台直接改动如何对账 |
| 活动与顺序 | 游标、丢失、重复、乱序、轮询/通知盲区和迟到回执 |
| 关联与外部反馈 | 依赖、跨工作关系、相关方异议和跨公司协议如何表达 |
| 导出与退出 | 如何导出完整历史与未决义务，如何冻结旧权威并接管 |

LocalFile、Taiga、YouTrack 是当前不同的候选绑定；Matrix 是消息入口/通知出口，不自动成为
工作事实源。某平台不支持关联、独立验收字段、平台防绕过或完整导出时，必须明示能力缺口及
补偿边界，不能用另一个同名布尔字段掩盖。

评论和知识文档可以提供人读上下文，不能成为权源、任务合同或验收结论的唯一藏匿处。
外部平台的 `done/completed/closed` 也不能直接映射为本规范的验收或结清。

### 6.2 工作目录是受限履职环境

逻辑工作区至少分：

| 区域 | 内容与权限 |
|---|---|
| 只读输入 | 指定公司/合同修订、授权引用、必要资料；不能因可读就全部注入 |
| 可变工作区 | 当前出工段的中间产物和允许修改的对象，范围随授权最小化 |
| 产物/证据暂存 | 待核验产物与证据材料；定稿/验收后通过受控写入形成不可变版本 |
| 交接区 | 合同、状态、行动、结果、未决、风险与接收确认，不是随手聊天摘要 |
| 临时缓存 | 可丢弃、明确非证据、受保留/清理约束，不能成为唯一历史 |
| 秘密代理面 | 按工作/动作短时提供秘密或受限句柄，秘密值不进配置、快照和证据 |

物理布局可按公司/工作/出工/attempt 派生，不必永远镜像部门树。组织调整不能无痕改变历史
证据位置。员工家目录是持久工作空间，不意味着一次任务可读其他任务或个人记忆；cwd 只影响
相对路径解析，不是读写、网络或秘密隔离。

工作区须落实读域、写域、网络、执行、资源与秘密边界。沙箱配置本身也要版本化并验证逃逸、
符号链接、绝对路径和外部句柄。git worktree/branch 是可选工作绑定，不是所有公司必须有的
事实源；合并、push、发布等外部副作用仍需独立授权与验收，不能由文件存在自动触发。

### 6.3 CLI 与外部操作面

| 操作面 | 合法用途 | 禁止旁路 |
|---|---|---|
| 公司作者工具 | 创建、校验、比较、打包、生成诊断与迁移候选 | 校验通过即自动激活；直接改历史 |
| 部署/运营工具 | 绑定宿主、供给秘密、激活已批准修订、对账与移交 | 用部署身份替公司批准、扩大授权 |
| 员工/执行工具 | 在任务授权内读写、提交证据、请求输入/决定 | 直接写权威平台/台账、伪造署名 |
| 监督/查询工具 | 只读检索、导出授权范围材料、提交异议 | 监控读取反向变成审批或验收 |
| 紧急处置工具 | 在预设边界内保全、止损、围栏与通知 | 以“管理员”名义无限扩权或抹去后果 |

CLI 的具体命令和参数属于实现，不属于跨框架规范。任何 CLI、HTTP、MCP 或 IM 入口都要经过
相同的身份、授权、输入校验、幂等、证据和失败路径。本地命令不天然可信，人工操作也不天然
免于记录。紧急权限不能成为日常直写数据库或绕过网关的后门。

框架生成框架、公司生成框架时，输出仅是工作产物与候选实现。它仍须经过独立验证、符合性
测试、授权与部署，不能因为由本公司/本框架生成而绕过上位不变量。若接管本公司运行，
还须满足 `72-§5.3` 的冻结/围栏、承诺与记忆移交、接收确认及旧外部连接处置要求。

## 七、本卷闭合判据与现实边界

- 能力状态逐级可分且逐级有证据：声明、解析、供给、安装/落位、来源与完整性核验、加载、
  探测、资格、执行计划、已授权（待生效）、已按计划生效（运行时暴露＝锁定计划）、授权撤回
  或到期、运行时偏离；“已授权未生效”“已生效但授权已撤回/到期”“运行时偏离计划”各有失败
  处置，任一缺项有合法出口。
- H0a（已安装/落位，宿主未承认）、H0b（宿主已挂载并承认）、H1（配置可观察）、H2（新出工
  备战）、H3（段间替换）、H4（宿主内原地更新）各不混称，各有独立闭合判据；H0a 不称静态
  装载，当前 daemon 的 L1 不冒充插件运行期接线，也不冒充 H2/H3/H4。
- 供给、安装/落位、来源与完整性核验、加载不合并；当前 registry 的同名替换是替换登记，
  不冒充 append-only，也不冒充历史或完整来源验证；解析结果与 L5 文本不等于真实能力。
- 能力变更与升级链按 72-§5.1 的段名运转，验证授权与激活批准是两道门；秘密类别与逻辑引用
  差分、部署供给确认、轮换与吊销不被版本批准夹带。
- 更换执行能力、CLI 或 agent loop 不换员工身份、不清历史、不重置禁配、不自动延续旧资格；
  交接保留身份、历史、承诺与资格处置；个人记忆不随 executor 复制，出工记忆随工作与责任
  关系、按授权访问。
- 工作主类型严格为 67 的六类（创造、维持、探索、调查、回收、清算），主类型唯一；回收与
  清算不合并；拒绝/避免/暂缓/撤回是无产物结果形态，不是工作主类型，拒绝仍是受理结果取值。
- 工作从来源、合同、五门到异常、验收、结清和重开均有责任位置与失败路径；异常按 63-§6.1
  定义可发现、可记录、有具名接收与升级终点，每类有期限/复审/终局；口径失效进入口径变更
  或元治理，不以“按高档”长期替代。
- 验收与恢复按四档执行，档位判定与争议终裁在 66；低档事后独立审计不可省，中档生效前或
  约定复审点，高档与不可逆重大生效前；紧急止损是唯一时序例外，且不追认原动作、不产生恢复权。
- 协作平台可替换但不能静默损失语义；工作目录与 CLI 不能绕过授权、隔离和唯一写入。
- 没有要求所有宿主实现不可能的暂停/快照/热更；不支持必须可见并导向安全处置。
- 本卷只提供工作事实与执行路径：多主优先关系与共同终裁、可分性判定、不可补偿损害认定、
  使命变更程序等治理主答仍在 66，不因本卷的分节而转移。

本卷是目标抽象。当前实现离这些条件的逐项差距、真实能力探针和验证证据，由 73 及后续
spike 记录。不得把本卷的存在当成 DSH 全链、跨平台无损迁移或 agent loop 自由切换已验证。
