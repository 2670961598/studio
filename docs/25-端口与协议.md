## 一、并行开发总则

1. **两类角色**（00-§二 解耦地图）：外部件=实现端口+过契约测试即可上岗；
   中心件（daemon 主循环/store/company 引擎/prompt/gateway/contract/panel/api）=唯一写入者与裁判，外部件不碰。
2. **依赖方向铁律**（可测）：
   ```
   contract（纯类型+schema，零运行时依赖）
     ▲                ▲                ▲
   实现包们        核心包们          测试套
   （adapters/yt/  （core/store/    （各泳道独立跑）
    localplatform/  prompt/daemon/
    matrix/…）       panel/api）
   ```
   - 实现包只 import `@studio-next/contract` 的端口类型，**不 import 核心包、不互相 import**
   - 核心包 import 端口类型，**零 import 任何实现**（23-§四：依赖方向测试）
3. **版本与分级**：每个端口带 `PORT_VERSION`；v0.1 全部标 `experimental`（08-§三分级），
   升 `beta` 需双实现（或实现+fake harness）全绿；升 `stable` 需制作人过目。
4. **错误语义统一**：一切端口错误的 `code` 必须能映射进两级分类（17-§9 枚举）；
   端口不抛裸字符串。
5. **选型纪律**：实现包引新依赖须登记进 16-§二 选型表并附理由（本轮已补：`yaml@2` 带行号 AST）。

## 二、共享内核类型（ports/kernel.ts）

```typescript
// —— 标识（全部 string 别名，语义自文档化）——
export type CompanySlug = string      // 公司目录 slug（概览路由 /<slug>/）
export type TicketId = string         // 平台侧单号（格式归平台适配器翻译，核心只见此别名）
export type PersonId = string         // 工号=档案文件名=永不变主键
export type AttemptNo = number        // 第几次尝试（指纹 t.<单号>.<att>）

// —— 计量 ——
export type Money = { usd: number }   // 成本统一美元微账（价目表折算后）
export type TokenCounts = { input: number; output: number; cached?: number }
export type DurationMs = number

// —— executor 归一化结果（收割输入）——
export interface ResultStats { cost: Money; tokens: TokenCounts; duration: DurationMs; turns: number }

// —— executor 归一化流事件（各家 stdout 差异在适配器内消化）——
export type StreamEvent =
  | { type: 'step_start'; step: string }
  | { type: 'step_end'; step: string; usage?: TokenCounts }
  | { type: 'turn_end'; completed: boolean; usage?: TokenCounts; error?: string; errorCode?: string }
  | { type: 'log'; text: string }
// ↑ turn_end.errorCode（v1.5）：机器可读错误码结构位（如 dsh 的 AUTH / MISSING_CREDENTIAL）——
//   message 原文保留在 error，前缀拼接方案废除（渐进兼容：字段可选，先填的家先受益）
//   v1.7：值域冻结为 EXECUTOR_ERROR_CODES（见 §3.1 末「errorCode 词表冻结裁决」+附录 A 映射附表）——
//   errorCode=subcause 的受冻结值域（executor 域），非第三路由键

// —— 任务书（装配管线的输出，executor 的输入）——
export interface TaskBrief {
  ticket: TicketId; attempt: AttemptNo
  briefPath: string            // 任务书落盘路径（含冻结验收命令）
  workspace: string            // 工作区根（AGENTS.md 落点由 L5 决定，适配器只接收）
  AGENTS_MD: { channel: 'native' | 'user_level' | 'append_system_prompt'; target: string }
  budgetCap?: Money            // 能力声明 budget_cap=true 时生效
  resume?: { sessionId: string; summaryPath: string }   // 续跑（F1-15）
  credentials?: Record<string, string>
  // ↑ v1.4：短命按单凭据——daemon 在 launch 前注入、适配器无条件透传进子进程 env；
  //   适配器不得记录/打印其值（红名单）；prompt/任务书/档案永不含（2026-10-18 制作人定调）
}

// —— 两级错误分类（17-§9，冻结进契约；处置语义归 core）——
export type ErrorCategory =
  | 'GATE_FAIL' | 'WORKER_DEAD' | 'QA_BACK' | 'STALL' | 'NO_LANE'
  | 'DISPATCH_FAIL' | 'MERGE_CONFLICT' | 'LLM_FAIL' | 'CONFIG_INVALID'
  | 'EVOLVE_REJECT' | 'EXTERNAL_REJECT'
export interface ClassifiedError { category: ErrorCategory; subcause: string; detail?: string }
```

### 3.1 Executor 端口（ports/executor.ts｜依据 18-§一）

```typescript
export interface ExecutorCapabilities {        // 静态声明，注册表按此路由
  budget_cap: boolean          // 是否原生接受预算帽
  cancel_turn: boolean         // 单轮可取消
  session_resume: boolean      // 续跑（--resume/--session-id/-S 家族）

export interface DetectResult { name: string; version: string; ok: boolean; gaps: string[] }  // launch 前必跑，不达标明报

export interface ExecutorAdapter {
  readonly name: string
  readonly capabilities: ExecutorCapabilities
  detect(): Promise<DetectResult>
  estimate(task: TaskBrief): Promise<{ estimated: Money; confidence: number }>
  launch(task: TaskBrief): Promise<Handle>
  stream(h: Handle): AsyncIterable<StreamEvent>
  resultStats(h: Handle): Promise<ResultStats>
  kill(h: Handle, graceMs: number): Promise<void>   // execa killDescendants 语义
```

**dsh 三件套裁决（2026-10-19，v1.5——制作人已批，对话记录 2026-10-19「报错兼容发现一个做一个」）**：

2. **Handle 补可选 `executorSessionId?: string`**（端口级原则）：dsh 适配器从流首 session 事件
   捕获 dsh 侧 `session-<uuid>` 写入 Handle（docs/31-§5-6）；续跑接线 resumeWithSession 预留

3. **StreamEvent.turn_end 补可选 `errorCode?: string`**（渐进兼容）：错误码从 error 前缀串迁到

**errorCode 词表冻结裁决（2026-10-21，v1.7——studio-dev-102 P2，制作人 2026-10-21 全批，批件②倾向修法照准）**：
1. **词表冻结**：`turn_end.errorCode` 受冻结词表约束——`EXECUTOR_ERROR_CODES =
   AUTH ｜ MISSING_CREDENTIAL ｜ EXTERNAL_RATE_LIMIT`（物理落位 contract 包 schemas/errors.ts：
   常量+`ExecutorErrorCode` 类型+校验函数 `isExecutorErrorCode` 三件套，照 §3.2 kind 词表三件套
   先例；kernel.ts 守纯类型纪律不落运行时）。
   - AUTH / MISSING_CREDENTIAL：v1.5 dsh 先行两码收编（docs/31-§7 P-04/A4）；
   - EXTERNAL_RATE_LIMIT：**既成漂移收编**——daemon fake（DEV-46 注入面）已产出的词表外值
     （studio-dev-102 证据 E7），收编不改其义（上游外部服务限速失败）；claude/codex/kimi 尚未
     产 errorCode，冻结的是**词表增长纪律**（只增不改，加码走批示），不是填表义务（v1.5「先填的
     家先受益」渐进语义保留）；词表外值=实现缺陷，消费方校验拒收。
2. **并轨语义**：errorCode 定位为 **subcause 的受冻结值域**（executor 域失败码），**非第三路由键**——
   两级分类仍是 category×subcause 二元组（17-§9），errorCode 是 subcause 在 executor 域的规范
   取值集；断路器「错误签名」键控面（17-§6）消费的仍是 category×subcause，errorCode 不改路由。
3. **映射降档**：errorCode→ErrorCategory 映射**降为 docs 附表**（本文附录 A：无守卫、无负测、
   不进契约）——首个消费方（daemon 收割/断路，17-§6）接线时随批示定稿；本刀只登记不接线
   （不接 daemon 断路消费）。

### 3.2 FlowPlatform 端口（ports/platform.ts｜依据 23）

```typescript
export interface IssueRecord {
  id: TicketId; title: string; state: string; type?: string
  dept?: string; level?: number; assignee?: PersonId; parent?: TicketId; lane?: string
  updated: string
}
export interface ActivityPage { items: PlatformActivity[]; nextCursor: string | null }  // 游标语义见下
export interface PlatformActivity {
  id: string; ts: string; issue?: TicketId
  kind: string          // 冻结词表 PLATFORM_ACTIVITY_KINDS（v1.6，见下「修订刀」第 3 条）
  actor?: string        // 平台侧可归因主体（v1.6 选A，见下「修订刀」第 2 条）
}
export interface PlatformRole { slug: string; name: string; permissions: readonly string[] }  // v1.6 guards 读位（形状锚=Taiga roles 快照）

export interface FlowPlatform {
  issues: {
    list(q: IssueQuery): Promise<IssueRecord[]>
    get(id: TicketId): Promise<IssueRecord>
    create(input: IssueCreate): Promise<IssueRecord>
    transition(id: TicketId, toState: string): Promise<IssueRecord>   // 状态权威在平台侧（18-§二）
    setField(id: TicketId, field: string, value: unknown): Promise<void>
  }
  comments: { add(id: TicketId, body: SignedBody): Promise<void>; list(id: TicketId): Promise<Comment[]> }
  fields: { schema(): Promise<FieldSchema[]>; provision(map: FieldProvisionMap): Promise<void> }  // D12 自建字段
  kb: { upsert(path: string, md: string): Promise<void>; search(q: string): Promise<KbHit[]>; get(path: string): Promise<string> }
  activity: { since(cursor: string | null): Promise<ActivityPage> }   // 增量轮询契约
  links: { link(a: TicketId, b: TicketId, type: LinkType): Promise<void>; children(id: TicketId): Promise<TicketId[]> }
  guards: {
    install(company: CompanySlug, rules: GuardRule[]): Promise<void>
    uninstall(company: CompanySlug): Promise<void>
    read?(company: CompanySlug): Promise<PlatformRole[]>  // v1.6 读位（暂可选，见下「修订刀」第 1 条）
  }
}
```
- **游标语义**（NA1 教训）：游标是**不透明字符串**（YouTrack 实现内部用「倒序头取+最后活动 id 边界」）；
  核心不解释游标内容，只存取。**坏游标必须显式报错，禁静默当从头**（LocalFile 实现已示范）。
  - 补充（2026-10-17，yt 游标×作用域修复单沉淀）：`cursor=null` 返回**自最旧起的对账全量**（靠 nextCursor
    翻到最新，超过 pageSize 时返回最旧一页）；增量语义只对 `since(边界)` 成立。作用域外边界=全量重放（裁决 a）。
- 写入面全部收口：平台适配器的写方法只被 gateway 调用（17-§7），核心其他模块走只读面。
- **适配器实例=公司作用域**：公司/项目绑定在构造时注入（PlatformBinding），故 IssueQuery 无 project 维、
  guards 的 company 键与 transition 的单号在实例内自洽。
- **端口错误标准形状 = kernel.ClassifiedError**（category+subcause）：实现抛错必须可映射两级分类。

**Platform 泳道首刀反馈裁决（2026-10-16，v1.2）**：
1. IssueQuery 删 project 维（作用域归构造绑定，见上）
2. IssueRecord 补 `description?`（可写必须可读回）
3. SignedBody 补 `author: PersonId`（Comment.author 由此派生，signature 只是展示形态）
4. PlatformActivity.issue 改可选（kb/fields/guards 类平台级变更可无单）
5. 写方法不带 actor——归因归 gateway/wkey 层，端口不承载（by design，LocalFile 反馈确认）
6. FieldProvisionMap 补 `types?`（缺省 string）
7. 晋升时迁移 localplatform 到 v1.2 口径（去 project 过滤、SignedBody 补 author、活动 issue 可选）

**FlowPlatform 端口契约修订刀（2026-10-19，v1.6——制作人圈选定案，四项）**：
1. **guards 补读位**：`read?(company: CompanySlug): Promise<PlatformRole[]>`，形状
   `{ slug: string; name: string; permissions: readonly string[] }`（锚=Taiga roles 快照，docs/32-§二⑤：
   成员类 33 枚/stakeholder 19 枚）——onboard 守闸补偿（30-§6「⑤ 安装的角色权限数组即写权限
   收窄闸」）的审计/回读素材。本刀落地：localplatform（=已装 guard 规则的角色投影，LocalFile 无
   平台角色真源，如实投影不造）与 yt（读位同 install/uninstall 归 N6 后续单，显式明报不静默）；
   **taiga 侧接线明确推迟**——platform 泳道在飞改 packages/taiga（readTaigaRoles 素材已备），
   下刀归该泳道，本刀不碰避冲突。**故 read 暂为可选位**（taiga 在本仓已实现 FlowPlatform，必选
   即断其编译）；三实现接线齐后**转必选**；缺位≠支持——调用方应视为实现缺口明报，不得静默当空清单。
2. **actor 语义（选A）**：`PlatformActivity.actor` = **平台侧可归因主体**（平台账号名：
   yt=author.login、taiga=username；LocalFile 例外=工号——本就无平台账号层）；**工号翻译归框架侧**
   （公司目录账号映射表，docs/04-§五）——翻译机制本身归后续刀，端口不承载。
3. **kind 词表冻结**：`PLATFORM_ACTIVITY_KINDS = created | commented | transitioned | field-set | change
   | unknown`（三家实现**实际产出**归并：前四=localplatform/yt 归一动词、change=taiga history 兜底、
   unknown=yt 退化档）。词表**只增不改**，加词走批示；词表外值=实现缺陷，契约校验
   （`isPlatformActivityKind`）拒收——yt 未知类别原样透传通道随之废除（归入 unknown 兜底档）。
   注记：**created 类事件以 webhook 为主通道，轮询不保证**（Taiga 建单不进 history 实测，docs/32-§七）。
4. **lane/level 统一约定（选B）**：IssueQuery/IssueCreate/IssueRecord 的 lane/level 两维 =
   **onboard 统一约定的自定义属性映射（所有平台同形状）**——平台无原生维时（Taiga 一律无、
   YouTrack 部分）由 onboard 步骤统一建名（30-§6-⑥ 本步一并建），适配器只做同形状翻译，
   未映射时显式报错（不静默吞）；lane/level 本身是公司目录概念（04），平台侧只存字符串。

### 3.4 唤起源端口（ports/invoke.ts｜依据 22，原文冻结）

```typescript
export interface InvokeIntent {
  kind: 'ticket' | 'mention' | 'schedule' | 'relay' | 'resume' | 'webhook' | 'escalate' | 'data-change'
  company: CompanySlug; ticket?: TicketId; payload?: unknown
  source: string; priority?: number
}
export interface InvokeSource {
  readonly name: string
  start(emit: (intent: InvokeIntent) => void): void   // 只产意图，绝不直接驱动 worker
  stop(): void
}
export interface SourceManifest { name: string; kind: InvokeIntent['kind']; configSchema: string }  // 注册用，走进化管线
```
