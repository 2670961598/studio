## 一、结论

1. **P0 = 2，P1 = 6，P2 = 1（共 9 条）**；子报告已报的 P0 **至少 29 条**（`**P0**` 粗体行 26 + V06 的 3 条非粗体写法，见 §3.2），本报告**不重复**它们，只补跨卷可见、单卷看不见的断点。
2. 最严重三条：**O5-01（P0）独立性的供给缺口**——每卷都把"独立位置"当既有资源，而 63-§三 明文承认的单人公司/单 agent 公司没有任何合法履职路径；**O5-02（P0）撤回只定义"本次授予"，不定义"派生执行体与被复制凭据"**——授权撤回可以在子 agent 仍持有可用凭据时"完成"；**O5-04（P1）验收人失联没有合法出口**——67/77 把"转呈"写成验收位置缺位的失败出口，但待验收态没有到转呈或暂停的迁移边。
3. 系统性问题 5 条（§2.4）：**①必填字段悬空到可选位置或未实现组件；②独立性被当既有资源；③撤回/撤销不管派生与复制；④同一语义在三层各有一个主表；⑤失败出口指向不存在的迁移或记录。** 每条都能覆盖 3 个以上单卷问题。
4. 十个自建反例中，**2 个完全未被覆盖**（S3 撤回后凭据留在子 agent、S5 冷启动），**5 个只被报了一部分**（S1 跨公司+派生执行体、S4 验收人失联、S8 未激活就开面板、S9 必填悬空、S10 记录注册），**3 个已被子报告覆盖**（S2 DSH+PRM、S6 台账分裂、S7 学习改判据）。
5. 本报告的分级与个别子报告不一致**一处**：V01-09 把"`REC-AUTH-07` 被当作出工授权来源"判 P2，本报告判 **P1**（§2.2 O5-08，理由见该条）。另有 3 组子报告对同一根因各报各的、未合并（§3.2）。
6. 一句话判断：**这套文档在"证明边界"上是诚实的（76-§12.1、77-§12.3、78 头注、82-§0 都自认未执行），但在"谁来提供独立性与谁给第一张记录授权"这两处，把设计选择伪装成了既有事实。**
