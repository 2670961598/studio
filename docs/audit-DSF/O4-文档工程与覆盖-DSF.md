## 一、结论

1. **P0 = 1，P1 = 5，P2 = 4（本报告新增 10 条）**；另有 3 条系统性问题模式（§2.5），每条覆盖 ≥4 份子报告的单卷问题，不另计分。**本报告不新增逻辑/权责层的 P0**——那层已由 O1（归并 5）、O2（4）、O5（2）与 C/L/V 组计分。
2. **文字层好，状态层坏**。机械面很干净：跨卷节引用 2,101 条只有 6 处断（0.3%）；`F-*` 1,163 个，76–82 全部引用**缺失 0**；无零入边文档；81-files 对第一方文件的覆盖**成立**。坏的是四类**状态**——版本、审查状态、覆盖声明、P0/P1 清零口径——都没有主表、没有失效规则、没有裁定主体。
3. 最严重三条：
   - **O4-01（P0）过审门禁不可判定**：75-§九 要求「P0/P1 必须清零」，而同一批子报告的 P0 总数有**五种数法**（GLM 16、O5「至少 29」、O2「51 行」、O1「57 条」、本报告机械加总 62）；没有登记表、去重规则与裁定者，「全组复核」是匿名主体，两族又互不复读。于是「清零」既不能证明也不能证伪，门禁不是控制。
   - **O4-02（P1）审查 PASS 无失效规则**：68:301 自订「后续修改…必须重新审查」，65–67 已改 v1.1.1/v1.1.2，73:299 却明示「不追改 68 的历史结论」，而 73:542-544 仍把「四路复审 PASS（P0=0、P1=0、P2=0）」写成呈审结论——70/72 已被本族判出 P0（C03b-P0-01、L2F-01、C07-P0-01）。
   - **O4-03（P1）批准对象不可指认**：00 头注 v0.9（10-15）而正文含 10-16 拍板（00:76）；73 头注 v0.2.1（10-26）而 §九 记录 10-27（73:553/591）；25 头注 v1.7 而正文写 v1.8（25:3）；74 的代际表落后 4 个版本号（74:40-41）。制作人若批"v0.9"，批的是哪一文本不可判定。
4. **覆盖结论**：84 份顶层文档 + 19 份附录中，63–74 与 75–82 交叉覆盖最好，00–08/16–20 有全文读；**21–62 这 42 卷没有任何报告对其中任何一卷负全卷责任**（C09 是唯一专项，读全文的只有 21/22/23/38/40/50）。`09–15` 从未存在（08:116-132、08:135 承诺），`39` 缺号；21A/26/30/32/33/34/36/37/41/45/46/47/48/53 无任何专项。
5. **81-files 覆盖第一方文件成立，但"逐册审过"不成立**：我独立复核 src 310/310、test 209/209、模板 225/225、guards 3/3 的文件名全部在 81 语料出现，`F-*` 零缺失；但七份 L3 逐文件报告每份都自述只通读部分附录。只能写「抽样 + 机械核对」，不能写「逐条审计」。
6. **两族审计互不复读**：GLM 自认「DSF 侧仅做统计并排未逐份复读」（GLM 00:66）；DSF 58 份（测量时）中只有 5 份提到 GLM，全为「存在性/未读」。而 GLM 的并排表把 DSF 写成「覆盖 01-82 全代际」（GLM 00:53），与 DSF 各报告自述的未覆盖清单相反。
7. **三分法（§2.4）**：必须现在修 = O4-01/02/03/04；可以带着走 = O4-05/06 与全部 P2；只能真机或代码验证 = 210/2976 全绿、81 逐件"现有/目标"状态、审计语料入库与合并。**置信度 high**（机械面可复算）；覆盖矩阵 **medium**（依据子报告自述，未逐卷重读）。

### 2.5 三条系统性问题模式（每条覆盖多份单卷问题）

**模式 A · 状态无主表**（覆盖 O4-01/02/03 + V14-P1-3、V14-P2-5、L2-D-P1-1）
这套库对"对象状态"极其苛刻（十态工作、十三态能力、四态身份、六态观察、五种证据状态），但对**文档自己的状态**只有散文：版本写在头注（且会落后于正文）、审查状态写在审查记录的结论段（且不随文本变更失效）、覆盖状态写在每份子报告的"未覆盖清单"里（且无人汇总）、清零状态根本不存在。四类状态全部没有表、没有失效规则、没有裁定主体。这不是四个孤立缺陷，是同一层缺失：**文档作为被治理对象，没有自己的状态机**。

**模式 B · 局部写成全量**（覆盖 O4-05/06 + C08-1、L2-D-P1-3、V12、O2-08、C04 的幻影节号）
五处同形：①一次全绿 → "当前基线"（73→75→82）；②多个组各覆盖一部分 → "覆盖 01-82 全代际"（GLM 00:53）；③抽读 19 册中的 12 册 → "81 附录逐文件契约已审"；④"设计面已闭合" → 被读成"实现/验证已做"（82-§14.3 自己防了这一条，但 GLM 的 A 档仍要按"设计已闭合"放行 MIG）；⑤子报告复述幻影节号（C04 引 `69-§0.1`）——局部错误被引文放大成全量证据。**这是本族最需要警惕的行为模式**，因为每一条单独看都"大体为真"。

**模式 C · 入口五套、读者无路**（覆盖 O4-04 + V14-P0-1、V14-P1-1、L0-A-P1-01、C04-P0-2）
00 按"文档库结构"索引、05 按"读者平面"分置、20 按"施工依据链"排序、73 按"代际基线"分表、75 按"卷间唯一边界"分卷——五套分法各有其理，但没有一套是**超集**。后果具体：新接手者从 00 进入找不到 63–82；从 73 进入找不到 75–82；从 20 进入回到 17/18；从 75 进入又被告知"事实与审查入口为 73"。任何"读完 X 即可开工"的指引都会在第五跳失效。V14 已就"唯一入口"计 P0；本条的价值是给出**补齐所需的字段**（卷/代际/审查状态/主入口/覆盖状态），使 00 可以成为超集。
