# C10 · 层间连接审计：跨层 ID 与术语（A 侧 → B 侧）

> 审计代号：C10 ｜ 轴：连接（层间）｜ 审计日期：2026-10-27 ｜ 口径：`_scope-DSF.md`
> 范围：`00`、`08`（L0）→ `63`、`64`（根理论/册界）→ `69`、`70`（技术抽象）→ `75`–`78`、`80`、`82`（技术细节）
> 性质：只读审计。本报告不修改任何设计文档、源码、配置，只写本文件。
> 定位：本报告只判「A 侧的概念/ID/承诺到 B 侧是承接、改写、丢失还是新增」，不重判 `C04`/`C05`/`L0-A` 已单独计分的议题；同源处只做引用不重复计分。

## 一、结论

- **P0 = 0，P1 = 5，P2 = 5。** 未发现使整套设计当场不成立的连接断裂；发现 5 处「按本设计自己的规则判定即非法，但可一句话修正」的层间冲突。
- 最严重 3 条：
  1. **「记录 ≠ 事实」这条宪法级区分在 80 被说反**：`RecordEnvelope<RecEvent>` 的角色被写成「事实」、`records` 被写成「事实面」（`80:752`、`80:762`、`80:1617`），而 `63:540`（I-2）、`69:27`、`76:1577-1586`、`77:80-84` 四处都规定记录不是事实、无记录只能写「未知」。这是唯一一处把不变量在**实现面用词上倒置**的地方。
  2. **「验收/判断结果」的可写入字面量在三卷出现两套互斥取值**：`72:126` 与 `76:2094`（STAT-E）是六个英文字面量，`77:1530`（`REC-EVD-04.verdict`）是四个中文字面量，`77:1519-1520` 又说该族「登记见 76-STAT-E」，`80:714` 声明「中文枚举例外只有一种」。按 `77:61` 自订规则「同一个枚举在两卷出现两套可写入值，等于 schema 与 payload 必有一边非法」，此处必然一边非法。
  3. **治理位置任命链的起点被降级为「可选项」**：`76:2003` 与 `82:522` 把「治理配置责任者」列为**不属于**核心 11 类的**可选项**，但 `76:1983-1993` 里 11 类位置的「设置/任命权源」全部是它，`70:383` 与 `66:221/691` 也把它写成「空缺则不得动作」的前提。照 76 的目录配置一家公司，可以得到 11 个位置齐全、却无人有权任命它们的治理层。
- 机械核对结论（用于校准，不是表扬）：`R1–R31` 的治理主答在 `64-§四`/`69-§七`/`76:2308-2340` 三处 **31/31 完全一致、0 处不符**；`I-1–I-16` 与 11 类治理位置在 82 各 16/11 行齐备；`DEF-*`/`REC-*`/`GOV-*` 的跨卷引用**未发现一处断链**（详见 §三）。
- 本报告的 P1 全部是「一句话可修」的登记/字面量/分类冲突，不是「必须重写」；但也全部不能带着走，因为每一条都会让实现者两头挨罚。

### 2.B 发现（P1 → P2）

#### C10-01 ｜ P1 ｜ A 矛盾＋C 漂移 ｜「记录」在 80 被当作「事实/事实面」

- **位置**：`80:752`、`80:762`、`80:1617`（对照：`77:80` §0.4、`76:1577-1586` §4.6、`63:540` I-2、`69:27`）
- **事实/引文**：
  - `80:752`：「| 交换/记录层 | `RecordEnvelope<RecEvent>` | **事实**；50 类之一；跨实现可交换 |」
  - `80:762`：「目标态是**另立事实面**（`records` 整封 + `record_payloads` 原始字节…）」；`80:1617` 亦称三表为「**事实面与机制面**」。
  - 对照 `77:80`：「### 0.4 记录不是事实」；`76:1586`：「有记录就说明外部影响已完成」／「没有记录就说明没发生」两条均列为**误读**，只能写「未观察到/未知」；`63:540`：「记录存在也不证明其内容为真…不得规定『无记录即外部未发生』」。
- **为什么错**：`63-I-2` 是全局不变量，`76-§4.6` 是它的信封级判据，`77-§0.4` 是它的记录级判据。80 是唯一被实现者逐行照抄的接口卷（TS 类型、表名、落点），它把**记录层**命名为「事实」和「事实面」，等于在实现词汇里预置了「库里有的就是事实、库里没有的就不是」这一被 I-2 明文禁止的读法。同一段 80 的正文（`80:764-769`）其实守住了「由投影派生不得伪造历史」，因此这不是立场错误，而是**用语把不变量说反**——但正是这种用语会变成表注释、类型注释和后来的验收口径。
- **不判 P0 的理由**：80 正文另有四处正确表述（`80:2281`、`80:2329`、`80:1617` 的「不是 `ProjectionName`」、`80:769`），且 76/77 的判据仍可直接引用；链条未被切断，误读风险落在实现面。
- **最小修复**：把 `80:752` 的角色列改为「**记录**（可交换的记录层，不是事实本身）」，把 `80:762`「另立事实面」改为「另立**记录层**（区别于投影）」，`80:1617` 同改；并在 §4.6 表下补一行「本段用『事实』仅指『非投影』这一相对位置，不表示记录证明事实（76-§4.6、63-I-2）」。

#### C10-02 ｜ P1 ｜ A 矛盾＋G 治理 ｜「验收/判断结果」的**可写入字面量**三卷两套

- **位置**：`72:126`、`76:2094`（STAT-E）、`77:1530`、`77:1519-1520`、`77:61`、`80:714`
- **事实/引文**：
  - `72:126`：`completed`、`accepted`、`conditionally accepted`、`rejected`、`terminated`、`settled`（六英文）；`76:2094` 逐字相同，并注明规范位置 `72-§2.2`、禁止「互换」。
  - `77:1530`：`verdict` ＝「`接受`/`附条件接受`/`拒绝`/`依授权终止`」（四中文）。
  - `77:1519-1520`：「执行完成、验收接受、附条件接受、拒绝、终止、结清必须保持不同语义…（该族的登记与禁止混用见 **76-STAT-E**）」。
  - `77:61`：「同一个枚举在两个卷里出现两套可写入值，等于 schema 与 payload 必有一边非法。」
  - `80:714`：「**例外只有一种**：77 已把中文定为 payload 值的枚举（如 `REC-WORK-04.verdict`…）」。
- **为什么错**：三卷对同一个「判断结果」族给出互斥的字面量规则，且 77 自己在两处互相指认（`1519` 指向 76 的英文登记，`1530` 用中文）。`80:714` 的「例外只有一种」也已被 77 自身证伪：`REC-WORK-02.outcome`（五中文，`77:818` 区段）、`REC-EVD-04.verdict`（四中文）、`REC-EVD-06.settled_state`（四中文，`77:1742`）、`REC-WORK-10.action_kind`（十一中文，`77:1184`）全都是中文 payload 枚举，而 `80` 只承认 `REC-WORK-04.verdict` 一处。实现者按 80 编 TS 联合类型必然二选一，两边都有被判非法的路径。
- **为什么不是 P2**：这不是文风，而是「schema 与 payload 必有一边非法」的硬判据被同时违反两处（77 与 80 各一处），且直接决定 TS 类型与校验器的取值域。
- **最小修复**：①在 `76-§7.7` STAT-E 行加一句「本族可写入字面量以 77-§6.4.1 的 payload 值为准，本表英文为语义标签」（或反向：把 77 的 `verdict` 改为英文四值并给中文映射表）——择一写死；②修正 `80:714` 的「例外只有一种」为「中文 payload 枚举清单见 77-§0.2 及本卷 §4.7 逐项登记」，并在 §4.7 为上述四个中文枚举各列一行。

#### C10-03 ｜ P1 ｜ B 缺口＋F 权责失真 ｜治理位置任命链的起点被降为「可选」

- **位置**：`76:2003`、`82:522` vs `76:1983-1993`、`70:383`、`66:221`、`66:691`
- **事实/引文**：
  - `76:2003`：「**附加推荐条目（不属于上述 11 类，可选项）**：…监督、外部锚、**治理配置责任者**。…目录可以收录它们，但不得据此宣称核心 11 类已完成。」
  - `82:522`：「附加推荐位置（…监督、外部锚、**治理配置责任者**）**不计入这 11 行**」。
  - `76:1983`（`GOV-POS-01`）起，`POS-01`–`POS-10` 的「设置/任命权源」全部写「治理配置责任者」；`76:2000` 第 11 类亦由该责任者设置。
  - `70:383`：「实际设置、任命、回避与替换由 `66-§5.2.1` 的治理配置责任者按宪制办理」。
  - `66:221`：「**治理配置责任者**是由最终责任位置或其明示上位授权者指定的具名岗位，负责…设置、任命、回避与替换本章所列工作治理位置」；`66:691`：「治理配置责任者或治理位置空缺则**不得动作**，仅保全与升级」。
- **为什么错**：`66`/`70` 把治理配置责任者写成**构成性前提**（没有它，位置不能设、人不能任、动作不能做），`76`/`82` 把它写成**可选增强**。两者不能同时为真。后果是：一家公司若严格按 76-§7.2 的「11 类下限」配置，可以在不设治理配置责任者的情况下宣称「核心 11 类齐全」，而这 11 个位置在 `76` 自己的表里**没有任何合法任命者**——`DEF-GOV-01.appointmentAuthorityRef`（`76:1406`）必填，却指向一个不存在的岗位。这正是 `I-4`（权责可结算）与 `I-9`（主语必须明确）在技术细节层的落地失败：位置有名、权源无主。
- **为什么不是 P0**：`66`/`70` 给出了唯一正确读法，冲突可被上一级文档裁决；被破坏的是 76/82 两卷的分类，不是整条链。
