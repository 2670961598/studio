## 1. 结论

1. **P0 = 1，P1 = 7，P2 = 2。** 断点不在"接口没写细"，而在**四个对象在 L2/L3 没有承载**：外部来源的委托主体、对外 MCP 面、责任分配（含对外最终责任）、跨公司承诺的相对方；以及**一个验证口径把参考实现的运行时当成了规范前置**。
2. 最严重三条：
   - **V11-01（P0）**：`01-C3-07` 的"派单人锚 + 等级封顶 + 来源署名"三件，在 69/70/76/77/80/82 **零命中**（机械核对：六卷 `派单人` 命中 0）。落单路径 `WebhookIntentPayload`（`80:2227`）与回执 `IntentReceipt`（`80:2250`）无调用者身份字段；`REC-WORK-01.source` 的子键被 `80:2298` 固定为 `{channel,dedupKey,ticket?,kind}`（无"谁"）；`SUBJECT-REF` 只允许六值且不含 `stakeholder`/`company`（`76:1557`）。外部 AI 的委托既不能落到外部主体，也没有兜底锚。
   - **V11-02（P1）**：`24-§三`/`45-§二`/`01-C3-14` 的"对外 MCP server 为主协议面 + 十工具"在 L3 **只剩一条损失声明和一个名字常量**（`78:1547`、`81f01:383`）。`80:3153` 把"MCP 工具目录"直接指成 `studio-tools`（内部 worker 写平台面，六动词=`GATEWAY_ACTIONS`），与对外十工具方向相反（`47:257-259` 明说两张表）——同名异义。
   - **V11-07（P1）**：`69:524` 把 V0–V4 定为**跨框架符合性最低层**，而 `82:126/174/195` 把 V2 的输入写成"真实 Node 24 进程 + 真实 SQLite + `user_version`"。第二实现必须跑本仓运行时才能"符合规范"，与 `69:568`（Node/TS/SQLite 只属实现说明）、`70:880`（不必复制 Node/DSH/git）正面冲突。
3. **通过项（不构成本报告发现，供作者留用）**：①"只落单不派工"在 L3 主路径上仍是硬的——`80:3292`「不得直接 `launch` worker…外部请求最多到'受理结论'为止」，且 API 不碰库/不碰平台（`80:3289`）；②`REC-WORK-01/02` 的受理链（`77:801-860`）与五取值、`intent_receipts` 可重建投影（`80-§6.6` 规则 1-6）承接完整；③**公司定义包复制 vs 公司身份迁移**这一条从 L2 到 L3 **没有断**（见 §2.0 第 11 行），是本链最结实的一段。

### 2.1 关键断点（8 条，各说明会让什么失效）

1. **V11-01** 让 **`C3-07` 的验收口径整条失效**，并抽掉权责链起点：外部意图进入系统后，"谁委托/几级/依据哪条请求"无字段可答；后续派工、验收、结案无法追到委托主体（`69:400` 的 I-1「正当性先于效率」失去可核对象）。
2. **V11-02** 让"公司成为 agent 生态里**可雇佣**的节点"（`45:86`）只剩"可查询"；并使"对外 MCP"与"内部 worker 工具面"同名——照 `80:3153` 实现即把 `GATEWAY_ACTIONS`（写平台）方向暴露到外部面，直接撞 `01-C3-14` 的"状态推进永不在列"。
3. **V11-03** 让 **R15/R16/I-7 的追溯对象无处落**：责任分配不是可独立登记/争议/结清的对象，只是一张合同或一次出工里的字段；对外最终责任只剩"合并/分立/联合/承继"一条记录类型（`REC-LIFE-03`），无法对"某一次联合承诺"逐项挂责。
4. **V11-04** 让"只落单不派工"从**硬边界**变成**默认关闭的开关**；`45` 是制作人三问落档（`45:12-15`），实现者照它建第三级比照探索稿 `47` 拒绝第三级更可能。
5. **V11-05** 让 `C3-04/C3-08/C3-10` **无法验收**：`80` 的 16 条是"唯一口径"，被删掉的端点没有任何"未表达/不支持"声明（`70:845-857` 要求逐项标损）。
6. **V11-06** 让外部面**不可按伙伴吊销**：单 token 无 scope、无 TTL、无 per-agent 吊销，与 `01:60`「吊销 30s 内失效；fail-closed」和 `45:95`「按 agent 签发 token、scope 化、可吊销」冲突；同一节又要求 per-partner credential ID，装配面却只有 `token: string`。
7. **V11-07** 让**跨框架符合性在证明层不成立**：`76/77/78` 正文的技术中立是成立的（`76:29` 明令禁止把语言/运行时/DB 写进规范），但"符合规范"的最低层被绑到本仓运行时——这正是本链"公共规范去掉 Node/TS/DSH/SQLite 后是否仍成立"的答案：**语义层成立，符合性机器不成立**。
8. **V11-08** 让**跨公司交付不可验收**：`82:422` 的 R16 唯一测试类型是 `V3·INT`，而 V3 的前置是"第二实现"（`82:127`、`82:724`），本项目无第二实现；R16 又是 `69:520` 规定"任何 profile 不得跳过"的强制核心反例。
