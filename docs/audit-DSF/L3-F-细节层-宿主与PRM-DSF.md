## 一、结论

1. **78 对 78a 是“真吸收”，不是另写一套**：四平面、position 插件九职责、PRM 九段、E0–E6、七族矩阵、N1–N10、决策 1/3–10 均可逐条对上；决策 2 的改动也在 §0.5 明记（78a:683 → 78:96）。
2. **但吸收停在“方案层”**：78 把 78a 的“机制在哪”写成了“边界在哪”，而 78 自己标为“目标/未证”的写域、读域、沙箱，在 §7 与 §0.7 的“现状”列里被写成部署事实——这是本卷最系统的问题（L3F-01/02）。
3. **P0 1 条、P1 9 条、P2 6 条。**
4. 最严重三条：**L3F-01（P0）** E2 的签根 `gatewaySecret` 与被闸方同信任域，而 78 只登记了“工作区内文件可读”；**L3F-04（P1）** PRM `authority` 段没有元素形状与逐项来源，76 的四态判定在清单里落不了地；**L3F-02（P1）** 唯一已证的写域机制（seatbelt）只在 judge 路径，公司目录/安装根/台账的“只读”无机制或未探。
5. **十三态映射通过**：`4/5→H0a`、`6→H0b`、`9+10→H2`、`11/12/13→—` 与 77-§4.8（77:1137–1151）、§4.9（77:1165–1172）逐项一致，未发现非法迁移；问题不在状态映射，而在“按段计”的字段（L3F-06）与失败处置（L3F-07/08）。
6. **78a 的“未做真机探针”被如实继承**：78 头注（78:11）、§13.1（78:1666–1670）、§13.2（78:1674–1691，除 `P-78-05` 引既有负证据外全为 `not-executed`）、§13.3（78:1697–1715）一致；这一点通过。不通过的是把“随包 README 契约 + 局部已证”推成“部署现状”。
7. 交班结论：**可以带着走**的是 §4（插件职责/不可写面/事件）、§5.2–5.5（E 类定义与成本论证）、§6.3–6.4（loop/独立性）、§7.3（seatbelt 已证/不可证）；**必须现在修**的是 L3F-01/02/04/06，否则 82 的符合性声明与 81 的插件契约会按两套字段落地。
