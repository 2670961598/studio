## 1. 现状对照（诚实盘点，源码实查）

| 能力 | 现状 | 依据 |
|---|---|---|
| 优雅**停** | ✅ 已有 | SIGINT/SIGTERM 同一收口：先停唤起源（不进新意图）→ 在途 drain → 关台账落盘；真跑实证 101 拍 exit 0 |
| 硬杀**重启恢复** | ◐ 部分 | 崩溃注入五点测试证「重启同单重派 attempt 不漂、预算 adopt 不双落」；但 serve 头注明示「work_records 在途 running 的接管归后续刀」——接管面未收口 |
| 安全升级治理 | ✅ 已有 | 进化链四刀（v0.10）：candidates 状态机→判负闸→沙箱→切权（备份+原子写+复核+回滚+SCHEMA_EVOLVE 落账）→灰度窗（阈值自动回滚） |
| 切权后生效方式 | ◐ 提示不重启 | cutover 头注诚实边界：「supervisor 看护重启归运维刀（v0 只提示不实际重启）」——**切完权没有自动让它生效的机制** |
| **优雅重载（热重载）** | ☐ 无 | 无 SIGUSR/HUP 面、无进程移交、无配置热重载 |
| 自优化驾驶 | ☐ 无 | 进化链是「轨道」，没有「司机」——candidates 目前靠人/单驱动，无自动提案→验证→切权→重载闭环 |

**结论：治理轨道（进化链）已铺好，缺「重载机车」（让变更不停机生效）和「司机」（自优化驱动）。**

## 2. 优雅重载的两级语义（拟）

- **L1 配置级热重载**（低风险，先做）：org-config/提示词/价目表等**公司目录资产**变更 → drain 到拍边界 → 重新装载 → 继续跑，**不换进程**。触发：文件指纹变化（daemon 挂单 commit 的公司目录本就有指纹账）或 `studio-next reload --company <slug>`。适用面：docs/33 部门模板调整、提示词迭代、jobs 五段改配——自优化的绝大多数产物走这级。
- **L2 代码级优雅重载**（换进程不换体验）：框架自身代码变更 → 老进程 drain（在途单收口或快照）→ supervisor spawn 新进程（同库同目录）→ 健康自检（面板/引擎/台账三探针）→ 老进程退；失败=新进程起不来则老进程继续服役并告警（灰度窗语义延伸到进程面）。触发：`studio-next reload`（全量）或 cutover 成功后的自动动作（进化链第⑤环补齐）。
- **在途接管收口**（L2 前置）：work_records running 项的重启接管——崩溃注入测试已有重派 attempt 语义，把「重启接管」从测试面转正为 serve 启动例行。

## 3. 自优化闭环（拟）

```
StudioNext-开发公司（dogfooding：本公司业务=开发 StudioNext 本体）
  产出=候选变更（提示词/配置/代码单）→ 走既有进化链：
  sandbox（沙箱跑）→ gate（判负闸）→ cutover（备份+原子写）→
  ★重载（本案新增环：L1 直接生效 / L2 进程交接）→
  gray（灰度窗观察+阈值自动回滚——回滚也走重载）→ 复盘归档
```

- 司机=开发公司的岗位（架构岗提案/质量岗验证/宰相岗汇总），全部走真单真闸——**框架吃自己的狗粮**
- 首个 dogfooding 场景建议：把「面板前端重构」（docs/37 圈选后）作为开发公司第一张真单——产物进仓走 PR 纪律；提示词/配置类优化从第二张单起步走完整进化链

## 4. 分期拆刀（拟）

| 刀 | 内容 | 依赖 |
|---|---|---|
| **R-A** 配置级热重载 | 指纹监听+拍边界重装载+reload 子命令+单测 | 无（可立即开工） |
| **R-B** 在途接管收口 | serve 启动例行接管 work_records running（崩溃测试语义转正） | 无 |
| **R-C** 代码级优雅重载 | supervisor 化+进程移交+健康三探针+失败自愈 | R-B |
| **R-D** dogfooding 开张 | StudioNext-开发公司 onboard（首个自优化真单） | R-A + bridge 接线刀完工 |
