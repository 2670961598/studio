# 24 · AI 接入面（AGENTS.md 与 MCP 的分层）

> 2026-10-16 ｜ 回应制作人：我们的能力怎么给 AI 用——做成最大的 MCP？还是 AGENTS.md 拼接？
> 答案：**分层，不二选一**。知识归 AGENTS.md，工具归 MCP，对外归协议端点。

## 一、三层分工

| 层 | 内容 | 载体 | 说明 |
|---|---|---|---|
| 身份与知识层 | 我是谁/公司是谁/规矩/任务书/教训 | **AGENTS.md 组装**（L0-L5） | 上下文不是工具；MCP 塞不进"你是谁" |
| 工具能力层（对内） | yt 网关操作/kb-search/证据落盘/预算查询/工时上报 | **内部 MCP server**（`studio-tools`） | typed/可发现/可鉴权；schema 自带签名，AGENTS.md 不再教"怎么调" |
| 对外 AI 层 | 查公司/组织/进度/成本、提需求、触发探索、订阅事件 | **对外 MCP server** + A2A exporter（备选） | 外部 AI 只认协议端点 |

## 二、内部 MCP server（studio-tools）

- 每个 worker 的 CLI 原生挂载（dsh 插件/mcp 配置、claude `--mcp-config`、kimi/codex 各自的 mcp 接入）
- 工具集=网关白名单的机器化：comment/heartbeat/article/kb-search/evidence-write/budget-query……
  鉴权沿用 wkey（MCP 初始化时注入，按单签发关单吊销）
- **AGENTS.md 只教"什么时候用哪个"，不教"怎么调"**——后者由 MCP schema 承担，
  提示词体积下降、误用率下降（格式错误由协议层拒绝，不再靠模型自觉）
- 状态推进永不在工具集（协作纪律不变）

## 三、对外 MCP server

- 端点即 15-对外AI准入 的工具化：`company.get/org.get/people.get/progress.get/finance.get`
  + `request.create/explore.trigger/task.create/intel.submit` + `events.subscribe`
- 鉴权三档沿用 C3-03；触发类只落单不派工；外部主体台账独立
- A2A 只做 exporter（名片从 org-config 生成）；MCP 为主协议面

## 四、验收口径

1. 内部：worker 在任务书里零"怎么调"的教学文本，全靠 MCP 工具描述跑通一单
2. 外部：mock 外部 AI 经 MCP 完成"查进度→提需求→读回执"闭环，越权全 fail-closed
3. 两家以上 CLI（dsh+claude）挂同一 MCP server 行为一致
