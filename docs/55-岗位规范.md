## 〇、结论先行：三句话

1. **岗位不是定时任务，定时只是岗位的唤醒方式之一。** 岗位是持久的责任包：
   职责（mandate）+ 授权（authority）+ 义务（obligations）+ 接口（interfaces）+
   预算（budget）+ 记忆（memory）+ 技能（skills）+ 绩效（performance）+ 生命周期
   （lifecycle）。
2. **岗位（模板/编制）与工号（任职者实例）必须二分。** 任职者换，岗位不换；岗位配置
   变更不得改写历史工号的当时快照——台账必须能复算「当时谁有什么权」。
3. **本规范分两条轨定稿**：❄️=原则级（冻结；改动=提案流+制作人亲批，属判据类资产
   20-§九）；β=机制级（方向定稿；进实现单前必须挂 spike 证据，20-§十三第 5 步）。
   **没有第三条轨**——现在不定稿的东西不写进正文，只进 §九 待拍板项。前瞻性的载体
   不是「一次写死所有内容」，而是 §五 的版本演进纪律（怎么改规矩的规矩先定死）。

## 一、总判定：什么是岗位

**岗位（Position）= 组织内持久的责任包。** 它回答七个问题：拥有什么（mandate）、
能批什么（authority）、欠什么（obligations）、和谁打交道（interfaces）、花多少
（budget）、记得什么（memory/skills）、干得好不好（performance）。

与现有件的关系（不推翻，只归位）：

| 现有件 | 在岗位模型里的位置 |
|---|---|
| `people[]` + `people/<工号>.md`（51 B-3） | **任职者**：岗位可能被工号担任；档案=人读面 |
| `jobs[]`（51 B-4） | **触发器**：岗位的时间/节奏唤醒方式之一；jobs 不定义岗位 |
| `departments[]`（51 B-2） | **容器**：岗位隶属于部门树节点 |
| 章程 `charter/`（51 B-6） | **规范面**：岗位义务/授权不得与章程冲突（冲突=不合法，P-13） |
| 派单律（高一级方可派） | **授权图的默认边**（§二 authority 的缺省来源） |

合法岗位 = 满足 §七 P 组规则。判定器输出沿用 51-§七契约（规则号+文件+位置+修复建议）。

## 二、岗位字段规范（`positions[]`，org-config 可选扩展段）

`positions[]` 是 org-config 的**可选新段**（additive，与 `studio-next/org@1` 兼容，
详 §五）。逐字段形状与稳定轨：

```yaml
positions:
  - id: qa-lead                    # P-1：slug 语法域，全司唯一
    name: 质量部长                  # 非空串
    dept: departments/质量部        # P-2：必须命中 departments.path（C 组交叉）
    level: 4                       # 成熟度锚（沿用 35-§5 松绑语义：默认参数，非编制硬约束）
    type: govern                   # P-3：封闭枚举（下表）
    mandate: |                     # 职责边界（非空文本，人读面）
      对一切交付物的复验结论负责……
    sponsor: producer              # P-4：工号或保留字 producer；对人负责的锚
    mode: ambient                  # P-5：delegate|ambient；缺省 delegate（最小权限）
    authority:                     # 授权面（公司作者写；agent 只能提案，56-§三）
      - action: approve
        scope: { dept: departments/质量部, bill: proposal }
        limit: { budget_le: 500 }
        quorum: 2                  # 可选；>1 时按 56-AUTH-3 多方批准语义
        expiry: 90d                # 可选；到期自动失效（不续即消）
        delegable: false           # 缺省 false；true 时子授权必须 ⊆ 本授权（P-6）
    obligations:                   # 义务面：岗位欠什么
      - id: review-sla
        on: { state: 待复验 }       # 义务触发：state|event|cadence|sla（形状见 56-§二）
        due: 4h                    # 截止（SLA）
        breach: escalate:prime     # 违约后果：escalate:<岗位>|downgrade|alert（封闭枚举）
        accept: gate:review        # 验收引用——义务必须机器可判（P-7）
    interfaces:                    # 接口面
      reports_to: prime            # 向谁汇报（岗位 id）
      supervises: [qa-*]           # 谁向它汇报（支持后缀族）
      co_sign: [fin-lead]          # 联签对手方
      veto: []                     # 对哪些动作有否决（action 枚举子集）
    budget: { cap: 2000, unit: cny-per-month }   # P-12：有权/有义务者必有预算帽
    memory:                        # 记忆面（治理约束在 56-§六）
      max_entries: 100
      inject_chars: 10000
      scope: position              # position|dept|company
      expires: 90d
    skills:                        # 技能面：挂载引用（技能本体=Contract 资产，56-MEM-3）
      - { ref: skills/review-checklist, version: 1.2.0 }   # P-11：必须钉版本
    performance:                   # 绩效面：只声明指标，数据源=台账（P-9 禁止自评）
      metrics: [review_coverage, reopen_rate]
    lifecycle:                     # 生命周期面
      status: active               # active|suspended|retired
      retire_when: 90d 无有效产出   # 退役判据（机器可判文本→判定器语法域见 §七 P-14）
    oncall:                        # 可选值守面（吸收 35-§3）
      primary: QA-1
      backup: QA-2
      window: "09:00-21:00"
      tz: Asia/Shanghai
    triggers:                      # 可选唤醒面（语义规范家=56-§二）；缺省=纯事件/委派驱动
      cadence: daily
```

### 岗位类型封闭枚举（P-3）

| type | 主要职责 | 授权特征 | 指标示例 | 组织理论对应 |
|---|---|---|---|---|
| `execute` | 产出交付物 | 提议、执行、提交证据 | 吞吐/一次通过率/成本 | Stream-aligned |
| `coordinate` | 排期、派发、升级 | 分配、调优先级、升级 | 周期时间/在途数/阻塞时长 | Team lead |
| `govern` | 评审、审计、合规 | 批准/打回/veto | 闸过率/漏检率/复验时延 | VSM S3/S3* |
| `platform` | 工具、基础设施、标准 | 设标准、发版本、封禁 | 可用性/交付 lead time | Platform team |
| `intel` | 外部扫描、规划、研究 | 提议、立项建议 | 机会命中率/预测偏差 | VSM S4 |
| `watch` | 值守巡检 | **只读 + 告警 + 治理动作**（P-8 v1.1：业务写动作→不合法；告警/叫停/关卡主持允许） | 告警时延/误报率 | Gas Town Witness / on-call |

### 授权面两条 ❄️ 原则（字段为 β）

- **委派不放大（P-6 ❄️）**：任何由授权派生的子授权必须是父授权的真子集，且
  `delegation_parent` 必填、可沿链回溯到人（制作人）。授权链每一次行使落台账。
- **sponsor 必填且可追责（P-4 ❄️）**：每个岗位必须有一个对人负责的锚；sponsor 离场
  （人事事件）触发授权吊销 + 派单边关闭 + 在途处置（执行语义=56-AUTH-2）。

## 三、与 jobs[] / people[] 的关系（兼容与迁移）

1. **`jobs[]` 保留为触发器层**（51 B-4 不动）；新增可选键 `jobs[].position` 引用岗位 id
   ——「这条定时任务是在唤醒哪个岗位」。无 positions[] 的旧仓判定结果零变化（additive）。
2. **`people[]` 增三个可选键**（additive）：`position`（担任哪个岗位）、`sponsor`
   （覆盖岗位级缺省）、`mode`（覆盖岗位级缺省）。
3. **岗位无任职者 = 空编**（合法但报 warning，提示「该岗没人」）；任职者无岗位 = 现状
   语义（自由工号，合法）——「先建岗再进人」与「先有人后定岗」两种 staffing 都允许，
   空编可见即可（Workday staffing model 教训：有没有编制必须是显式状态）。
4. **吸收 docs/35-§6 待批示项 1-3**：triggers/oncall/sla/escalate 五段并入本文
   `triggers`/`oncall`/`obligations`（SLA=obligations[].due，escalate=breach）；
   35-§3 草案若与本文冲突，以本文为准（35 是拟稿，本文是规范）。

## 四、写作纪律（公司作者面）

1. **人读/机读分字段**（43-§三铁则重申）：mandate/档案正文=给模型与人读的文本（自由）；
   authority/obligations/triggers=给引擎执行的声明（schema 严格）。不混装。
2. **强制条款的形状**：authority/义务中的条件，用「主体-动作-对象-条件 + 禁止优先」的
   类 Cedar 伪代码块书写（人可读、可逐条测试）；**规范不引入任何策略引擎作为运行时
   依赖**——判定面归 wkey 网关与判定器，不多一个真相源。
3. **岗位说明书字段名**对齐公共词汇表（档案正文小节名）：
   `responsibilities / qualifications / skills`（schema.org JobPosting 命名）；技能词表
   可按 URI 引用受控词表（如 ESCO），不内嵌打包。
4. **prompts/charter 不变**（51 B-6）：行业差异继续落在资产面，不为行业扩张 schema。

## 五、版本与演进（前瞻性的真正载体）

1. `positions[]` 段纳入 `studio-next/org@1`（additive）；本规范生效后作为 docs/51 的
   v1.2 修订并入，判定器增 P 组规则。
2. **只增不删**：minor 内只加可选字段/可选枚举值；删除或改语义必须升 major。
3. **N/N-1 双读**：框架必须能读上一 major 的公司包；更老版本给明确报错 + 升级指引
   （未知版本=拒收，不尽力解析）。
4. **迁移是产物不是承诺**：每个 major 配 `migrations/vN_to_vN+1`，可回放、有单测。
5. **弃用有信号**：deprecated 字段判定器输出 warning（exit 0），至少保留一个 release
   才升 major 移除。
6. **规范与 schema 同源**：规范正文的字段表由 JSON Schema 生成（或反向），CI 跑
   「规范文档 ↔ schema 漂移」检查；schema 发布到固定 URL，模板首行加
   `# yaml-language-server: $schema=…` modeline——社区作者第一天就有 IDE 补全。
7. **模板即合规样例**：`templates/*` 全部进判定器 CI 闸。
8. 与 20-§九 的关系：本规范属判据类资产，定稿不轻改；必须改时按本节 2-5 条走。

## 六、不做什么（边界）

1. **不建模流程图/步骤顺序**：规范只声明义务的触发与验收，不声明工作步骤
   （BPMN 教训：声明式流程与执行鸿沟 + 五年 1.0 的治理成本）。步骤归运行时/任务书。
2. **不做通用企业 HR**：薪酬、招聘、考勤不进 schema。
3. **岗位内部 loop 归框架层**（56）：岗位规范不管 executor 怎么跑，只管岗位欠什么、
   有什么权。
4. **岗位不得自定权限**：authority 只能由公司作者写（git 目录 daemon 唯一写入者纪律
   不变）；agent 对授权的诉求走提案（56-EVO-8）。
5. **不做组织仿真的 schema 面**：仿真输入直接用 org-config 本体，不另建仿真配置格式。

## 七、判定器规则增量（P 组，并入 51-§七判定器契约）

| 规则 | 判定 | 轨 |
|---|---|---|
| P-1 | `positions[].id` slug 语法域、全司唯一（含与 jobs/people id 不撞名） | ❄️ |
| P-2 | `dept` 必须命中 departments.path | ❄️ |
| P-3 | `type` ∈ 封闭枚举六类 | ❄️ |
| P-4 | `sponsor` 必填，∈ people 工号 ∪ {producer}；悬空→不合法 | ❄️ |
| P-5 | `mode` ∈ {delegate, ambient}；缺省 delegate | β |
| P-6 | `delegable: true` 时授权必须可判子集（limit/scope 收窄方向可判）；委派链字段必填 | ❄️ |
| P-7 | `obligations[].accept` 必须引用可执行验收（gate 名/契约用例 id）；纯文本→不合法 | ❄️ |
| P-8 | `type: watch` 的 authority 只许只读动作 + 治理动作（告警/D8 叫停/I2 关卡主持）；出现**业务写动作**（对事实源/业务状态的写，B/C 族写面）→ 不合法 | ❄️ |
| P-9 | `performance.source` 固定 `ledger`；出现自评字段→不合法 | ❄️ |
| P-10 | `memory` 配额超框架上限（56-MEM-1）→ 不合法（框架夹紧值优先） | β |
| P-11 | `skills[].version` 必填（禁 latest/缺省） | β |
| P-12 | 存在 authority 或 obligations 时 `budget.cap` 必填 | ❄️ |
| P-13 | authority/obligations 与章程红线冲突（章程声明的禁项出现在授权面）→ 不合法 | β |
| P-14 | `retire_when` 语法域：`<N>d 无有效产出` 等封闭模板族；自由文本→不合法 | β |
| P-15 | 空编岗位（无任职者）→ 合法但 warning | β |

每条规则至少一对红绿夹具（51-§七纪律不变）；改规则=改规范=版本化修订。

## 八、六名词三动词映射（概念准入闸对账）

| 本文概念 | 映射 | 说明 |
