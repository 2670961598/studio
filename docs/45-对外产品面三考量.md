## 一、协作栈（Taiga + Matrix）：自研、打包、改源码（最关键，先答）

### 1.1 许可证事实表（2026-10-19 双证核实）

| 组件 | 许可证 | 维护状态 | 商用二开友好度 |
|---|---|---|---|
| taiga-back（Django 后端） | **MPL-2.0** | 活跃（2026-09-28 推送；6.10.1 已发） | 高：文件级 copyleft，修改的文件开放即可，可与专有代码组合分发 |
| taiga-front（前端源码） | **AGPL-3.0** | 活跃（2026-10-14 推送） | 低：修改后分发/网络服务须以 AGPL 公开衍生源码 |
| taiga-docker / taiga-front-dist | MPL-2.0 | — | 高 |
| Synapse（Matrix 家服务器） | **AGPL-3.0**（另售商业双许可） | 活跃（2026-10-19 当日推送） | 低（同上）；商业许可另谈 |
| Element Web（Matrix 客户端） | **AGPL-3.0** | 活跃 | 低（同上） |
| **Rust 家服务器线**：Tuwunel / Continuwuity / Conduit | **Apache-2.0** | 活跃（Tuwunel v1.9.4 2026-10-10；Continuwuity 双周发版） | **最高：修改、分发、商用均零义务**（保留版权与许可声明即可） |
| 备选协作平台 | Plane/Leantime=AGPL-3.0；OpenProject=GPL-3.0；Wekan=MIT；Huly=EPL-2.0 | — | Wekan(MIT) 最宽，但选型对比仍以 Taiga 现行为准（docs/30） |

### 1.2 三问直答

**自研可能吗？** 三层答案：
- **从零自研：不做**。项目管理平台与 IM 服务器是两个完整产品域，我们是框架公司，战线
  失焦（docs/06 职责边界精神）。
- **架构上的真自研路线已铺好**：docs/23 已把协作平台抽象为 FlowPlatform 七能力端口，
  YouTrack→Taiga 适配器只是「参考实现」，LocalFile 是「第二实现」——把 LocalFile 逐步
  长成**内置零许可证负担的最小实现**（够用的看板+单据+活动流），才是我们自己的资产；
  外部平台随时可拔插。这不是本季度的事，但方向已锁。
- **基于开源可商用二开：IM 侧完全成立**——Matrix **协议**是开放标准（客户端-服务器
  API 稳定），家服务器实现可整体替换为 Apache-2.0 的 Rust 系（Tuwunel 兼容大部分
  Synapse Admin API，且有 9.3x 初始 sync 性能的独立研究证据）。协作平台侧二开走
  taiga-back（MPL-2.0 温和）；**不碰 taiga-front**——我们对 Taiga 的全部消费本就走
  REST API（packages/yt/taiga 适配器），前端 UI 原样用、不修改、不分发。

**能一起打包进最终平台发布吗？** 按「打包」形态分三档，义务递增：
- **形态 A（推荐）：我们只发行自己的代码**——编排（compose/向导）+ 适配器 + daemon +
  公司包格式；Taiga/Matrix 由安装器**现场拉取**官方镜像。我们从未分发第三方代码，
  任何许可证都零义务。这也是业界惯例（MCP registry「元数据指向、代码在包仓」同构，
  docs/41-卡2）。
- **形态 B：原样再分发**（把官方镜像/包复制进我们的发行件）——MPL/AGPL/Apache 均允许，
  附许可证文本与源码指引即可。
- **形态 C：修改后分发**——taiga-back（MPL）：修改文件保持 MPL 并提供其源码，可与
  专有部分组合 ✅；Synapse/Element/taiga-front（AGPL）：衍生作品整体须以 AGPL 公开
  源码——**框架仓若开源则实质无碍；闭源商业版则禁止此形态**。
- 商标红线（所有形态）：保留 Taiga/Matrix/Element 归属标识，不得暗示官方背书。

**部署后改源码、重启、针对我们平台开发？**
- 技术上：现成路径——fork 后 docker build + compose 起停；热改热重启无任何技术障碍。
- 法律上：**纯内部使用（现阶段形态）不触发分发义务**——制作人员工与 agent 都是
  「自己人」，AGPL §13 网络条款只在**向第三方用户**提供网络交互服务时才要求公开
  修改版源码。现阶段：随便改、随便重启。
- **真正的决策点在未来**：若把 StudioNext 做成对外托管服务（别人的公司跑在我们的
  平台上），修改过的 AGPL 组件（Synapse/Element）就必须开源。规避路径明确：
  IM 家服务器届时切 Tuwunel/Continuwuity（Apache-2.0，协议同构、Admin API 大体兼容），
  协作平台维持「不改 AGPL 前端 + 形态 A 分发」——全绿。

### 1.3 建议路线（分层，按介入深度）

| 层 | 做法 | 许可证负担 | 时点 |
|---|---|---|---|
| 0 | 只走 API/插件/webhook（现状：REST 适配器） | 零 | 已在用 |
| 1 | IM 家服务器替换为 Tuwunel/Continuwuity（Apache） | 零 | 需要时（性能/商业化前） |
| 2 | 修改 taiga-back（MPL，文件级开放） | 低（开源修改文件即可） | 仅当后端功能不够 |
| 3 | LocalFile 长成内置最小平台（自有资产） | 零（我们的代码） | 中长期，docs/23 既定方向 |
| × | 修改并分发 AGPL 组件（Synapse/Element/taiga-front） | 高（衍生整体 AGPL） | 不做，除非框架整体开源且接受 |

## 二、对外 MCP 服务：让外部 agent 反过来调用我们

**产品定位**：公司包规范（docs/40/43）定义「下载别人的公司来跑」；对外 MCP 定义
「让任何 agent 给我们的公司派活/查账」。两者合成 StudioNext 的对外故事：**公司成为
agent 生态里可雇佣、可审计的节点**。docs/24（AI 接入面）已画「对外归 MCP server +
A2A exporter」骨架，本节按制作人令升为一等产品面考量。

- **形态**：packages/api（:8788，Hono）之上新增 MCP server 面，双传输（stdio 供本机
  客户端、streamable HTTP 供局域网/远程 agent）；工具面与现有 API 同源，不另立逻辑。
- **工具面三级 scope**（对齐 wkey 的 scope 思想，docs/43-条款7）：
  ①只读：公司概览/组织/单据/台账查询；②落单：建单/评论（外部投递）；③派工与收割：
  高权限，默认不授。
- **入站信任边界（安全设计前提）**：外部 agent=**不可信调用方**——按 agent 签发 token、
  scope 化、可吊销、调用全程入台账审计；外部投递的单据/评论内容按 untrusted 渲染
  （与 docs/43-条款2 同构——入站文本与公司包文本同罪假设）。这是红队视角下对外面的
  新增攻击面：钓鱼派单、垃圾洪泛、scope 越权尝试，须在实现单前出威胁模型补充。
- **排期**：v1.x，走提案流（提案→探索→定稿→spike→过审），不阻塞规范冲刺 v1。

## 三、桌面平台（Codex Desktop 类）

**定位：V 面（视图层）**——不新增事实源、不新增决策位，包裹现有三个 HTTP 面
（:8787 监控 / :8789 公司概览 / :8788 API）与 daemon。

- **选型建议**：Web 先行（docs/37 已定 Vue + Naive UI + ECharts，面板本就是桌面形态的
  底座）→ **Tauri 壳**后置（体积小、macOS 原生、权限模型适合「本地管 daemon」的场景；
  Electron 作备选）。daemon 保持 headless，桌面壳只是操作台。
- **桌面端独有价值清单**（Web 面不易做好的部分）：
  1. daemon 生命周期管理（launchd 装卸/日志/升级可视化）；
  2. 公司目录浏览器 + 配置编辑器（schema 校验内嵌）；
  3. 公司包 onboard 向导（docs/36 M-A..E 的天然宿主）；
  4. **批准指纹 re-approve 面与漂移告警**（docs/43-条款4 的天然 UI）；
  5. MCP token/scope/审计控制台（§二的安全面可视化）；
  6. 凭据按类别授予面（docs/43-条款7：偏离最小权限画像红字警告）。
- **排期**：规范冲刺（进行中）→ 面板收口（v0.8 线）→ 桌面壳立项（提案流）。先不立单。

## 四、共同落点

三问同属**对外产品面**：公司包规范=**资产格式**，对外 MCP=**可雇佣接口**，桌面平台=
**操作台**。三件套构成 StudioNext 对外发布形态的完整故事，且都建立在同一个底座上：
三事实源 + 端口抽象 + 台账审计，不因对外而新增事实源。

排期建议：规范冲刺 v1（进行中，最高优先）> 对外 MCP server（v1.x 提案）> 桌面壳
（面板收口后）。协作栈侧的即期动作只有一条：**维持形态 A（编排引用、不修改分发）**，
其余按 §1.3 分层表按需启动。
