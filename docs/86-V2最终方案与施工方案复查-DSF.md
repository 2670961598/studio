## 一、阻断项（B1-B6）

### B1 根授权只有“字段”，没有“老板证明”（P0-4 重新打开）

**事实**

- `03 §3.1` 第 1 步：老板“签署”公司设立记录；`05 §三 DOM-01`：公司 git 目录唯一写入者＝daemon；`11 §2.1 REC-AUTH-01` 的字段只有 `grantor`、`parent_grant`、`purpose/scope` 等，**没有 owner proof 字段**。
- `15 §二 SEC-SIG-02` 自承：控制面 key 由 daemon 同进程 `issueControlKey()` 现铸、同进程同密钥验签，签发者＝验证者＝被闸方同体；独立签发/验签是**目标（未证）**。
- 所以现行规范里的“老板签署”是一条由 daemon 写出的记录：`grantor='boss'` 是字符串，`grantor≠grantee` 只校验字段，不校验谁写的。宰相/daemon 可以伪造一条形式上合法的根授予，冷启动顺序和 `parent_grant` 都拦不住。

**为什么阻断**

整个模型的可信根是“老板为根、宰相投影、不得自授”。如果根授予的真实性只靠一个字段，权力树的可信根是空的。`17 §六.2` 把 DSF P0-4 标成“已解”，只解了“顺序”，没解“真实性”。

**修法**

1. 给四个硬核动作（设立/修宪、G8/G9 任免、公司级审计结论、公司级对外承诺）加 `owner_proof`：老板侧密钥/HSM，或带签名的离线批准件；daemon 只读校验，不能自签。
2. `REC-AUTH-01` 增加 `owner_proof_ref/digest`；启动/激活前验签；缺失或坏值＝拒绝，不落“待补”。
3. `15 §二` 把“老板签名通道”列为本卷机制；建成前把 P0-4 状态改为“方向已定，真实性目标未证”，不要写“已解”。
4. 如果制作人明确选择“daemon 是可信根、老板只在部署面授权”，就把这条 residual risk 写进 17 卷缺口表，并把 P0-4 改成“目标未证”；不能既说“可信根是 daemon”又说“P0-4 已解”。

**过门证据**

- 负向：daemon 自写 `grantor=boss` 且无 `owner_proof` → 拒绝；
- 正向：老板签名件验签 → 接受，且台账记 proof digest。

### B2 审计分离规则按字面会取消部门审计

**事实**

- `03 §3.3 表 B`：G8 的 +1＝G9；`03 §4.1 表 C`：G8 的审计者＝G9。
- `03 §4.3`：审计者不得同时担任被审计对象**任免的本次评价/提议者**；同一周期内 +1 已任评价者，本次审计上提一层。
- 按字面：G9 是 G8 的任免提议者 → G8 审计上提老板；G8 是 G7 的提议者 → G7 审计上提 G9；G7 是 G6 的提议者 → G6 审计上提 G8；表 C 的常态审计者全部命中回避。D8 部门审计最终落到老板（顶层自审），D7 及以下落到上上级——“部门层上一层审下一层”不再成立。

**为什么阻断**

84b 抉择 4 的核心是“部门层上一层审下一层”；这条规则把表 C 的每一行都推给上上级，D8 直接推给老板，与抉择 4、表 C 和“分层审计解决部门自审”的整个论证直接冲突。

**修法（二选一）**

- **A（推荐）**：把 §4.3 限定为“本次审计对象的**绩效评价者**，或对本次审计事项有直接利益/错误相关性者”；明确“任命提议本身不构成回避”。
- **B**：若确实要审免提议者，则把“专职部门审计位置”从 CL7 提前到 CL4，设独立审计位，而不是把审计上提。

**过门证据**

- 正向：G8 由 G9 审计且不触发上提；
- 负向：审计者＝本次绩效评价者 → 上提；
- 表 C 每一行至少有一条“留在本层”的合法用例。
