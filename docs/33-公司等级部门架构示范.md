# 33 · 公司等级部门架构示范（2-9 级逐级参考）

> 2026-10-18 ｜ 制作人定向：「每等级上级管 3~10 个下级（大概，不写死）；3-4 级以下整个部门只有单独的人事、财务、个别 agent，5 级以上才有专门部门；研发在低级把策划/程序/QA 合起来统称研发部；去搜前沿、多派 agent、真验证可行后再纳入工程」。
> 本文=**示范拟稿**（docs/04-§四 的部门粒度细化），**待制作人批示后并入 docs/04**；已按定向做前沿调研交叉验证，来源见 §1。

## 1. 依据（前沿调研摘要）

| 来源 | 关键事实 | 对本案的校准 |
|---|---|---|
| 管理跨度研究汇总（[Quantum Workplace](https://www.quantumworkplace.com/future-of-work/whats-the-optimal-span-of-control-for-people-managers)：理想 8-9；Gallup 中位 8-10；Amazon 6-8、Google 7-10；>10-12 明显衰减） | 跨度 sweet spot=**6-10**，初级/动荡团队取 5-7，player-coach 取下限，纯管理可到 10+ | 制作人 3-10 成立：**低等级（agent 初级、任务密集）取 3-7，高等级（成熟稳定）取 6-10**，管理管理者可更宽 |
| [OrgAgent](https://arxiv.org/html/2604.01020v1)（公司制多 agent 框架，治理/执行/合规三层，2026） | 层级制在开放式任务大幅省 token（**-46%~-79%**）且提质；但**刻意只做三层浅层级**；部分推理任务平级自治反而更好；收益依赖任务形态与模型能力 | **层级深度刻意浅**（组织树深 ≤4-5 层足够）；部门=检查点/SOP 载体，不是头衔摆设；能力弱的下级配更窄跨度 |
| [MetaGPT](https://www.ibm.com/think/topics/metagpt)（PM→架构→工程→QA 的 SOP 公司）/ [ChatDev](https://github.com/openbmb/ChatDev)（聊天链角色分工） | 软件公司隐喻已是多 agent 主流；角色绑定**工序节点**而非行政头衔 | 研发部内部的「策划/程序/QA」按工序角色建模，低级共享一个部门外壳 |
| 自组织反例（[Drop the Hierarchy, 2026](https://www.alphaxiv.org/abs/2603.28990)） | 强模型下平级自治可能优于强加人类科层 | 低等级保持极平（单岗制），科层只在**跨部门协调成本**真实出现时加 |
| [David Sacks SaaS 编制表](https://sacks.substack.com/p/the-saas-org-chart)（A 轮~50 人 / B 轮~125 / C 轮~400） | **1 经理 : 5-10 下属**；A 轮 G&A 极小（记账外包级）、**B 轮才首个 controller 级财务**、C 轮才有 CFO 组织与招聘部；比率 10% G&A : 40% R&D : 50% S&M；1 PM : 5-8 开发 | 职能岗**先于**职能部门涌现的节奏表——直接映射到制作人「5 级以下单岗、5 级起成部」的直觉（L4≈A 轮、L5≈B 轮、L6≈C 轮） |

## 2. 五条通用原则

1. **跨度按等级校准**：L2-4 取 3-7（下级能力弱、任务密集、返工率高），L5-6 取 5-8，L7-9 取 6-10（管理管理者可 8-12）。超限不新建层级，先拆部门。
2. **层级深度浅**：组织树 ≤5 层（制作人→总裁裁/事业部→部门→组→执行 agent）。OrgAgent 实证：层数增加不提质、只加协调 token。
3. **部门是涌现的，不预建空壳**：职能先以「单 agent 岗」存在（挂在负责人或研发部下），负载满载（docs/04-§四 已有触发阈值）才升格为部门。Sacks 节奏：财务从记账岗（A 轮）→ controller（B 轮）→ CFO 组织（C 轮）。
4. **研发低级合一、高级拆分**：L2-4 = 一个研发部（内部是策划/程序/QA 工序角色，无行政分割）；L5 起质量独立（裁判不归选手管）；L6 起按项目群拆工程。
5. **对外能力按等级出现**：L5 对外部（形象/API/合作）单岗 → L6 战略情报 → L7+ 事业部/集团职能。比率锚：R&D ≈ 40%、G&A ≈ 10%（SaaS 基准，AI 公司可上调 R&D）。

## 3. 逐级示范表（2-9 级）

> 图例：〔单岗〕=一个 agent 顶整个职能；〔部〕=已成部门；跨度=该级上级对下级的参考管理数。

| 等级 | 形态/编制 | 部门构成 | 跨度 | 说明 |
|---|---|---|---|---|
| **2 班组** | 5-8 agent | **不设部**。负责人 1 + 执行 agent 3-6 + 〔单岗〕财务人事（同一 agent 兼，或负责人兼）| 4-7 | 全员研发工序（策划/程序/QA 由同一批 agent 按单切换角色）；台账/账目由框架自动出，财务岗只做异常处置 |
| **3 小团队** | 15-25 | **研发部**〔部，唯一〕（内含策划 1-2、程序 4-8、QA 2-4）+ 〔单岗〕人事财务（1 agent）+ 〔单岗〕情报（1 agent，可选） | 4-7 | 研发部=一个屋檐不分割；人事财务仍是一个人；跨单协调仍由负责人直管 |
| **4 团队** | 40-80 | **研发部**〔部〕（内部分组：策划组 2-4 / 程序组 10-25 / QA 组 4-8——组≠部门，只是工序排班）+ 〔单岗〕人事 + 〔单岗〕财务（此时**分设两个岗**，宪章 §12.6：4 级起设人事）+ 〔单岗〕情报 | 5-8 | 第一道「成部前夜」：研发部内出现组长层；人事财务拆成两个单岗 |
| **5 部门化** | 100-250 | **工程部**〔部〕+**质量部**〔部〕（裁判独立）+ 产品策划部〔部，小〕+ **人事部**〔部，2-5〕+ **财务部**〔部，2-4，controller 级〕+ 〔单岗〕对外部 + 〔单岗〕情报/战略 | 5-8 | Sacks B 轮节奏：首个真财务组织；质量从研发剥离；对外形象/API 上线 |
| **6 多团队** | 250-600 | 工程部按**项目群**拆 2-4 个（每群 40-80）+ 质量部 + 产品部 + 人事部（招聘线出现）+ 财务部（FP&A 线）+ 〔部〕审计合规 + 〔部〕战略情报 | 6-9 | C 轮节奏：CFO 组织、招聘线、审计线成形；项目群=未来事业部胚芽 |
| **7 事业部** | 600-1500 | 每个产品线=事业部（内含各自的研发/质量小闭环）；集团职能：人事/财务/审计/**战略**/**平台工程**（内部工具与泳道群） | 7-10 | 事业部总经理层出现；集团职能服务化 |
| **8 集团** | 1500-4000 | 多事业部 + 职能层级化（部→中心）；共享服务平台（财务共享/人事共享/计算平台）；平台泳道群独立 | 8-10 | 「管理管理者」为主；跨度可至 10-12 |
| **9 控股** | 3000-10000 | 子公司群（各自完整 7-8 级结构）+ 控股职能（战略/资本/审计/法务）；制作人直管 | 8-12 | 上限形态；控股层只做资本与审计，不做经营 |

**示例编制树（L4，60 agent）**：
```
负责人(L4 锚)
├─ 研发部〔部〕 ─ 策划组 3 │ 程序组 18（3 组长×6）│ QA 组 6
├─ 人事〔单岗〕 1（等级锚+考勤+入转）
├─ 财务〔单岗〕 1（预算闸对账+报表复核）
└─ 情报〔单岗〕 1（前沿扫描+选型侦察）
→ 负责人跨度=4（部门/岗数）；组长层跨度=4-6
```

## 5. 公司目录落地形状（config.yaml departments 嵌套）

L2 示例（无部，扁平岗）：
```yaml
departments:
  root:
    lead: WORKER-1          # 负责人
    members: [WORKER-2, WORKER-3, WORKER-4, WORKER-5]
    posts:                  # 单岗：不设部门容器
      finance-hr: WORKER-5  # 财务人事（兼）
```
L5 示例（部门化）：
```yaml
departments:
  root: { lead: PRIME-0, members: [] }
  children:
    eng:   { lead: ENG-0,  members: [ENG-1..ENG-24] }    # 工程部（内部组由泳道表达）
    qa:    { lead: QA-0,   members: [QA-1..QA-7] }       # 质量部（裁判独立）
    people:{ lead: HR-0,   members: [HR-1..HR-3] }       # 人事部
    fin:   { lead: FIN-0,  members: [FIN-1, FIN-2] }     # 财务部
    outbound: { lead: EXT-0, members: [] }               # 对外部（单岗部长）
```
