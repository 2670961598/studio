## 1. 问题

审计实测 5 件零余量（run/runtime/config/dsh/repo-validate）、4 件低余量（ledger/engine/
dependencies/views），另有 3 件契约冻结面低余量（emp-neg 余 3、life 余 8、auth 余 29）。
#504 在 run.ts 内联 253 行，并用「注释折行」把 config 609→599 / runtime 601→600 规避
guard——这是屎山前兆。后续 28 单落仓必然撞阈。

## 2. 纪律（写死）

1. **撞阈一律拆件**：按域拆子模块，拆后每件 ≤550 行（阈 600，余量 ≥50）。
2. **禁止注释折行/压缩/删注释凑行数**：行数下降只能来自代码搬出，不能来自折叠。
3. **导出面零漂移**：原文件保留 `export`/`re-export`，既有导入路径零改行（barrel 模式）。
4. **行为零漂移**：SQL/事务/错误码/事件顺序/相位顺序/收割四要件判据一律不动；
   每拆一件跑 `guard:boundaries` + `typecheck`。
5. **契约冻结面只观测不拆不改**：`packages/contract/src/records/{emp-neg,life,auth}.ts`
   触碰须走批示流；低余量只告警（FROZEN-WARN），不得自动化改写。

## 4. 契约面余量告警（只观测，零写能力）

- `scripts/guards/margin-rules.mjs`：观测名单 + `softMargin=50` + 三件冻结面清单；
  阈值/基线**不复制**，运行时从 `boundary-rules.mjs` 读取（单一冻结源）。
- `scripts/guards/margin-watch.mjs`：wc -l 同口径计数，输出
  `OK / WARN / FROZEN-WARN / OVER / MISSING`；默认 exit 0（观测面），`--strict` 对非冻结面
  非 OK 判红，`--json` 机器可读；脚本无任何写文件能力。
- `package.json`：`margin:watch` / `margin:watch:strict`；`verify:v2` 在 `guard:boundaries`
  之后串接 `margin-watch`（告警不改变 exit 0 语义，CI 可见）。
- 当前观测：三件冻结面 FROZEN-WARN（余 3/8/29）——**未改一字节**；修法只能是批示流。

## 5. 基线净降

拆件后 engine/ledger/dsh/repo-validate/dependencies/views/hot-reload 均 ≤600，
`boundary-rules.mjs` 中对应 `lineBaseline` 条目除名（基线净降；§十五.三.3「基线值下降与
条目除名随任意提交顺带办理」）。此后这些文件回涨超 600 即 guard 判红，不再有「基线内可回涨」面。
