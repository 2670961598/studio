### 1.1 结论口径

本次审查不把“文档很多”“审查 agent 很多”“反例很多”当作通过理由。通过只采用以下口径：

- **P0**：根命题、核心定义或不变量互相否定，理论体系不能使用；
- **P1**：跨册权属冲突、责任落空、合法/非法两可、关键流程无出口，会阻断三册一致展开；
- **P2**：真实但不阻断的引用、措辞或范围不一致，已识别并已清理或明确保留为设计选择。

### 2.2 每项义务是否有承担者、完成标准和违约路径——PASS

- **承担者**：义务首先落到责任位置，实例化时落到具体任职者；空编可以存在，但不能解释
  实际履职（63-§1.4、66-§3.3）。临时任职者也承担完整事项责任（65-§一、§十）。
- **完成标准**：义务包含承担者、对象、触发、完成口径、时限或复审条件、违约去向
  （63-§1.3）。验收按低/中/高/未分类分档，低风险的日常对外事项保留相对方验收与异议
  位置（63-§1.2、I-8、67-§七）。维持、拒绝、避免、无新产物也可验收（67-§九）。
- **违约路径**：异常必须有接收者、处理时限或复审条件与终局（63-I-11、66-§10.3）；
  超时、冲突、无能、叫停和恢复均有强制出口，不允许静默悬置（67-§八）。

### 2.3 每个岗位是否有存在理由、能力要求和生命周期——PASS

- **存在理由**：岗位只在同类责任反复出现、需要跨时间承接时成为候选；临时协调也可以
  完成工作，不强迫设岗设部门（63-§三、66-§1.2、§3.2）。新增结构必须说明解决什么
  问题、增加什么成本、如何撤销。
- **能力要求**：66 提出岗位能力需求，65 组织独立专业认定，66 提供独立认定位置与争议
  终裁（64-§3.3、65-§三/六、66-§3.2、§7.3）。职级不等于能力，执行配置不等于授权。
- **生命周期**：65-§九 具有候选、在岗、暂停、交接、离岗待结清、已退役的完整路径；
  66-§十二 具有组织设立、继任、调整、撤销与清算；空编、代理、替补、重新任职与救济承接
  均有出口。晋升/降级为“程序在 65、职级与任免决定在 66、绩效证据在 67”（65-§九、
  64-§3.4）。

### 2.4 每条工作路径是否包含失败、异常、返工和恢复——PASS

- 工作从意图受理、任务合同、开工五门、派工协作、执行变更、证据验收、履约评价到结清
  与重开均有定义（67-§一至§十三）。
- 异常分类包括偏差、超时、资源耗尽、能力失效、来源存疑、验收争议、外部事件与协作僵局；

## 四、关键裁决与明确不采纳的过强要求

### 4.1 已采纳并闭合的关键裁决

1. **根命题是规范定义，不是经验存在解释**：不把不符合理论的组织改名为“不是公司”来
   排除反例（63-§〇）。
2. **自治是章程内无需日常介入，不是全能或自我授权**：自治可以组织独立验收与外部服务，
   不能自行扩大边界（63-§二）。
3. **最终责任不等于无限权力，也不等于对每个操作失误负同等责任**：最终责任需要实质
   控制、制度设计与止损位置，允许集体顶点，但不得集体匿名。
4. **五环是同一公司运动的五个责任视角，不是五套互证系统**：价值为主环，进化为二阶环，
   资源与异常贯穿，不另造第六环。
5. **验收按风险分档**：低风险可自检+可复核证据+事后独立审计；中高风险需要相应独立
   验收，高风险及不可逆且影响重大须生效前验收，紧急止损是唯一时序例外。
6. **剩余裁量预授权功能类别与上限，个案范围在行使时确定**：未预见不等于自由授权，无
   裁量者只能保全与升级。
7. **本纲层与公司层修宪隔离**：公司只能在本纲不变量之内修改自己的宪制；修宪权条款不得
   由被授权主体单方修改。
8. **可逆与不可逆分开**：不可逆行为不虚构可撤回，必须能停止继续影响并保留修复、补偿、
   承诺变更与责任结算路径。
9. **能力可替换不等于现实自治**：能力缺失必须明示，不保证所有能力都能获得；DSH 或其他
   工具只能作为后续可行性证据，不能成为理论前提。
10. **记忆四层分离**：个人、岗位、出工、组织各自有归属与授权；出工记忆随工作及其责任
    关系，离岗不自动转为个人记忆。
11. **治理配置责任者具名化**：工作治理位置不再由“本章”或“有权位置”泛称，任命、范围、
    回避、替换、空缺与退出均可追溯。
12. **一般变更与具体承诺变更分流**：变更决定不得绕过承诺授权与相对方程序；未设承诺
    授权位置不得作出新的具体承诺。

### 4.2 明确不采纳的要求

以下要求被审查后判定为过度、不可普遍成立或属于另一层工作，未纳入理论：

- 所有事项都必须由外部人员或外部机构验收；
- 联合交付只能有一个最终责任主体；
- 在总纲中写死统一的次数、比例、时限或阈值；
- 使命永远不可合法变更；
- 一切变更及其外部后果都必须可撤回；
- 多 agent 数量或一致投票本身就构成独立验收；
- 75 个权责原子或 24 个岗位范式必须宣称天然闭集，才能开始理论建设；
- 以具体模型、CLI、DSH 插件或运行时的当前能力证明逻辑自洽；
- 把所有设计选择都写成不可修改的逻辑公理。

不采纳的理由不是“更方便”，而是这些要求会破坏比例原则、条件性组织形态、外部责任
多样性或可证伪性。

## 五、技术独立性与剩余经验边界

### 5.1 技术独立性检查

- 总纲明确不规定模型、执行宿主、CLI、插件、接口、存储或运行时（63-§九）；
- 三册均只使用制度概念：岗位、任职关系、能力资格、执行配置、治理位置、证据与验收；
- 未把 DSH 的插件热更、agent loop 切换或任何工具能力当成自治的逻辑前提；
- 未把公司等同于 git 目录，也未把某种协作平台或目录格式当成公司存在的定义；
- 未把内部验收、记录、哈希、签名或台账等同于事实、价值或独立验证。

因此，更换模型、执行宿主、CLI、插件、协作平台或框架实现，不应改变权、义务、责任、
验收与禁止的概念含义。

### 5.2 仍属经验假设而非已证事实

| 假设 | 封版处理 |
|---|---|
| 在指定任务分布与风险水平内自治有效 | 必须声明任务分布、时间窗、比较基线、失败阈值与停止条件；公开声称须独立接受。 |
| 执行能力可替换而岗位语义不变 | 需要更换后的权责、历史、承诺与资格证据，不由热更本身证明。 |
| 独立验证的收益覆盖成本 | 同时记录避免损害、控制成本与漏检，按合法控制形式调整。 |
| 学习、记忆与能力更新长期改善 | 需要多轮后验、退化与撤回证据，不能由短期指标证明。 |
| 内部证据与外部反馈足以纠错 | 需要检查伪造、同源盲点、外部异议与未发现问题。 |
| 自治总成本与尾部风险可接受 | 监督、纠错、资源与不可补偿损害一并结算。 |

### 5.3 保留为设计选择而非缺陷的事项

- 返工次数、暂停期限、升级阈值、复审点与风险参数；
- 协调成本、贡献可分性、独立性与组织绩效的具体测量方式；
- 记忆密级、保留期、访问层级与具体审批形式；
- 联合协议、外部契约、公共程序与具体法域安排；
- 小样本、高方差任务中的绩效归因效力；
- 文档行数与排版形式。

这些事项需要实例化与验证，不应伪装成通用逻辑常数。
