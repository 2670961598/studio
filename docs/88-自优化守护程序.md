# 88 · StudioNext 自优化守护程序（Self-Optimization Guardian）

> 制作人 2026-10-31 令（照录要点）：「整个的提示词优化，DSH 我们也可以搜集一些我们可用的
> 插件，包括 Deepseek 提供的搜索 API 我们来搜索前沿内容等等，把框架的自优化全部开起来，
> 你给自己做好定时任务，作为 StudioNext 后续自优化的守护进程，临时向我报告即可，等后面
> 公司自己有和 AI 对话、新开对话的界面之后我再转过去即可。全方面的优化，岗位设计的优化，
> 提示词的优化，Agent 工作时的相关需要优化等等，包括和前沿对比等等的优化，全部开起来，
> 不计成本的优化 StudioNext 框架。」

## 一、定位与边界

- **执行体**：宰相（本守护）自任——定时任务驱动，产出经本对话临时呈报制作人；公司自有
  对话界面（203 编辑中心线）就绪后迁移呈报面。
- **优化对象**：提示词全链 / 岗位与组织设计 / Agent 工作面（工具链·沙箱·证据）/ DSH 插件
  资产 / 前沿对比吸收。
- **不在本程序内**：R0-R2 V2 文档返工（另线，仍按制作人前令挂起待令）；框架 doctrine 级
  决策（仍呈制作人拍板）。
- **成本口径**：制作人令「不计成本」——**不设预算闸，但账目照记**（台账卫生纪律不因放
  开而豁免；每次运行记录 token/耗时/花费进运行记录节）。

## 二、六轨定义（每轨=发现→对比→提案→（可立单的）立单/落刀→呈报）

| # | 轨 | 对象 | 产出物 |
|---|---|---|---|
| 1 | **提示词优化** | L0-L5 组装、AGENTS.md 注入、任务书模板、指令通道（instructions-store）、identity 注入 | 抽样实测纪要+改写 diff 提案；可立单的按 org 口径拟任务书 |
| 2 | **岗位与组织设计** | org-config 岗位（patrol/daily/queue/judge）、部门结构、等级配比、并发闸 | 岗位审计表（冗余/缺口/错配）+调整提案 |
| 3 | **前沿搜索与对比** | agent 编排/多智能体/提示词工程 SOTA 与竞品（todos.dev、Claude Code、Codex、OpenAI Swarm/Handoff、LangGraph、AutoGen、CrewAI…） | 对比纪要（吸收项/差异化项分列，逐条带来源）+改进项清单 |
| 4 | **DSH 插件搜集与资产化** | npm @deepseek-ai/dsh-* 生态+实验插件（agent-team/worktree/subagent/语音/持久终端/会话搜索/Ralph…） | 逐件评估卡（用途/架构冲突面/生产可用性/D1a 资产归类）→资产部登记候选 |
| 5 | **Agent 工作面审计** | worker 实况：沙箱摩擦（临时目录/写域/网域）、工具链（bash/glob/grep）、证据质量、断路/重试行为 | 摩擦清单+修复立单（常规线内宰相直接放行） |
| 6 | **综合晨报** | 五轨汇总+在途单状态（含 Taiga 洞影响面） | 呈制作人的日报（本对话） |

### 搜索通道矩阵（轨 3/4 用）
- 本守护自带 WebSearch/WebFetch（现役）；
- DeepSeek API 搜索端点（**首轮核实**其是否存在与形态——不存在则以 dsh web 插件评估+自带搜索兜底，如实呈报）；
- dsh `webbridge` 等插件（评估后资产化，worker 侧可用）。
