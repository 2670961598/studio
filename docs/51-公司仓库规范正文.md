# 51 · 公司仓库规范正文（normative）v1

> 定位：判定「**一个 git 仓库是不是合法的公司仓库**」的唯一标尺——docs/43 v1.1 的规范化
> 正文（43=设计依据与取舍，本文=可执行判定规则）。三种读者：**公司作者**照此创作；
> **框架**照此校验与初始化；**判定器**照此输出诊断。
> 规范版本 `schema:1`。规则的增删只经版本化修订（提案流），判定器与规范正文一一对应。

---

## 一、总判定

一个仓库是**合法公司仓库**，当且仅当同时满足五组契约：

| 组 | 契约 | 管什么 |
|---|---|---|
| A | 目录契约 | 仓库里**允许存在什么**（封闭文件集） |
| B | 文件契约 | 每个文件**内部长什么样**（逐文件 schema 与值域） |
| C | 交叉引用契约 | 文件之间**互相指着的东西必须存在** |
| D | 依赖契约 | dependencies.yaml 的绑定与版本 |
| E | 卫生契约 | 不携带危险物/本地产物 |

判定器输出二值+诊断：**合法**→可初始化（§七）；**不合法**→逐条违规（规则号+文件+位置+
缺什么/什么不合法+修复建议），**一条不留地指出**。

## 二、契约 A · 目录（封闭文件集）

```
公司仓库根/
├── org-config.yaml                      必备（B-1）
├── charter.md 或 charter/<名>.md         必备（org-config.company.charter_ref 指向）
├── departments/<部门>/config.yaml        ≥1（部门树，逐级）
├── departments/<部门>/people/<工号>.md   每名员工一份（people[].file 对应）
├── prompts/                             可选（提示词资产，自由组织）
├── docs/                                可选（公司自述/规章制度等文本）
├── dependencies.yaml                    可选（无=零插件公司）
├── plugins/<插件名>/                     可选（**唯一允许的代码位**，dsh 插件形态）
├── .gitignore / README.md               可选（白名单杂项）
└── （其他任何文件或目录）
```

| 规则 | 判定 |
|---|---|
| A-1 | 封闭集之外的文件/目录 → **不合法**（指名道姓列出每个越界路径；带 `--allow-extra` 可显式豁免并留痕） |
| A-2 | 必备位缺件（org-config.yaml / charter / 部门 config / 员工档案）→ **不合法**（指出缺什么） |
| A-3 | `.git/` 不参与合法性判定（传输层，导入一律剥离重建，docs/43-§一）——**克隆产物**另受 E 组结构闸约束 |
| A-4 | `.AIWS/` 出现在源仓 → **不合法**（员工工作区是**本地产物**，建司时由框架生成，不随仓库旅行） |
| A-5 | `.studio-next/`（信任锚目录）出现在源仓 → **不合法**（信任态劫持面，docs/44-§三-3） |

## 三、契约 B · 文件（逐文件 schema 与值域）

### B-1 `org-config.yaml`
```yaml
schema: studio-next/org@1            # 必备字面量
company:
  name: …                            # 非空串
  slug: …                            # 语法域：^[a-z0-9][a-z0-9-]{1,62}[a-z0-9]$（与 init 通道同一张表）
  version: …                         # semver
  level: 2-9                         # 整数
  level_distribution: { "3": n, … }  # 键=等级串 值=非负整数
  charter_ref: …                     # 非空，必须命中仓内章程文件（C-2）
  platform?: …                       # 声明性（localfile 等）；目标平台绑定归制作人侧，仓内不写地址
departments: [ … ]                   # ≥1
people: [ … ]                        # ≥1
jobs?: [ … ]
accounts?: [ … ]
```
非法示例（判定器须逐条指认）：schema 字面量不符｜slug 带空格/大写/连字符起止｜level 越界｜
level_distribution 与 people 实际等级分布不一致（C 组并判）。

### B-2 `departments[]`
`name`(非空)｜`path`(`departments/<名>` 形态，语法域同 slug 段)｜`leader`(非空→C-3)｜
`level`(整数)｜`parent`(null 或命中另一部门 path，禁环)｜`lanes[]`/`functions[]`(串数组)｜
`jobs?`(id 数组→C-5 双清单互检)。

### B-3 `people[]` + 员工档案 `people/<工号>.md`
条目：`id`(工号，语法域同 slug 段，全司唯一)｜`name`｜`login`｜`level`(1-9)｜
`dept`(必须=某 departments.path)｜`role?`｜`skills?[]`｜`executor?`｜`file`(必须存在且
路径=该员工 dept 下 people/<id>.md)。
档案正文=自由文本（提示词资产面）；**已知键封闭于条目字段**——档案正文里的自由字典不参与
依赖绑定（docs/43-§十-5）。

### B-4 `jobs[]`
`id`(全司唯一)｜`cron` 与 `triggers.cadence` **恰给其一**｜`role`/`type` 至少一｜
`level?`｜`budget_cap?`｜`output`/`outputs`：**相对路径语法域**（禁绝对路径、禁 `..`、
锚定公司目录内）｜`sla?`｜`escalate?[]`。

### B-5 `dependencies.yaml`（D 组详判）
### B-6 `charter` 与 `prompts/`：非空文本，内容自由（进提示词的资产面）。

## 四、契约 C · 交叉引用（指着的东西必须存在）

| 规则 | 判定 |
|---|---|
| C-1 | people.dept 悬空（不命中任何 departments.path）→ 不合法 |
| C-2 | company.charter_ref 指向的文件不存在 → 不合法 |
| C-3 | departments.leader 不是 people 成员工号 → 不合法 |
| C-4 | people.file 不存在 / 不在其 dept 目录下 / 文件名≠工号 → 不合法 |
| C-5 | 部门 config 的 jobs 清单与 org-config jobs 双向不一致 → 不合法 |
| C-6 | departments.parent 悬空或成环 → 不合法 |
| C-7 | dependencies.when.attr ∉ 档案已知键封闭枚举（role/dept/level/skills/executor/status）→ 不合法 |
| C-8 | level_distribution 总账与 people 逐人等级不一致 → 不合法 |

## 五、契约 D · 依赖（docs/43-§四）

```yaml
bindings:
  - when: { attr: role, is: frontend }        # attr∈C-7 枚举
    plugins: [{ name: dsh-web-test, version: ^1.2 }]
```

| 规则 | 判定 |
|---|---|
| D-1 | version 只收 `^x.y(.z)` 与精确两形态（`~/>=/通配/*` → 不合法，指认到值） |
| D-2 | 多绑定命中同名插件=约束并集；并集无解 → **合法但报 conflict 警示**（不装错版本，docs/43-§十-6） |
| D-3 | 绑定的插件既不在仓内 `plugins/` 也无可用源 → 合法但**能力缺失面明示**（missing 报告——依赖清单同时是能力声明） |
| D-4 | `plugins/<名>/` 内必须符合 dsh 插件形态（dsh.bundle 约定）；不符 → 不合法 |

---

## 六、契约 E · 卫生（克隆产物上的结构闸）

| 规则 | 判定 |
|---|---|
| E-1 | 符号链接（任意深度）→ 不合法 |
| E-2 | 可执行位文件：`plugins/` 约定入口外的一切 exec 位 → 不合法（exec 位经 git clone 可旅行，故闸在**克隆产物**上跑，docs/44-§三-10） |
| E-3 | 源仓自带 `.studio-next/`、`.AIWS/` → 不合法（A-4/A-5 重申） |
| E-4 | 单文件 >8MB 或文件总数 >5000 → 不合法（资源护栏，实现期参数，拟稿可调） |

## 七、判定器契约（框架面）

```
studio-next company validate <git-url | 本地路径 | tarball> [--json] [--allow-extra]
```

- **输出**：
  - 合法 → `PASS`+摘要（公司名/slug/等级/部门数/人数/jobs 数/插件数/能力面与缺失面）+
    「可初始化」；
  - 不合法 → 逐条违规 `{规则号, 文件, 位置(行号或键路径), 违规描述(缺什么/什么不合法),
    修复建议}`——**不许只说「校验失败」**，必须可据此修仓。
- **退出码**：0=合法；1=不合法（诊断已出）；2=判定器自身错误（网络/权限，如实区分）。
- **判定与初始化的关系**：导入流（DEV-27）内嵌同一判定器跑两遍（源仓一份、克隆产物一份
  ——E 组闸跑产物）；`company add` 前置=validate PASS。
- **规则集测试纪律**：每条规则至少一对夹具（合法+违法），判定器改动过全量门禁——规则集
  与本文一一对应，改规则=改规范=走版本化修订。

## 八、合法之后（初始化语义，引用 docs/43-§一）

克隆 → 剥离 `.git` 重建本地仓 → validate（产物面）→ 平台字段 provision → 信任锚
`trust=false`（制作人批准后受信）→ 建 `.AIWS/` 员工工作区树 → 依赖清单自动安装 →
daemon 上车开工。
