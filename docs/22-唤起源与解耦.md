# 22 · 唤起源与解耦（Invocation Sources）

> 2026-10-16 ｜ 制作人定调：唤起要解耦，后续可持续拓展唤起方式。
> 核心模型：**唤起源是插件**——任何源只产"唤起意图"，决策永远归状态机主循环。

## 一、唤起源接口（Source Registry）

```typescript
interface InvokeSource {
  readonly name: string
  // 启动时注册；返回或推送唤起意图流
  start(emit: (intent: InvokeIntent) => void): void
  stop(): void
}

interface InvokeIntent {
  kind: 'ticket' | 'mention' | 'schedule' | 'relay' | 'resume' | 'webhook' | 'escalate' | 'data-change'
  company: string; ticket?: string; payload?: unknown
  source: string          // 来源源名
  priority?: number       // + dedupKey?（幂等键 v1.3，docs/25-§3.4；'data-change'=129 批示② 增）
}
```

- 源只产意图，**没有任何源能直接驱动 worker**——意图进主循环，由状态机决定是否唤起
- 新源 = 新注册项（manifest 声明），不动主循环；源的增删走进化管线（可配可灰度）

## 三、解耦验收口径

1. 新增一个自定义唤起源（示例源：监听某文件变化）不改主循环一行代码即可注册生效
2. 任一源产 100 个重复意图，主循环只唤起一次（意图幂等）
3. 关掉任一源，其他源与主循环零影响

## 四、与其他文档的关系

- 调度（18-§三）只管"什么时候问"；唤起源管"因为什么唤起"；主循环管"该不该干"——三者正交
- 21-协作通讯：Matrix 频道同时是通知出口；本文件只管其作为唤起入口
