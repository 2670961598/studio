## 一、总体形态

```
studio-next/                      # 全新独立目录（不混现 Studio），monorepo
├── apps/daemon/                  # 唯一常驻进程（Node 24 LTS）
├── packages/
│   ├── contract/                 # 契约包：cases.json + JSON Schema + runner（规格测试）

│   ├── adapters/                 # executor 适配器：dsh（默认）/claude/codex/kimi
│   ├── company/                  # 公司目录：schema 校验/挂载/报表聚合/定时岗调度源
```

## 二、什么地方用什么（选型定稿，均已实测/调研背书）

| 位置 | 技术 | 理由（溯源） |
|---|---|---|
| 运行时 | **Node 24 LTS**（26 转 LTS 后跟进），TS 原生 type-stripping + `tsc --noEmit` 门禁 | Bun 的 child_process 兼容 90% 是命门；type-stripping 免构建链 |
| 打包分发 | `bun build --compile`（仅分发产物；daemon 开发期跑 Node） | 四方案中最成熟，单文件可执行 |
| 数据库 | **node:sqlite**（RC）+ drizzle migration | 零原生依赖，Bun 已 18/18 兼容；官方承诺支持到 2050 |
| 调度 | **自建 SQLite 调度表**（next_run_at/last_run_at，启动补跑 due 槽）+ croner 解析表达式 | APScheduler 补跑语义没有现成库（实测实锤） |
| 状态机 | 自研表驱动 FSM + zod 校验 | 状态外置本就表驱动；不引 xstate |
| 校验 | zod 4（Standard Schema） | 稳定、生态收敛 |
| YAML 解析 | yaml@2（带行号 AST） | 校验器错误定位「文件:行」依赖它（docs/25 登记补入） |
| Web | **Hono**（streamSSE），三端口 | SSE 单向推流够用，浏览器自动重连 |
| 子进程 | **execa**（killDescendants+forceKillAfterDelay） | 唯一内建进程组杀法 |
| YouTrack | 自研薄客户端（fetch+zod），活动流 `start` 游标 | 无 webhook（404 实锤）；openapi.json 可生成类型 |
| git | simple-git（包 CLI） | 不碰仓内部格式，出事有 CLI 日志 |
| executor | **dsh 默认**（锁 0.2.0-rc.2，锁版本升级走回归）+ claude/codex/kimi 四原语适配 | 附A-1 / 附A-2 探针实测结论 |
| 测试 | **vitest** + contract 包（cases.json） | 契约=新系统规格测试（不以外系统行为为标尺） |
| Lint | biome | 快、单一工具（可选，不挡路） |
| MCP | 锁新包 `@modelcontextprotocol/server` 2.x 线 | 2026-10-16 实测官方源 |

## 三、核心机制怎么实现（要点，详见各需求文档）

- **唤起**：六源意图 → 主循环按状态决策；定时岗全部来自公司目录配置（D9 模型）
- **装配**：`prompt/` 包 L0-L5 组装 → AGENTS.md（优先各家用户级通道，claude≥2.1.277 才原生读）+ 任务书 + 分层指纹
- **收割**：成功语义契约（completed+非空+REPORT+闸门 exit=0）；summary.json sidecar 落前情摘要
- **预算**：reserve→settle→refusal；价目表在 models.yaml；成本按"每成功交付"记账
- **网关**：一切 YouTrack 写入收口 wkey + 署名自动注入 + 结构化动作词（机器通道，中文由 LLM 回退解析）
- **进化**：候选制品+三态闸门+谱系；宪法内核在框架侧只读文件，启动校验
- **对外**：:8788 默认局域网；Agent Card 由 org-config 生成（带版本/有效期）

## 四、里程碑（完成一个算一个版本，每个版本制作人过目）

> **并行轨道（2026-10-16 制作人定调）**：五处解耦面（executor 适配器 / FlowPlatform /
> 模型档 / 唤起源 / 公司目录）在 **v0.1 契约包落地后**即可各自并行推进——每面一条泳道、
> 独立分支、独立测试套，互不依赖；契约是唯一共享前提。集成只在晋升闸发生（contract 全绿）。

| 版本 | 里程碑 | 交付物（制作人可见的证据） | 验收口径 |
|---|---|---|---|

**时间盒（D7）**：v0.1-v0.5（首单端到端）两周内跑通，跑不通回议。
**每个版本的过法（分支晋升，2026-10-16 定调）**：feature/* → dev（CI 全绿）→ gray（灰度零事故+崩溃注入全绿）
→ 里程碑完成 → 演示证据包（页面/单据流/测试报告）→ **制作人过目** → 合入 release 打 tag → 进入下一个。
**上线前的实现冻结为 bugfix-only 维护线，不发新功能**。

## 五、前置准备（开工前一次性）

3. 清理 agent-pm 账号（D13）
4. 建 studio-next 目录 + 仓（沿用 §10 公私边界：产品仓 public+MIT）
5. YouTrack 侧：POLY/GAMES 补挂 state-guard（复查 C 级欠账，可先办）

## 六、风险与回退

- node:sqlite RC 风险 → better-sqlite3 一行切换（隔离在 store 包内）
- dsh preview 破坏式升级 → 锁版本 + 探针回归 + 适配器层隔离
- 时间盒失败 → 回议（降级方案：保留既有实现，新栈先只做面板/新功能）
- 每个版本可独立回退（tag + 契约包 + 快照）
