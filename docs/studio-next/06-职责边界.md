# 06 · 职责边界：公司架构 × agent 周边设施 × agent 内部

> 制作人 2026-10-15 定调：公司架构与 CLI 调用分割清楚；我们的核心是**唤起 CLI、托管 CLI 配置、
> 管好公司与 YouTrack 流程**；agent 内部（loop/插件运行时）尽可能交给 DSH（DeepSeek Harness），
> Claude / Codex / Kimi Code 等经同一适配口接入。**我们不关注 agent 本身内部的东西。**

## 一、三层分治

```
┌─────────────────────────────────────────────────────────┐
│ 公司架构层（我们建）                                       │
│ 公司 git 目录 · org-config · 人事/财务/报表 · 权限分权      │
│ 升级链 · 公司概览 :8789                                   │
├─────────────────────────────────────────────────────────┤
│ agent 周边设施层（我们建，核心工程）                         │
│ 唤起（六源）· 配置托管（agent.yaml）· 上下文准备（AGENTS.md）  │
│ 流程流转（YouTrack 状态机/批示/网关署名）· 证据收割 · 台账监控  │
├─────────────────────────────────────────────────────────┤
│ agent 内部层（黑盒，我们不建、不看、不改）                    │
│ DSH（默认主力：agent loop + 插件运行时）                     │
│ Claude Code / Codex / Kimi Code（同一四原语适配）           │
└─────────────────────────────────────────────────────────┘
        界面向下：四原语 + agent.yaml + AGENTS.md + 任务书
        界面向上：stream/NDJSON + REPORT + usage/tokens
```

**纪律**：周边设施层与 agent 内部层之间只有四个接触点——**四原语（launch/stream/result_stats/kill）+
配置注入 + AGENTS.md + 输出收割**。内部层的任何版本升级、插件变化、loop 行为，只要接口不变，
公司层与设施层零感知。

## 二、我们的核心工程（周边设施层的六块）

### 1. 唤起（Invocation）——我们的第一职责
六源矩阵（状态/定时/事件/人际/接力/续命）+ 唤起装配清单（executor 配置、公司身份包、
上下文包、资源配额、证据契约）。任何唤起源只产意图，决策归状态机。

### 2. 配置托管（agent.yaml）——每个 executor 的"人事档案"
框架级外置配置，版本化、改动走批示（可进化资产）、按泳道/等级可覆盖：

```yaml
executors:
  dsh:                              # 默认主力
    default: true
    version: "0.2.0-rc.2"           # 锁版本，升级走回归（developer preview）
    profile: headless               # headless --json（NDJSON）
    patches:                        # Cordis patch 层，按泳道切换
      prod:  profiles/dsh-prod.yml      # 禁自装插件（红线）
      explore: profiles/dsh-explore.yml # 放开自修改（试验田）
    plugins: [yt-gateway, webbridge, kimi-cu, ifind]   # 我们的工具=它的插件
    model: { provider: glm, name: glm-5.3 }
    budget: { reserve_usd: 15 }     # 预留-结算
    watchdog: { wall_s: 2700, heartbeat_s: 5400 }   # 它无墙钟参数，我们兜底
  claude:  { cmd: "claude -p --output-format stream-json", max_budget_usd: 15, ... }
  codex:   { cmd: "codex exec --json", ... }
  kimi-code: { cmd: "kimi -p --output-format stream-json", usage_from: wire.jsonl, ... }
```

### 3. 上下文准备
L0-L5 分层组装 → 工作区 `AGENTS.md`（抗 auto-compact）+ 任务书 + 冻结验收口径 +
同类历史教训。agent 醒来的世界由我们布置，它只需要干活。

### 4. 流程流转（YouTrack）
状态机/批示/联签/网关 wkey 收口/署名自动注入/活动流轮询。平台能扛的交平台（03-§二）。

### 5. 证据收割
成功语义契约（completed+非空+REPORT+闸门）、usage 按 executor 分派解析、
成本按价目表折算、全部落 SQLite 台账。

### 6. 台账与监控
events/工时/预算/人事变动 + 监控 :8787 + 概览 :8789 + 对外 API :8788。

## 三、DSH 的定位（默认主力，不是唯一）

- **默认 executor**：新单缺省走 dsh（`profile: headless`，锁版本）；它的 agent loop、
  插件运行时、工具循环全部是它的事
- **我们的工具 = 它的插件，且插件是我们自研的（制作人 2026-10-16 定调：DSH 开源 MIT，
  我们可以自己写插件）**：yt-gateway、webbridge、kimi-cu、ifind 之外，以后为公司定制的
  任何工具都优先写成 dsh 插件——这是我们自己的插件资产；必要时可 fork/patch。
  **这是工具投递通道，不是治理让渡**：生产泳道禁自装插件（patch 双保险），
  自修改只在 explore 泳道放开，它的自进化输出只能作为提案进我们的管线
- **其他 CLI 同权适配 + 按岗位配型（同日定调）**：claude（参考实现+预算帽）/ codex /
  kimi-code 走同一四原语；**不同岗位可按 CLI 特长绑定不同 executor**（org-config 的
  people[] 加 `executor` 偏好字段）——策划用长文档强的、QA 固定用"另一家"（异源监控）、
  探索用 dsh。调度优先级：单据指定 > 岗位绑定 > 探针竞标默认（§5.3）
