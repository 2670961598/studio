## 二、本次设计的总纲（制作人定调 + 主 PM 落实）

1. **框架不变，公司 = 代码外部的一个 git 目录**：一家公司的等级、人事、等级分布、上下级、部门职能关系全部在目录内配置化（org-config.yaml + 部门/人事文件）；加一家公司 = 加一个目录，零改码
2. **人事定义独立成文**：每人一个文件（定位/职责/做过的事/技能/表现/自述），公司网页可编辑，编辑 = 人事变动，走草稿→批示→留痕，永不直接写文件
3. **提示词分层组装**：L0 框架 → L1 公司 → L2 组织 → L3 个人 → L4 项目 → L5 工具，每层有来源、责任人、版本指纹、裁剪优先级
4. **1-9 级纵向保留**，对接 YouTrack（等级字段/批干矩阵/账号锚点）
5. **对外 API**：独立网关（独立进程/端口/凭证），外部只落单不派工
6. **实现路径**：全部设计过审 → YouTrack 开新项目 → opendesign 出图 → 监控/公司界面设计 → 文档库定稿 → V3 派工

## 三、九路调研挖出的关键事实（V3 生产实例实测）

> 定位（制作人 2026-10-15 澄清）：1-5/7 是**当前 V3 生产实例**的数据与配置现状，
> 对 Studio Next 只是**迁移输入与教训，不是约束**；6/8 是平台能力与设计问题，与 V3 无关。
> YouTrack 实例本身沿用（同一 :8080，Studio Next 新公司开新项目，V3 老项目随冻结自然停更）。

1. **done.json 实测只有 194 份**，不是蓝图里写的 1167 份（1167 是 LLM 事件数，口径混淆）——回填前必须先对账（F2-13）
2. **`studio onboard` 命令从未被实现**（宪章 §9 承诺的一条命令全建，实际零代码）——YouTrack 侧的项目/字段/泳道全靠手写配置（Y3-N10）
3. **平台 guard 只有 STUDIO 挂了，POLY/GAMES 裸奔**——非法迁移在平台层不设防（Y3-N6）
4. **YouTrack 免费版 10 用户已满**（opengames + agent-1..9）——"账号=等级锚点、工号=人"是永久决策，不能再走"账号=人"回头路（Y3-N9）
5. **本机零 Agile 板**（`/api/agiles` 为空）——平台自带看板/Gantt/报表/工时全部未启用，是一大笔未兑现红利（Y1/Y2）
6. **平台算不了业务口径**：成本/token/证据哈希/工号平台都不会算——正确姿势是"框架算 → 写回字段 → 平台展示"（Y2）
7. **角色权限无法 API 化**（`/api/assignedRoles` 只读）——平台权限只能一次性 UI 配置，自动化边界在此（Y3-N8）
8. **config.yaml 与 org.yaml 事实源冲突**需要拍板（见待拍板 D1）
