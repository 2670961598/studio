# 05 · 文档体系设计（谁在读它，它就放哪）

> 2026-10-15 ｜ 回应制作人：文档库放 YouTrack 还是自己的目录？——分平面安放，各得其所。

## 一、判断标准与四平面

**谁在读它，它就放哪。**

| 平面 | 位置 | 读者 | 内容 | 关键性质 |
|---|---|---|---|---|
| 公司文档 | 公司 git 目录 `docs/` `reports/` `prompts/` `departments/**` | 制作人（老板）+ 出工的 agent | 章程/部门规定/人事档案/报表/总览/公司级提示词片段 | **路径即引用，可到处引用**；git 历史；随公司目录迁移；网页按约定直读 |
| 工作知识 | **YouTrack Articles**（按项目分区） | 干活中的 agent | SOP/案例库/历史教训/单据相关知识 | kb-search 已接网关，干活时检索最快；派工自动注入同类教训（现有机制）；与单据同平面 |
| 产品文档 | GitHub 产品仓 `docs/` | 外部用户/贡献者 | 蓝图/迁移方案/本设计库/README | §10 公私边界：产品是给别人的 |
| 运维文档 | 框架仓 + 监控面（:8787） | 主 PM/框架自身 | daemon 运维/故障手册/探针口径 | 随代码走，版本同步 |

**YouTrack 的定位澄清**：它不是"纯外部流程"——它是**流程流转 + 工作知识**的事实源
（宪章 §7 知识库本就定在 Articles）。流程和工作知识在一起，干活的 agent 不用跳两个系统。

## 二、引用规则

1. **公司内引用一律用路径**：`departments/工程部/people/W-0001.md`、`reports/工程部/2026-10-15-daily-工程部-*.md`——网页、提示词、agent 任务书统一用相对公司根的路径
2. **YouTrack 引用用文章 ID/标题**：任务书写"必读：知识库「质量战役/案例库」"，kb-search 可检索
3. **跨平面引用只许单向**：公司文档 → 可引用 YouTrack 文章与产品文档；YouTrack 文章与产品文档 → **不引用公司目录路径**（公司目录是本地的，外部不可达）
4. **同一内容不两写**：每类内容只有一个家；需要别处可用时引用，不复制（防漂移）

## 三、写作与归档纪律

- 公司文档：daemon 唯一写入者（人事变动/报表生成挂单 commit）；制作人/主 PM 可直写
- YouTrack Articles：长期单定时整理（现行机制），干活的 agent 不直接写
- 产品文档：主 PM 维护，随发版同步（README 计数一致，§10.3）
- 报表：数字机械生成（台账），文字负责 agent 写，标注口径（04-E3 待拍板）

## 四、网页呈现

- 公司概览（:8789/<slug>/docs、/reports）按目录约定渲染公司文档与报表
- 工作知识在 YouTrack 原生界面 + 概览页做检索入口（iframe 或链接，不复制内容）
- 产品文档在 GitHub（V7 形象岗保鲜）
