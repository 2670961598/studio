## 一、总纲领

**「V4 Studio 总纲领架构图」**（OpenDesign「Studio Next 设计」项目）是唯一母版图，含三视图：
公司层面 / 框架层面 / YouTrack 关系层面。一切内部图（公司目录模型、公司层面图、框架层面图、
职责边界图及后续界面稿）都是它的局部放大，冲突时以总纲领为准。

总纲领的三句话版本：
1. **公司层面**：我们造的是一家公司——公司 = 代码外部的一个 git 目录，制作人只定方向和口味
2. **框架层面**：周边设施是核心工程（唤起/配置/上下文/流程/证据/台账），agent 内部是黑盒（DSH 默认）
3. **YouTrack 关系**：流程+工作知识的事实源，一切经网关，平台能扛的交平台

## 二、V4 工作方法（文档先行，全程保证）

**顺序铁律**：抽象层（总纲领/边界/契约）→ 文档（需求/设计/界面稿）→ 制作人过审 → 代码 → 测试。
倒序或跳级视为废件，不得进合并流。

具体保证机制：
1. **文档先行**：每个 Epic/单子开工前，设计文档（需求+验收口径+界面稿如涉及）必须已在
   docs/studio-next/ 呈批并获制作人批准——**验收命令里包含"文档已批准"检查项**
2. **抽象先行于选型**：涉及新技术选型的单，必须先更新对应抽象文档（总纲领/06 边界/契约包），
   注明该选型在抽象层的位置，才允许写选型对比
3. **代码跟着文档走**：实现单的任务书必须引用设计文档章节号；实现与文档冲突时，
   停手改文档（走批示流），不默许代码漂移
4. **测试跟着契约走**：测试只对契约（contract 包 cases.json）和冻结验收口径负责，
   不对实现细节负责——实现可换，契约不随便动
5. **文档保鲜**：README/文档计数与实现一致（§10.3）；漂移看门狗覆盖文档-代码不一致类（F3-10）
