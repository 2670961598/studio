### 0.2 四条总纪律

1. **fail-closed 是默认不是选项**（v2/00 §五-8）：任何安全控制件，缺配置、坏输入、组件失能时的**唯一合法行为是拒绝**；「返回裸对象＋警告日志」不是控制，是放行加台词。
2. **差值必须登记**：现状与目标的差值一律按三列写明（§一）；「文档写机制保证、代码写放行分支」而差值不入登记表＝违规（治 DSF S4「最危险的不是漏洞，是差值未登记」）。
3. **目标（未证）强制标注**：本卷机器强制点在现状代码中无一建成，§一至§六全部强制点按「目标（未证）」对待；建成前相应控制以审计断言与登记缺口代偿，不得宣称「已保证/机制保证」。
4. **枚举与 ID 纪律**：本卷新立六族 `SEC-FC-`/`SEC-SIG-`/`SEC-WD-`/`SEC-SEC-`/`SEC-RD-`/`SEC-REV-` 与三组枚举值（五型秘密、署名主体三值、控制面动作词族），语义唯一主表在本卷、统一登记 v2/09；他卷只引 ID，禁裸字母、禁重述字面量。

## 一、fail-closed 清单（SEC-FC-）

**禁止形态判定**：一个配置键或分支，若「关掉/缺省/喂坏值」的结果是**放宽或裸化**（返回未过闸对象、跳过校验、回落公开常量、只打警告），即列为本表禁止形态；必须给出 fail-closed 替代与机器强制点。现状列全部为审计已核代码事实（DSF P0-9/V08-P0-03；锚点为仓内源文件，只读参照）；**机器强制点列全部为目标（未证）**。

## 二、署名可追溯（SEC-SIG-）

**命题**：每次平台写入的署名必须能回到**真实决定人**（人的工号，或承载决定记录引用的 agent 工号/控制面位置）——「daemon 做的」「工具做的」「公司做的」都不是可结算的署名（I-9 主语明确）。

**SEC-SIG-01 署名主体三值**（语义唯一主表本卷；**值集唯一主表 v2/09 ENU-118**，本节不复列机器值——09 §六-4 收口）：`person`（人员工号）｜`control`（控制面位置＋决定记录引用）｜`system`（系统代写＋可还原工号或触发源，`onBehalfOf` 必填）。

- **现状（fail-open）**：`SignedBody.author` 规范口径为 PersonId（工号一等公民），实际恒为常量 `daemon`；署名部门取 `departments[0]` 与本次工作责任部门无关；平台侧评论作者/状态 history actor 都是平台账号，三个面都回不到决定人（V08-P0-02 已核）。
- **目标**：署名对象扩为 `{actorKind, actorRef, onBehalfOf?}`（字段形状 → v2/11；端口 → v2/14）；网关落款不改写正文的既有纪律保留（gateway.ts 头注）；「署名回不到决定人」判负，审计断言建成前以抽样代偿。
- 机器强制点（目标未证）：署名构造层（同 SEC-FC-06）＋网关校验面。

**SEC-SIG-02 控制面凭据签发与验证分离**：

- **现状**：控制面 key 由 daemon 同进程 `issueControlKey()` 现铸、同进程同密钥验签（一调用一签发，TTL 15m）——签发者＝验证者＝被闸方同体，闸退化为**同进程信封**；署名因此回不到 daemon 之外的任何决定人。
- **目标**：签发者与验证者**不同进程、不同密钥**（验证件部署于独立信任域，见 §五 SEC-RD-02 与 v2/12 §3.4 处置）；建成前该闸**只准自称「同进程信封闸」**，不得称独立授权或外部闸门（对齐 v2/12 BIND 损失口径）。
- 机器强制点（目标未证）：验签件独立部署＋密钥分离；台账记「闸形态＝信封/独立」供审计判读。

**SEC-SIG-03 控制面动作词族（ctl-）**（**值集唯一主表 v2/09 ENU-119**，语义唯一主表本卷——09 §六-4 收口；端口冻结 → v2/14，改 contract 走批示流）：

- **现状（借道）**：控制面状态操作（create/transition/setField/link/provision/guards）在冻结白名单 `GATEWAY_ACTIONS`（六动词，全 worker 面）内无对应动词，借道 `comment`＋`args.op` 自述真实操作（gated-platform.ts 头注已挂账）；网关只校验 comment，`op` 不参与校验——状态迁移与评论在审计面不可区分，「agent 永远拿不到状态推进通道」对 daemon 自身不成立。
- **目标**：`ctl-*` 动作词族入网关校验（申报动作与实文一致性校验沿用 `gw-action-mismatch` 机制）；审计面 transition 不得显示为 comment；`op` 自述迁移期允许但须记台账降级标记。
- 机器强制点（目标未证）：contract 动作词表扩展＋网关校验面；负向探针「ctl 申报与实文不一致必须拒」（→v2/17）。

**SEC-SIG-04 投影验签通道**（承接 v2/12 §1.6 登记、机制归本卷）：策略投影的签名封套要素＝签名者独立于持有者｜信任锚｜单调代次防重放；建成＝**目标（未证）**，建成前以启动器侧摘要＋引用可解析校验代偿，不得宣称「策略投影已防篡改」（GAP 登记 v2/17；探针 PRB-08）。与 SEC-SIG-02 共用独立信任域施工件。

## 三、写域与多公司维（SEC-WD-）

**命题**：写域＝分域权威表（v2/05 §三 DOM-01..07）的**写侧**——每条写路径必须同时回答「写到哪个域、以哪个唯一写入者身份、属于哪家公司」；三问缺一即裸写。

**SEC-WD-01 每写路径携带公司维**：

- **现状**：外部 API 支持 `?company=` 多公司读，触发面却持单一注入 platform；`issues.create` 无 company/project 维，`POST /v1/requests?company=B` 的票据会落到该 platform 绑定的项目（可能是 A），却以 B 的名义记账回包——错绑/跨公司写不被拒绝（V08-P0-04 已核）。
- **目标**：写调用必带公司维；解析出的公司维与 platform 绑定维不一致＝4xx 拒绝（不得静默落错库）；单公司部署可省略 company，多公司部署缺维＝请求非法。
- 机器强制点（目标未证）：写端口字段加公司维（→v2/14）；负向探针「跨公司/错绑必须拒绝」（→v2/17）。

**SEC-WD-02 绑定唯一源与一致性校验**：

- **现状**：org-config 的 `platform` 与 daemon.yaml 的 `platform/taigaProject` 两个事实源并存，daemon 运行时不读前者，无优先级与一致性规则；validator 缺省值与 daemon 枚举面甚至不同域。
- **目标**：唯一绑定源＝部署面（daemon.yaml），org-config `platform` 降为声明/期望；启动时二者比对，不一致＝`CONFIG_INVALID` 拒启（一行校验关闭静默错绑）；拓扑二选一并写死：一 daemon 一公司，或多公司＝「公司→平台实例/项目/凭据」注册表路由（SEC-WD-01 的承载）。
- 机器强制点（目标未证）：启动比对＋注册表；绑定源规则入 v2/14 端口装配说明。

**SEC-WD-03 写路径对照表**：全部写路径逐条登记「域（DOM-）｜写入者身份｜公司维｜过闸与否」；网关外写面（外部 API 直写、onboard/迁移脚本、平台 UI 直改）的处置——前两者按 SEC-FC-07 收口或登记为独立写面；平台 UI 直改＝**明写不支持**，由平台角色权限禁止＋对账（Taiga created 事件缺席、轮询不可见的现状如实登记，v2/12 §2.2 各卡）；「唯一写入者」在机制层面成立以本表全行为 gated 为判据（现状不成立，AGENTS.md 事实源表按 V2 修订时引本表）。

## 四、秘密面（SEC-SEC-）

### 4.1 五型分类（语义唯一主表本卷；**五型值集唯一主表 v2/09 ENU-117**，本表 ID 列即 SEC-T1..T5 语义承载——09 §六-4 收口）

| ID | 型 | 例 | 注入面（谁经什么拿到值） | 逻辑引用纪律（台账/简报只准出现什么） |
|---|---|---|---|---|
| SEC-T1 | 平台凭据 | Taiga/YouTrack token·密码·refresh | daemon 进程 env（缺键＝`CONFIG_INVALID`，只报键名不打印值——wire.ts resolveTaigaAuth 现状已有） | 类别＋逻辑引用（如 `taiga:main`） |
| SEC-T2 | 模型密钥 | provider API key | profile 只出现 `apiKeyEnv` 变量名，值经 env 透传（v2/12 §1.3 现状已有） | 类别＋env 名 |
| SEC-T3 | 签根与控制凭据 | gatewaySecret·wkey 根·control key | 独立信任域（目标，SEC-RD-02）；worker 面永不注入 | 类别＋签发者引用；值与密钥材料零出现 |
| SEC-T4 | 按单短命凭据 | 派发 wkey（随任务书签发、关单吊销） | 派发时注入收割时吊销；一调用一签发面沿用 | 单号＋TTL＋scope |
| SEC-T5 | 外部服务与出站凭据 | webhook 验签 secret·MCP 凭据·refresh 链 | 出站通道专用，不经提示词 | 类别＋端点逻辑名 |

通则：值**只经 env/短命句柄通道**流动；任何型落入台账、公司目录、配置文件、提示词、日志之一＝事故（4.3/4.5）。

### 4.2 差分——谁可见什么（SEC-SEC-02）

- 供给差分：每型秘密登记「可见位置集合」（岗位/控制面/部署者），集合外供给＝越权；差分变更（新增/扩大）不得随版本升级夹带（v2/07 §六），须单列经部署供给确认。
- 变更差分：HCL-2 闭合的**权限差分＋秘密差分双单列**（PRB-19/20，v2/12 §5.3）——「秘密未进上下文」（PRB-07）不得代证差分（治 GLM V8-P1-2：差分要件在 v1 探针矩阵零对应）。
- 观察差分：MON-09 访问留痕（谁何时为何读了哪域，v2/08 §3.3）覆盖秘密供给与使用；只统计次数不算访问记录。

### 4.3 轮换与吊销（SEC-SEC-03）

- 轮换触发：周期到期｜泄漏怀疑｜持有者离岗/撤回｜事故复盘指令；轮换＝新值生效＋旧值全量失效验证（不是换文件）。
- 吊销＝**运行时停用验证**（v2/07 CAP-04）：撤销句柄、停止注入、围栏旧凭据三动作逐项留证；迟到的旧凭据使用进后验对账（MON-13/OBS-02）。
- 台账只记类别＋逻辑引用＋轮换/吊销事件（事件名入冻结词表，见 4.4）；完成无据可查不得宣称轮换/移除完成。

### 4.4 出站扫描的承担者与观察面（SEC-SEC-04；治 P0-10「红线无对象、无承担者、无观察面」）

- **现状**：AGENTS.md §五.6「密钥永不入库；出站内容过密钥扫描」在 v1 全库无承担者；唯一实现对八个出口只覆盖三个且只对 hrSync 生效；三个失败事件名（redaction-failed/notify-blocked/unknown-shape）不在冻结词表——扫描成败不可判定。
- **目标**：①**承担者**＝框架出站文本闸（daemon 出站通道统一件，覆盖全部出站出口——平台写、通知、证据导出、日志外发、对外 API 响应）；②**判成败可表达**＝失败事件名入冻结词表（词表改动走 contract 批示）；③**观察面**＝扫描失败/跳过/覆盖缺口入 MON-12/15 行（证据与审计、监控自身），无扫描通道的出口登记缺口不得静默放行；④**仓面扫描**＝提交门禁扫描仓内容（本机路径/IP/真实凭证模式），命中即拒（AGENTS.md §五.6 第三句的机器化）。
- 机器强制点（目标未证）：出站闸装配＋词表＋门禁脚本；负向探针「注入探针秘密后全部导出物检索不到该值」（PRB-07 扩全出口）。

### 4.5 三不入与机器强制点（SEC-SEC-05）

「不入库｜不入提示词｜不入日志」各自的强制点（均目标未证，现状仅有零星纪律）：**库**——daemon.yaml/公司目录 schema 无秘密值字段位，台账写入前 redaction；**提示词**——派发简报只携带类别＋逻辑引用（v2/07 EXEC-01），组装器对成品简报跑出站闸同款扫描；**日志**——日志层模式扫描（值形态＋env 名全打印检测）；违反三任一＝安全事件入账（失败如实分类上报，AGENTS.md §五.5 同源）。

## 五、读面知悉范围（SEC-RD-）

**SEC-RD-01 知悉范围可表达**（治 P0-10「读面授权在端口上不可表达」）：

- **现状**：读面端口无 readScope/callerContext 字段——「谁能读」无法从端口判定，只能靠调用方自觉。
- **目标**：读面端口携带 `readScope`（按角色/部门的知悉范围声明，语义主表 v2/02 §八/v2/05 信息需求行）＋`callerContext`（调用者身份引用）；端口二选一必须成立：**字段承载**，或**明写「读面授权由调用方承担」并登记为损失**（不得两头都不写）；多公司视图按公司与知悉范围隔离（v2/08 §4.4）；秘密代理面读按 4.2 供给差分判定。
- 机器强制点（目标未证）：端口字段（→v2/14）或损失登记（→v2/12 各卡）；读面越界访问入 MON-09 留痕。

**SEC-RD-02 同信任域处置（DSF 术语 E2；规范 ID＝TRUST-SAME，09 §一-64）**（治 P0-10；承接 v2/12 §3.4 签根 P0 登记）：

- **现状（已证负向）**：签根与被闸方同部署可读面（配置值形态）；读域不可收口（PRB-05：本 OS sandbox-exec 读域规则 apply 即 SIGABRT，strictRead 已删）；进程/网络隔离均无（BIND-LOSS-11/13/14）——worker 读到部署配置即可自签越单冒充。
- **处置三段**：①**机制目标**＝签根值位移出可读面（独立用户/容器/broker 短时供给）＋验签件独立部署（SEC-SIG-02）——施工件，目标（未证）；②**建成前口径**＝EX-2+「外部闸门」现状一律目标（未证），禁写「部分已有（网关）」；同域即同体，**不构成独立签名**，独立性主张按 BIND-LOSS-11 判负；③**过渡防线**＝秘密不放进工作区＋部署最小化（读域模型唯一可行面），配合 MON-06「撤回后仍在暴露」观察行。
- 判据：「把模型换成恶意模型，这条控制还在吗」（v2/12 §0.3）——同进程信封、提示词叮嘱、配置注释警告都不在。

## 六、撤回后代凭据（SEC-REV-）

**命题**：撤回完成＝后代清单＋停用证据（I-6/EVD-RVK）；「网关 revoke 一行＋清单删一行」不是撤回。

**SEC-REV-01 三件套对齐**（对象语义 v2/07 §四、证据对象 v2/08 §1.8，本卷只定机制并锁三处对齐）：

1. **枚举派生执行体**：撤回触发时按派生树登记（派生即登记规则）枚举全部后代——子 agent/子进程/会话快照/被复制被注入凭据；v1 记录 `REC-AUTH-03` 只清点「已发出凭据」不枚举后代的缺口，由 v2/11 记录形状扩展闭合（后代枚举＋停用证据字段，形状 → v2/11）。
2. **吊销其凭据**：逐后代执行 4.3 吊销动作并留证；凭据默认不继承（v2/07 §四规则 3）使枚举分母可控——继承须显式批准，故登记表即完整分母。
3. **停用证据**：机制性证据三选一留档——撤销回执/注入停止确认/围栏拒绝记录；无后代时**显式确认方法**（探测方法＋最后探测时点）不得留空视为零。
- 完成判据：三件齐＋残留检查期观察义务（v2/04 §八·四要件）方得记撤回完成；否则撤回记录标未完成，工作面不得结清（v2/04 §六）。

**SEC-REV-02 撤回网关强制**：撤回指令触发网关侧后代枚举＋凭据批量吊销（关单即吊销的推广：从按单 wkey 扩到整树）＝**目标（未证）**；建成前以审计断言代偿（v2/07 §四同款口径）＋MON-13 行观察。

**SEC-REV-03 停用后观察**：迟到旧凭据使用与残留副本＝后验对账范围（MON-13/OBS-02 独立发现通道：围栏拒绝记录/平台活动流/写入审计交叉对照，不依赖执行体自报）；撤回后仍存活的执行体按「未知」处理不得记「已停止」（MON-ST）；记忆面同步防御：撤回引发的知悉范围收缩触发 MEM 访问重审批（v2/08 §3.3）。
