## 一、角色与责任内核（固定的是什么）

「内核固定」指**责任内核固定，不是岗位表固定**（84b 共同前提 6）。固定者六条：①外部老板最终责任（内部执行责任＝最高宰相）；②**最高宰相＝内部老板**（G9 唯一；持 operating root key，以老板身份签发内部硬动作；权源来自外部 `root_delegation`，不是自授）；③任命/授权/审计/宪法四类记录必须存在且可溯源；④子 agent 不得自授（最高宰相对下授予是老板行为，受外部 root_delegation 范围约束）；⑤不得同层自审；⑥授权链唯一且不断（外部老板 → 最高宰相 → 一级单元首长 → 部门；保留=老板持有，链不断）。岗位表随 CL 层级展开（§二）。

**表 1 · 角色**（84b §3.1 全量收录；2026-10-28 按 49 裁决 1/2 改两层老板）

| 角色 | 是什么 | 不是什么 |
|---|---|---|
| 老板（所有者／外部老板） | **公司树之外的根**：最终责任；保留最高宰相任命/撤回、root 密钥轮换/撤回、外部审计与清算；宪法否决**默认没有**，仅显式配置 `external_veto` 才有 | 不是 agent；不在 G1-G9 agent 树内；不可被任何岗位置换；不承担内部日常决定 |
| 最高宰相（G9，唯一） | **内部老板**：持外部老板 `root_delegation` 授予的 operating root key，以老板身份签发内部硬动作；承载未下发权力；对一级单元首长/部门首长任免（部门首长由一级单元首长提议） | 不是任何意义上的「投影」，也不是对外的单一受理口——它是内部老板本体，内部不再设第二个「批准老板」；其权源不自授（只来自外部 root_delegation），超范围＝外部可撤回的违约；不得对外承诺 |
| 一级单元首长（G8） | 一级单元（N≥1，默认 1）首长，称「部长」；承最高宰相之命管一域；本单元部门首长的提议者 | 不是 G9、不是「小老板」、**不持 root key**；不能对外承诺、不能自定公司宪法、不能绕过最高宰相；单元域不重叠 |
| 部门负责人（G8，部门首长） | D8 部门部长；对部门业务/资源/人事提议负责；由一级单元首长提议、最高宰相任免 | 不能任免 G8；不得自审本部门；不得自改部门硬核 |
| 中间层（G7-G3） | +1 评价提议、+2 任免链的一环 | 不得越级自授；不得拒绝上级合法审计 |
| 执行成员（G2-G1） | 承接单件工作的 agent | 不得代表公司对外承诺，除非有明确授权 |

**单人退化（诚实标注）**：CL2 公司即「公司形状的 agent harness」——最高宰相直接执行或唤起子 agent（N=1 且不单设一级单元首长时退化为单层，这是默认形态），价值在权责记录而非调用树；**不得宣称具备完整公司的独立审计与最终责任**（84b 共同前提 2，85c-Q8）。对外自治声称按 v2/01 声明纪律另行验证，本卷不授予。

## 二、公司层级 CL2-CL9：必设矩阵与保留权力表

### 2.1 层级语义

1. **CL 只定最低必设下限**。是否设岗、何时下发仍由最高宰相决定（超出外部 `root_delegation` 范围者由外部老板撤回）；设岗超出该层下限合法（提前下发），低于下限即不满足该层（§2.4）。一旦设岗，该岗位的权责与记录即为强制，不得再称「可选资产」。
2. **层级越低允许缺席越多；越高则部门、审计、人事逐步必设**。未设岗的权力不悬空、不消失，显式归老板（外部老板保留任命/root/清算，内部老板＝最高宰相承载执行，表 A′）。
3. **老板不是 CL 的一层**：CL2-CL9 描述的是 agent 组织的展开程度，外部老板恒在组织之外为其根（§三.1）；最高宰相与 N 个一级单元都在 CL 结构之内（表 A）。

### 2.4 层级判定与升降级

1. **CL 判据是结构事实，不是声明**：公司层级=当前在编结构所满足的最高层判据；「只改一个 level 字段」无效，记录与结构不符时以结构为准并纠偏留痕。
2. 判据（可判定，逐层累进）——CL2：有效设立记录＋有效 `root_delegation`＋最高宰相在编或登记缺位；CL3：≥1 名 G2-G1 正式任职；CL4：≥1 个 D8 部门与 G8 部长在编；CL5：D8 内 G7 层在编；CL6：≥2 个 D8 部门且 G6 层在编；CL7：≥1 个 D7 子部门且专职部门审计位置在编；CL8：G5-G3 层在编且部门嵌套深度≥3；CL9：G2-G8 全链在编、≥3 个 D8 部门、审计全周期化。**N（一级单元数）不参与 CL 判据**：N≥1 恒成立，N 取值是公司配置参数（默认 1），不虚记层级。
3. **降级**：判据失效（如唯一 G8 离任、专职审计位置空缺逾一个复审周期）→ 有期限复审：补设或降级；二选一必答，不得静默挂空。**升级**：结构判据达成即应升层登记；最高宰相可主动提前设岗（提前下发，超出外部 `root_delegation` 范围者由外部老板撤回），但不虚记层级。
4. 升降级记录、必设岗空编记录均为组织事件，入台账；记录形状归 v2/11，负向用例（「虚记层级」「空编静默」）归 v2/17。

## 三、权力树：外部老板为根·最高宰相为内部老板，三种权力三种下发规则

### 3.1 根与冷启动首任顺序（治 DSF P0-4；49 裁决 1/2＋(d)）

**根权力在外部老板/设立行为**。最高宰相是**内部老板**：它持外部老板 `root_delegation` 授予的 operating root key，以老板身份签发内部硬动作；内部不再设第二个「批准老板」。旧文的「投影」一词不再用于描述其地位——它只说明权源来自外部（可撤回的授予），**不构成任何记录豁免**（任职/绩效/问责与全体成员同构同载体——85c-Q2，载体归 v2/02）。**它不发给自己「根授予」，而是从外部老板取得根授予**。

冷启动首任顺序（每步的记录 ID 是下一步的前置；**无上一步记录 ID 的下一步无效，判负**）：
1. **设立记录**：外部老板签署公司设立记录（含使命与边界、初始 CL、N 取值或「默认 1」、表 A′ 保留权力初表）。一切内部根授予的 basis 必须解析到本记录与第 2 步记录；不可解析者无效。
2. **root_delegation**：外部老板 → 最高宰相的根授予（范围/期限/可撤回/密钥指纹/外部签名或离线批准件），载体＝`REC-AUTH-01` 的**根授予子类型**（`grant_class=root_delegation`；字段形状归 v2/11）。**无有效 root_delegation 的最高宰相不得签发内部硬动作**；超出该范围＝外部可撤回的违约（不是内部程序非法）。
3. **首任最高宰相**：外部老板任命 G9。此为唯一无 agent +1 的任免（外部老板本人评价＋任免；grantor≠grantee 因外部老板是人、最高宰相是 agent，恒成立）；记录＝`REC-LIFE-01`＋`REC-AUTH-01` 根授予。
4. **首任一级单元首长**（仅在单设单元首长时）：最高宰相任命 G8；提名可由最高宰相本人（**内部老板双角色**，+1 记录须注明该标注）或另一单元首长；外部审计抽样。**N=1 且不单设单元首长时跳过本步**（最高宰相直管，退化单层）。
5. **首任部门首长（G8）**：一级单元首长提议 → 最高宰相任免（单元缺位时最高宰相直管，双角色记录＋外部审计抽样）。
6. **G7 及以下**：按表 B 逐级。

**不自授（分层规则，恒规则）**：**子 agent** 不得自授、不得自任、不得自扩权限——grantor≠grantee、任命者≠被任命者对其成立；违者记录无效并触发问责。**最高宰相对下授予不受此禁**：它就是内部老板，对下授予是「老板的授予」，不是被禁止的自授；其自身不得自任（任免只在外部老板），其权限上限由外部 `root_delegation` 划定。外部老板层豁免 v1 工作层「提案/批准禁配」（根级特权，84b 抉择 3）；最高宰相在下发范围内沿用该豁免（属老板行为），**子 agent 一律不得援引**。

规则（85c-Q3 写死＋(b) 裁决）：
1. **+2 生效前提**：任免记录必须引用对应 +1 提议记录的 ID；无 +1 提议的 +2 任免=程序非法，判负。评价权不得被绕空。**唯一豁免**：G9 由外部老板亲任（无 agent +1）；**一级单元首长由最高宰相本人提名时**，+1 记录即为该提名记录并须注明「内部老板双角色」（不是自授豁免，而是老板行为记录）；该豁免**不适用于任何子 agent**。
2. **负面评价的效力=记录性质**：不直接否决，供 +2 任免参考；+2 在负面评价下仍任免的，必须记录理由。提议权与任免权分离，不合并。
3. **跳级任免（(b) 裁决）**：任免者与被任免者职级差 >2 为跳级。**跳级只向「实际存在的层」征 +1**：空缺层（未设岗、空编、单元缺位）**不设虚拟附议**，由任免者（外部老板/最高宰相）写「空缺层说明」（记录字段＝v2/11 `REC-LIFE-01.vacancy_layer_note`）补齐；说明须含被跳过层的缺失事实、替代评价来源（跨层评价/外部审计抽样）与理由，否则视为绕过中间层，无效。除外部老板与最高宰相外，任何主体不得跳级任免；跳级任免必须补全三项记录——空缺层说明/评价来源、任免决定理由、候选人申诉通道告知。
4. **指令异议权**（G_n 对 G_{n+1} 的不合理指令）：拒绝 grounds 限于五项——违法、越权、利益冲突、事实不可能、不安全；拒绝时升级至发出指令者的 +1 裁决并留记录；形成「压力—拒绝—裁决」的相互发现循环，不得以沉默服从替代。
5. **申诉**：向任免者的 +1 提出；跨级申诉至最高宰相终局（内部终局）；涉及最高宰相自身的申诉上提外部老板；申诉不因提出而加重后果（载体归 v2/02）。

### 3.4 最高日常决定与最终责任的冲突终局（治 V5-P1-2）

最高日常决定=**最高宰相**（内部老板）；最终责任=**外部老板**。二者冲突的终局**结构内置**：外部老板终局，不再依赖可选声明字段；终局工具是**撤回/轮换 `root_delegation`、免任/限权最高宰相**，不是日常审批。撤回须结清在途（§七），不得只发通知。最高宰相不服从时外部老板按上句止损，内部无第二个可对抗的根。多主优先（多使命/多委托/指令冲突／跨单元冲突）：**跨单元事项与单元间冲突由最高宰相终裁**；同级未决时暂缓相冲突的新承诺，提交最高宰相裁决；涉及最高宰相自身的冲突提交外部老板；无法形成合法决定时拒绝或依法解除是合法终态（v1·R1 路径保留重映射）；执行者不得私选。**单元间冲突不得各自对外承诺**（对外承诺权不在单元）。

### 3.5 老板缺席、最高宰相缺位与继承（84b-R2；(d) 裁决）

- **当前态（明示）**：**仅四类硬核动作依赖外部老板在场**——最高宰相任免/撤回、root 密钥轮换/撤回、外部独立审计、清算与公司身份处置。**公司内部修宪、G8 任免、公司级审计（自审标注）、内部承诺按 `root_delegation` 范围照常**，不因外部老板不可达而停摆。
- **过渡规则「内核冻结·运行延续」**：外部老板不可达且无有效代行授权时——冻结上述四类，其余照常运行；冻结状态登记并触发复审，不得无限期。
- **最高宰相缺位（G9 缺位，(d) 裁决的上位情形）**：内部无自动继任。由外部老板按 `root_delegation` 处置（暂停/重授/指定临时承载），处置期内四类硬核动作冻结；缺位登记为组织事件。
- **一级单元缺位**：不向上冻结——登记「单元缺位」，最高宰相直管该单元（双角色记录＋外部审计抽样），缺位期该单元不得新增 G8（§2.2 注）。
- **目标（未证）**：继承/代行程序——外部老板书面可验证授权的代行人（**不得是最高宰相**，因为它就是内部老板；也不得是本次被处置对象）、失能判定由外部锚承担、代行权限限额。建成前不得宣称「公司可脱离老板运行」。

### 4.2 公司层：内部老板自审（明示）+ 外部独立审计（目标未证）

公司级审计在最高宰相——**它就是内部老板**，因此公司级审计=**内部老板自审**：可以接受，但必须明写——审计结论须标注「**内部老板自审**」字样，**不得自称独立**，也不得写成「所有者自审」而隐去内部老板身份（外部老板是公司树之外的根，不承担内部日常审计）。**唯一独立审计来自外部**：外部老板本人或外部锚（董事会/定期外部审计/宪法程序等至少一个非公司内部的独立主体）——制度化的外部独立审计＝**目标（未证）**，建成前列为缺口登记，不冒称已有。「公司脱离人运行」的目标态需要该外部锚，且**不得由最高宰相自称**。

### 4.3 部门层：上一层审计，且审计者≠本次评价者（治 84b-R4／B2 分离规则）

1. 常态：部门首长（G8）/D8 部门由所属**一级单元首长**审计；单元首长由**最高宰相**审计；公司级=最高宰相自审（标注，§4.2）。逐级下推。
2. **分离规则（B2 的收紧口径）**：审计者不得同时担任被审计对象**本次**绩效评价/提议者；冲突时本次审计上提一层（部门→最高宰相；单元→外部老板/外部锚或跨单元首长互审）。**审计回避只限「本次评价/直接利益」，不因「任命提议者」身份无限上提**——否则部门审计会被抽空。跨单元互审须声明审计者对本次评价无直接利益，且不得审计本单元。
3. 审计权可随层级下发，但**不得下发给被审计者本人**；公司级审计不下发给部门或一级单元。审计与评价可能同体的问题是结构性的，分离规则即其强制出口；分层审计解决部门层与单元层自审，顶层自审按 §4.2 诚实标注。

### 4.4 发现处置权与冻结

审计者产出发现与建议；**处置决定权在被审计对象的任免者（+2）或该权力归属者**（表 A′）。审计者仅持有限紧急冻结权：防止损害扩大的最小冻结、必须有依据与期限、到期强制复审、不得永久叫停；冻结不构成对被审计事项的终局认定。审计记录、被审计者申诉（至审计者的 +1，申诉不加重）与救济的记录形状归 v2/11。

## 六、部门等级 D 族与部门硬核

### 6.1 D 族定义（治 85c-Q10 重号）

**部门等级 Dn 的唯一判据=部门负责人的个人职级 Gn**（n=3..8）。D 族不另立数字体系、不与 CL/G 并行计数；D9 不启用（G9＝最高宰相即公司层，不设「九级部门」；**一级单元是 G8 结构、不是 D9**；跨公司联合另立联合对象，§七.3）。D1=未达部门判据的协作组（无 G3+ 负责人）；D2=班组（G2 及以下带班作业单元）——两者不享有部门硬核，不入表 C 审计矩阵的部门行。

### 6.3 部门硬核不可自改（治 84b-R8）

部门硬核（部门章程、预算与资源上限、部门验收口径、部门审计）由**部长上一层**批准与保管（D8＝一级单元首长；单元缺位/不单设＝最高宰相）；其合法性源自公司硬核的授权链（外部老板设立行为＋`root_delegation`→最高宰相→逐层批准）。**部长与部门自身只能改部门软外围**；部门自改硬核=无效，判负。部门不得自立宪法、不得以部门规则对抗公司宪法（宪法分层总表归 v2/01，此处只落部门级分配）。

## 七、组织变更：合并、分立、联合与生命周期

### 7.1 合并与分立

决定权：涉及 D8 部门的设立/合并/分立/撤销=**最高宰相**（外部老板保留公司身份与清算）；D7-D3 级=部长上一层批准；**跨部门/跨单元=共同上级，无共同上级=最高宰相终裁**；单元间冲突不得各自对外承诺。责任连续（v1·66 §12.4 可用部分保留重映射）：在途事项、承诺、资源、记录、记忆、外部关系、未结救济七项清单+接收者明确接受+历史不改写；没有清单与接收确认的合并/分立不得宣称完成。

### 7.2 组织生命周期（治 V5-P1-1）

v1 七值生命周期在新模型的表达=**身份四态（值集唯一主表 v2/09 ENU-02，本节不复列机器值）＋组织事件记录（形状归 v2/11）**的复合视图，映射如下：

| v1 生命周期值 | v2 表达 |
|---|---|
| 设立 | 外部老板设立记录＋`root_delegation`（§3.1 步 1/2；身份态 ∅→active 的首条事件，具名作出者=外部老板） |
| 运行 | active 常态 |
| 调整 | 普通组织变更事件（升降级/岗位增减），非独立状态 |
| 合并或分立 | Continuity 决定记录（§7.1），非独立状态 |
| 撤销、清算 | 外部老板专属决定（最高宰相执行）＋清算承接确认；**外部接收者独立、残余责任主体＝外部老板**（两角分设，(c) 裁决；本体 v2/01 I-16）；残余责任承接预设于设立记录 |
| 已承接 | 接收者确认记录（终态事件） |

### 7.3 联合（跨公司）

v1·66 §13.3 可用部分保留重映射：联合交付必须在**承诺前**约定对外最终责任（一方/按份/共同）、验收、争议、终止与剩余承诺承接；未约定不得作出无法界定责任的联合承诺，只能作可分割的具体承诺。新模型补充：**公司对外作出联合承诺的权力=外部老板保留**（内部以最高宰相按 `root_delegation` 范围行使，或再按资源权规则显式转授并带范围期限，表 A′ 行 7）；承担对外最终责任者必须拥有相称的实质控制（信息/监督/救济/止损）；各方内部审计闭环不替代联合交付的外部交代；D9 不用于联合体（§6.1）。
