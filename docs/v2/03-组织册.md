## 一、角色与责任内核（固定的是什么）

「内核固定」指**责任内核固定，不是岗位表固定**（84b 共同前提 6）。固定者六条：①老板最终责任；②宰相投影；③任命/授权/审计/宪法四类记录必须存在且可溯源；④不得自授；⑤不得同层自审；⑥授权链唯一且不断（保留=老板持有，链不断）。岗位表随 CL 层级展开（§二）。

**表 1 · 角色**（84b §3.1 全量收录）

| 角色 | 是什么 | 不是什么 |
|---|---|---|
| 老板（所有者） | 根权力持有者；最终责任；公司级审计/制宪/G8 任免 | 不是 agent；不在 G1-G9 agent 树内；不可被任何岗位置换 |
| 宰相（G9） | 老板在框架中的投影；公司对老板的唯一接口（低层）；G8 任免的提议者 | 不是权力来源；不得自授/自任/自扩；不得代老板任免 G8 |
| 部门负责人（G8） | D8 部门部长；对部门业务/资源/人事提议负责 | 不能任免 G8；不得自审本部门；不得自改部门硬核 |
| 中间层（G7-G3） | +1 评价提议、+2 任免链的一环 | 不得越级自授；不得拒绝上级合法审计 |

**单人退化（诚实标注）**：CL2 公司即「公司形状的 agent harness」——宰相直接执行或唤起子 agent，价值在权责记录而非调用树；**不得宣称具备完整公司的独立审计与最终责任**（84b 共同前提 2，85c-Q8）。对外自治声称按 v2/01 声明纪律另行验证，本卷不授予。

## 二、公司层级 CL2-CL9：必设矩阵与保留权力表

### 2.1 层级语义

1. **CL 只定最低必设下限**。是否设岗、何时下发仍由老板决定；设岗超出该层下限合法（提前下发），低于下限即不满足该层（§2.4）。一旦设岗，该岗位的权责与记录即为强制，不得再称「可选资产」。
2. **层级越低允许缺席越多；越高则部门、审计、人事逐步必设**。未设岗的权力不悬空、不消失，显式归老板并由宰相承载（表 A′）。
3. **老板不是 CL 的一层**：CL2-CL9 描述的是 agent 组织的展开程度，老板恒在组织之外为其根（§三.1）。

### 2.4 层级判定与升降级

1. **CL 判据是结构事实，不是声明**：公司层级=当前在编结构所满足的最高层判据；「只改一个 level 字段」无效，记录与结构不符时以结构为准并纠偏留痕。
2. 判据（可判定，逐层累进）——CL2：有效设立记录+宰相在编或登记空编；CL3：≥1 名 G2-G1 正式任职；CL4：≥1 个 D8 部门与 G8 部长在编；CL5：D8 内 G7 层在编；CL6：≥2 个 D8 部门且 G6 层在编；CL7：≥1 个 D7 子部门且专职部门审计位置在编；CL8：G5-G3 层在编且部门嵌套深度≥3；CL9：G2-G8 全链在编、≥3 个 D8 部门、审计全周期化。
3. **降级**：判据失效（如唯一 G8 离任、专职审计位置空缺逾一个复审周期）→ 有期限复审：补设或降级；二选一必答，不得静默挂空。**升级**：结构判据达成即应升层登记；老板可主动提前设岗（提前下发），但不虚记层级。
4. 升降级记录、必设岗空编记录均为组织事件，入台账；记录形状归 v2/11，负向用例（「虚记层级」「空编静默」）归 v2/17。

## 三、权力树：老板为根，三种权力三种下发规则

### 3.1 根与冷启动首任顺序（治 DSF P0-4）

**根权力在老板/设立行为，不在宰相**。宰相是老板在框架中的投影：解释权力来源，不给任何记录豁免（任职/绩效/问责与全体成员同构同载体——85c-Q2，载体归 v2/02）。

冷启动首任顺序（每步的记录 ID 是下一步的前置；**无上一步记录 ID 的下一步无效，判负**）：
1. **设立记录**：老板签署公司设立记录（含使命与边界、初始 CL、表 A′ 保留权力初表、首任宰相任命或空编安排）。一切根授予的 basis 必须解析到本记录；不可解析者无效。
2. **首任宰相**：老板任命 G9。此为唯一无 agent +1 的任免（老板本人评价+任免；grantor≠grantee 因老板是人、宰相是 agent，恒成立）。
3. **首任 G8**（若设部门）：宰相提议 → 老板任免。
4. **G7 及以下**：按表 B 逐级。

**不自授（恒规则）**：grantor≠grantee、任命者≠被任命者；宰相不得给自己发根授予、不得自任、不得自扩权限；违者记录无效并触发问责。老板层豁免 v1 的工作层「提案/批准禁配」（根级特权，84b 抉择 3），**该豁免仅老板享有，宰相不得援引**。

### 3.2 三种权力，三种下发规则（84b §3.2 全量收录）

| 权力 | 例子 | 下发规则 | 记录（形状归 v2/11） |
|---|---|---|---|
| 资源/访问权 | 部门目录访问权、预算额度 | 可逐级转授，但不得超出父授权的目的/范围/条件/期限；每层留转授边与衰减 | 转授边记录：范围+期限+父引用 |
| 人事选拔/任免权 | G7 提议、G8 任免 | +1 评价提议、+2 任免；G8/G9 恒老板；**+2 生效前提=存在 +1 提议记录**（§3.3） | 提议记录+任免记录+评价记录+申诉 |
| 审计/制宪权 | 公司级审计、修宪、部门审计 | 公司级不下发；部门级在部长上一层；**不得下发给被审计者本人** | 审计记录+宪法版本+批准记录 |

规则（85c-Q3 写死）：
1. **+2 生效前提**：任免记录必须引用对应 +1 提议记录的 ID；无 +1 提议的 +2 任免=程序非法，判负。评价权不得被绕空。
2. **负面评价的效力=记录性质**：不直接否决，供 +2 任免参考；+2 在负面评价下仍任免的，必须记录理由。提议权与任免权分离，不合并。
3. **跳级任免**：任免者与被任免者职级差 >2 为跳级。除老板外任何主体不得跳级任免；老板跳级任免必须补全被跳过各层 +1 的评价、任免决定理由、候选人申诉通道告知三条记录，否则视为绕过中间层，无效。
4. **指令异议权**（G_n 对 G_{n+1} 的不合理指令）：拒绝 grounds 限于五项——违法、越权、利益冲突、事实不可能、不安全；拒绝时升级至发出指令者的 +1 裁决并留记录；形成「压力—拒绝—裁决」的相互发现循环，不得以沉默服从替代。
5. **申诉**：向任免者的 +1 提出；跨级申诉至老板终局；申诉不因提出而加重后果（载体归 v2/02）。

### 3.4 最高日常决定与最终责任的冲突终局（治 V5-P1-2）

最高日常决定=宰相；最终责任=老板。二者冲突的终局**结构内置**：老板终局，不再依赖可选声明字段。宰相不服从时的止损路径=老板撤回投影（免任/限权）；撤回须结清在途（§七），不得只发通知。多主优先（多使命/多委托/指令冲突）：同级未决时暂缓相冲突的新承诺，提交老板裁决；无法形成合法决定时拒绝或依法解除是合法终态（v1·R1 路径保留重映射）；执行者不得私选。

### 3.5 老板缺席与继承（84b-R2）

- **当前态（明示）**：G8/G9 任免、修宪、公司级审计结论、公司级对外承诺四类硬核动作依赖老板在场——已知人工依赖，如实标注，不写成机制。
- **过渡规则「内核冻结·运行延续」**：老板不可达且无有效代行授权时——冻结上述四类硬核动作；既有授权链内的运行、部门审计、G7-G1 任免照常；冻结状态登记并触发复审。冻结不是停摆，也不是永久例外。
- **目标（未证）**：继承/代行程序——老板书面可验证授权的代行人（不得是宰相）、失能判定由外部锚承担、代行权限限额。建成前不得宣称「公司可脱离老板运行」。

### 4.2 公司层：所有者自审（明示）+ 外部锚（目标未证）

公司级审计在老板；未下发时由宰相作为投影**承载执行**，最终责任与结论署名仍在老板。若老板=所有者，公司级审计即**所有者自审**——可以接受，但必须明写：审计结论须标注「所有者自审」字样，**不得自称独立**。「公司脱离人运行」的目标态需要至少一个非宰相的外部锚（董事会/定期外部审计/宪法程序）——**目标（未证）**，建成前列为缺口登记，不冒称已有。

### 4.3 部门层：上一层审计，且审计者≠本次评价者（治 84b-R4）

1. 常态：被审计部门负责人的 +1 审计该部门（八级部门由九级宰相审计，逐级下推）。
2. **分离规则**：审计者不得同时担任被审计对象任免的**本次**评价/提议者。同一周期内 +1 已任评价者时，本次审计上提一层执行；连带上提至顶层仍同体的，由老板执行。审计记录须登记审计者与本次评价者的分离事实。
3. 审计权可随层级下发，但**不得下发给被审计者本人**；公司级审计不下发给部门。审计与评价可能同体的问题是结构性的，分离规则即其强制出口；分层审计解决部门层自审，顶层自审按 §4.2 诚实标注。

### 4.4 发现处置权与冻结

审计者产出发现与建议；**处置决定权在被审计对象的任免者（+2）或该权力归属者**（表 A′）。审计者仅持有限紧急冻结权：防止损害扩大的最小冻结、必须有依据与期限、到期强制复审、不得永久叫停；冻结不构成对被审计事项的终局认定。审计记录、被审计者申诉（至审计者的 +1，申诉不加重）与救济的记录形状归 v2/11。

## 六、部门等级 D 族与部门硬核

### 6.1 D 族定义（治 85c-Q10 重号）

**部门等级 Dn 的唯一判据=部门负责人的个人职级 Gn**（n=3..8）。D 族不另立数字体系、不与 CL/G 并行计数；D9 不启用（G9=宰相即公司层，不设「九级部门」；跨公司联合另立联合对象，§七.3）。D1=未达部门判据的协作组（无 G3+ 负责人）；D2=班组（G2 及以下带班作业单元）——两者不享有部门硬核，不入表 C 审计矩阵的部门行。

### 6.3 部门硬核不可自改（治 84b-R8）

部门硬核（部门章程、预算与资源上限、部门验收口径、部门审计）由**部长上一层**批准与保管；其合法性源自公司硬核的授权链（老板设立行为→逐层批准）。**部长与部门自身只能改部门软外围**；部门自改硬核=无效，判负。部门不得自立宪法、不得以部门规则对抗公司宪法（宪法分层总表归 v2/01，此处只落部门级分配）。

## 七、组织变更：合并、分立、联合与生命周期

### 7.1 合并与分立

决定权：涉及 D8 部门的设立/合并/分立/撤销=**老板**（与 G8 任免同权级，宰相提议）；D7-D3 级=部长上一层批准；跨部门=共同上级，无共同上级=宰相提议→老板决定。责任连续（v1·66 §12.4 可用部分保留重映射）：在途事项、承诺、资源、记录、记忆、外部关系、未结救济七项清单+接收者明确接受+历史不改写；没有清单与接收确认的合并/分立不得宣称完成。

### 7.2 组织生命周期（治 V5-P1-1）

v1 七值生命周期在新模型的表达=**身份四态（active/suspended/liquidated/dissolved，主表归 v2/09）+ 组织事件记录（形状归 v2/11）**的复合视图，映射如下：

| v1 生命周期值 | v2 表达 |
|---|---|
| 设立 | 老板设立记录（§3.1 步 1；身份态 ∅→active 的首条事件，具名作出者=老板） |
| 运行 | active 常态 |
| 调整 | 普通组织变更事件（升降级/岗位增减），非独立状态 |
| 合并或分立 | Continuity 决定记录（§7.1），非独立状态 |
| 撤销、清算 | 老板专属决定+清算承接确认；残余责任承接预设于设立记录 |
| 已承接 | 接收者确认记录（终态事件） |

### 7.3 联合（跨公司）

v1·66 §13.3 可用部分保留重映射：联合交付必须在**承诺前**约定对外最终责任（一方/按份/共同）、验收、争议、终止与剩余承诺承接；未约定不得作出无法界定责任的联合承诺，只能作可分割的具体承诺。新模型补充：**公司对外作出联合承诺的权力=老板保留**（或按资源权规则显式转授并带范围期限，表 A′ 行 7）；承担对外最终责任者必须拥有相称的实质控制（信息/监督/救济/止损）；各方内部审计闭环不替代联合交付的外部交代；D9 不用于联合体（§6.1）。
