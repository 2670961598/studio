### 0.2 四问分立（沿 v1 78a-§1.4/78-§0.3，全部绑定结论适用）

| 问题 | 回答什么 | 谁能作证 | 典型偷换 |
|---|---|---|---|
| 正当性 | 谁有权决定 | 公司宪制与具名决定（v2/03/04 记录） | 「宿主允许」当「公司授权」 |
| 技术许可 | 这个宿主/平台技术上允许做什么 | 版本化文档+真机探针 | 「文档写了」当「本形态下可用」 |
| 能力 | 本部署本形态下实际能做什么 | PRB 探针+负向结果 | 「装了插件」当「策略生效」 |
| 证据 | 做过什么、被拒过什么、可否复核 | 事件导出+独立复核（采集者独立，CAP-02） | 「日志很长」当「证据充分」 |

一句结论跨两问＝缺陷。**绑定不是授权**；任何 BIND- 卡/投影/沙箱模式的「允许」只答技术许可，授权只有 v2/03 四态。

### 0.3 硬边界 / 软限制 / 不可表达（三分，78a 二分的前进）

| 类 | 定义 | 例 | 处置 |
|---|---|---|---|
| 硬边界 | 运行时拒绝且拒绝可观测 | 工具隐藏、guard deny、写域拒绝、审批超时 fail-closed | 可作「机制在内」承载，仍需外部验收 |
| 软限制 | 只降低误用概率，不阻止 | persona、AGENTS.md、plan mode、任务板 | **不得**写进「已满足某授权条件」的证据 |
| 不可表达 | 宿主词汇里没有该维度 | 网络、进程、秘密、组织、验收、跨进程互斥 | 必须外置；「配置里写了」不冒充 |

判据：把模型换成恶意模型，这条控制还在吗——在＝硬；不在＝软；连位置都没有＝不可表达。

### 0.5 六条全局口径

1. 绑定不是授权（四态归 v2/03）。
2. 部署只能收紧；任何「为了方便先放开」的绑定默认值判缺陷。
3. 探针通过只升级到「该形态下观察到一次行为」，不升级为能力证明；跨版本/岗位/工作重验。
4. 配置回显（`--dump-config` 类）不是运行行为证据。
5. 平台「已关闭/完成」永不映射为已接受或已结清（§2.3）。
6. cwd 不是隔离（v2/07 §五）；只影响相对路径解析。
7. **每级 H 闭合判据在本卷 §五必须有登记探针行——无登记行即不得宣称该级可闭合**（v2/07 §六立规，本卷落地）。

### 1.3 profile 结构与插件挂载法（现状事实，键名级）

- profile 目录（`~/.dsh/profiles/<name>/`）＝**bundle 层**（`cordis.yml`）+ **patch 层**（`cordis.patch.yml`）+ pnpm 插件树（`node_modules`/`package.json`/`pnpm-lock.yaml`）。profile 是部署绑定工件，不是公司定义。
- patch 层形状：顶层 YAML 数组，每条目 `{id, config}`——id 定向的配置覆盖/禁用/插入。已用键面（只举结构，不举值）：`providers.<p>.{displayName, apiKeyEnv, api, models[]}`（models 元素含 `id/name/contextWindow/maxTokens/input`）与 `agent-default-model.{provider, model}`。
- **秘密只以 `apiKeyEnv`（环境变量名）出现在 profile**；值经 env 通道供给，不落 profile 文件（与 §3.4 短命按单凭据通道同一纪律）。
- 挂载法：executor 命令（`agent.yaml` 的 cmd）显式 `--patch <overlay>`；**daemon 不代改 executor 命令**；overlay 由框架生成于 `<rootDir>/tmp/`——**该落点是否在 worker 可写范围未证（PRB-22，治 V8-P1-4）**。
- 换默认模型/模型档＝改 patch 层配置：不升绑定档案版本，但构成执行配置变化→新出工段（v2/02 §六）；模型档与任职资格不互推。

### 2.3 状态映射规则（治 L3G-09）

- **允许**：平台状态→工作十态（v2/04 §五，带损失声明）；平台字段→公司定义字段（带转换与丢失）。
- **禁止**：平台状态→判断结果态（验收）；→能力态（不同轴）；「已关闭」→已接受/已结清；平台「待验收」≠已提交验收。
- **未映射返回契约**：未映射但非空合法⇒Ok（`verification:'unverified'`、工作态集为空、原值逐字保留、只观察）；**消费方**不得据空集推进/判验收/判结清，报缺映射即停；仅空串/畸形⇒Err（配置缺陷）。观察缺口记录由消费方写（v2/11），不是写回执不明（那是未知回执面，PRB-13）。
- **逐平台值映射表是部署工件**：状态板值域随实例配置（YouTrack 状态板可自定义、Taiga 项目级配置、LocalFile states 数组），规范卷不冻结平台字面值；每部署按本节规则生成「平台态→十态」表并逐行标 verified/unverified，**不确定即 unverified 不得猜**（探针 PRB-23 落证）。此为 v1 骨架缺表的 V2 处置：规则与格式在本卷，值表在部署工件。

### 2.4 平台迁移（换平台＝权威激活，不是配置变更）

- **根密钥分级（2026-10-28 修订；机制主表 v2/15 §七 SEC-ROOT-01..05——09 §一-65 已预登记本族，条目语义以 15 卷为准）**：**operating root key 只由最高宰相（G9，唯一，内部老板）持有**，用于以老板身份签发内部硬动作；其权源是外部老板的 `root_delegation`（范围/期限/可撤回/密钥指纹/外部签名或离线批准件），**外部撤权/轮换是对最高宰相的终极硬控制**。**子 agent 与执行体只持 scoped key**（`REC-AUTH-04` 的 credential_class＝root/scoped，值集归 v2/09 **ENU-136**、字段形状 v2/11）；root key 不入库、不进提示词/日志/快照/派发简报，也不经 env 通道下发给 worker。**持 root key 的子 agent 与「root 撤回后旧签名」均为负向用例**（v2/15/v2/17）。本卷只落宿主面约束：任何绑定卡/工作区/注入面都不得成为 root key 的可读路径。
- **签根信任域缺口（blocking，如实登记）**：当前网关签根与被闸方同部署可读面（部署配置值形态）——按 §3.3 读域模型**无法宣称 worker 读不到部署配置**；读到即可自签 wkey 越单冒充。因此「EX-2+ 外部闸门」的现状＝**目标（未证）**，不得写「部分已有（网关）」当作已成立的外部边界；处置（值位移出可读面、配置只留逻辑引用、独立用户/容器/broker 短时供给）属 v2/15/v2/16 施工件，本卷登记损失 BIND-LOSS-08。

## 四、会话续跑的宿主级约束

### 4.1 能力声明与 DSH 现状

- `session_resume` 是执行体能力声明的一个维度（声明不超证据，拟稿按不支持——v2/07 §五）。
- **DSH＝已有**：`capabilities.session_resume=true`（2026-10-23 真单证翻转：`--session-id` 透传，原工位原 cwd 跨进程复验 turn:N+1 缓存命中）；`resumeWithSession(task, executorSessionId)` 已接线；dsh 侧会话 id 由流首 session 事件捕获收存于 Handle（v2/14 端口字段）。
- **续跑前提三件**：同执行器＋同会话句柄＋**cwd 逐字节一致**（cwd 是调度纪律，随单落档）；换宿主/换路径即不能续跑→段边界。

### 4.2 跨进程续跑（现状事实：daemon 合并跑）

合并跑按断点解析**原工位原会话**唤起（`resumeWithSession`）自合并（`merge-run.ts` 头注）：断点可解析条件＝末位工时单 `executor_session_id` 在场＋summary sidecar 可读＋executor 在册且 `session_resume=true`＋工位 repo HEAD 可解析；收割四要件同一条链（终态 completed+非空输出+REPORT 落盘+闸门 exit0）；合并跑在途零平台写、wkey 恒不签发；断点不可解析或四要件不齐＝如实降级手工链，不冒充。宿主级含义：**跨进程续跑已真机走通**（断点解析→原工位原会话唤起→同链收割）。

### 4.3 纪律与四家对照

- **续跑同一会话≠恢复同一出工段**：中断/恢复是段边界，恢复是新的决定（决定型，v2/04 §五）；静默恢复＝W-06 违规（v2/07 EXEC-04）。
- 不支持续跑的家**明报降级新派**，不得静默新开会话冒充续跑。
- 会话证据归档收割入台账＝**目标（未证）**（会话表无生产写者，v2/07 §五/§八）。

| 家 | 续跑形态 | 证据强度 |

| DSH | `--session-id` 透传 | 真机实证（跨进程、cwd 逐字节一致纪律） |
| Claude | `--resume` | 较硬（未按我们的形态复验） |
| Codex | `codex exec --resume`（两形待探） | 拟稿（PRB-25） |
| Kimi | `-S <id>` | 拟稿（PRB-26） |
