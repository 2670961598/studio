## 一、公共标量与标识（SCH-SYN）

本章只定义「一个值合法长什么样」，供 §四 schema 与 §二规范化引用；任何对象字段不得就地发明新标量。

### 1.1 标量族表（SCH-SYN-01）

| 族 | 语法与规范形式 | 边界 | 明确禁止 |
|---|---|---|---|
| `text` | 自由文本，允许换行/制表符，其余控制字符禁止 | 长度上限由字段声明（缺省 65 536 码点，以码点计不以字节计） | 作判定依据；作标识 |
| `token` | 小写 ASCII `[a-z][a-z0-9-]{0,63}`，无前后空格 | 固定 | 由自由文本自动生成；大写 |
| `dotid` | 一至四段，段间 `.`，每段为 `token` | 固定 | 裸 `/` 分隔（那是 qid 形态，登记 v2/09）；段超长 |
| `integer` | 可选负号＋十进制数字，无前导零、无小数点 | −9007199254740991…9007199254740991（±(2^53−1)），越界拒收 | 回绕；以整数冒充金额/时刻 |
| `decimal` | **字符串形态**承载：可选负号＋无前导零整数部＋可选 `.` 小数部，无指数 | 有效数字 ≤34，标度 ≤9，标度由字段声明，不做隐式舍入 | 以 JSON 数值承载；二进制浮点；跨标度直接比较 |
| `boolean` | 仅 `true`/`false` | 固定 | `0`/`1`/`"true"` 隐式转换 |
| `timestamp` | 日期时间，必须带偏移（`Z` 或 `±hh:mm`），秒必填，小数秒 ≤9 位 | 闰秒 `:60` 拒收；无偏移本地时间拒收 | 用日期冒充时刻；用「当前时间」填缺省 |
| `duration` | ISO-8601 时长子集 `P[nD][T[nH][nM][nS]]`，非负 | 不含年/月（除非字段声明日历参照） | 用「一个月」做可判定时限而不声明日历 |
| `semver` | 语义版本三段 `MAJOR.MINOR.PATCH`，可带预发布与构建元数据 | 预发布必须可表达；构建元数据不参与优先级、参与内容标识 | 引用「最新/稳定版」 |
| `enumRef` | `{vocab, vocabVersion, code}` 三元组 | 三者必填；词表必须可按版本解析（§5.5）；值集解析后合法性以 v2/09 登记集为准 | 裸字符串当枚举 |
| `list<T>` | 有序数组，元素为某族 | 元素数上限由字段声明；缺省不允许重复 | 用列表承载「是否」 |
| `record<Name>` | 封闭字段集，逐成员列出类型/必填 | 未声明字段即拒收（扩展位除外） | 开放任意键的字典 |
| `null`/缺失 | `null` 仅 `nullable=true` 字段；「成员不存在」不是可序列化值 | — | 用 `null` 冒充「未提供」，反之亦然 |

**组合语义（治 DSF L3B-02）**：本卷 schema **一律扁平字段表＋就地内联展开**——复合字段以 `record<Name>` 在本卷内逐成员列出，不设跨对象复用的字段组、不设「组名.成员」引用路径；字段路径即成员路径，统一以 JSON Pointer（RFC 6901）书写（诊断定位同此，治 L3B-16 的路径无语法项）。`extensions` 字段全卷只在 SCH-EXT-01 定义一次，凡引用处类型均为 `list<SCH-EXT-01>`。

**归一比较**：默认按码位逐字比较；仅字段声明 `normalizedComparison=true` 时按 NFC 归一后比较；归一钉 **Unicode 15.1.0**（登记 v2/09；变更走 core 轴 minor 版本——治 H3a-P2-4）。未声明而归一＝缺陷。

### 1.2 保留段（SCH-SYN-02）

`studio-next` 为**规范保留段**：专用于 V2 规范自建公共工件的身份（canonical 规则、公共词表、冻结 schema 工件），不经公共 namespace 登记者分配、不回收、不复用；交换工件把该段用于其他用途即拒收。示例：`studio-next.jcs`——段 1 `studio-next`（token ✓）＋段 2 `jcs`（token ✓）＝合法 dotid **按 §1.1 合法 ✓**。

对象 namespace（qid 的命名空间）与此不同：由公共登记者分配，现状未建成（§5.4，目标未证）。本卷因此**不给出任何对象 namespace 示例取值**（治 V7-P1-3「全卷无示例取值」的现状如实化）。

### 1.3 版本约束（SCH-SYN-03）

封闭结构：`{lock?: semver, lower?/upper?: {version, inclusive}, prerelease?: 策略（缺省 none）, note?: text}`。规则：`lock` 存在时必须同时满足区间与预发布策略；约束可解析出多个候选版本合法（集合可判定），但**进入引用/激活时必须落到唯一精确版本**（选择权属有权位置，候选唯一性不等于选择权）；通配/脱字符/波浪号是包管理器语法，只能在绑定边界映射，不入公共规范；每个引用钉版本，不得引「当前最新」。

### 1.4 缺失、空值、假、零与未知（SCH-SYN-04）

五形态互不相同：缺失（成员不存在，可触发缺省；必填缺失即拒收）、空值（`null`，仅 `nullable=true`，是明确声明）、假（`false`，仅 boolean）、零（`0`，是事实值）、未知（**不是可序列化值**，来自记录侧观察状态或求值结果；不得显示为零/空/绿/「未发生」）。硬规则：不做隐式真值转换；缺省只在字段声明处生效；`null` ≠ 未知；零 ≠ 无数据；未知必须可传播、不得被下游折算为通过。记录侧未知语义主表在 v2/11。

### 1.5 精确十进制运算（SCH-SYN-05）

金额/比率/阈值比较统一算术语义：有理数表示，`add/sub/mul/div` 精确计算并约分；输出 ≤34 位有效数字、≤9 位标度，默认 `half-even`，保守方向可由字段指定 `floor`/`ceiling`（舍入与比较结构块值集唯一主表 v2/09 ENU-105）；中间精度上限 128 位十进制有效数字；单位不隐式换算；每次计算留输入、规则版本、舍入方式、输出与失败原因。

**失败判据（治 DSF L3B-11）**：「无法按声明精度表示」＝**超 34 位有效数字、或超 128 位中间精度、或无可用舍入规则**，此时显式失败（`unsupported`）。**非终止小数按声明标度舍入＝成功**：`1/3` 在 `scale=9` 得 `0.333333333` 是舍入成功样例，不是失败。最小共同向量：`0.1+0.2=0.3`；`1.20` 与 `1.2` 数值相等但其 `semanticDigest` 不要求相同（词法不同，§2.5）；`-1.5` 在 `scale=0, half-even` 得 `-2`；除零与超精度失败，不得给近似值。以上为公布判据，无实现运行记录（**目标未证**）。

## 二、canonical 序列化规则（ENC）

### 2.1 身份与版本（ENC-01）

规范化规则的稳定身份为两个字段：`canonicalizationId`（类型 **dotid**，§1.1）＋`canonicalizationVersion`（类型 integer）。本规范版本的取值：`canonicalizationId = studio-next.jcs`、`canonicalizationVersion = 1`——**按 §1.1/§1.2 合法 ✓**（段一为规范保留段、两段均为 token；类型与值一致，治 H3a-P0-3）。行文简写 `studio-next.jcs@1` 仅为叙述便利，**线上形态恒为两字段**；出现单字段斜杠形态（如 v1 的 `studio-next/jcs`）即旧稿残留，按未知规范化身份拒收（E-ENC-001）。

该身份归属 §5.1 版本轴的 `record-format` 轴，是轴下**子版本**，不新增轴。规则任何实质变动（键序、转义、数值表示、输入前置）必须发新版本号（`studio-next.jcs@2` 起）并重发公布向量与期望摘要；**不得原地改版**；旧摘要不得跨版本比较。

### 2.2 输入前置（ENC-02）

以下任一不满足即拒收（E-ENC-002）：顶层是对象或数组；同一对象内成员名不得重复（解析阶段即拒，不得「后者覆盖前者」再规范化）；字符串是合法 Unicode 标量序列（拒 lone surrogate 与非法转义）；数值不得出现 `NaN`/`Infinity`；编码为 UTF-8 无 BOM（有 BOM 拒收）；无注释与尾随分隔符（JSON 语法层）。

### 2.3 序列化规则（ENC-03）

以 RFC 8785（JCS）为基线，**采用范围如下**（其余条款不采用或按 §2.4 域化）：

- **键序**：对每个对象的成员，按未转义字符串的 **UTF-16 code units 字典序**递归排序（RFC 8785 §3.2.3 口径；不是码位序、不是字节序），递归应用于所有嵌套对象。
- **数组**：保序，不排序、不去重、不合并。
- **空白**：不输出任何多余空白、缩进与换行；成员间 `,`，键值以 `:` 分隔且 `:` 后无空格；无 BOM。
- **字符串**：按 RFC 8785 §3.2.2.2 逐码点最小转义，只有三种写法：①U+0008/0009/000A/000C/000D 必须写两字符短转义 `\b`/`\t`/`\n`/`\f`/`\r`；②其余 U+0000–001F 控制字符必须写 `\u00xx`，**xx 为小写**十六进制；③`"`→`\"`、`\`→`\\`。其余字符（含 U+007F 及以上）一律按 UTF-8 原样输出，不转 `\uXXXX`。不做 Unicode 归一（NFC/NFD 均不做）、不做大小写折叠、不做空白折叠、不截断。
- **`null` 与成员不存在不同**：前者输出 `null`，后者该成员不出现，不得折叠。
- **不注入**时间戳、路径、主机名、环境值或任何采集时刻。

### 2.4 数值域规则（ENC-04）

**本域 JSON 数值只允许安全整数**（±(2^53−1) 内十进制整数字面量，无指数、无小数点）——该上限是 I-JSON/RFC 7493 的跨实现互操作约束，不是语言偏好。超出安全范围的整数、一切 `decimal` 一律以**字符串承载**（§1.1 decimal 族），不得先转 IEEE-754 双精度再序列化。整数规范形式＝最短十进制（无 `.0`、无指数、无正号）。`decimal` 字符串不补零、不去尾零、不改标度；`timestamp`/`duration` 等字符串在规范化阶段**只当字符串**，不解析、不改时区、不重排。

### 2.5 同一性口径（ENC-05）

`semanticDigest` 证明的只有一件事：**在同一 `canonicalizationVersion` 下两输入的规范字节一致**。词法与结构同一，**不是**数值同一、瞬时同一或语义正确：`"1.20"` 与 `"1.2"` 数值等价但摘要不同（刻意行为，VEC-03/04）；不同偏移的同一瞬间摘要不同。数值/瞬时等价判定走类型层比较语义（§1.1 decimal 按数值、timestamp 按瞬时、归一见 §1.1），两套比较并存各管一段，不得互相顶替；同一处既要求「数值等价」又要求「摘要一致」而不说明归一义务，即缺陷。

**三种材料不得混用**：

| 材料 | 计算对象 | 证明什么 | 绝不能证明 |
|---|---|---|---|
| `byteDigest` | 收发确切字节 | 两次传输字节一致 | 语义相同；真实/安全/合法/已授权 |
| `semanticDigest` | 规范形式 UTF-8 字节 | 同一规范化版本下规范字节一致 | 数值/瞬时等价；语义正确；无碰撞；作者身份 |
| 签名 | 某摘要（必须写明何种） | 某主体某时刻对该摘要作过声明 | 主体有权；内容真实；已验收；许可清晰；撤销已执行 |

### 2.6 确定性与版本状态（ENC-06）

同一已解析并通过类型校验的输入，在同一 `canonicalizationVersion` 下必须得到相同规范字节；摘要不一致表示输入不同或规则版本不同（含实现偏离），不得解释为「语义不同」；摘要一致只支持「规范字节一致」一个结论。**不得声称**：摘要一致即语义等价、数值等价即摘要相同。

版本状态三值（必须随版本声明；值集唯一主表 v2/09 ENU-92）：`defined`（规则写定，无可执行向量）／`vectors-published`（期望值已算出并公布，实现未运行）／`supported`（至少一个实现实际运行并通过 §2.7 验证门全集，结果可复算）。不得跳级声明。**当前状态：`studio-next.jcs@1` = `vectors-published`**——无任何实现运行记录（**目标未证**）。

### 2.7 验证门（ENC-07；治 H3a-P0-4）

v1·76 §1.5.1「必须通过 RFC 8785 §3.2.2.3 数值样例与附录 B」的原句**作废**：本域数值只含安全整数（§2.4），附录 B 的 IEEE-754 双精度样例（`1e+30`、`4.50` 等）属域外输入，原表按文不可执行。替代的**等价判据**（在自身数值域内可执行）：

1. **正向**：RFC 8785 §3.2.2.2 字符串转义样例全部通过；§3.2.3 官方键排序测试数据（即 VEC-06 键集）通过；附录 B 样例中筛出的**安全整数字面量子集**＋全域边界 VEC-08 通过（期望＝最短十进制整数形式）。
2. **负向**：附录 B 其余样例逐条作**域外断言**——含指数记法/小数点/超安全整数的数值字面量，按 §2.4 拒收（E-ENC-003）；若所在字段类型声明为字符串形态（decimal 族），其值按字符串转义规则处理、不进入数值序列化。
3. `supported` 判定＝一个实现实际运行并通过：上述 1＋2、本卷 VEC-01..VEC-08、自写反例组（VEC-09/10），并留可复算记录。三组结果随 `canonicalizationVersion` 一起发布。

### 2.8 摘要与签名结构（ENC-08）

摘要结构：

| 字段 | 类型 | 必填 | 含义与约束 |
|---|---|---|---|
| `algorithm` | token（登记制，至少 `sha-256`——**按 §1.1 合法 ✓**） | 是 | 摘要算法；`value` 长度由算法定（sha-256=64） |
| `value` | 小写十六进制 | 是 | 摘要值 |
| `kind` | enum{byte, semantic}（值集登记 v2/09） | 是 | 必须显式写明何种摘要 |
| `canonicalizationId` | dotid | 仅 kind=semantic 必填 | `studio-next.jcs`（**按 §1.1 合法 ✓**）；byteDigest 出现即拒收（E-ENC-001） |
| `canonicalizationVersion` | integer | 仅 kind=semantic 必填 | `1`（**按 §1.1 合法 ✓**） |
| `computedAt` | timestamp | 否 | 仅诊断，不参与判定 |

签名结构（压缩为八字段；完整语义 v1·76 §1.5.2 口径保留）：`scheme`（token，登记制）｜`keyRef`（逻辑密钥/信任锚引用，不得含密钥值或本机路径）｜`signerRef`（主体引用，形状 v2/11；不得「系统/框架/公司」匿名代名）｜`signedDigestRef`（引用＋必须写明 kind）｜`scope`（`{partIds, digestRefs, coverageNote}`；一份总签名不得替全部 part 背书）｜`createdAt`（timestamp）｜`verificationState`（enum，值集 v2/09；`verified` 必附核验材料引用）｜`value`（编码由 scheme 决定，不含密钥材料）。运行时不得重新生成权威工件：冻结公共工件只能在发布流程生成，运行时只消费。

## 三、交换编码（ENC-10..30；治 V7-P1-1）

### 3.1 唯一交换编码（ENC-10）

**机器可交换工件的物理编码唯一为 JSON**（UTF-8 文本；解析结果必须能无损映射公共数据模型）。适用于：聚合体（PKG-AGG）的全部机读 part、冻结 schema 工件、公共词表（§5.5）、namespace 登记表（§5.4）、向量 fixture。摘要与等价判定一律按 §二 canonical 形式计算——「能解析」不等于「语义可判」。JSON5/TOML/INI/CSV 不是交换编码；聚合体物理打包（归档格式）与获取通道归传输面（v2/12），归档安全限额归 v2/15。

### 3.2 YAML 投影子集（ENC-20）

YAML（含 51 现状公司目录全部机读文件）定位为**人读源/作者格式**，不是交换编码；公司目录（DOM-01 权威载体）内 YAML 形态合法存续（51 现状），但**装载时必须**按以下子集投影为 JSON 数据模型后才进入判定与摘要，不得依赖具体解析器缺省行为：

1. 仅 YAML 1.2 core schema、字符串键；锚点/别名、合并键（`<<`）、多文档（`---`）、标签、复杂键、重复键一律拒收（E-ENC-004）——锚点展开会引入隐藏共享语义，重复键按 §2.2 前置拒收。
2. **标量类型由字段声明的标量族决定，不由解析器猜测**：声明 `decimal` 的字段其 YAML 标量按字符串原样承载（保留词法）；整数标量映射 JSON 数值且必须落在安全整数域内，越界拒收（E-ENC-003）。此条消除「同一目录在不同解析器下判定不同」的隐含私有耦合（V7-P1-1 所指 zod/yaml 缺省行为缺口）。
3. 注释剥离且**不承载任何机读语义**；YAML 映射键序不保留语义，canonical 化按 §2.3 排序；投影产物为 JSON 数据模型值，此后一切判定与摘要不再看 YAML 源。
4. 51 目录按本子集装载＝兼容绑定的只读投影（v2/06 §四.3）；原格式无法表达的语义显示「未表达/不支持」，不得由默认值虚构完整；51 文本修订与迁移归 v2/16。

### 3.3 迁移期绑定标识（ENC-30；治 V7-P1-6）

`studio-next/org@1` 族私有字面量（org/dependencies/trust/plugin-registry，51 现状随包传播）处置三则：①登记为**迁移期绑定标识**，不是 V2 公共 schema 标识；定义部**新工件**不得再写入；②跨框架接收方遇之：可按绑定档案（v2/12）作兼容绑定投影，无绑定档案时按未知必需扩展拒收（E-SCH-002），不得默认忽略、不得降级为文本；③V2 正式替代为 SCH-PKG-01 的 `schemaRef`（dotid 形态）。51 现行标尺不变（现状），迁移归 v2/16。

输入＝按 `partId` 的 UTF-16 码元序升序排列的数组，每项 `{"partId":…, "partType":…, "digest":…}`（`digest` 取该 part 清单声明的摘要 `value`，小写十六进制字符串原样）；对该数组按 §二（`studio-next.jcs@1`）规范化后取 semanticDigest。`parts` 列表必须有序且逐项可复算；摘要不符即拒收该 manifest。

### 5.4 namespace 登记（SCH-NS-01；治 V7-P1-3/L3B-04）

登记条目形状：`{namespace: dotid（1..4 段）, registrantRef: dotid 引用, allocatedAt: timestamp, status: enum{active, retired}（值集 v2/09）, purposeNote?: text}`。规则：分配后不回收、不复用；`retired` 段不再分配；登记表=公共工件（工件身份登记 v2/09，分发与获取待决 §十一）。

**现状：无登记者、无登记表、无示例取值——目标（未证）**；登记者的设立=制作人待决项，本卷不代决。建成前跨框架同一性对账以「谱系主张＋可取得记录对账」代偿（v2/06 §一.1/§八.2），不得冒称已有公共 namespace；`studio-next` 保留段（§1.2）不经登记者，不在此列。

### 5.5 公共词表工件（SCH-VOC-01；治 V7-P1-4/V7-P2-4）

`enumRef` 所引词表是公共工件，形状：`{vocab: dotid, vocabVersion: semver, codes: list<{code: token, meaning: text, deprecated: boolean}>, publishedAt: timestamp, semanticDigest: ENC-08}`。规则：码值只增不改义，含义变化必须新版本；引用方必须写精确版本；解析不到＝拒收（E-SCH-005），不得默认放行；`deprecated` 码可读不可新写。冻结 schema 工件以 `schemaRef`（§4.1）取得身份，与词表同属公共工件，其发布、命名与公开标签属制作人待决（§十一）。

## 六、规则求值档（RULE；求值语义唯一主表）

> 最高宰相裁决 2026-10-27：Rule Profile 求值语义唯一主表**归本卷**——v2/05 表 D 与 v2/06 §八.1 的上位引用成立。本节条目前缀 `RULE-`，登记于 v2/09。

### 6.1 定位与合并口径

凡把验收口径、边界、触发条件、风险分档或授权范围写成**可求值表达式**，它就从文本升级为规范工件，必须绑定版本化的规则求值档。档只决定「怎样算出一个可判定结论」，**不决定**结论是否被授权采纳——采纳须具名位置与证据（记录归 v2/11）。只能定性判断的语义（信任、尊严、长期价值、损害可接受性）保留判断位置、证据、异议与复审，不因无法机械化被删除或伪造成表达式。

**唯一条数与合并口径（治 H2a-P1-3）**：v1·69-§3.5 的五项要求与 v1·70-§0.3 转述的六项要求两表并存、条数不一——V2 将其并集去重，并补入 v1 缺失的输入声明承载、结果字段形态与步数计数口径，收拢为本节 **RULE-01..RULE-08 共八条**唯一封闭条目集；**条数与内容以本表为唯一口径，v1 两表作废**。

**字面量纪律（①档位枚举引 v2/09）**：档身份、档状态、求值结果四值、相位、算子名等一切封闭字面集唯一主表 v2/09；本节只定义语义、约束与判定规则，不重述字面量。

### 6.3 关键判据细则

**存在性谓词真值表（治 L3C-P1-04；`absent` 只覆盖成员不存在，不覆盖 null，与 §1.4 一致）**：

| 输入态 | present | absent | isNull |
|---|---|---|---|
| 成员存在、值非 null | true | false | false |
| 成员存在、值为 null（nullable=true） | true | false | true |
| 成员不存在 | false | true | false |

`if` 条件为 unknown 时：结果为 unknown，**不求值任何分支**（两分支仍受 RULE-04 全子树静态检查）——分支内错误不得把 unknown 变 refused。

**三结构块机器字段（治 L3C-P1-07；档内必填、逐字段可比；除注明外类型均为 integer。限额机器名与求值结构块值的**值集唯一主表 v2/09 ENU-104/ENU-105**，本表为字段承载视图，不是值集第二登记处——09 §六-4 收口）**：

| 结构块 | 字段 |
|---|---|
| limitsApplied（七项可收紧） | maxNodes／maxDepth／maxListItems／maxTextCodepoints／maxSignificantDigits／maxScale／maxEvalSteps |
| 档内固定三项 | maxPatternInputCodepoints／maxPatternSteps／maxQuantifierNesting |
| patternModel | matchingModel（值 `linear-nfa`——**按 §1.1 合法 ✓**）、anchoring（值 `full-match`——**按 §1.1 合法 ✓**）、caseSensitivity（参数声明，禁内联开关）、maxQuantifierBound ≤1000 |
| determinism | unicodeVersion、linebreakDef、strComparison（值 `codepoint` 或 `nfc`——**按 §1.1 合法 ✓**，nfc 引 §1.1 钉版）、decimalContext{precision, rounding（默认 `half-even`——**按 §1.1 合法 ✓**）} |

模式匹配受限子集：字面字符、字符类（含范围/取反）、`.`（默认不含换行）、锚 `^$`、量词 `?*+{m,n}`（m,n≤1000）、分组与选择、`\d\w\s` 及取反；禁止反向引用、环视、原子组、条件组、递归、占有量词、内联模式开关、`` 类零宽断言与代码插值；实现可用任何算法，但接受/拒绝结果必须与线性时间自动机完全一致，不得以「超时保护」代替模型一致。**实现身份不入档**（implementationId 归激活记录，v2/11）——防档绑死单一实现。

**相位修正（治 L3C-P1-09/H3a-P1-8；同一 code 不得跨相位复用）**：必需输入缺失与容忍字段的**实际缺失**只能在输入到达后判定→独立 `inputBinding` 相位（E-RULE-005/006）；静态声明错（路径不可解析、缺省与容忍冲突、隐式转换）归 `typecheck`；策略消费侧判定（条件 unknown 按方向表命中）归 `policy`（W-RULE-001）。**策略/审计违规不得配 typecheck 码**——v1 把档位推论违规配 E-RULE-006 的做法作废。
