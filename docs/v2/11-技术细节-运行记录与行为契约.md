## 〇、读法与通用记录契约

### 0.1 职责边界

| 关系 | 本卷义务 | 本卷不做 |
|---|---|---|
| 对 v2/02-04 | 为其全部对象提供**记录形状**（字段/类型/必填/不变量/生产者/消费者） | 不重定义身份、任职、任务、验收等概念本体 |
| 对 v2/05-08 | 为 OBJ-01..05、EVD-/MEM-/MON-/OBS-、CAP/H 族、派生树提供记录层落位 | 不重定义对象与端口语义（引位） |
| 对 v2/09 | 登记全部 `REC-` 记录类型 ID；枚举一律引其唯一主表 | 不定义任何枚举字面量（§0.6） |
| 对 v2/10 | 只消费公共信封/引用/标量形状 | 不重述信封字段（payload 判定规则唯一主表在本卷） |
| 对 v2/14 | 只声明记录族的端口维度要求 | 不写接口签名与端口-文件映射 |
| 对 v2/15 | 引用凭据停用/围栏/fail-closed 机制 | 不定义机制实现 |
| 对 v2/17 | 每族末给负向用例引位 | 不写断言本身 |

本卷不承诺任何记录格式已实现、任何协议已运行、任何网关已强制；凡未建成机制一律标**目标（未证）**。

### 0.2 责任主体与记录五分型

1. 每条改变状态的记录必须能追到**具名决定者**与**写入路径**；「框架/系统/平台/流程/daemon/监控/自动策略」不得作为决定者或异常接收者（I-9）。任何「自动」行为须能展开为四问：谁事前授权、范围谁定、当时谁判断、异常谁接收。
2. 写入者不得替决定者补写理由；决定者不可达时写入者只能**保全并转交**（落 REC-WORK-17 异常或 REC-EVT-03 未知登记，带具名接收位置与时限）。
3. 记录五分型不可互换：**命令/请求**（希望发生，不证明已批准）｜**决定**（某位置作出何判断，不证明有权或已生效）｜**回执**（权威端确认，不证明端到端恰好一次）｜**事件/观察**（被观察到，不驱动状态迁移）｜**修正**（追加更正，不删除历史）。每类记录在 §一总表标注分型。
4. **记录不是事实**：记录是事实材料；缺失一律记「未知」，不得记为零、空、健康、未发生；派生物（投影、摘要、记忆、评分）不得反向改写历史或自封第二事实源（v2/05 §三通则）。

### 0.3 一事件一身份与决定面

1. 一次语义事件只产生一个 `recordId` 与一个主 payload；需要附带判断的在同一记录上携带**决定面**（嵌套槽位：决定者、权源引用、理由与依据、判定范围与未判范围、异议位置、生效状态与时点），不另写 REC-DEC-01。
2. **决定面封闭清单**（恰为下列类型，其他类型不得强加）：REC-AUTH-07、REC-AUTH-08、REC-WORK-02、REC-WORK-04、REC-WORK-06、REC-WORK-07、REC-WORK-09、REC-WORK-12、REC-LIFE-01、REC-LIFE-02、REC-LIFE-07、REC-LIFE-09、REC-CAP-ACTIVATE、REC-ACC-02。清单外类型（如 REC-WORK-11/17、REC-LIFE-10）由本类型自有的决定者/依据/异议字段承载决定面，**也不得另写 REC-DEC-01**。
3. REC-DEC-01 只承载**没有专用记录类型**的决定（主体分类结论、利益关系声明、受理口径复议、汇总接收等，语义源 v2/02 §一/§七）；已有专用类型再写 REC-DEC-01 即不合格写入（双身份）。
4. 决定面是权威值，顶层同名字段（若存在）为只读投影；两处冲突即拒收。随程序推进而变的字段（接受状态、交接完成度等）**只留主 payload**，不复制进决定面。

### 0.4 身份、版本、幂等与并发

1. 记录身份一经分配不复用；显示名、会话号、账号、平台单号均为别名。**对象身份＝首版 `recordId`＋版本链**（`supersedes` 逐版链接，旧版本保留）；修改产生新版本，不覆盖。实例版本槽位与信封承载方式归 v2/10，本卷只冻结该规则（治 H3a-P1-5）。
2. 一切引用形如「ID＋版本」；引用「当前最新」视为不合规，解释历史必须按当时版本。
3. 双时间轴：业务生效时间与系统获知时间分别记录；补录、追溯生效、迟到记录各自标注，不得合并为单时间戳。
4. 任何改变状态的写入必须带**预期版本**；不匹配即拒绝并返回当前版本与差异摘要，不得「最后写入为准」。同一对象同一版本只允许一次成功迁移；重复提交返回既有结果，不产生第二次副作用。
5. **幂等键**：通用作用域＝（公司标识、对象类型、对象标识、操作类别、请求方序列）。协议特化键必须：①含公司标识；②可显式映射回五元组；③在本卷登记。本卷登记的特化键——任命：**「位置引用＋任职者＋任期起点＋拟任版本」四元组**（唯一口径，v2/02 §二；v2/14 不得缩写，治 V4-P1-3）；权威激活：（事实域×目标端点×新代次）；收割：（出工段×采集区间）；权威激活与收割键均声明为五元组在该协议的实例化（治 H3a-P1-6）。
6. 调用失败语义（类别/可否重试/副作用可能/对账入口/责任位置）沿用 v1·77 §11.1 十四类口径，**字面量唯一主表登记于 v2/09**；失败分类是调用语义维度，不得替代异常类别与终局出口（§五 REC-WORK-17）。

### 0.5 时间字段与 payload 存储规则（治 H3a-P0-1/K8）

生效语义两类分开：**内部判断类**（验收、分类、迁移、任命、激活等）以「记录成立＋适用规则版本＋前置条件证据」生效，不要求外部回执；**外部效果类**（对端点写入、对外通知、凭据生效）须取得回执或可复核观察（REC-RCP-01 / REC-EVT-01/02）方可声称已实现。时间字段分层如下，**全库唯一口径**：

| 层 | 承载 | 规则 |
|---|---|---|
| 信封（v2/10） | 生效状态三值（主表 v2/09）；`effectiveTime{from, until?}` | `pending`/`effective` 时必填；`from` 在 pending 时是**预计/复审起点**（计划轴），在 effective 时是实际生效起点；`until` 为失效/复审终点，**唯一存放点** |
| payload | `effective_time`：单时刻 | 仅**实际生效时刻**；`pending` 时必须为空；写入时与信封 `from` 同值校验（effective 时） |
| payload | **禁止项** | **payload 一律不得出现 `until`，也不得出现任何区间型生效窗口字段**（v1·77 REC-AUTH-07 `effective_window`、REC-COR-01 `effective_window` 两处自相矛盾形态废止） |
| payload | 独立单时刻语义字段 | 确需表达「复审到期」「向前适用起点」等业务语义时，用独立字段（如 `review_due`、`effective_from`，均为单时刻、各自语义），**不与信封 `until` 同值绑定、不复制终点** |

配套规则：payload 声明生效状态槽位时必须与信封同值，不一致即拒收（全部决定面封闭清单类型 payload 必含该槽位，治 L3D-10）；`pending` 不得被投影为生效、不得被结清清单当作已完成、不得被引用为已授权/已验收；预计/计划起点不得回填为实际生效时间。

### 0.6 枚举零重述纪律（治 H3a-P0-2/K9）

1. 本卷**不定义任何枚举字面量**。凡枚举字段一律写「取值唯一主表 v2/09（语义源 v2/0X §Y）」。已登记引位：受理五取值（v2/04 §二）、工作十态（v2/04 §五）、验收四取值（v2/04 §六）、结清清单项与结清四态（v2/04 §六）、维持结论三值（v2/04 §七）、EX- 效果级（v2/04 §1.1）、六类结果面（v2/04 §二/§七）、任职六状态（v2/02 §三）、任命四类型（v2/02 §二）、个人记忆四子类（v2/02 §八）、身份四态（v2/03 §7.2）、政策结论四态（v2/05/v2/10）、授权策略、异常类别与终局取值（v2/04 §五/§九）、终态判定五值（v2/07 EXEC-05）、事后审计结论集（v2/08 §1.6）、投影六态（v2/08 §4.1）、变更链段名（v2/08 §六）、观察面清单 MON-01..15（v2/08 §4.2）、回执类别、修正类别、问责结论与救济类别（v2/05 OBJ-01/02、v2/01）、义务形态（v2/06 定义包）、失败十四类。
2. 状态名在 §十四迁移表中按边**使用**，不构成状态集重述；状态集、机器值、可写入字面量唯一在 v2/09（治 DSF P0-8(c)）。
3. 「不适用」是合法取值但不得空着：须记不适用＋理由＋判者（84b 抉择 6）。

### 0.7 证明边界、失败出口与升级链

1. **证明边界**：证据类与决定类记录（REC-EVD 族、REC-WORK-07/08/09/12、REC-LIFE-01、REC-ACC 族、REC-PERF-01）必填 `proof_boundary`（本记录证明什么、不证明什么）；其余类型以各节「不能推出」行为准（治 L3E-15）。
2. **失败出口三要素**：每类记录的失败去向必须写明**具名接收位置、期限或复审条件、到期再升级去向**；本卷逐记录登记，通用兜底＝既有升级链至老板/宰相（v2/03 表 D），无「等待处理」结案形态（I-11，治 L3E-17）。
3. 位置空缺按预设替补与升级链处理；替补也空缺时进入悬置登记（具名接收位置＋时限＋再升级去向）。

### 0.9 `REC-` AREA 登记处（治 H3a-P1-10）

`REC-` 前缀**分卷登记、各自封闭**：本卷 §一总表是运行记录 AREA（AUTH/LIFE/PERF/WORK/EVD/ACC/CHG/CAP/REV/EVAL/ASSET/OBS/MEM）的唯一登记处；v2/10 登记数据形状 AREA（ENV/PROV/REF/CASE/MIG/LOSS）。两组不重叠、不得互相充当替代品；未在本卷 §一登记的 `REC-<AREA>-*` 引用一律视为悬空引用（§十五）。

## 二、AUTH 权责族

> 负向用例引位：v2/17（权源冒充、代批、围栏/代次互推、镜像升权威等断言行）。

### 2.1 通用骨架（七类，压缩规格）

**REC-CMD-01 命令请求**（语义源 v2/05 §四｜DOM-03｜生产者：请求方｜消费者：权源检查、受理位置）。
**适用范围写死**：仅用于**外部/人工入口**与**无专用记录类型**的动作请求；域动作（受理、开工、验收、结清等）由专用记录承载，不得为同一语义事件并列再写一条 REC-CMD-01（治 L3D-12）。
字段：command_kind（枚举，主表 v2/09）、target_ref（引用＋预期版本）、requested_effect（可判定，禁「处理好」）、claimed_authority（引用列表）、scope、idempotency_key、issued_at/received_at、source_verification（已核验/未核验/核验失败/来源不明——主表 v2/09）、payload_digest。
不变量：未核验只能暂缓或拒绝，不得进入执行步。失败出口：退回补来源/摘要；超时限拒收并升级入口位置。

**REC-CMD-02 权源检查**（生产者：检查位置｜消费者：各决定型记录前置）。
字段：checked_command、resolved_grants（可空列表=无可用授予）、policy_verdict（政策结论四态，机器字面量唯一主表 v2/09）、conflict_check、delegation_chain_ok（子授权不超父授权目的/范围/条件/期限）、effective_scope、fail_reason。
不变量：禁止优先；未覆盖不自动允许；包含关系不可判不得视为已授权；「命中显式未覆盖条目」与「无条目命中」须区分诊断。失败出口：禁止→停止；保留→转呈；未覆盖→请求决定（拒绝事件保留）。

**REC-DEC-01 泛型决定**（生产者：具名位置｜消费者：观察面 MON-03、申诉链）。
适用范围：仅无专用类型决定（主体分类结论、利益关系声明、口径复议、汇总接收）。字段：decided_by、decision_kind、subject_ref、verdict（由对象类型决定，不得借用专用类型取值集）、conditions、rationale（不得为空）、basis_refs、scope_judged（判了什么/没判什么）、dissent_position、生效槽位（§0.5）、external_effect_state。

### 14.4 能力状态链与变更链段（非独立状态机）

3. 执行体派生树的「派生即登记」落 REC-AUTH-04 引用＋派生登记字段（v2/07 §四）；撤回时的后代停用判定走 REC-AUTH-03＋REC-EVD-RVK，不设独立状态机。

## 十五、字段不变量与跨记录引用完整性（治 C3-P1）

1. **引用完整性**：本卷正文与观察面映射表引用的每个 `REC-` ID 必须在本卷 §一总表有行（本卷自检：§一 74 行全覆盖）；引用其他对象族用其唯一主表 ID（EVD-ELM-01..08、MON-01..15、OBJ-01..05、EX-、I-、R-/E-/W-、PORT-）。**引用未在本卷或其唯一主表定义的记录类型＝悬空引用**，v2/17 机械自检判负（F3 口径）。v1·77「变更链记录」「异议记录」「资源账」三处非 REC 指代（C3-P1-1/L3E-14/P2-2）已分别收口为 REC-CHG-01、各记录 dissent 字段族、REC-WORK-05＋REC-EVD-01＋REC-EVD-04 组合。
2. **跨记录不变量**（全库判负口径，断言落 v2/17）：
   - 出工（REC-LIFE-04）必引生效版本的 REC-LIFE-01；任命未生效不得出工。
   - 迁移（REC-WORK-06/REC-LIFE-02/REC-LIFE-07）必引前置记录与权源；事件（REC-EVT-01）不得作为任何迁移的 trigger 权源。
   - 验收（REC-WORK-09）必引证据包（REC-EVD-03）；EX-2+ 附加收割批次（REC-EVD-01）且采集者独立。
   - 结清（REC-WORK-12）的迁移边（M-26..28）必以本记录为前置；已终止路径必含承接确认与派生面。
   - 撤回完成必含 REC-AUTH-03 后代枚举＋停用证据（与 REC-EVD-RVK 同构互证）。
   - 履约状态（REC-WORK-16）为派生值：无独立写入路径；已兑现必含相对方验收引用。
   - 绩效（REC-PERF-01）输入必含验收结论（REC-WORK-09）与分级完成记录（REC-WORK-08），不得以执行面终态为输入。
   - 激活批准（REC-CAP-ACTIVATE / REC-CHG-01 激活批准段）不得由验证通过倒推，不得由被进化对象或直接受益方单独作出。
3. **证明边界与「不能推出」**：每类记录的「不能推出」以本卷各节为准；记录格式通过校验不等于有权、有能力、已验收、已结清。
4. **类型版本**：全部 74 类初始类型版本 `1.0.0`；同主版本内只允许新增可选字段，已登记字段的含义、必填性与取值不得改变；未登记的更高版本一律拒收；类型版本独立于实例版本与规范版本。
