## 一、命中项目（3-5）与证据

### 1) Paperclip — 「自托管 AI 劳动力控制面」（MIT；100k+ stars；最相关竞品）
- 定位：self-hosted 控制面：**org chart（角色/汇报线）+ tasks + approvals + budgets + 每次 run 的记录**；agent runtime 自己接（Claude Code/Codex/…），模型用你自己的 key；Node 24.11+、内嵌 PostgreSQL、`~/.paperclip`。
- 与 StudioNext 重合：公司式组织、任务/审批/预算、审计记录、runtime 适配器、单机自托管。
- 差异：Paperclip 是**管理层控制面**（BYO runtime、不替 agent 框架）；我们是**框架+daemon 单写者**（三事实源/QTrack→Taiga 网关/台账事件哈希链/验收四要件/模型路由/seatbelt 沙箱/公司目录 git）。
- 证据：https://paperclip.app/product/open-source/（产品页）；https://github.com/paperclipai/paperclip（仓库，页面拉取超时）
- 其自承限制：recorded-cost budgets can overshoot（记账延迟/在途可超预算）、task review 不拦截所有外部调用——**恰是我们在预算预检/日闭上更强的一侧**。

### 2) cft0808/edict — 「三省六部制」多 agent 编排（OpenClaw 上层；2026-03 约 6.5k stars）
- 结构：12 agent=太子（消息分拣）+ 三省（中书规划/门下审议封驳/尚书派发协调）+ 六部（户礼兵刑工吏）+ 军机处看板；实时进度/叫停/恢复；model config + full audit trails；基于 OpenClaw 渠道（飞书/企微等）。
- 与 StudioNext 重合：**规划者/执行者分离 + 门下独立审核（封驳打回）= 我们的策划/评审岗与 verifier 退回**；看板=我们的面板；审计=台账。
- 差异：edict 是**概念性实验**，多 agent 层级带来 **token 指数成本**（作者自述"结构越复杂烧的 token 越多"），无单写者/账本/预算闭环；我们是可审计工程，非角色扮演。
- 证据：https://github.com/cft0808/edict ；解读：https://www.bianews.com/news/details?id=233531

### 3) OrgAgent（arXiv 2604.01020）— 学术验证「公司式层级」
- 结论：治理层/执行层/合规层三层；**company-style hierarchy 通常优于扁平/其他组织结构**（GPT-OSS-120B 在 SQuAD 2.0 上比 flat 提升 102.73%、token 降低 74.52%）；层级在"稳定技能分配、受控信息流、分层验证"时收益最大。
- 意义：**学术背书**我们的"岗位/评审/验收分层"和"分档模型"路线；可作为对外解释材料（我们是工程实现+账本，非论文）。
- 证据：https://arxiv.org/abs/2604.01020

### 4) PROMETHEUS（Zenodo，2026-10-26）— 企业 AgenticOps 参考架构
- 四能力：**Intelligence（目标/规划/编排）/ Execution（runtime/工具/适配器）/ Governance（契约/策略/注册/安全）/ Trust（可验证证据：observability/eval/lineage/replay/人工监督）**；原则：Governed Autonomy、Evidence by Design、Registry Pattern、Determinism Before Generation。
- 意义：与我们"三事实源+审计链+验收四要件"高度同构，**Evidence by Design/Registry** 概念可用于 Phase1 sidecar/audit 设计词汇。
- 证据：https://zenodo.org/records/23676962

### 5) （对照）Kortix vs Paperclip 讨论
- 观点：Paperclip=开源的"公司系统"，Kortix=agent 控制面；两类产品分层不同（管理记录 vs 运行时控制）。提醒我们定位："我们是框架+事实源，不做纯控制面"。
- 证据：https://github.com/kortix-ai/suna/blob/df1eeecbedbacb6df4c243747128115e42194dd8/apps/web/content/posts/kortix-vs-paperclip.md

## 三、可借鉴（按优先级）

- **P1（Paperclip）**：heartbeats（per-agent 自驱唤醒 cadence：被指派/评论/阻塞解除/时间到）→ 我们的 tick+定时岗可加"按角色 heartbeat 的唤醒源"；linked tasks/approvals 的**人机协同 UX**（面板增量）。
- **P1（Paperclip 反面教材）**：其 recorded-cost budgets 可超支 → 印证我们"预算预检+settle+日闭 delta≈0"必须保留，不可改用"记账后置"。
- **P2（edict）**：门下省"封驳打回"流程与我们 verifier RETURN 等价（已覆盖）；其**看板叫停/取消/恢复**可参考补我们面板的操作面（当前只读偏多）。
- **P2（PROMETHEUS）**：Evidence by Design / Registry Pattern / Governed Autonomy 词汇直接可用于 Phase1（sidecar registry、audit、回滚证据链）设计文档。
- **P2（OrgAgent）**：层级/受控信息流/分层验证的学术结论可写入对外材料与内部设计 rationale（支撑分档/评审/验收）。

## 四、不建议学

- edict 的 12-agent 全链路角色扮演（token 成本指数上升，且无单写者/账本/回滚）——我们保持"角色少而实、账本硬"。
- 扁平 group-chat 式多 agent（AutoGen 类）——已被我们验收/四要件体系取代。
- Paperclip 的"recorded-cost 预算"与"review 不拦截外部调用"放宽面——与我们钱/权限红线冲突。

## 五、结论
- **最相关=Paperclip**（产品化公司式控制面，100k+ stars；建议列入竞品常跟踪，关注其 org chart/heartbeats/adapters 三块）。
- **edict**=概念验证，高话题低工程保障；**OrgAgent/PROMETHEUS**=理论背书（层级/治理/证据设计）。
- 无需改动本仓；以上 P1/P2 可进 Phase1 设计素材与产品对比文档（待制作人决定是否立项跟踪）。
