# 提案：B2 —— PriceEntry/价目链扩展 cache 读写价（2026-11-10 制作人过审）

> 依据：制作人 2026-11-10 22:3x「全部按你建议即可」；本提案走「提案→探索→对比→方案（含不做什么）→过审→实现→验证」流；契约冻结面（`packages/contract` PriceEntry）变更已获制作人过审。

## 1) 问题

- 现行 `PriceEntry` 仅 `inputPerM/outputPerM`；`foldCostUsd` 对 cache 桶缺价按 0 计并登记 `unpricedBuckets`（下界），日闭 `cache-unpriced` 计数可见但不入账。
- GLM-5.3 实际用量中 cache 命中占 token 大头（11-08 未计价 96.3M tokens≈$26.8；11-09 64.7M≈$18.0）→ **日闭 USD 显著低估**（诚实但低）。

## 2) 方案（最小、不回填、不动账本语义）

1. **契约**：`PriceEntry` 增可选 `cacheReadPerM?`、`cacheCreationPerM?`（USD/百万 token，非负有限）；`ModelTier.price` 随之携带。
2. **配置面**：`models.yaml` 三档价目补 `cacheReadPerM`（GLM-5.3 官方 cache-hit 2 元/M ÷7.2 ≈ 0.2778 USD/M）与 `cacheCreationPerM: 0`（官方缓存存储限时免费）；parser（`core/models.ts` PriceSchema）接受两可选键，坏值 fail-closed。
3. **折算链**：`publish.ts` 档位 unit 读取 cache 键 → 生成价目表已支持渲染 cache 键 → `parsePricingTable`（SlotPriceSchema 已含 cache 可选键）→ `price_snapshots.cache_read_per_m/cache_creation_per_m` 落列（store 表列已存在）→ `resolveSnapshotPrice`/`bridgePriceFor` 产出的 `UnitPrice` 携带 cache 价 → `foldCostUsd` 计价、`unpricedBuckets` 仅在价缺失时登记。
4. **可见性**：日闭 `cache-unpriced` 归零即证明 cache 已计价；报告 `price_basis=snapshot/models-yaml` 口径不变。
5. **测试**：parser 接受/拒收、fold 计价、bridge 透传、publish 渲染+快照列、cost-close `cacheUnpriced=0`、seed 幂等回归。

## 3) 不做

- 不回填历史（11-06 前 usage/cost=0 不改）；不改 `usage_daily`/`cost_daily` 既有行；不新增事件词/台账 schema；不引外网取价（价目仍来自 models.yaml 人工声明）；不改日闭结算口径（USD=Σ桶×价）；不动 28 项 V2 验收面。

## 4) 验收

- `verify:v2` 全绿（含契约/核心/daemon 测试）；部署后次日日闭 `cache-unpriced` 计数=0、USD 含 cache；`price_snapshots` 新行 cache 列非空；报告注因段不再出现 cache 缺价低估提示。

## 5) 风险/回滚

- 契约变更向后兼容（新增可选键）；若 GLM 实际 cache 价与 list price 不同，仅影响估值口径（报告注明）；回滚=恢复 models.yaml（备份）+ revert 代码提交。
