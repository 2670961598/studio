## 一、前置条件（全部满足才可进窗口）

1. **插件 ready**：`fields.schema/provision`、活动流（activity.since 语义）、评论面必补齐（评估 §一.1 ✗/◐ 项）；`type/dept/level/lane` 或扩包或经 labels+adapter 双向读回，**不得只写不读**。
2. **接口冻结**：FlowPlatform 七能力（issues.list/get/create/transition/setField/comments.add/list + activity.since）契约测试冻结；状态映射表 v1（新单→1 … 已收口/关闭/取消→8，与 `scripts/workbench-issues-migrate.ts` STATE_MAP 同源）冻结，改动走提案流。
3. Phase0 证据复验通过（`a097003`：stateMatched 10/10、ID roundtrip 10/10、exemptions 0）。
4. Taiga 全量导出（issues/comments/父子/时间戳）落盘备份，含导出时间戳；`ticket_mirror` 确认为投影（可重建，`packages/store/src/records.ts:113-129`）。

## 二、迁移窗口

- 建议：周末低峰（单量/评论量小、daemon 派发空转窗口）；预估 2–4 小时含对账，超 4 小时未达双跑门槛即中止回滚。
- 窗口内 **Taiga 冻结写**（不派单、不评论、不流转）；导出快照时间=冻结点，此后 Taiga 增量一律不追（回滚重做，不打补丁迁移）。

## 三、双跑门槛（进入切换的必要条件）

1. 双跑期 **Taiga 唯一写、Workbench 只读影子**；不双写（评估 §二.1 台账/回滚口径）。
2. 影子导入 + 对账连续 **3 个工作日 0 差异**：`workbench-issues-diff` exit=0，gap 清单为空或逐项制作人书面豁免。
3. 抽样人工核：每日 ≥10 单（覆盖每状态×每类型×父子链），标题/正文/状态/评论/时间戳逐字段目检。
4. 幂等重验：同导出重跑计划生成两次 planHash 一致（审计域除外）；重导出（含重复记录）不改变目标载荷 hash。

## 四、回滚

1. 切换失败/回归超标：daemon 配置回 `platform: taiga`，Taiga 数据未动（冻结只读），分钟级恢复。
2. Workbench 侧 issues.db 标记弃用并保留（审计），不删除不重放。
3. `ticket_mirror` 由 events 重建（投影，非事实源），重建脚本属切换实现单交付物。
4. 已切期间新产生的 Workbench 单：导出为 JSON 存档、人工回录 Taiga（预期量≈0，因窗口内冻结）。
