# 前沿侦察 2026-11-22（只读；近一周 GitHub/arXiv/Zenodo/厂商）

## 结论（TL;DR）
本周最相关是一篇**生产级多 agent 组织的 53 天全量写级审计**（"An Error-Memory Institution in an Agent Organization"，Zenodo）：1 个人类主控 + 26 个 AI 岗位、5,130 commits、约 7,000 次闸门拦截、约 100 条错误档案。核心结论：治理可靠性不来自模型，而来自**两类组织制度——写前闸门（pre-commit gate）+ 错误记忆机构（error archive，把错误类收敛成一次性事件）**；违规尝试量不随时间下降，但"写进历史的东西"变可靠；规则可在 1 天内成文、维护成本约写流量 1.8%。这与我们的"网关写 + 台账 + 验收闸 + 进化链"高度同构，可直接借鉴"错误类一次性"制度与 5 条行为规律清单。工程侧 AZOWL AgentOps 的**任务域治理**（任务 ID 绑定发送者权限/执行者/审批/证据、范围变更重新审批）也值得对照。产品侧 Kortix 推出 CompanyOS（agent 操作系统）。

## 3-5 个最相关对比

### 1) An Error-Memory Institution in an Agent Organization（Zenodo，53 天全量审计；最相关）
- 证据：https://zenodo.org/records/23597096
- 要点：生产组织（1 human + 26 AI 岗位）53 天写级审计；5,130 commits、~7,000 gate interceptions、~100 error-archive；违规尝试**不下降**，但错误类被收敛为"一次性事件"后不再复发；两大制度：**pre-commit gate** + **error archive**；规则 1 天内成文，维护成本 ~1.8% 写流量；提炼 5 条行为规律（incentive myopia / rhythm of closure / convergence by outsourcing / script-model division of labor / sycophancy amplification）各配制度性对策。
- 可借鉴：①把"错误记忆机构"制度化：错误类 → 一次性规则 + 复发检测 + 维护成本度量（我们已有台账/进化链，但缺"一次性"与成本口径）；②5 条行为规律做成**哨班/验收风险清单**；③写前闸门成本统计（我们验收闸/GATE 有，但没算维护成本占比）。
- 已覆盖/更强：三事实源、唯一写入者、hash 链台账、验收四要件、真实执行器；论文是单一组织观察研究，我们是可运行框架。
- 不该学：不因"违规不下降"放松闸门；不把单组织结论当普适律。

### 2) AZOWL AgentOps: Task-Scoped Governance（arXiv 2611.25562，2026-11-19）
- 证据：https://arxiv.org/abs/2611.25562
- 要点：共享治理面；任务有稳定 ID，绑定发送者权限、执行 runner、必要审批、结果证据；默认 enrolled PC profile = 只读；scope gate 在交付地址变更时**重新请求审批**；28 组合成运行验证：对话中零业务任务、拒绝未授权 handoff、变更后零写入；配对保护写入用 mock provider。
- 可借鉴：**单据即治理单元**——一个 stable work ID 串起 authority/runner/approval/evidence（我们 ticket + ledger + acceptance 已接近，可补"审批与证据绑定"字段）；**范围变更触发重新审批**（对我们=派发参数/目标变化需重审）。
- 已覆盖：单号/台账/验收/网关；缺：把"权限-执行-审批-证据"显式绑在一个记录上。
- 不该学：合成 pilot 结论规模小，仅作设计参考。

### 3) Kortix CompanyOS（开源 agent OS，产品侧）
- 证据：https://github.com/kortix-ai/CompanyOS （“Introducing Kortix, the open source operating system for AI agents”）
- 判断：与 OneManCompany/Papperclip 同赛道；产品化/可安装性继续内卷。我们 M5 的 tarball/`stack up|run`/doctor 已补上可安装性，**产品叙事可差异化**（真实单据闭环 + 闸门 + 审计链，非 demo）。
- 行动：列产品观察，不引入外部依赖（供应链/责任边界）。

- 判断：四层基座 + per-skill trust gradient；我们已出设计稿（plan/10），等制作人过审后排实现。

## 对 StudioNext 的建议
1. **P1（高优，证据强）**：把"错误记忆机构"落到制度层——错误类一次性规则（`error-class → one-shot rule`）+ 复发计数 + 维护成本口径，挂到进化链/哨班；同时把 5 条行为规律做成风险清单进周审。
2. **P1**：验收/审批记录补"权限-执行-审批-证据"绑定的稳定 work ID 视图（对齐 AZOWL），并加"范围变更重新审批"检查。
3. **P2**：agents-radar 加入前沿侦察信源清单；Kortix 等产品维持观察。
