> 只设计不写码；不改代码/Docker/生产，不 commit/push（Lead 提交）。依据：Phase0 两切片（`a6ff308`/`a097003`，verifier PASS）、`docs/quality/phase0/collab-wake.md`、`vendor/workbench-core/PROVENANCE.md`、A 路线图（`docs/sentinel-logs/提案-A全替代路线图-2026-11-17.md`）。

## 〇、结论
- **启动 Phase1（建议）**：新 `workbench-chatd` sidecar（每公司一实例，Unix socket，非 TCP）持 `<companyDir>/var/workbench/chat.db`；daemon 新增 `WorkbenchTransport v1` 客户端 + `MentionSource`/`Notifier`/conversation 适配；Matrix 只读回滚。**不写** sidecar 业务代码（本单）。
- **P1 必须补 5 个缺口**：relay/lease/ack（Phase0 为进程内模拟）、跨进程 wake、cursor/租户密钥、`chat_events/outbox`、Matrix→collab 历史迁移；Element 不做 bridge，做**最小面板**（否则仍要 Docker）。
- **范围**：最小切片功能 + 双跑观测，**不做**单子、Element/外部 IM、HR/注册器、权限迁移；回滚 Matrix ≤10 分钟。
- **估时 30–45 人日**；0.4–0.5 FTE 约 8–12 周，低强度不阻塞运维；P1 只替 Matrix，**Docker 仍不能关**（Taiga 还在）。

## 一、sidecar 设计

### 1.1 进程/存储/生命周期
```
daemon ── Unix socket <companyDir>/var/workbench/chat.sock ──> workbench-chatd (每公司 1 实例)
  │  token 0600 + peer credentials/loopback-only                         ├─ chat.db（vendor collab + sidecar 扩展表）
  └─ 只经 daemon/panel 鉴权；浏览器/外部不可直连                         └─ cursor.key / logs / backups
```
- **每公司一实例**：`<companyDir>/var/workbench/{chat.sock,chat.db,cursor.key,logs/}`；0700；不写公司 git/ledger/.AIWS。
- **看护**：launchd label `io.studionext.workbench-chat.<company>`（KeepAlive、`RunAtLoad`、stdout/stderr 归档）；daemon 启动/每拍探活；sidecar 先起、daemon 后连；失败=Matrix 回滚，不阻塞 daemon 启动。
- **健康**：`GET /v1/health` → `{ok,version,db,migrations,pendingWakes,activeLeases,uptime}`；异常 fail-closed，daemon 切回 Matrix（只读）。
- **升级/回滚**：版本+`UPSTREAM.md` sha 钉住；升级前 `VACUUM INTO` 备份 chat.db → 停旧→启新→health+smoke→失败回退旧二进制+DB 快照；**不自动迁移不兼容 schema**；Matrix 只读保留。
- **鉴权**：Unix socket 文件权限 0600 + `X-Workbench-Token`（daemon 生成，存 `<companyDir>/var/workbench/transport.token` 0600）；不接受浏览器/外部；身份由 daemon 传 actor（来自 wkey/公司目录），sidecar 不登录、不注册、不判 HR。
- **多公司**：socket/DB/token/cursor key 均按公司隔离；daemon 配置按公司生成；不共享 actor/room 命名空间。

### 1.2 `WorkbenchTransport v1` 草案（JSON over Unix socket）
| 方法/路径 | 请求要点 | 响应/语义 |
|---|---|---|
| `GET /v1/health` | — | 版本/DB/迁移/pending/leases；只读 |
| `GET /v1/rooms` | `actorId`、可选 `roomIds` | 房间摘要（kind/name/member count/head/unread） |
| `POST /v1/rooms/:roomId/messages` | `senderId, body, kind?, mentions?, mentionAll?, replyToSeq?, idempotencyKey` | `{seq,roomSeq,messageId,replayed}`；幂等键 `(sender,room,key)` |
| `GET /v1/rooms/:roomId/messages` | `actorId, cursor?, limit?` | `{items,nextCursor}`；cursor 为不透明 HMAC，绑定 room+actor |
| `POST /v1/rooms/:roomId/read` | `actorId, upToRoomSeq, idempotencyKey` | `{unread,readAt}`；monotonic/clamp |
| `GET /v1/inbox` | `actorId, roomIds?, lastN?, includeMentions?` | 摘要/未读/mention/pendingWakeIds（不返正文） |
| `GET /v1/wakes/claim` | `holder, limit, leaseMs` | `{wakes[],leases[]}`；lease TTL；**P1 新增** |
| `POST /v1/wakes/ack` | `holder, wakeIds[], idempotencyKey` | `{acked[],alreadyAcked[]}`；**P1 新增** |
| `GET /v1/presence`（可选） | `actorIds` | `lastReadAt/lastSeenAt`（仅本地观测，非权威在线） |
| `GET /v1/audit`（可选） | `cursor` | 只读 `chat_events`（send/read/ack/delivery）；供 daemon 观测，非新事实源 |
> 错误码冻结：`UNAUTHENTICATED/FORBIDDEN/NOT_FOUND/CONFLICT/CURSOR_INVALID/LEASE_LOST/RATE_LIMITED/INTERNAL`；不新增 daemon 事件词。

## 二、daemon 侧适配
| 面 | 适配方式 | 开关/回滚 |
|---|---|---|
| **matrix source** | 新 `WorkbenchMentionSource` 实现 `InvokeSource`：轮询 `/v1/inbox`→`/wakes/claim`→按 wake 产 `InvokeIntent`（`dedupKey=wake:<id>`）→emit→`/wakes/ack`；mention/DM/reply/mention_all 直接映射；无 Matrix `/sync` | `matrix:false, workbenchChat:true`；回滚 `matrix:true` |
| **notify** | 新 `WorkbenchNotifier`/`NotifyBroadcastFace`：targets（company/alert/dept/room）→sidecar room ID；发送失败软失败+重试；不依赖 Matrix alias | 同上；Matrix notify 可保留只读回退 |
| **DM conversation** | sidecar DM 为传输；现有 `<companyDir>/conversations/<person>.jsonl` 降为**daemon 侧投影/审计**（由 sidecar 事件单向派生），不再由 Matrix 写；panel 通过 daemon 读写 | `conversation:true`；回滚 Matrix DM 只读 |
| **HR/房间** | **不迁 HR/账号/注册器**；公司目录 people→sidecar actor、部门→group 房间的映射由 daemon 配置；最小切片不做自动 HR 建号/入房（沿用现有 Matrix 只读） | 显式非目标；后续另议 |
| **鉴权** | 只走 wkey/daemon：daemon 从公司目录解析 actor，sidecar 只收 daemon token+actor；panel 不直连 sidecar；不引入 sidecar 登录 | 无公开端口/路由 |
| **双跑** | sidecar 承接新消息+notify+wake；Matrix 保持**只读历史**，不双写；daemon 记录 sidecar 事件/指标；1 周观测后切 | 停 sidecar→`matrix:true`→恢复 Matrix 消费者（≤10min 演练） |

## 三、P1 缺口补齐方案
1. **relay/lease/ack（必须）**：vendor 无 API（Phase0 进程内 lease 模拟）。在 sidecar **自有扩展表** `wake_lease(wake_id,holder,expires_at,attempts)`＋`wake_delivery`，不 fork vendor 业务表；claim=原子选 pending/过期租约，TTL 30–120s；失败退避≤3 次→dead-letter（sidecar 日志 + daemon `ESCALATE` note，不新增事件词）；ack 幂等；daemon 侧 `dedupKey` 兜底。
2. **跨进程 wake**：不做 push；daemon 轮询 Unix socket（500ms–2s；可选 long-poll `waitMs≤5s`）；lease 保证重试不双投；指标 `claim_latency/lease_expired/dead_letter`。
3. **cursor/租户密钥**：每公司 `cursor.key` 0600；vendor cursor HMAC 绑定 room+actor；sidecar 不接受跨公司 cursor；轮换=旧 cursor 失效（可观测）；不落日志/不入 git。
4. **chat_events/outbox（必须审计）**：sidecar 自有 `chat_events`（append-only：send/read/ack/delivery/deadletter）+ `chat_outbox`（同事务）；daemon 只读 `/v1/audit` 做观测；**不新增 daemon 事件名/不改 ledger**；审计事实在 sidecar，daemon 台账仍只记自己的事件。
5. **历史迁移（必须）**：Matrix 账号/房间/消息导出（只读）→`actorMap.json`/`roomMap.json`；MXID→actor、alias/room→sidecar room、成员/owner→membership；按时间导入 body/kind/reply/mentions；旧历史**不重放 mention**；read cursor 基线=导入末 seq；导入脚本幂等+count/hash diff；失败回滚 Matrix。
6. **Element/UI（取舍）**：**不做 bridge**（bridge 保留 Matrix/Docker，违背目标）；做**最小面板**（复用现有 Hono panel conversation 面：房间列表/DM/消息/发送/@/read/wake；无搜索/附件/富文本）；面板不直连 sidecar，只经 daemon。UI 延后则 P1 不切 Matrix。

## 四、最小切片与验收
- **功能**：1 broadcast 房 + 1 DM；mention/reply/read/wake；daemon notify 可达；producer DM conversation 回读；sidecar restart 后消息/read 状态保留。
- **非目标**：Element/手机/外部 IM；HR 建号/入房/PL/kick；单子；权限/注册器迁移；多租户外部分发。
- **指标/验收**：双跑（sidecar 主 + Matrix 只读）≥7 天；消息/通知/唤醒 **0 漏、0 重复**（按 sidecar audit + daemon 事件/去重键核对）；wake 恰一次（lease+dedup 断言）；回滚演练 ≤10 分钟且 Matrix 历史可读；`verify:v2`/typecheck 绿；无新事件词/契约变更；独立 verifier PASS。
- **测试**：幂等 send/ack、lease 过期重投、dead-letter、cross-room/cross-actor cursor、sidecar kill/restart、socket 断连、history import 10→全量、回滚脚本。
- **负责人**：Lead 统筹；1 名实现 owner；阶段末独立 verifier；制作人验收。
