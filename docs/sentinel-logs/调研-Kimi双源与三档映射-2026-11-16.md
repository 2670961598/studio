# Kimi K3.1 Pro 双源接入可行性 + 三档映射方案（只读调研，task-45）

> 2026-11-16 制作人构想：best=Kimi K3.1 Pro｜mid=GLM-5.3｜low=DeepSeek Flash 4.1。
> 本单只做证据调研，不改 models.yaml / host 配置 / 生产 daemon / 不 commit。结论供拍板后另立实现单。

## 0. 一句话结论

- **opencode-go 确实提供 `kimi-k3.1-pro`**（模型目录 + 本机 API key 实测 `/models` 可见 + 实际 chat 调用 HTTP 200），走 **dsh provider** 就能接，**无需新 adapter**；但账号实测为 **Go Plus** 且响应 allowance=4×list_cost（Kimi 月度额度需按保守 **$15 list 等价/月**理解，不是 $60 现金），覆盖不了“全部 GLM 流量”，只适合**高层/低频 high**；高频需 KimiCode 订阅或另买额度。
- **本机 KimiCode CLI 可非交互调用**（`-p --output-format stream-json -m kimi-code/k3.1-pro`，实测 OK），但**现有 kimi adapter 不能直接用**：实际 wire 路徑/usage 记录形状与 adapter 拟稿不符（`sumWireUsage` 返回 undefined），且 Kimi 无 seatbelt 端子、workspace-write 构造期会被拒；改造量远大于 opencode-go 方案。
- **推荐阶段1**：high=**opencode-go/kimi-k3.1-pro**（单源，dsh 四档，热切秒生效）；mid=GLM-5.3 不变；low=**opencode-go/deepseek-v4.1-flash**。KimiCode 作为**阶段2备源**（需补 adapter/usage/seatbelt，不建议本期做自动 fallback）。

## 1. opencode-go 是否有 kimi3.1pro

`.../pi-ai/dist/providers/data/opencode-go.json` 含 `chat:kimi-k3.1-pro`：
- id=`kimi-k3.1-pro`，provider=opencode-go，api=`openai-completions`；
- contextWindow=**1,048,576**，maxTokens=**131,072**；
- cost（list，USD/M）：input **2.00** / output **10.00** / cacheRead **0.20** / cacheWrite **2.00**；
- baseUrl `https://opencode.ai/inference/go/openai/v1`。

**账号 entitlement 实测（只读 GET）**：用本机 `~/.dsh/.credentials.yaml` 的 OPENCODE_GO_API_KEY 调
`GET https://opencode.ai/inference/go/v1/models`（key 未打印）→ HTTP 200、32 个模型，含
`kimi-k3.1-pro`（及 kimi-k3、kimi-k2.7-code）。证据：`/tmp/kimi-evidence/opencode-go-models.txt`（脱敏后）。

**Go 套餐口径（官方 docs，实测页面）**：
- Go $10/月、Go Plus $40/月、Go Teams $20/人/月；Kimi K3.1 Pro 在 included models 列表内。
- token 计量价（Go/Go Plus/Teams 同价）：$2/$10/$0.20/$2 per 1M；**Kimi 月度额度 Go=$15、Go Plus 控制台 $60（allowance 口径；实测 4×list，保守按 $15 list 等价理解）**；5h=月度 20%、weekly=50%。
- 估算请求：Kimi K3.1 Pro ≈ **147 req/5h（Go）/588 req/5h（Go Plus）**；官方估算每请求约 1,050 input + 76,500 cached + 300 output tokens。
- 历史：profile 注释记录 2026-11-07 opencode-go Go 额度耗尽（GoUsageLimitError 429 风暴）→ 当前需要把额度上限当硬约束。
- **实际调用实测（2026-11-16）**：`POST https://opencode.ai/inference/go/openai/v1/chat/completions` model=`kimi-k3.1-pro` → HTTP 200；响应 model=kimi-k3.1-pro，usage.opencode=`{billing_source:"go-plus", list_cost:0.000218, allowance:0.000872}`；第二次/list_cost 0.000496、allowance 0.001984（**allowance 恒 4× list_cost**）。按本月度上限列 $60（Go Plus 控制台）÷4≈**$15 list 等价/月**（与 Go 档 Kimi 月 $15 同量级）；该单位语义需 OpenCode 确认，先按保守 $15 预算。证据 `/tmp/kimi-evidence/opencode-go-kimi-probe.json`。
- 隐私：Kimi K3.1 Pro 不用于训练、0 天保留（OpenCode docs 表）。
- **注意**：现有 models.yaml 对 deepseek-v4.1-flash 用 0.015/0.06（list 的 1 折）；OpenCode 官方计量表是 $0.15/$0.60（off-peak），说明现有“1折”是项目内折算约定，**不是模型计量口径**。Kimi 若沿用 1 折会低估 Go 额度消耗 10 倍——见 §4。

## 2. 本机 KimiCode（kimi3.1pro）

**安装/配置**：`~/.kimi-code/bin/kimi` v2.1.1；`config.toml` default_model=`kimi-code/k3.1-pro`；
`models."kimi-code/k3.1-pro"` = managed:kimi-code / model k3.1-pro / context 1,048,576 / thinking+tool_use；
`kimi provider list` 显示 `managed:kimi-code models=6`（OAuth source）。

**非交互调用实测**（不写真实台账/不改 host 配置；用临时 `KIMI_CODE_HOME` 隔离数据面）：
```sh
KIMI_CODE_HOME=<tmp>/kimi-home ~/.kimi-code/bin/kimi \
  -p '只回复两个字符：OK' --output-format stream-json -m kimi-code/k3.1-pro
```
结果：exit 0，stdout 3 行 JSON（system.version / assistant "OK" / session.resume_hint），
无 usage；`--help` 确认 `-p/--prompt`、`--output-format text|stream-json`、`-m/--model`、`-S/--session`；
`-p` 与 yolo/auto/plan 互斥（维持 kimi.ts 头注纪律：框架只发 `-p` 基座）。
注意：默认 HOME 下直接跑时 **storage write failed: permission denied**（当前会话沙箱只允许 workspace/tmp 写）；
用临时 `KIMI_CODE_HOME` 可跑通，说明 daemon 必须把 CLI 数据目录**重定向到可写工位内**。

**usage 取数（关键差异）**：真实 wire 落
`<KIMI_CODE_HOME>/sessions/wd_<workspace>_<hash>/<session_id>/agents/main/wire.jsonl`；
本次实际含：
`{"type":"usage.record","usage":{"inputOther":7102,"output":34,"inputCacheRead":12800,"inputCacheCreation":0}}`
与 `step.end` 同形 usage；`token_counting.turn_recorded.tokens=19936`。
但现有 `packages/adapters/src/streams.ts` 的 `sumWireUsage` 只认 `type:"usage"` 且字段名
`input_tokens|input` 等——对真实 wire 实测返回 **undefined**（证据见 `/tmp/kimi-evidence/kimi-wire-usage-sample.jsonl`）。
因此：**kimi adapter 的 usage 假设需重写**（支持 `usage.record` + inputOther/inputCacheRead 映射），
且 wire 路径 resolver 当前拟稿 `<workspace>/.kimi/sessions/<harnessSessionId>/wire.jsonl` 与真实路径不符；
session id 来自 stdout `session.resume_hint.session_id`（`session_<uuid>`），需与 wire 目录对齐。

**seatbelt/daemon 环境**：
- Kimi 无 seatbelt 端子：`packages/adapters/src/agentconfig.ts` `assertSeatbeltTerminal('kimi', …)` 对
  `workspace-write` **构造期 CONFIG_INVALID**；生产 daemon `seatbeltTier: workspace-write`，所以 kimi executor
  **不能仅靠加 agent.yaml 就上线**，必须补 seatbelt 端子或将其降为 read-only（与生产安全档冲突）。
- 本会话内直接用 `sandbox-exec -f` 套 Kimi：**exit 71 `sandbox_apply: Operation not permitted`**（macOS 拒嵌套
  sandbox；与本仓既有 PRB-04 结论一致），不能在此环境验证真 seatbelt 圈定；静态 profile 已生成
  （`/tmp/kimi-evidence/seatbelt-profile.sb`，628B），daemon 在非沙箱宿主侧 apply 的路径未被本单证明。
- 结论：KimiCode 本地路径要上生产，需 kimi adapter 真 CLI 探针单（usage/wire/路径/seatbelt 四项）一起做。

## 3. 接入最小路径与风险

**A（推荐，阶段1）opencode-go/dsh provider**：
- models.yaml：high `{provider: opencode-go, model: kimi-k3.1-pro, price: ...}`；mid/low 不变/另配。
- agent.yaml 不需要新增 executor：`dsh-high` 已挂 `<rootDir>/tmp/dsh-tier-high.yml`；daemon 热切重写 overlay 后，下一次 dsh spawn 即用 `provider: opencode-go, model: kimi-k3.1-pro`（task-34 热切已验证同类路径）。
- 风险：Go 额度（Kimi 月 $15/$60 list 等价；当前账户按 $40 Go Plus 口径）、opencode-go 对 Kimi 的 session header/路由兼容（官方 validated clients 表未列 DeepSeek Harness，属“可用但不保证”）、价格口径（见 §4）、失败时无自动备源（需人工热切）。
- 改动量：models.yaml + 映射表 + 部署验证；**零 adapter/零契约**。

**B（阶段2）本机 KimiCode/kimi adapter**：
- 需新增/启用 kimi executor 档位（agent.yaml cmd `kimi -p --output-format stream-json -m kimi-code/k3.1-pro`）；
- 需补：真实 wire 路径注入、`usage.record` 解析（inputOther→input、inputCacheRead→cache_read、inputCacheCreation→cache_creation）、session id 映射、KIMI_CODE_HOME 写域重定向、seatbelt 端子（否则 workspace-write 拒启动）；
- 风险：headless 行为/续跑/额度未知；当前 fake-only 绿不能当证据。**不建议本期作为生产主路径**，仅作为“订阅额度备源”阶段2候选。

## 5. 双源设计选择

- **(a) 单档单源（推荐本期）**：每个 tier 的 models.yaml 只写一个 provider/model；换源=改 models.yaml 热切（秒级、不重启；task-34 已验证）。实现风险最低，成本口径单一；缺点是源故障需人工/脚本热切。
- **(b) 主备自动 fallback（不建议本期）**：需要 daemon 支持“档位多源+健康探测+失败重试+价格归属+预算分离”；会把 dispatch/adapter/价目/收割链路都扩大，且自动切换时在途单模型归属与 COST_RECON 更难解释。改动量中高、风险高；建议等 (a) 跑稳且有明确 SLA 需求再立提案。

## 7. 风险与缺口

1. **KimiCode 订阅额度/计费不透明**：本机 OAuth 可用但无套餐/usage API；按订阅 sunk cost 记账前必须问清套餐。
2. **OpenCode Go 额度是硬约束**：Kimi 月 $15（Go 表）/控制台 $60（Go Plus）；本机实测 allowance=4×list_cost，保守按 **$15 list 等价/月**；147/588 req/5h；历史有 429；高优/评审流量一旦涨会撞顶。
3. **现有 DS 1折口径 vs OpenCode 官方 list**：Kimi 若照抄 1 折会低估额度消耗；建议另单统一 price snapshot 口径。
4. **KimiCode adapter 真 CLI 未验**：wire 路径/usage 形状与拟稿不符（实测 sumWireUsage undefined）；无 seatbelt 端子，workspace-write 构造期拒；Kimi 的 `KIMI_CODE_HOME` 又是 AGENTS.md user_level 通道候选，写域重定向需设计。
5. **opencode-go 对 DeepSeek Harness 兼容**：官方 validated clients 列表未列 DSH，标注“可用但不保证”；Kimi 路由历史撤过，key/隐私区域需账户侧确认。
6. **质量风险**：Kimi 在 verifier/judge 的判据一致性未 benchmark；建议先影子 A/B（同一任务双跑）再切 high。
