## 四、预演抓出并修复的真缺陷（迁移器活动流 id 重复）

dry-run 平台树校验（脚本 §1）对 M2 实跑树（`/tmp/lp-real-sandbox`，保留未动作证）报 **769 个重复活动 id**：

- 根因：`taiga-localplatform-migrate.ts` 旧版为 created 活动自持 `max` 计数器，而评论/lane 走平台 API
  （`appendActivity`→`nextActivityId`=文件态 max+1），**双计数器交错写**→id 撞号（1554 created 与
  584 commented/185 field-set 共 2323 行只占 1554 个 id）。
- 危害：违反 `packages/localplatform/src/activity.ts` 头注「id 单调递增」不变量；daemon 每 tick 经
  `platform.activity.since(cursor)` 增量翻页（engine/tick/collect.ts:125），游标语义=**严格大于边界**——
  同 id 后行会被分页边界永久跳过（丢活动）。
- 修复：created 活动 id 改从文件态取（`nextActivityId`，平台唯一计数权威）；`existingActivityIds`→
  `existingCreatedActivityIssues`（幂等判据保留）。修复后重跑（1.365 s，planHash 不变，issues/、
  meta/fields.json、migration-audit 与 M2 产物**逐字节一致**——只有 activity id 分配变了）：2323 行 2323 个 id，
  0 重复 0 跳号（a-000001…a-002323）；G2 幂等复跑 written=0、树哈希 `25c793a8…` 不变。
- 结论：**切换日必须用修复后迁移器重迁**（或对既有树先过 dry-run 树校验）；本预演拷贝树即修复后产物。
