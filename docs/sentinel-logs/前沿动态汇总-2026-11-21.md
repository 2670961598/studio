# 前沿侦察 2026-11-21（只读；近一周 GitHub/arXiv/厂商页）

## 结论（TL;DR）
本周最相关的是 **"The Agentic Company OS"（arXiv 2609.13334，AGENTICS 2026 正式短论文）**：主张给企业 agent 重建"认知基座"（Data/Knowledge/Intelligence/Governance 四层、Sync Agent 动作边界、per-skill 信任梯度、Markdown 为当下实例而非已证原语）。这与我们"公司目录=基座 + 网关动作边界 + 台账审计 + 验收闸"同构，且给了两个可落地补强：**per-skill 信任梯度**与**动作边界隔离**。产品侧 OneManCompany/AG-UI/PaperOrchestra 继续升温；治理/审计论文（RelLedger、GAMPO）延续。

## 3-5 个最相关对比

### 1) The Agentic Company OS（arXiv 2609.13334，最相关学术）
- 证据：https://arxiv.org/abs/2609.13334
- 要点：企业 agent 演示成功但持续运营失败，根因是数据按"人类/传统应用"结构而非 LLM 推理面组织；主张**重建认知基座**（四层：Data/Knowledge/Intelligence/Governance），把 schema 转换隔离到**动作边界**（Sync Agent），治理与可审计性成为基座的结构属性（per-skill 信任梯度 + 审计），并讨论 compile path 的间接提示注入风险。
- 可借鉴：①**per-skill 信任梯度**——我们可按技能/命令面定义信任等级（只读/可写/需审批），比"一刀切闸"更细；②**动作边界单一收口**（我们已有网关/单写入者，可写进对外文档与 M5 打包说明）；③**基座=Markdown/YAML** 的利弊实证（我们公司目录已如此，应补一条"为什么适合 LLM 阅读"的设计依据）。
- 已覆盖/更强：我们有三事实源分离、唯一写入者、验收 enforce、证据链/独立验证、真实执行器；论文是 position paper（无生产数据），我们是可运行系统。
- 不该学：把"基座反转"当唯一解（他们自认 Markdown 未证明）；不因此重写现有目录结构。

### 2) OneManCompany（产品级对标，延续上周）
- 证据：https://github.com/1mancompany/OneManCompany
- 判断：仍是最直接"一人公司 Agent OS"产品；Vessel+Talent、会议室、绩效/PIP、一键 npx。我们 M5 的 `stack up/run`、tarball、doctor 已补上"可安装性"差距；下步可做 1 页能力对照（前周已有简报），不引入其外部 Talent 市场。

### 3) AG-UI（agent↔UI 交互协议，生态继续扩张）
- 证据：https://docs.ag-ui.com/introduction
- 判断：我们自研 Transport v1 管 daemon↔chatd；AG-UI 是"前端↔agent 事件流"层，若面板要接第三方 UI 可作参考，不与 Transport v1 混用。

### 4) RelLedger / When Agent Governance Helps（治理/审计延续）
- 证据：https://arxiv.org/html/2610.16281v1 、https://arxiv.org/abs/2609.05531
- 判断不变：归因账本+下游回放、answer-blind 逐任务 DoD；我们已有台账 hash 链/验收四要件，建议把"answer-blind DoD 审计项"补进验收检查单（前周建议，未落地）。

### 5) Google PaperOrchestra（AI 论文写作框架，趋势观察）
- 证据：https://blockchain.news/news/google-paperorchestra-ai-research-framework
- 判断：科研自动化赛道信号；与"公司式多 agent 交付物（游戏/漫画/研究）"方向相关，暂列观察，不引入。
