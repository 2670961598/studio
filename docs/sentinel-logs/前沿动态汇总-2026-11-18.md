# 前沿侦察 2026-11-18（只读；范围：近一周 GitHub/arXiv/厂商公开页）

## 结论（TL;DR）
本周与 StudioNext 最相关的不是"又一个 agent 框架"，而是**"AI 公司控制面"**这一层的成熟化：Paperclip（MIT、10 万+ stars）把 org chart/任务/审批/预算/运行记录做成自托管产品；MiniCorp（arXiv 2610.05912v2）把"AI 公司"做成可回放、可反事实对比的企业数据生成器。二者都印证我们"事件/证据/治理"方向，但都没有我们已有的**失败即拒（fail-closed）验收闸 + 三事实源 + 执行器中立**。可借鉴：heartbeat 唤醒节奏、审批队列 UX、反事实回放评估；不学：记录式预算（会超支）、默认遥测、把"审阅"当安全边界。

## 3-5 个最相关对比
### 1) Paperclip（最相关竞品/控制面）
- 证据：https://paperclip.app/product/open-source/ ；https://github.com/paperclipai/paperclip （MIT；v2026.1106.0；10 万+ stars）
- 定位：自托管控制面（本地/服务器），公司记录、org chart、任务、审批、预算、每次运行记录；agent runtime 自带（Claude Code/Codex/process/HTTP adapters）；嵌入式 PostgreSQL。
- 可借鉴：**heartbeat 按节奏唤醒 agent**（任务/评论/阻塞/时间驱动）；审批队列的产品化 UX；org chart（角色/经理/预算线）——与我们 org-config/岗位模型同构，但产品面更完整。
- 我们已覆盖/更强：三事实源分工、网关唯一写口、验收四要件 + enforce、预算前置 fail-closed 检查（其"记录式预算可超支"是明确短板）、执行器适配器与多公司隔离。
- 不该学：recorded-cost 预算（超支；我们保留 precheck+HOLD）；默认遥测开（我们默认关）；"任务审阅"不拦截外部调用（我们以网关/证据闸兜底）。

### 2) MiniCorp（arXiv 2610.05912v2，2026-10）
- 证据：https://arxiv.org/abs/2610.05912v2
- 定位：AI 公司办公模拟器：外部市场（客户/竞争/机制）+ 内部 agent（观察/讨论/决策）；持续记录沟通与决策、支持 checkpoint 回放与"同一情境不同决策"反事实对比；用于生成企业级纵向训练/评估数据，并对真实市场模式做保真度评估。
- 可借鉴：**反事实回放（counterfactual replay）作为评估面**——我们的事件账本已是 append-only/可重建投影，天然支持"同起点不同决策"回放，值得进评估 backlog；纵向记录"当时可得信息 + 后续结果"的样本化。
- 已覆盖：层级组织/角色协作/长期战略指导；我们多公司 + 真流程（Taiga/工单/验收）。
- 不该学：把"模拟公司"当产品替代真实经营（我们是真公司跑在真流程上）。

### 3) awesome-agent-orchestrators（索引，非框架）
- 证据：https://github.com/erson/awesome-agent-orchestrators
- 价值：metrics-backed 的编排工具索引（multi-agent swarms、personal assistants 等分类），适合做**竞品观察清单**。
- 行动：纳入季度前沿扫描源，不引入依赖。

### 4) Paperclip Companies（公司模板仓，检索到）
- 证据：https://raw.githubusercontent.com/paperclipai/companies/main/README.md （本次 raw 拉取失败，仅检索可见）
- 价值：预置"公司"定义（角色/技能/流程）作为模板分发的思路，与我们 `templates/` 公司脚手架同向；可借鉴"可安装的公司模板"命名/版本化。
- 注意：需下次网络可达时核实内容与许可证（本次未读到正文，不下结论）。

### 5) edict/cft0808（延续跟踪）
- 三省六部式多 agent 概念项目（前日报告已对比）；本周未见需要改变结论的新证据：概念可借鉴、token 成本高、无我们的事件/验收治理面；不采纳实现，只保留在观察清单。

## 对 StudioNext 的建议（按优先级）
1) **P1 评估 backlog**：用现有 append-only 账本做"反事实回放"原型（同一起点重放不同决策，比较验收/成本/耗时），服务模型路由与组织策略评估。
2) **P2 产品面**：借鉴 Paperclip heartbeat 节奏与审批队列 UX（我们已有 scheduler + mention wake + acceptance gate，缺"人可读的审批收件箱"）。
3) **坚持差异化**：fail-closed 预算/验收闸、三事实源、多公司隔离、执行器中立（Kimi/GLM/DSF 可换）；这些恰是 Paperclip 的短板（预算超支、审阅非边界、遥测默认开）。
4) **不引入**：Paperclip 作为依赖（控制面与我们重叠且 MIT 但会引入第二套事实源）；MiniCorp 模拟器（仅借鉴评估方法）。
5) 把 awesome 索引 + Paperclip Companies 加入季度扫描源；待网络允许时补读模板仓与 boardroom-os/aicompany 等 npm 包正文。
