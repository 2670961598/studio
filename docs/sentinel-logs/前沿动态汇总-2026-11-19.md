# 前沿侦察 2026-11-19（只读；范围：近一周 GitHub/arXiv/厂商公开页）

## 结论（TL;DR）
本周最相关的是**"Agent 组织的治理/审计"从概念走向可审计协议**：RelLedger（arXiv 2610.16281）给出"哪些事实能进入共享记录"的关系性信息治理审计框架；DGF-Bench（arXiv 2609.34913）把"治理委员会 gate"做成可判定的对抗基准，强调**权威记录 vs 不可信叙事**分离与归因成功判定。两者都在证明我们"三事实源 + 证据链 + 验收闸"方向正确，并给出可借鉴的**归因账本/对抗验收语料**两种工程形态。控制面类（hiveplane/Paperclip）继续成熟，但无新威胁。

## 3-5 个最相关对比

### 1) RelLedger（arXiv 2610.16281v1，2026-10-12）
- 证据：https://arxiv.org/abs/2610.16281 ；https://arxiv.org/html/2610.16281v1
- 内容：审计 LLM agent 组织中"关系性上下文是否改变事实入库/传递给下游"（relational policy leakage）；交叉历史/角色重指派/历史重写/记录可见性控制；attribution ledger 把每个主张映射到所需干预单元，区分缺失干预与采样不确定性；recipient replay 追下游决策；5 模型×302,764 记录，Claude 事实通知 62.22pt 差异、下游复核 −45.83pt。
- 可借鉴：**归因账本**（claim→必要干预→覆盖 vs 不确定）与我们事件台账/验收证据链互补；**recipient replay** 可作"证据进入下游后是否改变决策"的审计面；"显式损失规则→关系差异变小"支持我们"规则/闸门优先于模型自觉"。
- 已覆盖：事件台账/append-only/可重建投影、验收四要件、enforce 闸；**不覆盖**：关系性信息泄漏审计（可作为研究 spike）。
- 不该学：模拟实验当产品；指标不可直接移植。

### 2) DGF-Bench（arXiv 2609.34913，2026-09-28）
- 证据：https://arxiv.org/abs/2609.34913 ；摘要页：https://aisecurity-portal.org/en/literature-database/dgf-bench-a-benchmark-for-simulating-and-auditing-deception-against-multi-agent-governance-boards/
- 内容：多 agent 治理委员会（专家 gate+General gate）审核合成项目卷宗；61 条可执行规则/42 权威记录/32 叙事文档；攻击者只在"组织不担保的叙事"里注入；攻击不改变权威值，成功必须**归因**（收到注入且采取与干净卷宗不同的精确动作）；6 模型 DGF 分 96.2–26.9；"模仿组织自身流程"的任务对齐攻击对 4/6 模型有效。
- 可借鉴：**权威记录 vs 不可信叙事**分离（正是我们的公司 git/Taiga/SQLite 事实源 vs LLM 上下文）；**gate 可判定性**（决策可由记录判定）；**对抗验收语料**：给验收闸/审计加"伪造流程/假权威"红队样本；归因成功判定思路。
- 已覆盖：事实源唯一写入者、验收四要件、enforce、独立 verifier；**不覆盖**：针对治理 gate 的系统性对抗基准（可作 QA 设施 backlog）。
- 不该学：把"委员会模拟"当真实组织运行。

### 3) hiveplane（PyPI 0.2.0，2026-11）
- 证据：https://pypi.org/project/hiveplane/0.2.0/
- 定位：生产 agent 舰队控制面（轻量 control plane）。
- 判断：与 Paperclip 同类，作为**观察清单**；无证据表明其具备我们的事件/证据/验收治理面；不引入依赖。

### 4) AI 开源趋势日报（gittok / agents-radar，2026-11-08/11-12）
- 证据：https://github.com/Chestnuts-Sisyphus/gittok/issues/1919 ；https://github.com/duanyytop/agents-radar/issues/4244
- 用途：趋势/高星项目索引（自动摘要，需二次核实）；加入季度扫描源，不据此决策。

### 5) 延续跟踪：Paperclip / MiniCorp（前周已对比）
- Paperclip（MIT 自托管控制面）、MiniCorp（arXiv 2610.05912，公司模拟+反事实回放）结论不变：借鉴 heartbeat/审批 UX、反事实回放评估；不引入依赖、不做模拟公司。

## 对 StudioNext 的建议（按优先级）
1. **P2 研究 spike（1-2 天）**：把 RelLedger 的"attribution ledger + recipient replay"映射到我们的 events/验收链，出 1 页可行性（不接生产、不新增契约）。
2. **P1 QA backlog**：DGF-Bench 思路 → 给验收闸/审计做"权威记录 vs 叙事注入"红队语料（伪造流程/假权威/假数据），仅测试面；先做 acceptance E2E 的 3-5 个对抗样本。
3. **P2 观察**：hiveplane/Paperclip 纳入季度扫描；趋势日报作为索引（需核实）。
4. **不引入**：RelLedger/DGF-Bench 代码依赖；模拟组织/委员会当产品。
5. **固定节**：日报/前沿汇总持续跟踪"agent 组织治理/审计"方向。
