# 预案：模型路由（多源）启用（2026-11-17）

> 只读预案，不改配置/生产；待制作人批准后按此执行。依据：`docs/quality/model-routing.md`、`提案-模型优先级与自动切换-2026-11-16.md`、task-56/66/67（切片2 落仓 `64ddb2f`，**未部署**）。

## 〇、结论

当前 deploy 树 `85f18ec` **不含**路由切片2（其落仓 `64ddb2f`）；启用需一次"部署新 ref + 重启 daemon"。启用后 `models.yaml` 改 sources 列表走**热切**（无需再重启），回滚改回单源同理。建议**先只给 high 档配双源**（低频、可观察），mid/low 保持单源；`allowBudgetDowngrade=false`（默认，不擅自降档）。

## 一、前置条件（全部满足才启用）

1. 部署含 `64ddb2f`（或更新）的 ref，`deploy.mjs` 通过、healthz/tick/preflight 正常；
2. 备份：`daemon.yaml`、`models.yaml`（带时间戳，出问题可秒回）；
3. `verify:v2` 全绿（含 manifest/old-ledger/scan）；路由 E2E 4/4（failover/fail-all/budget/single）；
4. 制作人批准：源选择、价格、quota、观察期。

## 二、配置模板（high 档双源；mid/low 不动）

```yaml
tiers:
  high:
    sources:
      - id: glm-main
        provider: glm
        model: GLM-5.3
        priority: 10
        price: {inputPerM: 1.1111, outputPerM: 3.8889, cacheReadPerM: 0.2778}
        cooldown: {baseMs: 60000, maxMs: 28800000, circuitAfter: 3}
      - id: go-kimi
        provider: opencode-go
        model: kimi-k3.1-pro
        priority: 20
        price: {inputPerM: 2, outputPerM: 10, cacheReadPerM: 0.2, cacheCreationPerM: 2}
        quota: {kind: monthly, limitUsd: 15, resetAt: resetAt=null}   # 仅登记/审计；Go Plus allowance≈4×list≈$15/月
  mid: {provider: glm, model: GLM-5.3, price: {...}}     # 保持单源
  low: {provider: glm, model: GLM-5.3-Flash, price: {...}}  # 保持单源
roles: {main_worker: mid, verifier: high}
```

- **不得**同一档混写 `sources[]` 与旧三键（CONFIG_INVALID）。
- 价格按实际源归属写 work_records/price snapshot；日闭按"混合源日"口径说明。
- Kimi 只在 GLM 429/额度/5xx/网络失败时兜底（低频）；opencode Go Plus allowance 较小，需盯当日用量。

## 三、启用步骤（制作人批后）

1. 部署新 ref（重启 daemon 一次）：`deploy.mjs deploy --ref <含路由切片2的 commit> --log ...`；验证 healthz pid 变更/tick 前进/启动无 preflight 失败；
2. 备份 `models.yaml`；写入上面 sources 配置（原子写）；
3. **热切验证**：daemon 日志 `MODELS_RELOAD`（或等价热切事件）；healthz `routing.sources[]` 显示两源 available；`models.yaml` fingerprint 变化；
4. 低成本冒烟：派一张 high 档小单（或等自然 verifier 单），确认 DISPATCH note 含 `modelsrc=glm-main`/价格，无异常降级；
5. 观察 3–7 天（见下）。

## 四、观察指标（每日）

- `DISPATCH` note `modelsrc=`/`price=`：主源应为 glm-main；出现 go-kimi 说明发生降级（应有对应 `MODEL_ROUTING_FAILOVER` + 冷却）；
- `ESCALATE`：`MODEL_ROUTING_FAILOVER`（降级/冷却）、`MODEL_ROUTING_BUDGET_HOLD`（预算拒绝，去重）；
- 冷却/半开：healthz `routing.sources[]`（cooldownUntil/lastFailureClass）；
- 成本：日闭 delta≈0；按 model 归属核对（GLM vs Kimi）；Kimi 用量是否超 allowance；
- 异常：`ALL_SOURCES_UNAVAILABLE`（理论不应频发）。

## 五、回滚（≤5 分钟）

- **配置级**：`models.yaml` 改回单源（原子写）→ 热切生效，无需重启；
- **代码级**：若路由接线本身有问题 → `deploy.mjs` 回部署 `85f18ec`（旧 ref）+ 配置备份恢复；重启 daemon；
- 回滚后确认 healthz/tick/派发正常、无冷却残留影响（单源=现状）。

## 六、已知限制（启用前知悉）

- 同一次 dispatch 内 launch 失败**不自动换源**（下一 attempt 换）；
- 预算预检为 `cap−settled−reserved` 的引擎折叠近似（未逐笔双帽对账）；
- `allowBudgetDowngrade` 无配置来源，MVP 固定 false；
- 源配额仅登记/审计，不主动探测（无余额 API）；
- 热切新增源的价格 snapshot 不即时补种（需确认 seed 时机，必要时下次重启）。
- 在途 worker 不换源（argv 快照）；这是有意设计。
