## 〇、总判断

1. **六层职责干净、依赖单向**：sdk（注册契约）→ core（引擎+feature+runtime+wiring 纯逻辑）→ ports/adapters（SQL 唯一落点）→ host（DSH 宿主半，transport-free）→ client（浏览器半）→ lib（构建产物）。全仓只有 `lib/index.js` 一个文件 import DSH 包。
2. **它不是"面板皮肤"，是一个自洽的微内核平台**：权限引擎、事件/订阅/join 引擎、多公司物理隔离运行时、conformance kit、bench 阈值门都在仓内成型，且零第三方依赖（`workbench-plugin/README.md:3`）。
3. **与我们 11-16/11-17 两篇评估的结论仍成立**：issues/org 不能直接替代（字段/流程/事实源冲突），chat 内核最接近；StudioNext 已按此落了 workbench-chatd/workbench-transport/localplatform（见 §五映射）。
4. **主要风险是文档漂移与路径硬编码**：README 记 539 用例、目录树缺 wiring/subscription/host 写面等新件，实测顶层 `test()` 已 907；`cordis.patch.yml:22-25` 与 `src/host/config.ts:53` 硬编码本机绝对路径。
5. **最值得吸收的三件**：产物逐字节比对门禁、conformance kit（checksum+golden+strict）、错误面单点收口（冻结错误码目录+ErrorMapper）。

## 一、分层架构

### 1.1 文字图（依赖方向自上而下，禁止反向）

```
DSH daemon 进程                          浏览器（DSH web shell）
─────────────────                        ─────────────────────
cordis.patch.yml (bundle 行, config)
  └─ lib/index.js  ←唯一 import DSH 包的文件（Cordis Service + TypertRemote）
       └─ src/host/  组合根：config→registry→resolver→{meta,hr,chat,issues}
            └─ src/core/
                 ├─ engine/access   权限引擎 v1（纯函数判定+次数授权+租约）
                 ├─ engine/event    事件引擎（契约/信封/快照/join/订阅/wiring 编译）
                 ├─ engine/trigger  占位
                 ├─ feature/{org,issues,chat,im(占位)}   领域内核
                 ├─ runtime/        多公司工厂（每公司四库物理隔离）
                 └─ wiring/         纯规则包（连接矩阵/过滤三值/join 状态机唯一源）

```

### 2.2 协议

- 契约版本冻结 `workbench-ui/1`（`src/host/meta.ts:29`）；四个 Remote 命名空间：workbenchMeta/Hr/Chat/Issues（`lib/index.js:80-304`）。
- bootstrap 单握手：身份+可访问公司列表+聚合能力位+静态目录一次拉齐（`src/host/meta.ts:37-83`）。
- 错误协议：14 个冻结 `workbench/*` 码带 httpStatus/retryable 种子；域错误（ORG_*/ISSUES_*/COLLAB_*）经 ErrorMapper 折叠，域码/域消息落 details 透传（`src/host/errors.ts:24-59,162-203`）；client 只分支 code 不分支 message 文本（`src/client/model/api.js:1-19`）。

### 2.3 存储

- 每公司四库物理分离：`<dataRoot>/<companyId>/{org,issues,chat,access}.sqlite`（`src/core/runtime/company-runtime.ts:39-49`）；事件/订阅另有 sqlite-event-store 平面（`src/adapters/sqlite-event-store/`）。
- 隔离论证是物理的：不同公司从不打开同一数据库文件，不靠行级 company_id 过滤（`README.md:246-247`）；同进程同 (dataRoot,companyId) 重复 open 拒绝（`company-runtime.ts:24-27`）。
- 全部 `node:sqlite`（WAL），零第三方依赖；companyId 必须单路径段（`company-runtime.ts:56`）。

### 2.4 生命周期

- host 是常驻 Cordis fiber：构造时读 config→建 host→enabled 时挂四个 Remote controller→dispose 时 closeAll（`lib/index.js:311-359`）。
- `enabled:false` 回滚开关：不注册任何 controller，client 命名空间 miss 即整体回 mock 源（`lib/index.js:341-353`、`src/client/model/api.js:9-15`）。
- CompanyRuntimeRegistry：allowlist 校验→懒开→LRU(4) 驱逐→closeAll；开库失败折叠为 workbench/unavailable 不自动重试（`src/host/runtime.ts:109-175`）。
- 身份解析四步：sessionIds 精确→workspaceId→cwd 最长前缀→identity-unbound（不猜人）；绑定人必须 org active（`src/host/identity.ts:1-18`）。

### 2.5 README 关键结论摘录

- 零第三方依赖、Node v25 原生类型擦除直跑、无 install 步骤（`README.md:13-17`）。
- 注册全有或全无、深冻结、快照不可反向改（`README.md:132-134`）。
- 次数授权 100 并发不超发、租约过期不归还容量（`README.md:180-184`）。
- 不做什么：不做认证/key 解析、不做委派五维/审计哈希链（v2）、不做 trigger 执行器、不做 DSH 适配（指 core 层）、不装第三方依赖、不改 StudioNext 核心（`README.md:304-312`）。

### 3.2 SDK 扩展点

- `defineFeatureModule`：id/version/capabilities/actions/triggers/configSchema + events/handlers（v2）+ param-schema + requires（manifest 版本区间）+ deprecation；校验失败一次报全 issues（`src/sdk/index.ts` 全导出面）。
- 注册器支持 events/handlers/unregister/同 id 多版本（活动=最高 SemVer）（`README.md:216-217`）。
- **conformance kit**：五套件 manifest/params/events/wiring/join，对"已定义模块"做静态一致性断言；报告带 cases+sha256 checksum；strict 模式 skip 即 fail；刻意不重实现编译器（M-P2-1 边界），编译等价由 S1/S2 golden 证（`test-support/conformance/index.ts:1-8,65-90`、`test/conformance/kit.test.ts:44-77`）。

### 3.3 与 DSH 宿主关系（cordis.patch.yml）

- 本包是**组合包（bundle）**：`package.json` 声明 `dsh.bundle.patch="./cordis.patch.yml"`（`package.json:14-17`）；bundle 层插入 `studio-workbench` 行，装载顺序=profile bundles 序→各 bundle patch→profile 自身 patch（`cordis.patch.yml:1-8`）。
- 行内 `config:` 即 host 全部配置：enabled（回滚）/dataRoot/companies allowlist/bindings（D9 身份表）/projects/pollMs/cacheTtlMs（`cordis.patch.yml:20-39`）。
- client 半：`dsh.client.platform="web"`、`exports["./client"]="./lib/client.js"`；`inject` 声明 Cordis 服务注入（`package.json:10-24`）；React 由 web shell 静态模块表提供，bundle 不重复打包（`README.md:338`）。
- host 半：`lib/index.js` 以 `ctx.plugin(...)` 挂 TypertRemoteService，不开新端口、无自有 HTTP 面（`lib/index.js:16-24`）。

### 3.4 安装与打包

- 构建：`node scripts/build-client.mjs`——无打包器，去 `export`+固定顺序拼接+loader 包装；任一产物 >600 行直接失败；`node --test` 以 `write:false` 重跑构建并与 `lib/` 逐字节比对，过期即红（`README.md:338`、`scripts/build-client.mjs:1-19`）。
- 安装：`dsh plugin --profile <可丢弃> add "file:<checkout>"`；开关=从 `dsh.profile.bundles` 移除/加回该包（`README.md:342-352`）。
- 种子：`scripts/seed-company.mjs`（org 公开写面+access 最小 grant 集，幂等，--dry-run 只打印）；部署顺序=种子→绑定→验收（`README.md:367-373`）。
- 产物清单 `lib/client-bundles.json` 记行数/SHA-256/来源（`README.md:328-330`）。

## 四、优势 / 风险 / 债务

### 4.1 优势

1. **端口-适配器纪律严格**：SQL 只在 adapters 文件；测试只断言行为；双适配器同套契约测试（`README.md:168-169`）。
2. **契约冻结文化**：错误码目录冻结+逐码测试（SDK 9 码+workbench 14 码）；CONTRACT_VERSION；ErrorMapper 单点折叠。
3. **产物字节级门禁**：测试重建 bundle 与 lib/ 逐字节一致——构建漂移在 CI 就红。
4. **回滚设计**：enabled=false→client 自动 mock 源；real/mock 经 shapes 归一同一视图形状。
5. **纯函数注入**：now/id/store 全注入；判定/编译/规则无隐藏 IO（`src/core/wiring/rules.ts:14-15`）。
6. **物理隔离+单写者论证**：多公司四库、LRU、幂等 close，拓扑论证一句话讲清（`src/host/runtime.ts:1-17`）。
7. **bench 阈值门**：`.bench/*.json` 带 CI 基线阈值并明示"非产品 SLO"（`.bench/event.json` thresholds 节）。
8. **尺寸门禁+拆分件模式**：≤25 文件/目录、≤600 行/文件，超限即拆 internal/（`README.md:89`）——与我们的 20-§十五 同源。

### 4.2 风险

1. **文档漂移**：README 记 539 用例（`README.md:180`），实测顶层 `test()` 907、112 个测试文件；目录树缺 core/wiring、event/{join,subscription,wiring}、host chat/issues 写面、conformance——以 README 为知识源会失真。
2. **本机绝对路径入库**：`cordis.patch.yml:22-25`（file: URL+dataRoot）与 `src/host/config.ts:53`（DEFAULT_DATA_ROOT）硬编码；checkout 搬家/换机即断，`test/client/bundles.test.ts` 只查文件存在+包名（`README.md:352`）。这也是我们纪律明令禁止的形态（AGENTS.md 纪律 6）。
3. **LRU 驱逐静默吞错**：`src/host/runtime.ts:195` 驱逐 close `.catch(() => {})`，关库失败无观测面。
4. **事件引擎复杂度**：test/event 37 个文件；join/订阅/wiring 三子系统耦合 sdk 校验；S1 规则 TS 源→S3 生成 `lib/client.wiring-rules.js` 2946 行 JS 拷贝，靠字节门禁防漂移但审阅成本高。
5. **client 拆分触顶**：`lib/client.workbench.js` 恰 600 行顶格、wiring-canvas 593——人肉拆 chunk 接近上限，无打包器的代价会累积。
6. **host 入口无测试**：`lib/index.js` 自述"untested by the repo suite"（`lib/index.js:22-24`），DSH 装配面只有存在性检查，真实挂载靠 profile 冒烟。
7. **身份绑定手工**：bindings 表 config 手维护，workspace/path 匹配依赖 DSH sessionController 提供 cwd；session 目录 TTL 1s 轮询（`src/host/identity.ts:55`）。

### 4.3 债务

- `engine/trigger`、`feature/im` 占位 README 位置未随迁移更新（`README.md:50,66`）。
- org-config.ts 手写 YAML 子集解析器（零依赖的代价，`README.md:366`）。
- `scripts/migrate-event-store.mjs`+订阅迁移并存（`test/event/subscription-migration.test.ts`），schema 仍在演进期。
- 权限 v2（explain/listEffective/simulate/审计哈希链）与 P2 投递接线、P4 drain 租约均欠账（`README.md:186-221`）。

### 4.4 测试覆盖形态与 conformance 思路

- 分布：root 13 / client 13 / conformance 1 / event 37 / chat 10 / issues 15 / org 11 / host 9 / runtime 3（2026-11-18 计数）。
- 形态分层：契约（storage-contract 双适配器）> 单元（纯函数矩阵）> 集成（service+:memory: sqlite）> 压力/浸泡（stress/soak/100 并发不超发）> 重档 env 门（LOCAL62_SCALE=1 默认 skip）> golden（join-simulator-golden、conformance golden 钉 definitionChecksum）> 字节比对（bundles）> 主题审计（token 白名单+亮暗对比度数值断言，`README.md:396-399`）。
- conformance 思路：**把"外部作者的自证"产品化**——五套件+checksum 报告+strict 模式，外部模块带 fixture 自跑即可拿到可审计的一致性报告；与"测试不对实现细节负责"同构，但多了跨仓可移植的输出物。

## 六、给插件侧后续开发的建议

**我们值得吸收的做法（对方已验证）**：
1. 产物逐字节比对门禁：凡"生成物落仓"必须能由源重建且测试比对（对应我们的 verify:v2 可加一项）。
2. conformance kit：契约包增加 `runConformance` 式对外一致性报告（checksum+golden+strict），供插件侧/外部模块自证，替代口头"我过测试了"。
3. 错误面单点收口：冻结错误码目录（含 httpStatus/retryable 种子）+单点 ErrorMapper 折叠域错——panel/api/gateway 可对齐，终结"UI 分支 message 文本"。
4. bootstrap 单握手 + real/mock 同形状数据源 + enabled 回滚开关：panel 发布风险面可借鉴。
5. bench 阈值化：`.bench/*.json`+ok 门进 CI，标明"内部基线非 SLO"。
6. 主题 token 纪律：无第二主题源、无字面色 fallback、对比度数值断言——我们概览页若做主题化直接照抄该测试形态。

**给对方（经工作台公司）的改进建议**：
1. 刷新 README：补 wiring/subscription/host 写面/conformance 目录与真实用例数，或改为"目录索引指向各 README"避免整树漂移。
2. 去路径硬编码：`cordis.patch.yml` 的 file:/dataRoot 改 profile 相对/环境变量注入；`DEFAULT_DATA_ROOT` 移出源码（这是我们的硬纪律，建议对齐）。
3. LRU 驱逐 close 失败上报 logger/health，不要静默吞。
4. `lib/index.js` 补最小装配测试（fake ctx.plugin 收集器），把"唯一无测试文件"清零。
5. client.workbench.js 600 行顶格，建议按 boot/shell/tab 再拆一刀，避免下次加功能被迫重排 chunk。

## 七、结论

插件侧是一个**工程纪律与我们同源、但宿主与事实源模型不同**的平行实现：分层、端口、契约、门禁四件套成熟度高于预期；直接替换我们任何模块都不可行（chat 最接近、issues/org 冲突最深），正确路径仍是 11-17 研究文档定的"一核两壳、interface-freeze 后对齐"。短期收益不在替换，而在**吸收其门禁与契约工具形态**（字节比对/conformance/错误目录/bench 阈值）。
