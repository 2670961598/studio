# 研究：插件版 vs 原生 APP 架构差异与核心共用收敛

> 只读研究/设计，不改 Docker/生产/代码，不 commit/push（Lead 提交）。配套 `docs/sentinel-logs/提案-A全替代路线图-2026-11-17.md`（task-61）。
> 目标（制作人）：那边（Workbench）做 **DSH 插件**，我们做**原生 APP**；最终**核心共用**，慢慢统一为“那边接插件、我们外部接原生 APP”；插件完全结束后可能向插件版设计靠拢。

## 〇、结论
- **一核两壳**：共享 `issues`/`collab` **领域内核 + DTO/事件/审计契约 + 存储/wake/trigger 端口**；两边各自保留 **认证/会话/人事/注册器/UI/生命周期/进程/存储位置** 的宿主壳；不把认证/人事/UI 抽进 core。**Workbench 插件不单独起服务**：插件壳内服务由 DSH Host 提供；原生服务由我们的 sidecar 提供。
- **依赖方向**：`plugin shell / native shell → 各自 host adapter → shared core`；**core 不依赖 DSH，也不依赖 StudioNext 核心**；插件不依赖 StudioNext，原生不依赖 DSH。共享 core 只认 actor 引用/端口，不认 wkey/DSH session。
- **收敛节奏**：短期先让 A 路线 P0/P1/P2 使用同一内核（先 `collab` 后 `issues`）；中期抽 `workbench-core` 包/仓 + 双宿主 CI；长期同一 core、两种宿主壳，插件接口冻结后再对齐，不硬切。
- **硬前提**：Workbench 无 `.git`、无 `LICENSE`（`packages/*/package.json` license=null/private）；先定**代码归属/许可/唯一 canonical 仓**，否则不做 core 抽取，只能 clean-room 按 DTO 重实现。

## 一、两边定位/功能对照
| 面 | Workbench（DSH 插件） | 原生 StudioNext（native APP） | 关系 |
|---|---|---|---|
| 宿主/进程 | DSH Host 进程内 bundle；插件只提供工具/面板/内核；DSH 0.x（`Workbench/docs/07-DSH集成与开发计划.md:1-20,77-91`） | daemon + launchd/guardian + sidecar/面板/API；单写者、七相位 | **不同**：插件宿主 vs 常驻 daemon |
| 单子 | `packages/issues`：状态 1..8 + T1–T16、动作权限、reviewer 独立性、evidence/gate、评论/父子、审计（`packages/issues/README.md:89-125`） | Taiga `FlowPlatform`（自定义流程/字段/类型/部门/lane）+ 台账镜像；目标被 A 替换 | **领域重叠、模型不同** |
| 聊天 | `packages/collab`：broadcast/group/dm、mention/reply/read、directed wake；无 relay（`packages/collab/README.md:67-133,187-199`） | Matrix source/notify/HR/rooms/持久 DM；daemon `InvokeSource` | **语义重叠、传输不同** |
| 触发器 | wake→DSH `followup/steer`；Host relay（`docs/07...:196-221`） | mention/notify→`InvokeSource`→七相位派发；lane/epoch 并发 | **可共享 wake 语义，不共享投递** |
| 权限 | principal/membership/roles + 包内动作权限（`issues/README.md:97-108`） | wkey/网关/root delegation/任职闸门/公司目录；权源不迁 | **必须分离**：不复制其认证/权限源 |
| 人事/注册器 | 包内不实现完整人事；docs 建议独立 Identity/HR（`Workbench/docs/11...:28-43`） | 公司目录 people/departments + hr-sync + Taiga/Matrix 账号 | **各自宿主**，不共享 |
| 通知 | DSH 面板/聊天；无 Matrix 生态 | Matrix notify/broadcast/Element/外部 IM | **传输/UI 各自** |
| 审计 | issues 事件+hash 链；collab 无 chat_events（`collab/README.md:200-203`） | ledger events/records/外部锚/证据四要件 | **契约可共享、事实源各自** |
| 存储 | `node:sqlite`/memory；插件 dataDir（`packages/*/package.json` 零依赖） | 公司 `ledger.sqlite` + 公司 var + 公司 git | **同引擎、不同位置/所有者** |
| UI | DSH client panel（`docs/07...:223-246`） | Hono panel + 公司概览 + API | **DTO 可共享，组件不共享** |
| 验收 | 80/80、133/133、独立 84/84（`verification/report.md:30-40`） | V2 28/28、`verify:v2`、七相位/证据/日闭 | **各自门禁 + 共享 core 合同测试** |

## 二、共享 core 边界建议
```
                 ┌──────────── shared core（无宿主依赖）────────────┐
                 │ issues 域：ticket/state/comment/evidence/audit   │
                 │ collab 域：room/message/read/wake                │
                 │ DTO/事件/审计 envelope；storage/authorizer/wake ports │
                 └───────────────▲──────────────────▲───────────────┘
                                 │                  │
                     plugin host adapter     native host adapter
                                 │                  │
                     ┌───────────┴──────┐   ┌───────┴──────────┐
                     │ DSH 插件壳        │   │ 原生 APP 壳       │
                     │ DSH session/auth  │   │ wkey/公司目录/daemon│
                     │ DSH UI/lifecycle  │   │ panel/launchd/API  │
                     └───────────────────┘   └────────────────────┘
```
- **建议共享（core）**：`issues` 领域状态/迁移矩阵/评论/父子/evidence/gate/审计 envelope；`collab` 房间/消息/mention/reply/read/wake 语义；公共 DTO/错误码/cursor；`StoragePort`（memory/SQLite 适配器）、`WakePort`/`TriggerPort`、`Authorizer` 抽象；纯 golden/contract 测试。
- **建议各宿主（不共享）**：认证/登录/session/owner（DSH vs wkey）；人事/组织/注册器；UI（DSH client vs Hono/Element）；生命周期/进程模型（DSH Host vs launchd/sidecar）；存储位置/备份（插件 dataDir vs 公司 var/ledger）；投递（DSH followup/steer vs `InvokeSource`/Matrix）；对外 API 形态（DSH tools/`connection.fetch` vs HTTP/MCP）。
- **权限引擎拆法**：core 只保留**动作/状态词汇与迁移矩阵**；`Authorizer` 端口由宿主提供（插件用其 principal/membership 策略，原生用 wkey/网关/任职闸门）；**不把任一侧的认证/HR/注册器复制进 core**。ticket 状态 core 采用 1..8+T1–T16 作为规范模型；Taiga 自定义状态/字段由**原生 adapter 映射**，不反向污染 core。
- **依赖约束（硬）**：core 禁止 import DSH 或 `@studio-next/*`；插件壳禁止 import StudioNext 核心；原生壳禁止 import DSH；两边只能经 core public API + 各自 adapter；core 不建网络/UI/进程/密钥依赖。

## 三、收敛路径（与 task-61 对齐）
### 短期（A 路线 P0/P1/P2）
- **P0（5–8pd）**：从 Workbench 两包抽出**DTO/事件/领域契约快照**；10 单导入/字段状态比对；collab mention→wake 模拟；同时让插件侧和原生侧各跑一次 core 合同测试（双宿主 sanity）。
- **P1（聊天）**：原生 sidecar 使用 **collab 内核**；插件宿主使用同一内核（或同版本快照）；只做 adapter/transport，不复制认证/UI；双跑验收见 task-61。
- **P2（单子）**：原生 sidecar 使用 **issues 内核**；FlowPlatform adapter 做 Taiga 状态/字段/评论/附件映射；插件宿主使用同一内核；P2 双轨期间以同一 core 版本跑两侧合同测试。
- **原则**：先 vendor/快照同一版本，禁止两边各改一份；P0/P1/P2 不因“共用”扩大范围，仍按 task-61 的门槛推进。

### 中期（抽 core 包 + 版本策略）
- 将 `issues`/`collab` 的**领域层 + DTO + ports + 纯契约测试**抽成独立私有包（名暂定 `@studio-next/workbench-core`），两个宿主都依赖它；**不抽** auth/HR/UI/lifecycle。
- **版本**：semver + 源码快照 sha256；core 发布必须同时过 **native adapter contract** 与 **plugin host adapter contract**；任一侧红=不发版；兼容矩阵（core 版本 ↔ 插件版本 ↔ 原生 service 版本）。
- **防漂移**：单一 canonical 仓；插件/原生不得各自 fork；改动先在 core 提交 + 双宿主测试；每季度一次 API 兼容审计。

### 长期（同一核心、两种宿主壳）
- 插件壳：DSH Host + session/auth + DSH client panel + followup/steer relay；原生壳：daemon/sidecar + wkey/公司目录 + Hono panel/API + launchd；两者只共享 core。
- 插件完全结束后设 **interface-freeze checkpoint**：冻结 core DTO/事件/错误码，再决定是否把 native sidecar 的部分 host 逻辑向插件设计靠拢；**不一次性硬切**。
- 形态目标：插件版负责“插件内工作台”，原生 APP 负责“公司外部/常驻面”；同一 core、不同壳，数据不共享一个 DB。

## 四、差异障碍与隔离
- **认证/人事/注册器**：不复制。插件用 DSH session/owner，原生用 wkey/公司目录/任职闸门；core 只收 actor 引用 + `Authorizer` 结果；注册/登录/HR 表不进 core。
- **ticket 模型**：core 1..8+T1–T16 vs Taiga 自定义流程/字段/type/dept/level/lane；原生 adapter 维护公司级映射表，未知状态显式 `legacy_state`，不压缩、不猜；core 不因 Taiga 加任意状态。
- **API 形态**：插件 tools/`connection.fetch`（`docs/07...:227-246`）vs 原生 `FlowPlatform`/HTTP/MCP；用 core service API + 两套 transport adapter，禁止在 core 里写 HTTP/DSH 类型。
- **UI**：DSH client panel vs Hono/Element；共享 DTO/视图模型，不共享 React/Hono 组件；两套 UI 各自验收。
- **并发/权限/审计**：原生 lane/epoch/wkey/外部锚；插件 DSH Host 内串行/宿主信任。core 只定义域内 CAS/幂等/事件 envelope；调度、授权、锚、告警归宿主；**不把原生审计链与插件审计链合并**。
- **存储/生命周期**：插件 dataDir vs 原生公司 var；core 只接 `StoragePort`/path，生命周期由宿主 open/close/migrate；不共享 SQLite 文件。

## 五、工程与治理
- **许可/归属先决**：Workbench 无 git/LICENSE，包 license=null/private（`verification/snapshot.txt:1-6`）；先由制作人确认归属/书面许可 + 指定 canonical 仓；无许可→不做 core 抽取，只能 clean-room（工作量和风险上调）。
- **版本钉**：源码树 sha256 + 包版本（当前 0.1.0）+ Node 基线（v25.6.1）；升级必须双宿主回归；禁止自动跟随上游。
- **CI/测试**：core 单测 + golden；native adapter contract；plugin adapter contract；独立 verifier 每阶段；core 变更未过双宿主=不发布。
- **维护归属**：1 名 core maintainer（约 0.2 FTE）+ 两侧 host owner；共享 core 变更需双侧 review；task-61 的 0.4–0.5 FTE 内消化，不另起大项目。
- **发布/回滚**：core 版本与插件/原生 service 版本绑定；回滚=core pin 回退+宿主 adapter 版本回退；schema 迁移 forward-only，先备份后迁移。
- **低强度**：月度 gate；core 抽取只做 P0/P1/P2 必需面，不追求一次统一 UI/认证/存储；任何阶段可停，不阻塞运维。

## 六、现在做什么 / 不做什么
**现在做（P0 内，5–10pd 增量）**
1. 确认许可/归属与 canonical 仓；无则只做接口/契约研究，不 vendor。
2. 抽 DTO/事件/审计/存储端口契约 + 双宿主合同测试骨架；以 Workbench 现有 80/133/84 套件为基线。
3. 在 task-61 P0/P1/P2 中**同一 core 版本**跑原生 sidecar 与插件宿主；先聊天（collab）后单子（issues）。
4. 明确 `Authorizer`/`StoragePort`/`WakePort` 端口，宿主各自实现；core 不 import DSH/StudioNext。
**现在不做**
- 不统一认证/人事/注册器/公司目录；不把 wkey 或 DSH session 塞进 core。
- 不统一 UI/进程/存储位置；不共享一个 DB/fact source；不合并 daemon 与 DSH 生命周期。
- 不复制 Workbench 权限/HR/注册器；不为 Taiga 自定义流程改 core 状态机。
- 不一次性硬切、不双写、不在插件结束前锁死接口。
**待制作人裁决（≤5）**
1. 代码归属/许可与 shared core 的 canonical 仓（先决）。
2. core 边界：是否接受“领域内核+DTO+端口”、权限/认证/HR/UI 全留宿主？
3. ticket 规范模型：core 固定 1..8+T1–T16，Taiga 差异全由原生 adapter 映射（推荐）还是 core 支持 workflow profile？
4. 中期 core 包维护人/0.2 FTE 与双宿主 CI 预算。
5. 插件结束后 interface-freeze 时点，以及是否把 native 部分 host 设计向插件版靠拢。
