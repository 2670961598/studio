# 提案：models.yaml 动态模型热切（零重启换模型档）

> 2026-11-16 制作人批「动态模型热切」；本提案为 task-34 实现单前置（先提案后写码）。
> 依据：docs/17-§4（三档/价目/overlay）、docs/38-§2（L1 配置级热重载 R-A）、studio-dev-885（mid overlay 单源/自动挂载）、studio-dev-196（overlay 生成/档位一致性闸）、studio-dev-882（model 声明镜像注入）。

## 1. 动机与现状

现状：`models.yaml` 在 serve 启动期一次性装配——`provisionModelTierOverlays` 写
`var/tmp/dsh-tier-{high,mid,low}.yml`；`createModelCatalog` 生成内存价目表（预算闸/收割
成本/日闭）；`parsed.roles` 生成 modelTierByRole 路由；agent.yaml patches 的 model 声明
镜像在 wireRegistry 前注入。换模型 → 必须重启 daemon（~50–60s，打断在途 worker）。
需求：修改 `models.yaml` 后运行时生效、零重启、不打断在途单；保留重启兜底。

## 2. 方案（选文件监听，不扩 L1 reload 语义）

选择 **新增 models.yaml 文件监听（fs.watch + mtime/hash 去抖 + 启动盲窗补检）**，理由：
L1 reload 的触发/幂等/信任锚门以**公司目录指纹**为键；models.yaml 不在 companyDir，
且手动 reload 在公司目录未变时会判定 `unchanged` 而**不进入 apply**——扩 L1 需改其幂等
键/锚语义，风险大于收益。文件监听与 `engine/sources.ts` 既有做法同型，独立面、可单测、
失败不影响 L1。

执行链（拍边界单线程，不新增相位）：
1. 监听/轮询 `models.yaml` 的 mtime+size；内容变化稳定 ≥500ms（去抖）后读全文。
2. `parseModelsYaml` 校验（strictObject/三档/价格非负/角色 main_worker）→ `createModelCatalog`。
3. `provisionModelTierOverlays` **重写** `var/tmp/dsh-tier-{high,mid,low}.yml`（mid executor
   cmd 已由 885 挂载该文件路径，内容更新即下次 spawn 生效；不改 cmd 数组）。
4. `engine.applyModelsUpdate({catalog, modelTierByRole})`：刷新内存价目表（预算/
   GATE_PASS 成本/日闭）+ 角色路由；同步刷新 dsh adapter 的 model 声明镜像
   （`DshAdapter.setModel`；新增 launch 捕获 modelAtLaunch，在途 worker 的 resultStats
   仍按其 launch 时 model 归属，防混合口径串档）。
5. 留痕：成功 `SCHEMA_EVOLVE`（issue '-'，note `MODELS_RELOAD;trigger=watch;...`）；
   失败 `ESCALATE`（`MODELS_RELOAD_INVALID;...`）——**复用既有事件词表，不新增事件名**；
   日志一行。
6. 原子/fail-closed：先解析校验全部→再写 overlays；任一步失败保持旧 catalog/路由/overlay
   （overlay 写失败按备份回滚），不半切换；坏文件记录后不再每拍重试（内容再变才重试）。

## 3. 不做什么

不改 agent.yaml/宿主 profile；不新增 CLI/事件词/契约/schema；不做模型 API 健康探测；
不改价目表数据源（仍 models.yaml）；不自动重启；不改 L1 reload 语义。

## 4. 风险与回退

- 在途单模型归属：新 spawn 用新 overlay；在途 worker 的 `ResultStats.model` 用 launch
  捕获值（非当前值），避免旧 worker 被记新模型/新价；混合日成本按各单实际模型归属，
  COST_RECON 仍按 cost_daily 对齐（报告注明混合口径）。
- 价目缓存一致性：catalog 换引用一次性替换；预算闸/日闭/收割读取同一新 catalog。
- 写一半：overlays 原子写；失败回滚旧文件与旧内存引用。
- 回退：恢复 models.yaml 内容 → 监听到变化即回切；无效 YAML 保持旧配置继续跑（fail-closed）。
- 验证清单：见 task-34 三、真机（pid 不变/tick 连续/新 spawn overlay 含新模型/新价生效/
  非法 YAML 拒且不崩/在途 worker 不断/回切生效）。
