# 双方架构对比与替换映射（2026-11-18，task-129/130 合成）

> 制作人 2026-11-18 指令：开两单分别评估插件侧与我们侧，做整体对比、替换映射，并给出"我们好的做法反向影响插件后续开发"的建议。
> 来源：`插件侧架构评估-2026-11-18.md`（220 行）、`我们侧架构评估-2026-11-18.md`（205 行）；本文件为合成总表 + 裁决建议，事实引用回两份分报告（`文件:行号`，不写本机路径）。

## 一、总判断（一页）

1. **不是"谁替换谁"，而是"一核两壳"**：我们侧是**治理/证据/多公司/执行器中立**的常驻 daemon 框架；插件侧是**轻宿主、域内精致**的内核切片（issues/collab 状态机+审计+权限+多公司四库）。两者宿主模型（独立 daemon vs DSH 进程内 Cordis）与事实源模型（Taiga/git/SQLite vs 插件四库）都不同。
2. **替换只能"按面适配"**：chat 最接近（可替换经适配）；issues 可替换经适配（状态/字段映射、ID 保留）；org/权限/台账/执行器/UI/生命周期**不可替换**（权源/事实源/宿主面）。
3. **双方各有值得吸收的硬东西**：我们吸收插件侧的**产物字节比对门禁、conformance kit、错误码目录+ErrorMapper、bench 阈值、主题 token 纪律**；插件侧吸收我们的**wake 投递闭环、幂等 replay+planHash、冻结码表+版本纪律、fail-closed 缺省、observe→enforce、机制保证非自律（触发器 append-only/依赖方向门禁）、迁移三件套、多公司隔离**。
4. **当前正确动作**：保持"插件先做完 + 我们只做可演练不接生产的准备件"；interface-freeze 后按 §四映射表逐面适配；**不要合并**认证/人事/UI/生命周期/审计链。迁移下一刀=**模块 D WorkbenchMentionSource 最小闭环（对 mock sidecar）**——全部准备件与 daemon 主循环之间的第一根真接线。

## 五、双方互相值得吸收的做法

### 5.1 我们从插件侧吸收（已写进建议清单）
1. **产物逐字节比对门禁**：凡"生成物落仓"必须由源重建+测试逐字节比对（可加到 verify:v2）。
2. **conformance kit**：契约包增加对外一致性报告（cases+sha256+golden+strict，skip=fail），供外部模块自证。
3. **错误码目录+ErrorMapper 单点收口**：冻结码表（httpStatus/retryable 种子）+域错折叠，UI 只分支 code。
4. **bootstrap 单握手 + real/mock 同形状 + enabled 回滚开关**：发布风险面。
5. **bench 阈值化**：`.bench` 基线进 CI，明示"内部基线非 SLO"。
6. **主题 token 纪律**：无第二主题源/无字面 fallback/对比度数值断言。
7. **多公司 LRU+幂等 close 组合根范式**（可观测教训：驱逐失败别静默吞）。

### 5.2 插件侧从我们吸收（建议经工作台公司推动）
1. **wake 投递闭环**：claim/lease(TTL)/重试≤3/dead-letter+append-only 投递审计（chatd 7049a9f 现成参考；插件 collab wake 现停 pending）。
2. **幂等与 replay**：全端点 idempotencyKey+`replayed:true`；迁移 planHash=canonical 载荷 sha256。
3. **冻结错误码+协议版本纪律**：码表不自造、加码=升版本、字段只增不改。
4. **fail-closed 缺省**：无 token 拒启、占位符拒启、缺 API 显式 UNSUPPORTED 不静默 no-op。
5. **observe→enforce 渐进**：先观察后强制，避免阻断缺陷直上生产。
6. **机制保证非自律**：append-only 用 schema 触发器、唯一写入者、依赖方向表+尺寸阈串测试前置。
7. **迁移三件套**：dry-run→hash 对账→回滚 SOP→真实 fixture 演练，先于任何切换。
8. **多公司隔离**：每公司独立 DB/socket/token/命名空间（若插件走向多租户，这是第一课）。
9. **让插件侧吸收其自身教训**：README 刷新、去本机绝对路径硬编码、LRU 驱逐上报、`lib/index.js` 装配测试、client 再拆 chunk。

## 六、路线与下一步（建议）

1. **保持分工**：插件侧继续把产品做完（其开发主线）；我们只做**可演练不接生产**的准备件。
2. **interface-freeze 前置**：插件侧接口冻结后，按 §四逐面适配；freeze 前我们不接真实接口（Transport v1 与插件 facade 未互验）。
3. **下一刀（我们侧）**：模块 D `WorkbenchMentionSource` 最小闭环（对 mock sidecar）——inbox→claim→emit(dedupKey=wake:<id>)→ack；这是全部准备件与 daemon 主循环的第一根真接线。
4. **不合并清单（硬边界）**：认证/权源、人事/组织事实源、审计链、UI 组件、生命周期/备份/部署。
5. **反向影响机制**：把 §5.2 清单整理成给工作台公司的 1 页建议（可附本文件链接），由他们排期吸收；不建议我们直接改插件仓（遵循"各自事实源/各自宿主"）。
6. **共同债务**：插件 README 刷新/去硬编码；我方 AGENTS/docs17 的 YouTrack→Taiga 文档回改、lineBaseline 清偿、chatd 入 v2 门禁时机。

## 七、结论

- **替换是"适配+迁移"工程，不是"对等换件"**：14 个映射面中可替换 2、需适配 6、不可替换 6。
- **我们侧护城河**：治理/证据/多公司/执行器中立；**插件侧杠杆**：轻宿主/域内精致/零运维。
- 双方最优关系是**"一核两壳"**：插件做内核与产品面，我们做治理/证据/多公司/执行器与迁移；互相吸收对方已验证的工程形态，而不是互相吞并。
