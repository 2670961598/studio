# 提案：策划提案 → 自动建单闭环（先人工确认，后自动；fail-closed）

> 任务：task-36（提案单）；2026-11-16 制作人问「策划不断提改进/新功能，这方面也没跑了吗」。
> 定位：消费 task-37 的评审过闸结果，把「值得做」的提案经平台网关落成 Taiga 单；验收标准字段
> 引用 task-38 `提案-单子验收口径标准化-2026-11-16.md` 的 `acceptance_criteria`。
> 三事实源/唯一写入者/平台网关契约不变；不绕 wkey；不新增 schema/事件词（如需新事件名另批）。

## 0. 结论先行

策划循环在跑（`pln-daily-review-研发部` 每日 09:00，今日单 studio-dev-1456，约 13.9KB 日报含 F1–F7；
另有 `int-frontier-patrol`、`arch-frontier-watch` 等定时岗），但提案只落日报与
`deliverables/plan.md`，**没有转成单据/待办**；「新单」9 张长期无人消费（936 破 200h），入口靠人工。
建议：定义可机读提案段 → 评审闸（task-37）过滤 → 幂等去重 → 经平台网关建单进「新单」→
留痕/失败 fail-closed；先人工确认 observe，再开自动；开关默认关。

## 1. 可机读提案段（固定结构）

策划岗位产出中新增/规范化一段（二选一，推荐 A+B 过渡）：

- **A（推荐主格式）**：报告同级 `proposals.jsonl`（一行一条，append-only 追加；daemon 只读）。
- **B（兼容）**：报告内固定 fenced JSON 段，如 `## 提案` + ```json [...] ```；解析失败=跳过并留痕。
- 每条字段（最小）：
  ```json
  {
    "proposal_id": "pln-20261116-f1",
    "title": "…",
    "background": "…",
    "expected": "…",
    "acceptance_criteria": [{"id": "A1", "check": "可测判据", "evidence": "证据方式"}],
    "priority": "P0|P1|P2",
    "source_report": "reports/研发部/2026-11-16-report-研发部-studio-dev-1456.md",
    "dedupe_key": "可选；缺省由 daemon 规范化生成"
  }
  ```
- 缺 `title/expected/acceptance_criteria` → 该条不建单，进 `pending-info`（task-37 退回补料），
  不静默丢弃。

## 2. 幂等去重

- 去重键：`sha256(company | source_report | proposal_id | normalized_title)`（或上游给定
  `dedupe_key`；实现先规范化 title/空白）；同键跨运行/跨报告只建一次。
- 持久化：优先 `daemon_kv`（`proposals.seen.<key>`）或既有台账索引；不新增表/schema；
  记录 `proposal_id → issue_id/建单时刻/结论`；重复运行命中即跳过（零写）。
- 评审闸（task-37）`reject` 的键也登记（防重复提案反复入库）；`pending-info` 同键续评不重复建单。

## 3. 建单路径（合规）

- 读策划产出（只读公司目录/报告）→ 评审过闸（task-37 `adopt`+批准）→ 构造 issue：
  title=提案标题、description=背景/期望/验收标准 JSON 块/来源链接、dept/level/type=研发部/默认、
  **初始状态=「新单」**（不进派发闸/不自动 approve、不自动 assign）。
- **经现有平台网关**（`wireGatedPlatform`/wkey 路径；daemon 唯一写入者）：不直连 Taiga、
  不绕 wkey/签名/审计；建单成功后写镜像与提案索引；失败不建/不写索引/不吞错（见 §5）。
- 与现有 8 定时岗/派发规则不冲突：本次只增「入口搬运」，派发/调度/收割主链不变；建出的单走
  正常候选/分类/审批流程。
- 留痕：提案编号、去重键、来源报告、评审 triage 文件、issue id、建单时刻/操作者（`PROPOSAL_IMPORT`
  可复用 `SCHEMA_EVOLVE` note 或报告文件；若需新事件词另批，不擅自扩）。面板可查提案→单链路。

## 4. 先人工确认 → 自动（两段）

- **阶段 A（默认，开关关）**：只生成「拟建单清单」+ dry-run 报告，Lead/制作人确认后一次性建单；
  审批人可逐条勾选/改标题/退 pending-info。
- **阶段 B（人工批准开启）**：task-37 `adopt`+立项批准的提案自动建单；其余不建；开关可随时关回 A。
- 开关/配置：`proposalAutoCreate: false` 默认（fail-closed: 关=不建单；不自动跑）；启用需显式批准。

## 5. 失败/边界（fail-closed）

- 解析失败/字段缺失 → 该条跳过 + triage `pending-info` + 日志/台账可见；不影响其它条/主循环。
- 评审未过/未批准 → 不建单；重复键 → 跳过（计数日志）；平台网关/网络错误 → 本次不建、不写索引、
  留 ERROR，下一次重试（按去重键幂等）；半成功=已建单才写索引（先建单后索引，崩溃重放可能
  重复建单→网关幂等键/去重键二次校验作为第二道闸）。
- 不自动关单/改单/改公司目录/改契约；不自动 approve/assign；不建空标题/无验收标准的单。

## 6. 不做什么

不在本单做「AI 生成新功能想法」（策划报告已承担，只搬运）；不绕 wkey/平台网关；不新增表/schema/
契约/事件词（除批过）；不自动改章程/组织/契约；不自动关闭既有单；不做复杂调度/优先级重排
（优先级由 task-37 评审给，派发规则沿用现有）。

## 7. 风险与回退

- 风险：重复建单（幂等键+索引+二次校验）、垃圾单（评审闸+验收标准强制+pending-info）、
  越权/网关合规（只走 wkey、固定字段、最小权限）、噪声/成本（开关默认关+每日批量+观测）、
  解析漂移（结构版本号+跳过留痕）。
- 回退：关闭 `proposalAutoCreate` → 停止建单（阶段 A 人工确认仍可用）；已建单不删不关（由人工
  处理）；去重索引保留可查；部署回退=回旧代码，不触碰事实源。

## 8. 验证清单（实现后）

- 同报告重复运行只建 1 张单（同键幂等）；坏 proposal 跳过并留痕；缺验收标准不建单（pending-info）；
- 网关失败：不建单/不写索引/ERROR 可见/重试不重复；建出的单出现在 Taiga+镜像+面板且状态=「新单」；
- 评审未过/未批准不建单；开关关闭=零建单；现有定时岗/派发/收割主链不回归；无新增事件词/schema。
