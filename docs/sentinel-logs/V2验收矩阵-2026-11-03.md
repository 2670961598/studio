## 〇、判定口径（不采信任何 agent 自述）

**四步验证法**，四条全过才可判「已验证」：

1. **代码落仓**：`git log --oneline -5 -- <路径>` 有对应提交；关键标识在**生产路径**的引用数 > 0（`grep -rn … apps/*/src packages/*/src | grep -v test`；=0 即未接线）。
2. **门禁**：`mise exec -- bun run verify:v2` exit=0 且失败集空；`node scripts/scan-repo-secrets.mjs --json` newHits=0。
3. **真机接线**：启动日志／`ledger.sqlite`（events/daemon_kv/records/work_records/sessions）／端口探测（8788/8789/8791）／sqlite 表计数——证明能力在生产链路上真被调用，而非只有代码。
4. **红→绿**（适用时）：构造对应负向/缺证场景，改前红、改后绿，原始输出归档（17 §五「交付方自报仅线索」；AGENTS.md §五.3）。

**三档判定**：**通过**（四步全过）｜**不通过**（有证据表明行为不符，或「被修到能跑」）｜**证据不足**（缺任一必需证据）。
**状态词**：未交付｜已交付未验证｜已验证｜未过｜待裁（本矩阵严格取这五值；「部分腿已落」写在证据列）。

**「已验证（代码级）」约定（2026-11-03 15:0x 起）**：代码落仓＋门禁绝对绿＋红→绿证据齐、但 **daemon 未重启部署**者，状态记「已验证（代码级）」，并统一计入**部署债**（§四-8）；真机证据补齐后改「已验证」。

**逐单归因原则（Lead 2026-11-03 确认，硬口径）**：每一单必须有**自己的 patch sha＋全树 `diff -rq` 零差异＋门禁原始输出＋真机证据**；**绝不接受合并绿证代单证**。验收时按单归因——同批多单合并落仓时，各单证据须可单独追溯。

### 〇.1 反「强行完成」质量判定（制作人 2026-11-03 指示，硬口径）

AI 会硬着头皮完成，验收必须防屎山。**六项检查，任一成立即判「未过（质量）」，写证据（文件:行）并立即报 Lead**；宁可报未过等返工，不许为覆盖率放行。

| 项 | 识别目标 | 检查方法（在 patch diff 上跑） |
|---|---|---|
| Q1 假接线 | 声称接线但生产引用=0／目标表仍空／端口仍不通 | 四步法负证（grep 生产引用数、台账表计数、端口探活）；声称的装配行须在 boot 日志可见 |
| Q2 特判硬编码 | 为过验收写死值/路径/票号/环境分支 | `git show <patch>` 新增 src 行 grep：`process.env.NODE_ENV`、`__TEST__`、`=== 'studio-dev-`、`issue === 'studio-dev-`、`hardcoded`、`HACK`、`FIXME`、`XXX`；命中逐条读上下文判「是否验收条件分支」 |
| Q3 绕道 | 绕过既有端口/门禁/fail-closed | 对照能力应有入口（ctl 必须 `gateWriteCtl` 不得 `gateWrite` 借道；出站必须过闸；异常必须 fail-closed）；grep 旧入口新增调用 |
| Q4 重复实现 | 仓内已有同类能力却另写一套 | grep 相似函数名/模块名（既有 PORT/记录/validator）；新增平行实现且未复用者判 |
| Q5 测试作弊 | skip/only/放宽断言/只测自己实现 | 新增 test 行 grep：`.skip(`、`.only(`、`xit(`、`xdescribe(`、`it.todo`；断言须覆盖失败面（只测 happy path／断言弱化＝判） |
| Q6 规模失控 | 单 patch 文件数/行数远超设计所需、顺手改无关文件 | `git show --stat`；改动文件清单须逐一对上单内领土（设计面/主循环面/测试面/文档面），无关文件＝判负 |

**质量判定取值**：待验（未交付/未审）｜合格（六项全过）｜未过（质量：Q1–Q6 项号＋文件:行）。
**每批摘要附一行「本批质量风险：低/中/高＋一句话理由」**（在无交付批，按实际审查面给）。

**环境噪声口径（Lead 2026-11-03 11:58）**：多 worker 并发（load 63+）下出现的 **timeout 类失败＝环境噪声**——验收时标「环境噪声」并**错峰重跑**，**不判质量负**；仅对非 timeout、可复现的失败做质量判定。
