## 〇、一句话判断

我们侧是一个**治理完备、执行器中立、多公司就绪的常驻 daemon 框架**（三事实源 + 四域 + 横轴包 + 机械边界门禁 + enforce 化验收闸）；插件侧是**轻宿主、域内精致的内核切片**（issues/collab 状态机+审计）。聊天/单子切换的准备件（Transport v1、chatd、127-A/B）已全部落仓且可演练，但 daemon 侧适配（模块 D 起）与生产切换未启动——**替换是"适配+迁移"工程，不是"对等换件"**。

## 六、我们哪些做法值得反向影响插件侧

1. **wake 投递闭环**：claim/lease(TTL)/重试≤3/dead-letter+append-only 投递审计——插件 collab 的 wake 现停 pending、relay 未实现（插 7.2 已列必补）；chatd `7049a9f` 即现成参考实现（含"不伪造审计"的存量回填口径）。
2. **幂等与 replay 语义**：全端点 idempotencyKey+`replayed:true`（types.ts:56）；迁移件 planHash=canonical 载荷 sha256 使重导出零漂移——插件侧引入同语义，双跑对账（0 漏/0 重复）成本大降。
3. **冻结错误码+协议版本纪律**：码表不得自造、加码=升版本、字段只增不改（types.ts:11-24；拆解 §四）——插件 facade 冻结时直接沿用此法。
4. **fail-closed 缺省**：无 token 拒启、占位符 token 拒启、UNSUPPORTED 显式报错不静默 no-op——插件侧"缺 API 显式报错"条款（研究 §7.1）可用同一测试范式背书。
5. **observe→enforce 渐进**：验收闸先观察后强制、路由先 observe 后启用——插件侧未来加验收/配额面时同法，避免阻断性缺陷直上生产（#1488 教训）。
6. **机制保证非自律**：append-only 用 schema 触发器 ABORT、唯一写入者、依赖方向表+尺寸阈串测试前置——插件仓多包生长（issues/collab→更多包）可复制分层宪法防漂移。
7. **迁移可演练纪律**：dry-run→hash 对账→回滚 SOP→真实 fixture 演演（127-A/B 模式）——插件侧将来承接导入/导出或数据面升级时同法；"可演练、可对账、可回滚"三件套先于任何切换。
8. **多公司隔离**：每公司独立 DB/socket/token/命名空间（提案-Phase1 §1.1）——插件若走向多租户，actor/room 命名空间隔离是第一课。

## 七、结语

我们侧的护城河在**治理与证据链**（三事实源+机械门禁+enforce 闸+可重建台账），插件侧的杠杆在**轻宿主与域内精致**。A 路线的正确姿势已定且正在执行：先把插件做完，我们只做**可演练不接生产**的准备件（Transport v1/chatd/127-A/B 已齐）；interface-freeze 后再按 §五 映射表逐面适配，认证/人事/UI/生命周期永不合并。近期最值得排的下一刀：模块 D 的 `WorkbenchMentionSource` 最小闭环（对 mock sidecar），它是全部迁移件与 daemon 主循环之间的第一根真接线。
