## 摘要

V6 主线的总体质量高：**「意图→受理→合同→开工→执行→验收→价值→结清→重开」在五层间逐字保真**——受理五取值、工作六类、开工五门三值、工作十态、验收四取值、风险四档、证据八要素、结清八项、异常十四类（67 §八的 8 类是 77 §6.7.2 十四类的子集，单向扩展无冲突）；「受理≠承诺、合同≠可开工、执行完成≠验收、接受≠结清、验收≠价值」的五重分离一路保真到 82 §2.3 的 V2 判负清单与 77 §12.2 X2/X3/X4；协作语义（八类协作动作的未响应语义、共同工作唯一协调责任者、联合验收整体作出、履约状态只能由工作状态推出）在 71 §4.5 → 77 REC-WORK-10/§7.2/§7.3 → 16 WORK-10/EVD 面完整落锚；store（通用三表 + append-only 触发器 + `proofRef` 无「已提交无证明」窗口）与 engine（`work/` 11 件 + `harvest/` 5 件 + obligations/lifecycle/decision 逐一对应 REC-WORK/EVD/OBL/EXC）对记录面支撑成立；82 §六 W1–W12 十二行齐备，每行有 REC/端口/绑定/文件/测试/预期证据/失败即禁止，§3.5 自报「0 项取得目标证据」属诚实陈述。67 十四章在 71/72 层无阶段消失（§九在 71 §4.2 有一句概述）。

**两处 P0**：①整类「维持性/无产物工作」的验收判据（状态指标与过程指标分别判断、独立抽样核验、避免类三段证据）在 77 记录层无任何载体、在 82 W7 被替换为面向执行的「四要件+产物+状态」——验收判据逐层弱化为不可断言；②82 TR-W-06「静默恢复」的对象记录锚（REC-EXC-02 紧急止损 + REC-AUTH-08 权威失能恢复）与 77/16 的语义锚（REC-WORK-09 T12 恢复决定）互相矛盾，且 77 明文「REC-EXC-02……不等于恢复」，验证可能测错对象。另 4 条 P1（能力激活批准/进化链段无记录锚、变更申请在途态无记录、交接包结构无字段契约、82 W 表主文件锚与 16 端口落点漂移）、5 条 P2。

## P0（矛盾 / 断链 / 弱化）

### P0-1 维持性/无产物工作的验收判据在 77 记录层消失，82 W7 锚被替换为执行面四要件
- 【定位】67 §九正常路径 3：「状态指标（界内时间比例、恢复时长、漂移幅度）与过程指标……分别判断，二者不可互替」；67 §九「避免」三段证据：「事前声明的风险条件与机制、期间可核验的监测……三段不全时，结论只能是『无法判断』」；77 §4.2 L886 仅剩反向禁令：「拒绝、避免、暂缓、撤回是**无产物结果形态**……不得塞进『维持』绕过各自证据要求」；82 §六 TR-W-07 预期证据：「四要件 + 产物 + 状态；动作数不计完成」。
- 【问题】63 §1.2 把「值守、维护」明列为工作（Work）的组成，67 §九为这一整类工作给出了独立的验收结构：双指标分别判断且不可互替、独立位置抽样核验（「抽查本身不得由被查方安排样本」）、避免类三段证据（缺段只能判「无法判断」）、结论三值（维持成立/不成立/无法判断）。71 §4.2 只保留一句「各有自己的验收对象与证据结构（例如避免类须有……三段）」的概述；到 77 层，全部 50 类 REC 与 29 条 RUN 协议中**无任何承载**——全文检索「值守／维持类／抽样／三段证据／状态指标／过程指标」零命中（仅 §3.0「三段与两轴」为权威域另一概念）；REC-EVD-02/03/04 的八要素与字段表是通用结构，表达不了「双指标分别判断」「独立抽样」这类可机械断言的判据；REC-OBL-01.form 的「维持状态/避免结果」只承载义务触发与到期，REC-EVD-05.state_account 只承载价值层状态账，都不承载验收程序。82 TR-W-07 的预期证据「四要件 + 产物 + 状态」是收割/执行面（终态、输出非空、退出码、报告落盘）口径，无法断言「状态连续性/界内时间比例/抽样核验」。
- 【影响】维持类工作（监控、值守、风控）是自治公司的常态工作类型，其验收从「结构化双指标 + 独立抽样 + 三段证据」弱化为「通用证据包 + 执行四要件」，67 §九最想防的「以动作充数」（W7）在记录与验证层只能靠人读材料判断，无机械判据；「无证据不完成」在这类工作上不闭环。
- 【建议】77 §六为无产物验收补最小契约：或给 REC-EVD-04 增设按工作主类型分化的判据结构（维持类必填状态指标与过程指标两组材料引用 + 抽样核验记录引用），或新增 REC-EVD-0x「无产物验收记录」（六类各列主验收对象与必需证据形态）；82 TR-W-07 的预期证据改写为引用该结构，而非收割四要件。若有意推迟，须在 77 §12.3 未验证边界中显式登记该缺口。

### P0-2 82 TR-W-06「静默恢复」的验证锚指向错误记录族，且与 16 的锚互相矛盾
- 【定位】82 §六 TR-W-06：「静默恢复｜`REC-EXC-02`；`REC-AUTH-08`｜`TS-PORT-WORK-06`……恢复决定独立且留记录」；77 §6.7.4 REC-EVD-…（REC-EXC-02）规则：「不追认原动作、不等于恢复、不推广为常态」；77 §5.3 T12：暂停→进行中须「恢复决定成立且恢复条件有证据」（REC-DEC-01 + REC-WORK-09）；16 §4.11 TEST-WORK-LIFECYCLE：「R/W：`REC-WORK-09`；W05、W06」。
- 【问题】67 §八 W6「叫停后静默恢复」的语义是**工作级暂停后无决定、无记录地继续**，其正路径是 T12（恢复决定＝新的决定，不得由被叫停交付方单独作出）。82 却把对象记录锚到 REC-EXC-02（紧急止损记录——77 明文它「不等于恢复」，是另一个概念）与 REC-AUTH-08（旧写者/承接者**失能**的权威域恢复判定），与本行自己的「预期证据：恢复决定独立且留记录」自相矛盾；同一反例在 16 被锚到 REC-WORK-09（生命周期）。两卷给出不同记录族的锚，W6 的 V2 用例照 82 行建造就会去断言紧急止损路径而非 T12。
- 【影响】W1–W12 是工作册的冻结反例集；W6 锚错意味着「被叫停方自行恢复」这条判负线可能永远不会被真正测试（测的是止损不追认，已是 R20/X10 的邻域），且 82 与 16 的锚漂移本身构成跨卷矛盾。
- 【建议】82 TR-W-06 的对象改为 `REC-WORK-09`（T12）+ `REC-DEC-01`（恢复决定），与 16 对齐；若保留 REC-EXC-02 作次要对象，须写明它只承担「止损不追认」侧写。同时按 82 §14.5 的回写责任把该修正记入跨卷冲突清单。

### P1-2 具体承诺变更申请的「在途态」（申请→受理→相对方表达→决定）无记录载体
- 【定位】67 §五：「程序：提交→承诺授权者受理→相对方表达→决定→记录→在途执行」；证据面要求「变更申请与批准、新旧版本对照、相对方意见」；77 §4.3 规则 3：「中途指令只是变更请求……未批准前按原合同继续」。
- 【问题】77 中合同变更只有生效后的 REC-WORK-03 修订（supersedes 链）与 REC-OBL-02.revision_chain（历次变更与批准依据）承载「事后」；申请被受理而未决、相对方意见表达中这两个中间态没有专用记录——REC-WORK-10 的 response 枚举（接受/附条件接受/拒绝/已答复/已签署/声明不能）可勉强承载协作请求，但「承诺变更申请」作为 67 §五单列程序（含六要素申请材料、相对方意见、未获同意时的三种去向）在 77 无对应对象。67 §五明确「变更申请长期不决」要走强制出口，无记录则该出口无计时依据。
