## 摘要

总体判定：**前缀式 ID 体系（DEF/SG/STAT/GOV/REC/RUN/BIND/TS/F/DEP/MIG/D75/TR/GAP/VEC/P-82/PB/U80/P-78/L78）机械一致性极好——全部 token 在主归属卷可解析，断链 0、孤儿 0；裸字母族（E/D/G/V）存在真实的同形撞号与体系外平行族**。具体：

- **断链（被引未定义）**：前缀族 0；裸字母族 0（无 R32/E13 反例族域外值）；唯一断链是**卷内章节锚**：82 三处引「§12.7」，82 §十二只有 12.1–12.6（P1-5）。
- **孤儿（定义零引用）**：0。I-1..I-16 / R1..R31 / E1..E12 / W1..W12 / H0a–H4 / V0–V6 / MIG-01..07 全部有跨卷引用（最稀薄的 I-14 也有 5 卷、E7/E8 除定义卷 65 外在 82 有 TR-E-07/08 追溯键）。55 个 `TS-PORT-*` 全部被引用；语料中第 56 个 `TS-PORT-PLAT-01` 仅为 82-GAP-82-04 的历史性提及（「不再引用」），与声明一致，不算复活。
- **重号（同 ID 异物）**：3 组 P0——①**E1–E6 双义**（反例族 vs 78-§5.2 效果分级 E0–E6，82 卷内即有双义用法）；②**D1–D6 双族**（73-§七 制作人六项边界 vs 80 卷自有决策表 D1–D34 裸号）；③**G-缺口族跨文件重号**（01-contract 与 15-studio-tools 各自定义 G-01 起，06-gateway 另用无补零 G-1 起，10-taiga 又跨引 01 的 G-22）。
- **体系外平行族**：18-boot 版本键 V1–V12（与验证层 V0–V6 撞形，P1）；19-root 回写族 W76/W79/W80/W82/W43/W51-`n`（占 W 前缀，P1）。
- **术语**：抽查 22 项核心术语，18 项一致；4 项同义异词（工单/工作单、「公司包」裸称、台账/记录面、canonical/规范化/JCS）。

- **编号格式**：无全角字母数字（全 41 份零命中）；「卷-§节」引用 6986 处为绝对主导格式；抽检 68 个高频跨卷锚点仅 1 个断锚；补零不一致集中在 E/G 两族与 TR-H 键。

## 四、分级问题

### P0（3 项）

**P0-1 E 族同 token 双义：反例 E1–E12 与效果分级 E0–E6 并存，82 卷内即有双义用法**
- 【定位】78-§5.2「### 5.2 七个效果类（E0–E6）」：89 行「效果分级 E0–E6……不是四态、不是 GOV-RISK-01..04」；82-§五 :464「E05/E12 的记忆存储……」与 82-§14.3 :864「E4/E5 与独立性受限」（此处 E4/E5 为**效果级**）；82-§五 TR-E-04/E-05（**反例**：能力退化降标/离岗删历史）。E0–E6 使用面：78/78a/80/82/79/12/06/65 共 8+ 卷。
- 【问题】75-§2.1 只登记了「E1–E12＝员工册绑定补充反例」；效果分级 E0–E6 是**未入登记表的平行 ID 族**，且与反例族在 E1–E6 区间完全重叠。同一 token「E4」在 82 同卷两处分别指反例与效果级，机械检索与人工阅读均不可区分。
- 【影响】任何按 E-号做追溯/统计/断言的工具或审查会把两族混算（例：统计「E4 已闭合」可能误并效果级 E4 的隔离要求）；82-§1.5「每个 E/W 行恰一个主绑定」的机器校验会被效果级 token 污染。
- 【建议】最小改动：78-§5.2 将效果类改为带前缀形式（如 `EFX-0..EFX-6`），并在 75-§2.1 补登记；或至少在 75-§2.1/82-§1.3 加一条「E0–E6 为效果分级，与反例 E1–E12 无关」的显式消歧行。82-§14.3 的「E4/E5」补全为「效果级 E4/E5」。

**P0-2 D 裸字母族双族同形：制作人六项 D1–D6 与 80 卷自有决策 D1–D34**
- 【定位】73-§七「D1 纯配置与可执行能力的正式分界……D6 完整符合与受限实现的声明方式」；78-§十六 :1829「D1–D6 是 docs/73-§七 提交制作人审核的六项边界」；80-§决策表 :3983 起「| D1 | src/index.ts 按 §3.2 单一方案收敛 |」…共 **34 行裸号 D1–D34**；82 :573/:679/:763「D1–D6 已裁」「D3 公开与许可」「D3/D6」；82 :587/:694「80-D3」。
- 【问题】80 卷内裸「D1」＝自家决策，73/78/82 的裸「D1」＝制作人六项之一——同一语料同一 token 两个对象族。82 靠「80-D3」前缀消歧，但 80 卷自身不带头衔使用裸号；且 **D1–D6（制作人六项）从未进入 75-§2.1 的 ID 登记表**（75 §七只写状态不认领归属）。
- 【影响】「D3」在 80 指 PORT_VERSION 维持 v0（决策），在 73/78/82 指「公开与许可」（待裁边界）——语义完全无关；按 D 号检索待裁项会把 80 的已决事项混入制作人待决清单。
