## 分级问题

### P0-1 终止与不可取消后的迟到副作用观察悬空（孤儿执行体级关键盲区）

【定位】71-§2.4「不能取消：限制新动作、撤销可用凭据并隔离写入，持续观察迟到副作用」；71-§5.6「终止须处理……未决责任和后续影响」；72-§4.2 十一个观察面无一对应。

【问题】71 一方面诚实承认部分执行体「不能取消」并施加「持续观察迟到副作用」义务，另一方面该义务四个要件全部缺失：观察主体未具名（谁持续观察）、无期限/复审条件（观察到何时可以结束）、无证据对象定义（观察留什么证）、72-§4.2 监控面无对应行。72 侧仅有的机制均为记录级且以「记录先到达」为前提：§1.3「迟到记录都要显式标记」只处理已到达的迟到记录；§1.4 的「迟到副作用对账」仅限权威迁移语境；§4.2「价值与承诺」行的相对方异议属被动渠道。71-§6.1 还自认「轮询/通知盲区和迟到回执」是平台固有缺口。

【影响】被终止/不可取消的执行体（孤儿进程）在无内部记录、无外部投诉时，其持续产生的外部副作用不可发现，直到损害显性化——这与 I-15「外部性不可内部抹除」及 72-§4.4「损害正在发生时，先停止继续影响」的意图直接冲突；回收类工作「撤而不清」的主验收对象（残留完整性）也失去观察依据，「持续观察」本身若无终局还会变成 71-§5.4 明文反对的无终局异常。

【建议】72-§4.2 增设「终止后在途/迟到副作用」观察面行（观察对象、最后可信观察点、期限、到期终局）；71-§2.4/§5.6 为「持续观察」具名责任位置、观察窗口与完成判据（观察何时可合法结束须是一项有据决定）。

### P1-1 「运行时偏离」等能力失败面缺持续观测锚点

【定位】71-§1.2 三失败面「已授权未生效｜已生效但授权撤回/到期｜运行时偏离」；72-§4.2「能力与出工」行仅列「实际执行计划、依赖缺口、段间替换、资格和重认」。

【问题】71-§1.2 定义十三个能力状态并要求三个失败面各有处置，其中「运行时偏离（缺失、降权、额外能力、版本或来源不符）」须「立即降级或暂停；额外能力按未授权处理」。但发现机制只有事前「已探测」与变更后「后验观察」两个时点，未规定探测节奏；72-§4.2 能力行不含「实际暴露 vs 锁定计划」偏离比对项。「授权到期」虽在「权责与治理」行，撤回后运行时仍在暴露的状态无任何观察锚点。

【影响】两次探测/后验之间的能力偏离（尤其额外能力暴露、版本漂移）不可见，属静默未授权风险；「已按计划生效」与「运行时偏离」的分账在持续运行期退化为时点性声明。

【建议】72-§4.2 能力行补「运行时暴露 vs 锁定计划偏离」与「撤回后运行时仍暴露」两目；71-§1.2 为偏离发现指定节奏或触发时点（如段开始、段边界、秘密注入时）。

### P1-2 探测、生效证据与吊销验证的执行/核验主体未指定

【定位】71-§1.2「已按计划生效……且有可核验证据」；71-§3.3 H0b「至少一次可用性探测通过」；71-§3.4「吊销后要验证运行时确实拿不到」。

【问题】三处都要求验证/探测，但均未指明由谁执行、谁核验。若由执行方自报「已按计划生效」或自测可用性，按 72-§2.3「不能把交付方自己……执行的检查包装成独立验收」只能算材料；而「生效」恰是「有权」与「真在用」分账的关键控制点。72 只处理验收独立性（§2.3），未给出生效类机械证据的采集者要求与复核分层。

【影响】「已授权」与「已生效」的分账可能被自报冒充；H0b「静态装载」的可用性与吊销「确实拿不到」可能沦为清单自查。

【建议】72-§2.3 或 §7.1 增补规则：运行时暴露、可用性探测、吊销生效属可复算事实时须由宿主回执或独立探测通道取得，自报仅作线索；71 三处补「由谁探测/由谁核验」字段。

### P1-3 带期限条件未要求义务实例化，监控面不可见

【定位】71-§4.1「暂缓必须有期限或复审条件」；71-§4.4「附条件必须含责任者与到期处置」「须写假设、验证和到期处置」；71-§4.5「派工者必须处理拒绝，不能让『已派出无人接』无限悬置」；72-§1.1「『合同里写过』『规则里要求』都不等于有人正在履行」。

【问题】71 大量制造带期限的条件态（附条件受理、附条件开工、暂缓、信息假设到期、派工拒绝处理），72-§1.1 已立「义务要有实例」原则、§4.2「义务与期限」行以义务实例为观察对象，但两卷均未显式要求上述条件态生成 Obligation Instance；71-§4.5 的请求时限清单（请求输入、评审、授权、移交、接力、会签、异议和裁决）也不含派工与领取本身。

【影响】这些到期点若不实例化，72-§4.2 义务行看不到，附条件接受/暂缓可能无限悬置——恰是 72-§1.1 明文反对的形态；「已派出无人接」的悬置无升级锚点。

【建议】71 各条件态处显式要求生成义务实例（承担位置、到期、违约去向）；将派工/领取列入须有时限与未响应语义的请求清单。

### P1-4 链后义务的证据对象与观察面在 72 无落位

【定位】71-§3.4「凭据轮换与吊销、旧版本退役与清理是……链后义务……完成判据仍须逐项保留」；72-§5.1 主答链止于「保留 / 停止 / 恢复 / 修复 / 再次修正」。

【问题】71 明确链后义务不扩充 72-§5.1 主答链、但须逐项留证；而 72-§5.1 及其后各节均无「轮换/吊销/退役/清理」的记录语义；72-§4.2「变更与进化」行的「撤回与残余影响」仅近似覆盖撤回，不含轮换完成、退役清理的完成证据与残余清点。

【影响】链后义务完成无据可查时，「移除依赖不得只从清单删除」（71-§3.4）退化为清单操作；退役后残留副本无观察入口。

【建议】72-§5.1 链尾补「链后义务」的记录要求段落，或在 72-§4.2 变更行增「轮换/退役完成证据与残余清点」目。

### P1-5 证据包「产物」要素未覆盖 71 全部交付形态

【定位】72-§2.1「产物｜交付对象的不可变版本与内容引用｜没有确定验收对象，不能判接受」；71-§4.2 六类结果面与「拒绝/避免/暂缓/撤回……各有自己的验收对象与证据结构」。

【问题】72-§2.1 证据包以「产物=交付对象的不可变版本」为要素，模板隐含创造类交付。71-§4.2 定义的维持（状态结果+过程）、探索（学习交付+边界）、调查（事实链）、回收（无残留证明）、清算（承接确认），以及无产物结果形态（避免类须「事前风险条件、期间监测与事后独立复盘」三段证据）在 72 无对应要素或结构定义。严格读 72-§2.1 产物行的缺失列，无产物形态会错误触发「没有确定验收对象，不能判接受」。

【影响】维度②缺口：72 的验证结构作用不到 71 的全部交付形态；探索/回收/避免类的验收对象（边界、残留、三段证据）可能被迫套用产物模板或各自为政。

【建议】72-§2.1 产物行改写为「验收对象」要素并枚举六类结果面与无产物形态的验收对象类型，或显式引用 67-§九 的分型证据结构。

### P1-6 执行体活性/健康信号无观察面消费落点

【定位】71-§1.1 能力表「能提供哪些真实事件、用量、成本和健康信号，盲区在哪里？」；72-§4.2 十一行无活性/停滞项。

【问题】71 要求能力声明健康信号与盲区，但 72-§4.2 无任何一行消费「执行体活性」；停滞发现完全依赖合同到期语义与可选复审点（71-§4.3）。长周期、中间无产物的工作在两次检查点之间停滞不可见。

【影响】执行体假死（活着但无进展、无消耗）属静默失败一类，须到到期/复审点才可能暴露，期间时限承诺与资源窗口持续流失。

【建议】72-§4.2「能力与出工」行增「执行体活性/最后进展信号」目；71-§4.3 要求长周期工作必设中间复审点或进展信号。

### P1-7 静默恢复与暂停期间动作的发现依赖自报

【定位】71-§5.5「静默恢复（无决定、无记录地继续）视为违规」；72-§4.2「工作与异常」行含「恢复」但无「暂停期间动作」项。

【问题】71 把静默恢复定为违规并要求「暂停期间的动作不能因后来成功获得追溯授权」，但其可发现性依赖行动回执如实入账（自报）；对不入账的动作，72 无专门观察锚点，只能靠资源消耗或外部反馈间接撞见。

【影响】违规的威慑依赖行为人如实记录，最不合规的主体恰最可能逃逸；恢复四档的独立性设计被绕过。

【建议】72-§4.2 工作行增「暂停/围栏期间的动作与写入」观察目（对照围栏拒绝记录、平台活动、资源脉冲），使静默恢复有独立于自报的发现通道。

### P1-8 71 的沙箱逃逸验证义务在 72 验证分层无归属

【定位】71-§6.2「沙箱配置本身也要版本化并验证逃逸、符号链接、绝对路径和外部句柄」；72-§7.1 V4 内容为「崩溃、重复、迟到、游标断裂、双写、恶意包、撤权、恢复与移交」。

【问题】71-§6.2 的隔离验证义务在 72-§7.1 各层内容清单无对应项：V4 未点名工作区隔离与逃逸（仅证据列的「攻击夹具」可宽泛涵盖），V5 探针限于「装载、暂停/恢复、更新与权限边界」。72 是验证分层唯一主答，该义务悬空。

【影响】工作目录是 71 受限履职环境的物理承载，隔离失效即读/写/网络/秘密边界整体失效；验证无归属则义务不可验收、不进符合性下限（V0–V4）。

【建议】72-§7.1 V4 内容清单显式增「工作区隔离逃逸（符号链接/绝对路径/外部句柄）」，或在 V5 绑定档案要求中点名。

### P2-1 「出工段记录同时是 Engagement Memory 的形成面」措辞层级歧义

【定位】71-§2.2「出工段记录同时是 Engagement Memory 的形成面」；72-§3.1 出工记忆「形成」列引「71-§2.2 出工段记录」。

【问题】段记录含行动回执、产物/证据引用，按 72-§1.1 属历史对象（只增、修正链）；记忆是历史派生物（72-§三「由历史派生，不反向改写历史」）。「形成面」可被误读为段记录=记忆对象，进而误用记忆清除程序处置段记录。合读可澄清（72-§3.1 清除列「不得清除责任、承诺与证据」已兜底），但缺一层显式分层。

【影响】实现者可能把段记录放进可清除的记忆存储，造成历史丢失。

【建议】71-§2.2 补一句「段记录本体属历史记录（72-§一），出工记忆是其受处置授权约束的派生物」。

### P2-2 两套「接受」族枚举的层级映射未声明

【定位】71-§4.1「受理结果至少有接受、附条件接受、暂缓、拒绝、转呈」；72-§2.2「completed、accepted……settled 必须保持不同语义」。

【问题】71 受理五值是入口决定，72 六判断是工作终局判断，71-§5.1 另有十工作状态；三组集合均含「接受/拒绝」同名词，两卷未显式声明三者的层级映射与不可互推关系（各自文内语义自洽）。

【影响】绑定档案做状态映射时易把受理「接受」直接写成工作 `accepted`。

【建议】在 72-§2.2 或 71-§5.1 加三组集合的映射说明（受理决定≠工作状态≠验收判断）。
