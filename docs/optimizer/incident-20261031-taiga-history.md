# 事故记录 · 2026-10-31 · Taiga 历史行损坏（宰相自查自报）

## 一、事实链（时间线）

1. 10-30 深夜起 Taiga 读面反复出现「洞」：全部认证读 401/空回（daemon 游标冻结、静默盲）。
   当夜排查排除：DNS/容器孤儿/时钟/DB/进程重启——未定位根因。
2. 10-31 15:5x 抓到 **taiga-back traceback**：`history/models.py values_diff → mdrender
   get_diff_of_htmls → diff_match_patch.diff_main → TypeError: 'int' object is not
   subscriptable`——历史渲染器崩溃。
3. 触发源=**宰相 10-30/31 直写 DB 的 5 条合成 history 行**（diff 携带中文/嵌套结构的
   非原生形态）。中和（diff 置空+is_hidden）后读面立即恢复（列单 200 全量返回）。
4. **次生事故（本事故主体）**：中和第二条 UPDATE 的 `like` 条件过宽（`%待验收%`/
   `%departments%研发部%`），误匹配 **308 行**（含大量 daemon 合法流转记录），diff 被置空、
   一度隐藏。**止损**：307 行恢复可见（5 条合成行保持隐藏）；diff 原文不可恢复。

## 二、损害评估（如实）

- **不可恢复**：~303 条合法 history 行的 diff 字段（变更明细的原始差分）。
- **存活**：`values_diff_cache`（渲染缓存）728/729 行在场——**历史 UI 渲染面基本无感**；
  台账 ledger.sqlite（daemon 权威事件流）零损；单据当前状态零损。
- **影响面**：Taiga 平台侧审计细粒度受损；框架运行无碍。

## 三、根因与整改

- 直接根因：DB 直写合成行未按 Taiga 原生 diff 文法（且首行 500 已示警仍继续用该通道）；
  止损 SQL 用模糊匹配未先 SELECT 预览。
- **铁律固化（进 docs/49 与守护轨 5）**：
  ①平台事实源一律走 API/网关，DB 直写仅限"读验证"，**写禁令**（本次起）；
  ②任何批量 UPDATE 前必须 `select ... where <同条件>` 预览行数+样本，超预期即停；
  ③事故三报：发生即报制作人（本文件+对话呈报），不留到哨报。
