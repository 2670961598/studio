## 裁决一（D1）：保留「包内 DSH 插件例外」——绑定 DSH 是设计特色，不是债务

**争议**：新方案 69/75 卷提案「正式废除 43-v1.1 的包内 dsh 插件唯一例外，公司包回归零私有依赖」；既有裁定（43-v1.1）允许例外。方向相反，须制作人定。

**制作人裁决：保留例外，绑定 DSH。** 原意照录（2026-10-27）：

> 「DSH 是我们默认并且未来必定认定的主力执行器，可以兼容其他的，但是最推荐 DSH……其他的 CLI 工具可以作为备选，但是肯定会失去我们提供的部分功能。我个人是更加倾向于，DSH 为主，其他也可，但是明确会牺牲一些。」
> 「搭建一个特化的、围绕 DSH 的公司，别人想用，也肯定是必须有我的插件的，我觉得无可厚非。但是也允许完全不用 DSH，但每个 CLI 都要适配……所以就以 DSH 为主，或者说几乎绑定 DSH，我是倾向并且赞同的。DSH 就是我们框架中的例外，我是想绑定 DSH的。」

**落地含义**：
1. 69/75 卷 D1 决策记录按此**改写**：43-v1.1 例外升格为长期设计——公司包允许携带 DSH 插件配置；「不用 DSH 则专属能力受损」是**明示代价**而非缺陷。
2. GLM 审计 B8（D1 顶替终裁簿）**关闭**；MIG-04 前置按此口径解除。
3. 修订波次中，70 卷公司包内容物清单需为 DSH 插件资产保留正式位置（见裁决一·附）。

## 裁决一·附（D1a，新增需求）：设立「公司资产部」概念

制作人批复中带出的新设计需求，照录：

> 「我们需要有一个公司资产部，例如保存很多的 Skill、MCP、其他的插件，包括 DSH 的插件也作为一种资产，但是只能 DSH 这个执行器用的资产。」

**落地含义**：Skill、MCP、插件成为公司**一等资产类型**；资产可分「执行器专属」（如 DSH 插件）与「通用」两类；公司包携带资产清单，特化公司可声明「必备资产」（接收方须具备相应执行器）。修订波次 B 档增补：70 卷（公司包内容物）与 77 卷（记录载体）增资产对象、专属标记与传播语义。**此为新增设计，非审计修补项。**

## 裁决二（MCP 范围）：studio-tools MCP 与对外 API 纳入本次大重构

**争议**：既有终裁簿条目「MCP 缓——经营面缓办、只留接口」与新方案波次涉及 studio-tools 的边界不清（GLM 审计 B9 呈请划界）。

**制作人裁决：不缓，纳入本次。** 原意照录：

> 「所有的执行器，例如人事可能要更改人事信息，财务要查看一些内容，研发要申请权限等等，我们都可能需要 StudioNext 的 MCP 来提供，而不是一股脑作为提示词塞进去。这部分需要随着这次一起展示出来。」
> 「并且我们对外的东西，除了给 CLI/Agent 工具使用的 MCP 之外，还需要提供很多 API 来和其他工具对接的，这些这次一起考虑了。我们这次从权责体系，到员工，到框架，到工作，相当于一次大重构了。」

**落地含义**：
1. 「工具走 MCP、不塞提示词」确立为**新设计原则**——人事/财务/研发等场景化操作全部经 studio-tools MCP 提供能力，提示词只含身份与上下文。
2. 对外 API 面（与其他系统对接）与 MCP 面一并纳入本次大重构整体设计；GLM 审计中 80/81 卷对 studio-tools/api 覆盖不足的缺口（H3b-P1、C4a 相关）在修订中**补齐为正式章节**。
3. 终裁簿「MCP 缓」条目由本裁决取代；经营面（商业化收费）仍未定，后续另裁。
