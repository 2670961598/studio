### 1.2 V1 契约先行法（本卷核心机制）

**形状与冻结**：`packages/contract/cases.json` 形状 v1 冻结（`{version:1, cases:[{id,domain,docs,title,input,expected}]}`；`expected` 恰含 `out`/`err` 之一；`__NULL__` 哨兵；匹配语义语言无关——CASES.md 是格式唯一规范，改 cases.json=改契约走批示）。

**施工节奏（每波三步，顺序不可倒）**：
1. **先落 case**：波内首批单=契约单——写 cases.json 新条目（可红跑：实现未落时期望 `err` 未抛即红）；同单在 CASES.md 域清单登记新域/新条目语义。
2. **再实现**：实现单必须引用所满足的 case id（单据验收口径=「case N 绿」）；subject 路由代码落 packages/contract/src（现状 meta/dir/evt/rpt/deps/mj/plat 七域模式沿用）。
3. **后收口**：波验收命令（第二节）含契约子集全绿；禁止「先实现后补 case」。

**命名与对应规则**：
- id：`C-<域>-<序号>`（三位序号），一经合入永不复用、永不改义；废弃标 deprecated 不物理删除（CASES.md 冻结规则 1）。
- **V2 新增域**（本卷登记，落 CASES.md 域清单）：`enc`（v2/10 §二/§七 canonical 与 VEC）｜`rule`（v2/10 §六 求值档）｜`sch`（v2/10 §四 纯配置 schema）｜`rec`（v2/11 记录族拒绝条件/迁移表）｜`asset`（v2/06/10 资产部与导入）｜`port`（v2/14 端口冒烟）。既有域不动。
- **docs 字段**：V2 来源 case 一律写 `v2/NN-§X` 形（如 `v2/11-§14.2`）；机械可查：`grep -c '"docs": "v2/' packages/contract/cases.json`〔实测现值 0；各波冻结值见第二节〕。
- **NEG 对应**：凡落 V1 的 NEG 条目，其对应 case 的 `title` 以 `NEG-<族>-<序号>｜` 开头（不改 JSON schema，title 为自由文本）；机械映射靠该前缀。负向 case 的 `expected` 用 `err` 通道断言拒绝（category 全等，subcause 给出才断）。
- **REC-/PORT- 对应**：`rec` 域 case 的 docs 引 v2/11 对应族节（13 分组行每族≥一正一负）；`port` 域 case 引 v2/14 §二端口-文件映射（MIG-06/07 落地后）；REC 74 类全量逐类 case 不求一次到位，**每族（13 分组行）一正一负为 V1 下限**（v2/17 §一 V1 行口径），逐类加密随各波实现单走。
- **VEC-01..10 直接入 enc 域**：VEC-01..08 为正向摘要 case（expected.out 比对规范文本与 sha256）；VEC-09/10 即 NEG-ENC-01/02（expected.err）。规范侧 digest 已由 v2/17 §二.6 复算 8/8（V0），实现侧=本域 V1。

**新增 case 量预估**（计划数非事实，波次对账复算）：MIG-03 约 +45（enc/rule/sch/rec 全族下限）｜MIG-04 +8｜MIG-05 +25（asset/sch）｜MIG-06 +25（rec 任务面加密/port 冒烟）｜MIG-07 +12（plat/gw 签名）｜MIG-08 +3——终值约 53→**≈171**。
