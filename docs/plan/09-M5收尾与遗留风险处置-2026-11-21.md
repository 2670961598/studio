## 四、notify 面实现记录（2026-11-21，§二#3 小刀）
- **形态**：`NotifyBroadcastFace`（engine/notify/broadcast.ts 端口不变）结构同形第二实现——
  daemon 侧零 matrix import 不变（docs/25-§一.2）；relay 调用面零改动（`face.send(notification,
  {alert/overview/dept/room})` 同一端口）。判例=chatd-mention-source.ts（transport/config 收口
  同款单孔）。
- **投递语义**：alert/overview/dept 三逻辑角色**折叠投配置房恰一条纯文本**（chatd 无部门频道
  拓扑，同房多条=噪音；report.sent 仍逐角色点名——惊动计量 byRole 口径不漂移）；显式
  targets.room 直投该房（同房并入同一条）；空角色零发送。文本=`[kind] title`+body+`- label: url`
  +`—— from`（无 markdown——chatd 按原文渲染）。
- **失败面**：send 永不抛（刀B-6 第一道；relay 双保险在外）；单次 sendMessage 失败按
  classifyChatdError 分类入 report.failed+日志（`[chatd-notify]` 前缀），面板仍 critical 第一落点。
  **幂等键不设**：本面 fire-and-forget 无重试，内容哈希键会吞并同文异事件通知（去重归 relay）。
- **密钥**：token 经 env WORKBENCH_CHATD_TOKEN（组合根供给，值永不入 yaml/日志/台账）；面内
  已知值自扫（err.message 理论回显也替换 `<redacted:chatd-token>`——不依赖出站闸 env 收集面
  未含该键的现状）。
- **配置**：`notifyChatdRoomId`（非空；键在场=面开）+ `notifyChatdSenderId`（工号样式，缺省
  PRIME-0）；孤儿 senderId / 与 matrix / 与 matrixChannels 互斥 / 缺 socket 又无 companyDir
  → 解析即拒（CONFIG_INVALID）；chatdSocket 复用唤醒源键（缺省 `<companyDir>/var/workbench/
  chat.sock`）。骨架注释已补（cli/serve.ts）。
- **boot**：`assembleChatdNotifyFace`（里程碑5 尾）——matrix: false + notifyChatdRoomId → 注入

  5000/10000，P1 加固单一源）；缺键零注入（现状不回归）。
