# 10 · per-skill 信任梯度设计（1 页；2026-11-22 研究刀，不实现）

> 依据：arXiv 2609.13334（The Agentic Company OS）——per-skill trust gradient 使治理/审计成为基座结构属性；结合我们 control key/审批面/网关动作边界（docs/17、20、25）。
> 状态：**设计稿**（研究刀；实现另立单）。

## 一、问题
当前信任面较粗：执行体（executor）级开关 + 网关单写入者 + 验收闸；**同一执行体拥有的不同技能/命令面风险不同**（只读查询 vs 写台账 vs 调外部 API），一刀切要么过松要么过紧。

## 二、定义
技能 = 执行体可调用的原子能力（如 `issues.list`、`gateway.write`、`exec.shell`、`net.fetch`、`deploy.prod`）。
信任等级 = 该技能在生产环境的许可级别：

| 级别 | 语义 | 判据 |
|---|---|---|
| T0 只读 | 允许直接调用（审计留痕） | 无副作用验证（幂等/只读） |
| T1 写入（可逆） | 允许调用但记审批锚；冲突时停 | 可回滚/有补偿 |
| T2 写入（不可逆） | 默认拒；需人/制作人审批 + 双签 | 无自动回滚 |
| T3 高风险 | 默认关；仅显式白名单 + 审计回放 | 生产/资金/外发 |

## 三、映射我们现有面
- 网关写路径（platform/company/ledger）= T1（单写入者已保证"唯一"；梯度管"可逆性"）；
- 验收/派发/回滚 = T2（不可逆语义：重试=新 attempt，回滚=新单）；
- deploy/daemon 重启/凭据修改 = T2/T3（走 ops + 制作人审批）；
- 聊天/面板只读 = T0；发消息 = T1；
- 执行体 shell 网络 = T1（沙箱/超时兜底）。

## 四、实现骨架（后续单）
1. 技能注册表（`skillId`/等级/审计要求）——单一源 JSON，随框架分发；
2. 网关与执行器适配层在调用前查等级：T0 放行、T1 记锚、T2 需审批句柄、T3 白名单；
3. 台账 `trust` 维度（调用记录 + 审批锚）用于审计回放；
4. 与现有 control key、验收闸、预算闸并列，不替代。

## 五、不做什么
- 不做通用 RBAC（过度设计）；不按"人"分权限（先按技能）；
- 不改当前生产行为（本设计不落地）。
