## 二、施工原则（从 V2 与两族审计直接导出）

1. **先冻结后施工**：MIG-01 基线冻结、MIG-03 contract/schema 冻结（v2/16 唯一主表；MIG-02 为 **V2 新测试基础设施＋旧测试台账**）是一切实现单的前置——冻结物以 v2/09 主表与 v2/11 记录族为字面。
2. **契约先行**：每波先落契约 case（packages/contract cases.json）与 NEG- 负向用例（v2/17），再写实现——契约测试是唯一验收标尺（AGENTS §五.2）。
3. **按分层宪法分泳道**：cli→assembly→engine→packages 单向；一单一领土（文件级），领土互斥的单可并行（docs/24 并行轨道先例）。
4. **fail-closed 优先级**：v2/15 SEC-FC-01..07 的七项在触及对应面时同波修复，不留 fail-open 过渡态。
5. **钱账限域**：cost_daily 备份不重放（v2/16 §cost_daily），rebuild 排除域先立再动 store。
6. **DSH 主绑定不动摇**：执行器面只做 v2/07/12 的 DSH 具体化与专属/通用二分，不做备选 CLI 的实机适配（终裁簿 kimi/codex 缓）。
7. **不杀活 worker、不动在途、不重写历史、不 force push**（红线照旧）。
8. **证据断言**：每单完成=终态事件+非空输出+REPORT+闸门 exit=0（AGENTS §五.3）；每波出口=**该波 V2 新套件绿＋触及面旧测试登记（红也登记、不阻塞）**＋该波 NEG 全过＋修订一致性复核/F8 并行对应节通过（开工令 §3；F8 未签不阻断）。
9. **根交接证据（root_delegation/外部撤权）**：施工期治理模型按 V2 v2.1 的两层老板执行——对外人类老板是根，对内最高宰相（G9，唯一）持 operating root key，其权源是外部老板的 `root_delegation`（范围/期限/可撤回/密钥指纹/外部签名或离线批准件）；超出范围＝外部可撤回的违约。**子 agent 不得自授、不得持 root key；最高宰相对下授予是老板行为**。任何组织/人事/审计单必须能出示 root_delegation／外部撤权（REC-AUTH-01/03）证据，不得按「单一宰相接口」「宰相只是投影」等旧模型施工（v2/03 §3、v2/15 §根密钥与外部撤权）。
10. **一级单元 N 参数**：最高宰相之下设 **N 个一级单元（N≥1，默认 N=1）**，每单元一个首长（G8）；「三省」只是 N=3 的示例，**不是规范、不写死 3、不要求制作人现在选 N**。N=1 且不单设单元首长时退化为单层。一单元一域、域不重叠；跨单元由最高宰相终裁；单元缺位登记组织事件并由最高宰相直管。组织/人事/审计/模板类实现单按 N 参数实现，不得硬编码三省（v2/03 §2）。
11. **旧测试不作施工门**：以 V2 开工 tag 为界，tag 前已有=旧测试，tag 后新增=V2 新测试。旧测试**不作为波门**，但必须逐文件登记台账（路径/状态/处置/责任波/理由），**37 红（审计基线；MIG-02 实测 20）逐条有归属、不许无声删除**；V2 新套件（contract 含 NEG＋unit＋integration＋e2e＋crash）是门，命令与阈值见 plan/04。旧测试存废由 V2 完成后制作人/DSF 判（判据：覆盖/维护成本/行为是否仍成立），不得拖成永远以后。
