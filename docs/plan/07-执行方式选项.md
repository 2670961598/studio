## 一、决策问题与选项总览

施工对象=把 StudioNext 从 v0.5 dev HEAD 按 docs/v2/01-17 重装为 V2（MIG-01..08 八波，
plan/03）。要决定的是：**每一波的活由谁干、谁验收、证据落哪个账本**。

| 选项 | 一句话 | 执行体 | 验收/合入 | 证据账本 |
|---|---|---|---|---|
| **A 框架服务自驱** | 恢复 StudioNext daemon，按 v2 立 T:devtask 单，框架派工/验收/自合并 | dsh 唤起的 worker（DSH 主绑定） | 框架验收岗+人闸（宰相∪制作人∪派单策划） | StudioNext SQLite 台账+YouTrack |

## 二、选项 A：框架服务自驱

**形态**：撤销停机令恢复 daemon → 宰相按 plan/05 实现单清单在 YouTrack 立 T:devtask 单 →
框架组装上下文/唤起 dsh worker/收割证据/跑门禁/真单刀自合并 → 人闸批示 → 下一单。施工组织
本身即 V2 权力模型（84b §三）的第一次实跑：制作人=老板终审、宰相=九级投影放行（放权令：
常规单直接放行、事后审计）、策划验收位打回工程。

**前置条件（5 项）**：
1. 制作人撤销 10-24 停机令，并设定施工期预算上限（配额墙预警线）；
2. MIG-01 基线冻结完成——停机四天 dev HEAD 已前进，恢复即先复算十三项基线，任一不可复算
   即触发 MIG-01 停止条件（v2/16 §一）；
3. daemon 在 dev HEAD 三门禁全绿（typecheck / test 209 件 / guard:boundaries）+ 真单刀流
   dry-run 至少 1 单走通（v0.5 合并机 230-234 生产实战少，先演练）；
4. YouTrack（wkey 网关）/ Matrix（群房间）/ dsh 执行环境在线可用；
5. 三档模型配额到位（见下）。

**成本（配额三档分配）**：单均成本三选项最高——每单全链=派单策划+工程执行+验收+审验+巡检
多轮唤起，全部经三档路由：**大档 DeepSeekFlash=工程 worker 主力**（实现+测试编写，量大）；
**中档 GLM-5.3=宰相/审验/策划验收**（判断密集）；**小档 Flash=判定器/选单/巡检哨**（轻量高频）。
对价：成本全链 v0.5 已跑通，每一笔可核算、可预算闸、入台账投影。

**风险**：
- **R-A1 边飞边换引擎（核心风险）**：daemon 自身是被改造对象——MIG-06 拆 engine.ts（2337 行）
  时框架正在跑施工单。对策：daemon 自改单走「停机窗合并」——在途单清空点停机→合并→三门禁→
  恢复（红线「不杀活 worker」由此满足）；即 A 模式内嵌局部 C 化的停机窗。
- **R-A2 v0.5 新缺陷阻断施工**：真单刀流/人闸实战里程少，施工中被自身缺陷卡死。对策：MIG-04
  起步波先跑低风险 store 单热身；缺陷本身走 T:devtask 缺陷单修复——**修框架的缺陷由框架自己
  派单修，正是 dogfooding 应有之义**。
- **R-A3 配额墙**：框架开销放大消耗。对策：巡检哨盯配额（49 决策包既有机制），触线降并发。
- **R-A4 恢复漂移**：停机期仓已前进，daemon 侧配置/凭据/环境可能过期。对策：前置 2 的基线
  复算+演练单兜底。

**与 V2 目标一致性**：**最高**。V2 的主张就是「公司脱离人运行」（AGENTS §一）、代理权网状化
（竞争 doctrine：不是一个人的超级外骨骼）。框架用自己的施工验证自己的目标，是唯一能在
施工期同时产出「V2 实现+V2 运行时证据」的路径；放权令的自治口径也在施工组织面自践行。

**证据链质量**：**最高**——终态事件+非空输出+REPORT 落盘+闸门 exit=0 四要件全，工时/成本/
事件入 SQLite 台账可重建投影，格式即 V2 目标格式（v2/11 记录族的真实生产数据）。

## 三、选项 B：旧 Studio 承载

**形态**：在 /Volumes/BigDisk/Studio 老 V3 系统上为 StudioNext 仓设公司/岗位，由 V3 的
daemon 派工。老系统成熟稳定、有生产里程。

**前置条件（3 项）**：
1. 制作人**解禁两条自家禁令**：旧公司搁置令（「旧的公司我们暂时不管，只管开发新的」10-20）
   与不碰旧系统红线；且终裁簿旧债口径已定「StudioNext 与 Studio V3 无任何关系」——用 B
   等于制作人推翻自己两条裁决；
2. 接受两套台账：施工期证据落老系统账本，StudioNext V2 台账**不含本施工期任何账**，事后
   不可补录（先例：DEV-37 V3 数据迁移已**永久拒绝**）；
3. 给老系统配置 StudioNext 仓的验收口径（cases.json 契约/NEG- 用例/boundary rules/三门禁
  脚本）——教会老系统新契约的适配成本本身即一笔工程。

**成本**：V3 栈自己的模型消耗（配额池若共用则同等烧钱），且台账记在老系统、无法进 V2 成本
投影；加上前置 3 的适配成本——**总成本不低于 A，产出却落错账本**。

**风险**：
- R-B1 红线违规即返工（AGENTS §五.5：违规即返工，两条制作人令在上）；
- R-B2 证据链断裂：V2 主打记录族/可重建投影，自己的施工账却在另一个将被替换的系统里；
- R-B3 契约盲区：老系统不识 V2 契约测试与分层门禁，验收口径失真=验收失守；
- R-B4 双 daemon 并跑的注意力与维护成本。

**与 V2 目标一致性**：**负相关**——用前身系统建造继任系统，等于宣告 V2 目标在施工期不可行；
且老系统本质同为「框架派工」，并不提供 A 之外的新能力。

**证据链质量**：差——格式≠V2 台账，重建投影不含施工期；两套账对账=新增旧债。

## 四、选项 C：新会话全程监督

**形态**：如本轮 V2 文档工程——制作人开执行会话（ZCode/GLM 子代理或 Kimi Code/K3.1+DSF），
按 plan/05 单清单施工，宰相审验合入（审验铁律不降）。已验证可行：17 卷 V2 文档即此法产出。

**前置条件（3 项）**：
1. plan/00-07 全部成稿并通过方案门（宰相审读→DSF 再审→制作人过审，plan/00 §四）——本就
   是任何选项的共同前置；
2. 宰相审验会话可用且愿意承担上下文负担（审验=review 分支 apply+三门禁亲跑+merge --no-ff，
   逐单执行）；
3. 执行会话配额（GLM/Kimi 池）到位。

**成本**：单均 token 开销最低——无框架调度/验收岗开销；**中档 GLM=宰相+主力执行子代理、
大档 DSF=再审/大批量查证、小档 Flash=零星判定**。但成本只在会话账单里，无核算无预算闸。

**风险**：
- R-C1 无台账证据链：施工期工时/成本/事件账为零，git 提交+审验记录文档是全部证据——V2
  证据四要件缺「终态事件+台账」两件（对策：施工日志与审验记录强制落 docs/，仍非台账）；
- R-C2 宰相上下文瓶颈：逐单审验亲跑门禁，单量上来后成为吞吐上限（对策：单拆小、审验清单
  化、DSF 分摊复审）；
- R-C3 零 dogfooding：V2「公司脱离人运行」目标在施工期完全未被检验，靠会话外骨骼（制作人
  doctrine 明确分类：辅佐人工作，非团队）造出一个从未自己跑过一步的公司；
- R-C4 会话断续：上下文丢失风险（对策：每单收尾即落盘，plan/00「单门」即断点续传点）。

**与 V2 目标一致性**：部分——能产出 V2 实现，但执行形态与 V2 主张相反（外骨骼而非组织）。
注：C 用 ZCode/Kimi 施工**不触框架 executor 面**（adapters 包不动，DSH 主绑定 v2/07 无契约
冲突），只是品味上「框架由非 DSH 工具建造」——中性事实，如实呈列。

**证据链质量**：中——git 可追溯、审验留痕，但无台账四要件，工时成本不可核算。

## 六、混合方案与推荐（宰相参考序，非结论）

**推荐形态：先 C 后 A，B 不用。**

- **MIG-01..03 用 C**：这三波=基线冻结（只读复算）/ test 修红 / contract 冻结工件——
  低量高精度、文档与 schema 密集、**不改 daemon 运行时行为**，恰是会话型执行强项；此时
  恢复 daemon 的前置（撤令/复算/演练）尚未发生，用 C 不空等，也零引擎风险。
- **MIG-04 起切 A**：进入行为改造（store v14 记录面→资产部→daemon 拆分），实现单量大、
  需要验收纪律与台账证据链，正是框架开销开始回本之处；且 daemon 先自驱两波包级改造
  （MIG-04/05 不动 daemon 自身）作为热身，到 MIG-06 拆自己核心时已有实战里程——把
  「边飞边换引擎」的窗口压到最小并配停机窗。
- **B 恒不启用**：与两条制作人令+DEV-37 先例冲突、证据落错账本、无 A 之外新能力。

**切换点**：MIG-03 出口（冻结工件+漂移检查过、typecheck:test 串入门禁绿、NEG- 对应用例绿）。

**切换判据（四条全过方可切 A，缺一则 C 续跑顺延）**：
- G1：MIG-01..03 出口验收命令全绿（plan/03 冻结口径）；
- G2：daemon 恢复演练通过——dev HEAD 三门禁全绿+真单刀 dry-run 1 单走通+Matrix/YouTrack
  链路在线；
- G3：制作人撤销停机令并批施工期预算上限；
- G4：三档配额到位（大档工程主力/中档宰相审验/小档判定巡检）。

**回退路径**：A 起跑后若 G2 类缺陷复发阻断施工——该缺陷修复单临时走 C，修复后 A 续跑
（判据重试，不弃换、更不转 B）；MIG-06 停机窗内若三门禁红——git revert 单提交回退点
（v2/16 各波回滚栏）。全案任何时刻不启用 B。

**理由摘要**：C 的快用在框架无风险处（冻结类），A 的贵花在物有所值处（行为改造+目标验证）；
施工全程「公司脱离人运行」从 MIG-04 起成为被验证的事实而非口号，同时保留 C 作缺陷修复与
停机窗的机动通道。
