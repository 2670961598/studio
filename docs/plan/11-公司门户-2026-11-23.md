# 11 · 公司门户（Company Portal）——设计文档（2026-11-23）

> 状态：已按「文档先行」落稿；实现单引用本文件章节号。
> 定位：把「公司明面上的东西」合成**一个**好看、好用、完善的只读网页——概览＋单子＋聊天＋组织＋报表；
> **监控面（:8791）保持独立**，不并入、不链接（两拨受众不同：门户=公司日常作业面，监控=框架运维面）。

## 一、信息架构

### 1.1 布局

- **侧边栏**（240px）：品牌块（logo mark SVG＋公司名）；导航＝概览 `/`、单子 `/tickets`、聊天 `/chat`、
  组织 `/org`、报表 `/reports`；页脚＝版本号＋`只读` 徽标。**不出现监控页入口。**
- **顶栏**：页面标题＋面包屑（`门户 / <页>`）；右侧＝daemon 在线点（绿/灰）＋主题切换按钮（月/日 SVG）。
- **内容区**：最大宽 1200px 居中；<900px 侧栏折叠为顶部横向导航（可横滚）。

### 1.2 路由与页面规格（全部 GET；HTML 页服务端渲染，无框架无构建）

| 路由 | 页面 | 规格 |
|---|---|---|
| `GET /` | 概览 | hero（公司名/mission/等级/平台绑定——平台 chip 显示 `PlatformBinding.platform` 可读名，如 `localfile`）；统计卡：单子总数、进行中、已交付、今日台账事件、今日成本(若有)、聊天房间/消息数；「最近活动」台账 events 最近 20 条（事件名 badge＋单号＋时间）；「最近单子」5 条（单号/标题/状态 badge/负责人/更新时间）；「组织摘要」部门数/人数/等级分布；快捷入口（去单子/去聊天） |
| `GET /tickets` | 单子列表 | 状态筛选 chips（全部＋按实际 state 动态）＋关键字搜索（GET 表单，无 JS 也可用）＋分页（page/size）；页头副题=公司 slug＋`平台全树 · 只读`（**永不渲染宿主机绝对路径**）；表格列＝单号/标题/状态/负责人/部门/泳道/更新时间；状态彩色 badge；空态文案；窄屏表格横向滚动 |
| `GET /tickets/:id` | 单子详情 | 头部（单号＋状态 badge＋标题）；meta 网格（类型/负责人/部门/泳道/等级/父单/创建/更新——部门显示短名（`departments/` 前缀不露），等级与组织页同款 `L<n>` 徽标，父单仅在有值时出行且链接到父单）；描述（pre-wrap）；验收标准（description 内 `验收` 段落文本，若有）；**事件时间线**（created/transitioned/field-set 逐条：图标＋时间＋字段变化，state 变化高亮 old→new；dept 字段同样显示短名）；返回列表链接 |
| `GET /chat` | 聊天 | 复用 `@studio-next/panel/chat`：API（rooms/messages/send/read）原样挂门户端口；页面=门户壳（layout）包 chat 内容片段（业务脚本单源复用，样式按门户 tokens 重写）；缺省操作者=在册工号（`--chat-actor`，缺省 `PRIME-0`——chatd 按房间成员校验，面板包缺省 `panel` 非成员会吃 `WB_INVALID_ARGUMENT`）；chatd 未配置/不可用→友好降级页（200），API 503 `CHAT_PANEL_DISABLED` 透传；操作者非房间成员→页面可读提示（切换房间或改操作者），不当内部错误渲染 |
| `GET /org` | 组织 | 组织树（部门层级缩进/负责人/泳道/职能）；人员表（工号/姓名/部门/等级/登录名） |
| `GET /reports` | 报表 | 公司目录 `reports/` 文件树列表（名称/大小/修改时间），点击进查看；**服务端过滤/分页**（1500+ 件不整页倾倒）：`q` 路径关键字（大小写不敏感）＋`limit`（缺省 100，上限 500）＋`page`（翻页）；页顶搜索框（GET 表单，无 JS 也可用）＋分页器（上一页/下一页＋`第 x–y 条 / 共 n 条 · 第 p/P 页`，链接续传 q/limit）；未过滤时页头标注 `共 N 个文件（显示前 L）`（N≤L 时省略括注） |
| `GET /reports/view?path=` | 报表查看 | 严格路径校验：仅 `reports/` 内、禁 `..`/绝对路径/反斜杠、仅 `.md/.txt/.json`；渲染为 `<pre>` 文本（HTML 转义）；越界/非法 400，不存在 404，>1MiB 截断提示 |

### 1.3 只读 API（JSON；统一 `{ok:true,…}` / `{ok:false,error:{code,message}}`）

- `GET /api/stats`：概览统计卡同源数据（含 daemon 在线推导、降级位 `available:false`）
- `GET /api/activity?limit=`（≤200）：台账最近事件
- `GET /api/tickets?state=&q=&limit=&offset=`：筛选/搜索/分页（limit ≤100）
- `GET /api/tickets/:id`：单据＋原始事件流
- `GET /api/org`：公司快照（部门/人员/组群）
- `GET /api/reports?q=&limit=&offset=`：报表文件清单（**可选三参**：`q` 路径关键字 ≤120 字；`limit` 0–500（0/缺省=不截断）；`offset` ≥0；返回 `{ok, total, q?, files}`——缺省=全清单，既有契约形状零变化，只多 `total`；坏参数 400 `bad-query`）

## 二、设计系统（自研 CSS，仓内自包含，禁外网 CDN）

心智模型（不引依赖）：Linear（侧栏克制分组/边框）、Vercel Dashboard（排版与卡片层级）、
GitHub Primer（badge/label/时间线）、Stripe（信息密度与留白）、shadcn/ui（中性色＋圆角＋细边框）。

- **tokens**（CSS 自定义属性）：色板（bg0/bg1/bg2/line/fg/fg-muted/fg-subtle/accent/ok/warn/info/danger/state-violet）、
  间距 4/8 递进（4/8/12/16/24/32）、圆角 6/10/14、阴影 2 级、`system-ui` 字体栈＋等宽数字（`font-variant-numeric: tabular-nums`）。
- **主题**：**深色默认**＋浅色切换；`localStorage('portal-theme')` 记忆，无记忆时随 `prefers-color-scheme`；
  首屏内联脚本提前落 `data-theme`（防闪白）；切换按钮 `addEventListener`（禁内联事件处理器，CSP 友好）。
- **可访问性**：对比度按深/浅两套分别调（正文 ≥4.5:1）；`:focus-visible` 明显描边；语义化标签＋aria-label。
- **组件**：stat tile、card、badge（状态语义色：新单=灰蓝 info／派发=琥珀 warn／交付=绿 ok／Archived=灰 neutral，
  其余态=紫 violet）、table（hover＋zebra）、timeline（圆点＋竖线）、chips、empty state、error banner、
  loading 态（服务端渲染为主；聊天轮询沿用原脚本）。
- **图标**：内联 SVG（描边风格，24 viewBox）；favicon=内联 SVG data URI。
- **响应式**：≥900px 侧栏布局；<900px 顶栏横滚导航；表格容器 `overflow-x:auto`。

## 三、数据来源（三事实源纪律不破；portal 零写）

| 数据 | 来源 | 读取方式 |
|---|---|---|
| 单子（列表/详情/事件流） | LocalFile 平台（`--platform-root`，缺省 `<companyDir>/../platform`） | `@studio-next/localplatform` 只读函数（本单为其**新增只读出口**：`listIssues/getIssue/parseIssueEvents`，绕开 `createLocalPlatform` 构造即 `ensureDir` 的写面）；列表结果带 TTL≈5s 进程内缓存（2035 单全量派生≈秒级，人看页面可接受；详情页每次直读盘） |
| 台账（今日事件/成本/最近活动/在线推导） | SQLite 台账（`--db`） | `packages/store` `openLedger` 只读查询（`queryEvents`；与 :8791 面板同款 `existsSync` 前置闸，不代建库）；daemon 在线=最近 `HEARTBEAT` 事件 ≤10min |
| 组织（部门/人员/公司名/等级） | 公司 git 目录（`--company-dir`） | `packages/company` `readDirectoryFiles`+`loadCompanyDirectory`（校验不过拒挂载）；mission 从 org-config.yaml 单行提取（同 cli/overview.ts 口径——契约 CompanySnapshot 尚无 mission 字段，拟稿注记） |
| 报表 | 公司目录 `reports/` | `node:fs` 只读 stat 扫描（占位件过滤，同 harvest-recon 口径）＋查看端点严格白名单 |
| 聊天 | 本地 chatd（Unix socket） | 复用 `@studio-next/panel/chat`：transport/路由/轮询脚本单源；socket/token 经 `--chatd-socket`/`--chatd-token-file` 或 env `WORKBENCH_CHATD_SOCKET`/`WORKBENCH_CHATD_TOKEN`（token 文件读入后只留内存，永不打印/入页/入日志）；缺省操作者三级 `--chat-actor` > env `PANEL_CHAT_ACTOR` > 内置 `PRIME-0`（面板包自身缺省 `panel` 不变——仅门户装配经 `loadChatPanelEnv(env, { fallbackActorId })` 改「env 未配时」的兜底） |

**降级矩阵（诚实呈现，不臆造空数据）**：

| 缺件 | 表现 |
|---|---|
| `--platform-root` 不存在/无 issues | 单子面/统计卡显示「未接平台（--platform-root）」空态；API `available:false`；**绝不 mkdir** |
| 台账缺失（`--db` 不存在） | 拒启（与 :8791 同判例：只读不代建库） |
| chatd 未配置/不可达 | 页 200 降级说明；`/api/chat/*` 503 透传；概览聊天卡「不可用」 |
| 操作者非房间成员（`WB_INVALID_ARGUMENT`） | API 400 透传；页面可读提示「操作者 X 不是该房间成员——切换房间，或在上方操作者栏改为在册工号」＋空消息列表（**不渲染为内部错误、不 500**） |
| 公司目录校验不过 | 拒启（04-§九 拒绝挂载） |
| 单子 id 非票形/报表路径越界 | 400（可读 code：`bad-ticket-id`/`path-out-of-reports`） |

**安全**：所有用户数据 HTML 转义（单号/标题/描述/事件值/文件名/消息正文）；路径参数严格校验
（票形 `^[A-Za-z0-9][A-Za-z0-9._-]*$`；报表路径白名单段校验＋realpath 前缀闸）；查询参数夹取
（limit/offset/q 长度）；无内联事件处理器；token 不落页面。

### 九.1 岗位会话档案（/sessions）

- **数据源**：`<companyDir>/../.AIWS/departments/<dept>/<PersonId>/tickets/<ticket>/att<N>/` 工位树——
  每次尝试一个目录，内含 `brief.md`（任务书）、`REPORT.md`、`summary.json`（含 `conclusion` 一句）、
  `deliverables/` 交付物树，以及 `.dsh-home/sessions/<ws>/<session-…>/session.v4.jsonl.zstd` 会话轨迹
  （`.dsh-probe-home` 同罩；workspace-key 目录名编码宿主机绝对路径——**永不展示**）。
- **路由**（全 GET，服务端渲染，页面可操控=链接/筛选/分页/折叠，无 JS 依赖）：
  - `GET /sessions`：列表页。筛选 `person=`/`ticket=`/`q=`（单号/岗位/部门子串）、分页（size 10–100 缺省 25）；
    行=单号/岗位/部门/尝试/更新时间/REPORT 徽标/摘要一句（`summary.conclusion` 截 90 字）。
  - `GET /sessions/:ticket/:attempt`：详情页。头卡（单号/att 徽标/岗位/部门/更新时间/会话 id/usage 统计）＋
    五标签页：**会话时间线**（事件逐条：时间/类别徽标/标题/参数摘要/正文 pre，脱敏后渲染）／**摘要**
    summary.json／**REPORT**／**任务书** brief.md／**交付物**（文件表＋预览链接＋白名单外标记）。
  - `GET /sessions/:ticket/:attempt/file?path=<att 内相对路径>`：文本预览页。白名单后缀
    `.md/.txt/.json/.log`；≤200KB 整读，超限只读前 200KB 并标注截断。
  - `GET /api/sessions?person=&ticket=&q=&limit=50&offset=0`：索引 JSON
    （`{ok,available,total,scanned,capped,limit,offset,items[]}`，updatedAt 倒序）。
  - `GET /api/sessions/:ticket/:attempt?sessionId=`：详情 JSON
    （`{ok,ticket,person,dept,attempt,updatedAtMs,sessionId,files{brief,report,summary,deliverables[]},
    sessions[],events[],usage,transcript{available[,sourceTruncated]|code+message}}`）。
- **轨迹归一化**（sessions-transcript.ts，纯函数）：JSONL 事件 → 视图事件
  （session/config/brief/user/assistant/reasoning/tool_call/tool_result/error/interrupt/compaction/turn/info；
  step/job/title 类噪声跳过并计数）；文本截 4000 字符、工具参数摘要截 300（码点安全）；usage 汇总
  （行数/坏行/回合/用户消息/助理消息/工具调用/工具结果/错误/时长/provider/model）。
  解压用 `child_process.spawn('zstd','-dc',file)`（**无 shell 拼接**）；超时 5s SIGKILL；输出上限 8MiB
  （越界截断并如实标注 `sourceTruncated`）；zstd 不可用/失败/超时一律**降级**（时间线横幅＋API
  `transcript.code`），不 500，其余标签页不受影响。
- **安全与性能**：单号/岗位/尝试/会话 id 严格正则（`^[A-Za-z0-9][A-Za-z0-9._-]*$` /
  `^att\d{1,4}$` / `session-<uuid>` 形）；`person` 过滤必须在树内实际存在否则 400；att 目录由索引行反推
  并做归一化前缀复核；文件预览拒绝绝对路径/反斜杠/空段/`..` 段（穿越=400 `bad-path`/`path-outside-attempt`），
  非白名单后缀=415 `unsupported-file-type`；索引全树扫描 TTL 5s、上限 3000 att 目录（越界 `capped` 如实上报）；
  轨迹单槽缓存（file+mtime+size 键，TTL 10s——翻标签页不重复解压）；>200 条事件折叠为百条一组
  （首组展开，其余 `<details>`）。会话正文/标题/参数在**归一化层**先 `maskHostPaths`
  （主机绝对路径→`<path>`，与聊天页同源单一正则）——页面（再罩幂等后 HTML 转义）与
  `/api/sessions` 详情回包都不带主机路径，workspace-key 目录名永不展示。

## 十、v3 第二刀：指令台（可操作）＋单子/聊天增强＋全局可用性（2026-11-23 制作人要求）

> 制作人 2026-11-23：「界面继续拓展，实际界面也可操控；组织架构图/聊天室/单子也都拓展拓展」。
> 本刀新增**一个写通道**：指令台经 chatd 聊天唤醒链路发消息（§九 e2e 已验证：面板/聊天发
> @工号 → wake → daemon 建单派工）。**三事实源写入者不变**：平台/台账/公司目录门户仍零写，
> daemon 是唯一写入者；指令台不新增任何直写面（§十.0）。

### 十.0 安全边界（指令台的「可操作」口径）

- **唯一写通道=chatd 消息**：`POST /api/console/send` 只调 `ChatPanelTransport.sendMessage`
  （panel 包同一 Port；token 服务端内存随 params 上帧，不回显/不落日志/不进页面）。
  发送者=门户缺省操作者（PRIME-0），正文含 `@工号` → chatd wake → daemon 走既有建单派工链。
- **不直写**：指令台无任何平台/台账/公司目录写路径；单子由 daemon 建派（聊天唤醒链路），
  指令台只发起意图不落单——「受控平台写操作仍待 daemon 通道提案」（§十.6 风险）。
- **校验前置**（过闸才触达 transport）：工号在册（org 快照 people id 全等）、text 非空 ≤4000
  （同 MAX_CHAT_BODY_CHARS）、roomId 在 rooms.list 实存；templateId 白名单内；ticket 参数须票形。
- **错误分类**（HTTP＋可读 message，统一 {ok:false,error:{code,message}}）：
  `chat-disabled`(503，chatd 未配)／`bad-json`·`missing-field`·`bad-template`·`text-too-long`·
  `person-unknown`·`bad-ticket-id`(400)／`room-not-found`(404)／transport 失败透传
  `classifyChatFailure`（WB_* 稳定码原样，HTTP 映射同 /api/chat/send）。
- **操作审计只存浏览器**：localStorage `portal-console-audit` 最近 20 条（时间/工号/模板/文本前
  80 字/结果）——服务端零落盘、零台账（不与台账事实源混淆）；「清除」按钮可清空。

### 十.1 指令台 `/console`

- **页面**（服务端整页渲染＋原生 JS；无 JS 时表单 GET 提交不可发送——写操作必须有确认门）：
  - 岗位下拉（/api/org 同源 people：`工号 姓名（部门）`；`?person=` 预选）；
  - 房间下拉：服务端预置缺省 `room-1`，页面 JS fetch `/api/chat/rooms` 刷新为实存房间
    （room-1 不在列时自动选第一个实存房间）；`?room=` 预选；
  - 模板下拉＋文本区＋发送按钮。模板（中文预填，`{{person}}`/`{{ticket}}` 占位）：

| id | 名称 | 预填文案 |
|---|---|---|
| `create` | 建单 | `@{{person}} 请处理：<描述>（验收：<标准>）` |
| `redraft` | 重派 | `@{{person}} 重派单 {{ticket}}：请按原验收口径重做并落 REPORT` |
| `ask` | 询问 | `@{{person}} 请汇报 {{ticket}} 进度与证据` |
| `daily` | 日报 | `@{{person}} 请产出今日日报（REPORT+summary）` |
| `custom` | 自定义 | 空白（`@工号 …` 提示） |

  - **发送确认**：点发送先出确认卡（完整文案＋接收工号＋房间；正文无 `@工号` 时提示
    「不会触发唤醒」）；确认才 POST。成功提示「已发送，工单将按聊天唤醒链路创建」＋ /chat 链接。
  - 请求体 `{person, roomId, templateId, text, ticket?}`；响应 `{ok:true, seq, roomSeq, roomId,
    message, chatUrl}`（`chatUrl=/chat?room=<roomId>`）；transport 回包 SendResult 原样透传字段。
- **预填链路**：单子/会话详情按钮 → `/console?person=<assignee>&ticket=<id>`（服务端预填重派
  模板并已替换占位）；`/chat?draft=<文案>`（聊天输入框预填，§十.3）。
- 落位：`apps/daemon/src/assembly/portal/console.ts`（页面＋模板＋发送编排，纯函数校验可测）。

### 十.2 单子增强（/tickets 与 /api/tickets；既有单参数契约零变化）

- 新可选查询参（加法式；`state`/`q`/`page`/`size` 原样保留）：`states=<a,b,…>`（多选，逗号分隔，

  排序/方向下拉同表单；分页/搜索链接续传全部参数。

  与页面同源筛选/排序纯函数（tickets-view.ts 单源），**上限 5000 行**（超出截断并在回包标
