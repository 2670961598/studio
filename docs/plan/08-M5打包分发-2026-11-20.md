### 7.2 status（探测口径）

- daemon：GET `/healthz`，**200 ∧ body.ok=true** 才算 up（503/坏 body/连接错=down）。
- chatd：unix socket NDJSON 两步（`health`＋`rooms.list`，`workbench-transport/v1`），
  token 从 token 文件读、**永不回显**；缺 `--company-dir` → 行标 `skip`（不算失败）。
- panel：GET `/` 任一 2xx 即 up。结论行 `failed` 只数 down；exit 0 ⟺ failed=0，否则 1。
- 本机冒烟实录（daemon pid 真在跑）：daemon ● up（ok=true tick 计数在涨）、panel ● up
  （http 200）、chatd 随目录状态如实标 down——**探测只读兑现**。

### 7.3 doctor（六项＝§三 5-1 判据）

1. node ≥24（`process.version` 可注入）；2. companyDir 存在；3. daemon.yaml
   `platform=localfile`；4. chatd 三件权限 **socket 0700／db 0600／token 0600**（§四 #2
   口径——socket 0700 为目录可达性留门，非 0600）；5. 备份目录存在→可写，不存在→最近
   存在祖先可写即绿（将建）；6. 磁盘余量 ≥2GiB（statfs 可注入，null=红）。
   任一红 → exit 2 逐项明报（表/`--json` 双面）；全绿 exit 0。

### 7.4 up/down（macOS launchd 首版——§六「首验 macOS」口径）

- label 三件：`io.studionext.daemon`（guardian）｜`<prefix>.chatd.<slug>`｜`<prefix>.panel.<slug>`；
  plist 落 `--launch-agents`（缺省 `$HOME/Library/LaunchAgents`）0600 原子写（tmp+rename）；
  日志落 `--log-dir`（缺省 `$HOME/Library/Logs/studio-next/<slug>`）。
- daemon plist=guardian 模型（§2.2 双 plist）：`node scripts/guardian.mjs --config <guardian.json>`；
  chatd plist 与 scripts/ops/chatd-setup.mjs PLIST_TEMPLATE 同构（env 四键
  WORKBENCH_CHATD_SOCKET/DB/TOKEN_FILE/LOG＋`--experimental-strip-types`）——**重复面

## 九、M5-3 第三刀实现记录（2026-11-21；代码已落树未 commit）

§2.2「无 init 系统：前台进程组」落地——**独立 `studio-next stack run` 子命令**，非
`up --foreground`。run/up 边界（§〇「一条命令起公司」的两个正交面）：

| | `stack run`（本刀） | `stack up`（M5-1/M5-2） |
|---|---|---|
| 场景 | 临时试用／CI／干净机器烟测：无 launchd/systemd 也能起 | 常驻服务：开机自愈、崩溃重启 |
| 机制 | node 裸跑 daemon＋chatd 两子进程（stdio 直通终端） | 三 plist／三 systemd user unit |
| 停机 | Ctrl-C/SIGTERM→先 chatd 后 daemon（SIGTERM→8s→SIGKILL），退出即散 | bootout／disable --now，单元文件保留 |
| 崩溃 | fail-closed：任一子进程退出→停另一个→exit 1（不重启不谎报） | launchd/systemd KeepAlive 自愈 |

选择独立子命令而非 `up --foreground` 的理由：up 的语义面是「安装常驻服务」（dry-run/
--apply、写管理器文件），混入前台模式会把 up 的参数面与生命周期搅浑；run 面干净——
`--company-dir`（必需）＋`--deploy-root`（缺省仓根推导）＋`--daemon-args`（透传 daemon
入口）＋`--no-chatd`＋`--ready-timeout-ms`/`--stop-timeout-ms`。

实现（apps/daemon/src/cli/stack/run.ts，计划纯函数＋子进程抽象＋编排三层）：

- 前置 fail-closed：公司目录存在＋daemon.yaml 可读且 platform=localfile（`--config` 可
  指位）＋探针端口可推导（`--port`＞daemon.yaml apiPort＞8788；`apiPort: 0`=ephemeral
  拒跑）＋部署树 node/两入口在场（run 无 dry-run，缺件硬拒 exit 1）；healthz 端口已有
  daemon 在跑（探针 200∧ok）→ 拒跑零 spawn **不触碰现有进程**（端口/路径全由参数决定）。
- token 纪律与 up 同款：var 0700；token **首产 0600 复用不覆盖**（atomicWrite 原子写），
  值永不打印（只经 `WORKBENCH_CHATD_TOKEN_FILE` 路径传递）。
- 就绪门：轮询 daemon `/healthz`（judgeDaemonHealth 同源判定）∧ chatd 两步探针双绿→
  打印 `READY daemon=<pid> chatd=<pid>`（`--no-chatd` 时 `chatd=off`）；60s 未双绿→停
  双进程 exit 1。信号面在 spawn 后、探活前注册（启动期崩溃也走 fail-closed）。
- 崩溃 fail-closed：任一子进程 READY 前后意外退出→停另一个→exit 1（子进程自身退出码
  写进报错行；不与 2/3 号保留码冲突）。
- StackDeps 注入面扩四件：spawnChild（真实现=node:child_process.spawn，stdio inherit）/
  sleep/now/onSignal——测试零真进程零真信号（fake 子进程可控退出/SIGTERM 装死、假信号
  源、步进时钟）。

### 10.1 pack-dist.mjs（打包）

`node scripts/ops/pack-dist.mjs [--out-dir <dir>] [--json]`（缺省 out-dir=`<repo>/dist`）。产物
`studio-next-<version>-<short-commit>.tgz`＋边车 `.sha256`。流程＝git rev-parse/log（dirty 只提醒）
→ mkdtemp staging → **git archive HEAD** 源码树解包（产物钉 HEAD，不含未提交变更——打包脚本
自身不在包内属预期并打印提醒）→ 剪除（tests/.git/.tmpcache/.bin/.cache/.DS_Store/vitest 配置；
源树 23 件）→ 运行时 node_modules 闭包拷入（`cpSync verbatimSymlinks`＋重建**相对**符号链接——
仓内 symlink 多为绝对路径，tar 保留 symlink 但目标必须相对）→ INSTALL.md 三步安装 →
dist-manifest.json（schema `studio-next/dist-manifest/v1`：commit/版本/件数/treeDigest/闭包目录
清单/排除面/limits）→ `tar -czf`＋sha256。

**运行时闭包算法（本刀核心，双种子 BFS）**：

- 种子①＝根＋各 workspace package.json 的 dependencies/optionalDependencies/peerDependencies
  （**不含 devDependencies**）；种子②＝**运行时可达 import 图**（`collectRuntimeImports`）：
  从各 workspace 真入口（main/bin/src/index.ts 兜底）沿相对 import 走传递闭包，bare import
  若解析到仓内 workspace 沿其 **exports 子路径**穿透续走（`.bun` 布局：各 workspace
  node_modules 链接全量 workspace；解析用收敛后的包名＋realpath 规范化——macOS `/var` vs
  `/private/var` 前缀混算会产生垃圾相对路径）。
- 可达性替代全目录扫描：src 内混居的 `*.test.ts`/`testutil.ts`/`platform-fixture.ts`（引
  vitest）天然不可达——首版全目录扫描曾把 vitest/esbuild/rollup/vite 拉进闭包（20.2MiB），
  改可达性后 12.5MiB、零误报。JSDoc 里的 import 示例也靠「剥注释＋单行匹配＋包名字符集
  校验」三重收口。
- **workspace 本体不入 stores**（源码树来自 git archive HEAD；从工作树拷会把未提交变更走私
  进「钉 HEAD」的包）——只记链接位。
- 判例实录：packages/panel 把 `@studio-next/company` 错标 devDependencies 而
  src/overview/reports.ts 运行时引它、且 daemon 经 `@studio-next/panel/overview` exports 子路径
  深进——正是种子②要兜的「bun 全量链接掩盖漏声明，本机跑得通、裁剪后干净机器才炸」；
  假 repo 回归用例已固化（leftpad2 经 `@studio-next/api/x` 入闭包）。

**manifest 自指矛盾**：tarball 内 manifest 不能含 tarball 自身 sha256 → 树内容摘要
treeDigest（排序文件内容＋symlink target 的总 sha256，skip manifest 自身）进包内，产物
sha256 写边车——解包侧复算 treeDigest 即验内容完整性。
