3. **验收命令口径**（全部为仓内真实可执行，对照根 `package.json` scripts 与各包 scripts）：
   - **V2 波门三件套**：`mise exec -- bun run guard:boundaries`｜`mise exec -- bun run typecheck`（根 program＝src 面）｜`mise exec -- bun run verify:v2`（＝guard＋typecheck＋typecheck:v2＋test:v2＋旧测试台账校验；MIG-02 落位后生效）。

   - **旧测试（非门）**：`mise exec -- bun run test`（旧全量，含 37 红＝审计基线；MIG-02 实测 20 failed）**不再作波门**；触及面用 `mise exec -- node_modules/.bin/vitest run <path>` 跑并登记台账（红也登记、不阻塞）。
   - 包级：`cd packages/<p> && bun run typecheck`（源码类型门）；旧包套 `bun run test` 只作触及面登记。
   - 基线复算：命令以 `docs/baselines/registration.md` §三 与 `docs/baselines/recompute.md` §六 CMD-00..06 为准（`node --input-type=module -e`/`find`/`grep`/`wc`，只读）；v2/16 §一为登记值，字面命令含已登记缺陷（CMD-00..06），复算不得照抄。
   - 标注「**本波落位后生效**」的命令＝该波产物自身新增的脚本/用例，落位即冻结，冻结后禁改（AGENTS §五.2）。
4. **三档模型口径**（token 成本量级）：T1 轻档（机械改动/夹具/文档回写）、T2 中档（常规实现单）、T3 重档（架构拆分/契约设计/长上下文审查）。每波给「低–高 Mtok」区间：低=T1 为主，高=T3 为主；细化归 plan/06。
5. **波门构成**（00 §四）：该波 **V2 新套件绿**＋**触及面旧测试登记（红也登记、不阻塞）**＋未触及面无新增红＋该波 NEG- 用例全过＋分层门禁绿＋无 fail-open 残留＋修订复核/F8 并行对应节通过（开工令 §3；替代门 §10）。真机探针（PB-）为波门伴随证据腿，批次顺序归 v2/17 §五。**旧全量 `bun run test` 绿不再是波门，也不得被引用为「全绿」证据。**
