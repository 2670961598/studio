## 1. 总原则

**可选项共存原则**：遇到两条都合理的路线，不做单选，做成可配置/可适配的并存项。
选型权下放给单据级配置与调度策略，由运行数据自然淘汰劣势项。
「能犹豫说明都有可取之处」——犹豫的终点是收编，不是取舍。

---

## 2. 终点（V∞）与验收口径

制作人只做两件事：**定方向（发 9 级单）**、**定口味（阅月报）**。

- 经营自治：三项目接单→拆单→排期→执行→验收→记账→复盘全闭环
- 组织自治：编制随业务量伸缩，人事全周期留痕，升级会签有数据可依
- 资产自治：框架自身、GitHub 形象、文档站、游戏平台等周边全部纳管、保鲜有责
- 能力自治：除模型本身外，一切皆为可进化资产
- 制作人权力保留清单（永不委托）：宪章修改、9 级单、总预算、口味裁决

**终点验收口径**：制作人连续 30 天只看月报不做批示，三项目吞吐不降、成本不超、无 A 级事故。

## 3. 五层模型

```
L5 进化层   观测→提案→沙箱→批示→灰度→切权→复盘   （零件已有，V6 统一成管线）
L4 经营层   ├ 4a 框架监控面：机器的温度计（成功率/派出/闸门/会话回顾）
            └ 4b 公司面：老板的公司（组织/人事/财务/项目进度）
            底座：SQLite 台账库（V4 新建，见 §4.1）
L3 组织层   org 引擎·分权·联签·升级会签          （有章程，机构半就职）
L2 流程层   YouTrack 状态机·单据·知识库          （健康，不动）
L1 执行层   worker·适配器·唤起·泳道·证据闸       （健康，V5 解耦 CLI 硬绑定）
```

**框架监控与公司面的分野（制作人 2026-10-15）**：
框架监控回答「这台机器运转得好不好」；公司面回答「这家公司经营得怎么样」。
两面共用 SQLite 数据底座，但口径、受众、抽象层级不同，不得混为一谈。
公司面不只是看板，还是注入每个 agent 提示词的"身份与方向"（§4.5）。

## 4. V4 · 公司架构（一整个公司的架构）

> V4 从"经营层报表"升级为**完整公司架构版本**：数据底座重构（SQLite）、
> 人事全周期（含变动留痕）、财务、两面监控、身份注入、外部交互接口、健壮性专项。
> 1-2 级公司现在就能用，schema 全部等级无关，同套结构平滑撑到 9 级。

### 4.1 数据底座：SQLite 台账库（底层重构，制作人已许可）

**三事实源边界（不越宪章 §12.5，不抢 YouTrack 和 org.yaml 的活）：**

| 事实源 | 管什么 | V4 后的关系 |
|---|---|---|
| YouTrack | 流程流转：单据/状态/批示/知识库 | **不动**，仍是流程唯一事实源 |
| org.yaml | 组织：编制/等级/部门/分权 | **不动**，仍是组织唯一事实源；SQLite 只镜像只读 |
| **SQLite（kernel/studio.db）** | **框架台账与公司数据**：事件/工时/成本/会话索引/人事变动/报表快照 | **V4 新建**；产物本体（REPORT/stream/证据）仍是文件，库里只存路径索引 |

**为什么必须换**：JSONL 只能顺序扫，公司面要的是关系查询——这个人经手哪些单、
这个部门本月成本、这次人事变动前后编制对比。实测体量（events 11k 行 / runs 23k 行）
对 SQLite 是微型负载，WAL 单写多读足够；且零依赖（Python 标准库），不引入新基建。

**核心表**：

```
events            事件账本（ts/pid/issue/event/actor/cost/tokens/duration）
work_records      工时单（done.json 索引化：工号/单号/泳道/分支/起止/成本/结果/session_id）
sessions          会话索引（单号/工号/归档路径/起止，支持回放定位）
people            个体（工号/名称/login/等级/部门/岗位/汇报线/状态[在职|停派|退休]）
personnel_events  人事变动台账（append-only，见 §4.2）
departments       部门（镜像 org.yaml + 统计列）
ticket_mirror     YouTrack 只读镜像（单号/created/状态/部门/等级/派单人，加速报表）
reports           报表快照（日报/月报结构化存档）
schema_version    版本与 migration 记录
```

**纪律**：
- daemon 唯一写入者；migration 脚本化管理；每日快照备份（kernel/backups/，不入 git）
- **可从 JSONL + YouTrack 全量重建**——库毁了能再生，这是"状态外置"基本法的延伸；
  每季度做一次恢复演习
- 存量回填：events.jsonl / runs.jsonl / done.json（1167 份）一次性入库
- 原有 JSONL 保留双写一个灰度期（30 天），核对无分歧后 SQLite 成为台账权威、JSONL 降级为导出格式

### 4.2 人事：个体、岗位与人事变动台账（公司的人事部）

**工号制（9 级前置，V4 落地）**：每个实名个体唯一工号，锚定 YouTrack login、等级、
部门、岗位、汇报线、状态。worker 池从"匿名池"升级为"编制池"：每次派工在
work_records 记工号+实例 id——实例一单一命可弃，**经验与成本累计到工号**。

**人事变动台账（personnel_events，append-only，每条必挂单据号）**：

| 变动类型 | 触发场景 |
|---|---|
| 入职 | 新角色设立、新 adapter 探针转正上岗（§5.3 招聘流程的终点） |
| 调岗 | 职责/泳道/汇报线变更 |
| 晋升/降级 | 等级变动，与 orggov 升级链接轨 |
| 部门调动 | 跨部门编制调整 |
| 停派/复派 | 连续劣化降权（§5.3 淘汰机制）、修复后复岗 |
| 退休下线 | 角色撤销、executor 退役 |

每条记录：{时间, 工号, 类型, 前值, 新值, 单据号, 批准人}。
**公司的历史 = 人事变动台账 + 工时台账 + 成本台账**——三者齐了，任何时候都能复盘：
谁在什么时候、在什么岗位、干了什么、花了多少、结果如何。

**人事档案（每个体一份，库存结构化，页面是渲染产物）**：
- 事实段（人事整理岗每日机械归集，零 LLM）：干了什么（工时）、做过哪些功能
  （REPORT+git+单据）、关联单据与会话索引、表现画像（一次通过率/单件成本/耗时/活跃曲线）
- 自述段（个体本人每周写）：我干了什么、卡在哪、下一步该接什么
- 用途：人事部（宰相）据档案做任务分配；财务部据档案分摊成本；身份注入包（§4.5）取摘要

### 4.3 财务面

- 成本四级 rollup：人 → 部门 → 项目 → 公司（源：work_records + events 成本字段 + 单据部门字段）
- 预算周期（周/月）与单项成本异常报警（如 POLY-29 单件 $28.6 类）
- **价目表服务**（V5 公共需求前置）：各 executor 的 tokens×单价折算统一在 daemon 侧，
  claude 原生成本作对账基准

### 4.4 监控两面（4a 框架监控 / 4b 公司面）

**4a 框架监控面**（机器的温度计）：执行健康（一次通过率，实测 78.5%）、派出面
（吞吐/泳道/卡单）、成本与超时、适应能力矩阵（V5 探针集）、上下文回顾（任意会话回放）。

**4b 公司面**（老板的公司），四个视图全部等级无关：
- **组织架构视图**：org.yaml 渲染——个体/部门/等级/泳道/汇报线/在干什么单
- **人事名录**：从 people 表进档案页（§4.2）
- **财务面**：§4.3 四级 rollup
- **项目进度面**：Epic→单据树、状态分布、需求吞吐、排期预测（在途÷近30日速率）、
  待制作人批示积压单独成栏

呈现：面板新增 `/company` 页；框架监控留 `/` 与 `/board`。
月报改两册：技术月报（框架面）+ 经营月报（公司面）。

### 4.5 身份注入包（公司 → 提示词）

每个 worker 出工，提示词必带"公司包"：
1. **公司是谁**：使命与宪章摘要（六条基本法）、当前战役方向
2. **你在哪**：组织架构位置——部门、汇报线、泳道、公司等级
3. **你是谁**：岗位职责、人事档案摘要（你做过什么、擅长什么）、署名协议
4. **该干什么**：本单任务书 + 验收口径 + 当前优先级

实现：`org_profile_block` 升级为 `company_pack(pid, role)`，数据从 SQLite 秒查；
修复已知 pid 未传递问题（GAMES worker 现仍注入 STUDIO 段档案）。
身份包为可进化资产，版本号随 PROMPT_VERSION 记账。

### 4.6 外部交互面（接口层，V7 的底座）

- **入口**：GitHub webhook（web.py 挂路由 + 签名校验 + _guard 放行）、
  YouTrack 活动流轮询加速至 1 分钟级（V4 实测 API 无压力）、群聊入口（已有）
- **出口**：GitHub（release/issue/README，V7 形象岗复用）、面板、通知
- **纪律**：一切外部刺激统一落成"探索单/需求单"再入流，不直接驱动 worker；
  出站内容过密钥扫描（红线）

### 4.7 健壮性专项（V4 内建）

- **daemon 心跳事件**：零活动日与采集故障可区分（V3 缺口#4）
- **持续报错升级电路**：同单同错误 N 连击自动开 bug 单（STUDIO-30 类 218 次/日不再无声）
- **配置漂移看门狗**：org.yaml vs 代码能力、未提交改动、注释与值矛盾（外审盲区二全覆盖）
- **SQLite 快照+季度恢复演习**（§4.1）
- **探针集回归**：adapter 升级/模型切换前必跑（与 §5.3 共用探针集）

### 4.8 V4 验收口径

1. SQLite 台账上线，全量重建演习一次通过（库删了能从 JSONL+YouTrack 再生且数据一致）
2. 人事变动 100% 挂单留痕（抽查任一变动能答出"谁批的、依据哪单"）
3. `/company` 页回答制作人三连问：「这个人在干什么」「这个单是谁干的」「这个月哪个部门钱花哪了」
4. 持续报错升级电路演练一次（人为制造卡单 → 自动开 bug 单）
5. 排期预测与实际关单偏差 <50% 且逐月收敛

## 5. V5 · 可插拔执行层（适配器协议）

### 5.1 适配器四原语

```python
class ExecutorAdapter(Protocol):
    def launch(task_brief, budget, watchdog, plugins) -> Handle
    def stream(handle) -> Iterator[Event]        # 心跳/进度/usage
    def result_stats(handle) -> {cost, tokens, duration_ms, turns}
    def kill(handle, grace) -> None
```

每个适配器自带**能力声明**：上下文规模、工具集、成本模型、权限模式、支持的插件清单。
现有 claude code 链路重写为第一个适配器（行为不变，纯重构，验证闸全流程走一遍）。

**公共需求（V2 实测）**：daemon 侧统一**价目表折算成本**（已前置到 V4 §4.3）——
kimi-code / codex / dsh 均不原生报成本；预算硬帽为 claude 独有（`--max-budget-usd`），
其余 executor 以墙钟看门狗为唯一硬约束。

### 5.2 启动装配（每次派单可指定）

派单参数 = `adapter × model × plugins × 唤起方式`，单据级可配，缺省走调度策略。
插件（webbridge / kimi-cu / ifind / 自研）manifest 化，声明依赖与挂载点。

### 5.3 适配器自生产（招聘流程）

新 CLI 出现 → 自动开「适配器开发单」→ worker 读对方文档生成适配器 →
**标准探针任务集**（5–10 个固定任务：代码修改/调试/研究/长链路各一）沙箱跑分 →
达标注册，进调度矩阵参与竞争，**personnel_events 记"入职"**；连续劣化降权直至停派
（记"停派"）。**这就是"招聘-试用-转正-淘汰"，全程入人事台账。**

### 5.4 dsh 接入方案（第一个真实客户）——2026-10-14 已实测（V1 探针，沙箱 /tmp/dsh-probe）

dsh = DeepSeek Harness（官方仓 deepseek-ai/deepseek-harness，MIT，2026-08-13 开源，实测 249k stars 且当天仍有提交；npm 包 `@deepseek-ai/dsh`，实测 0.2.0-rc.2）。**注意甄别：网上大量镜像站均非官方，接入决策只认 github.com / npmjs.com / deepseek.com 三个域。**

- **定位**：执行层新工种 + 自进化试验田；不替代任何现有层
- **实测接入面（两条都成立）**：
  - `dsh --profile headless "任务" --json`：一次性执行，stdout 出 NDJSON 事件流，`step_end` 带 `usage` token 计数；跑完自退
  - `dsh --profile sdk`：stdio JSON-RPC 常驻服务，`session.event` 已记录即推送
- **实测结论（四原语）**：launch ✅ / stream ✅ / result_stats ⚠️（tokens+耗时 ✅，**无原生成本字段，需 daemon 侧按价目表折算**）/ kill ⚠️（进程级 SIGTERM 可杀，但**协议层无单轮 cancel；被 SIGTERM 打断后退出码为 0、final 为空**——成功判定必须校验「存在 turn_end 且 reason=completed 且输出非空」，绝不能只看退出码）
- **无墙钟预算参数**：运行时长上限由调度器看门狗兜底（现有 wrap 机制可直接复用）
- **官方处于 developer preview，明示有 breaking changes：接入必须锁版本，升级走回归**
- **治理边界（红线级）**：
  - 生产泳道（games/core/studio）的 dsh 实例**禁用运行时自装插件**——实测 headless profile 默认已禁用 hmr/plugin-manager/tool-plugin-manager 三面，接入时再叠加 `--patch` 显式 `disabled: true` 双保险
  - 自修改能力仅在 explore 泳道与沙箱放开；验证出价值后按批示流转正
  - 进化审批权永远留在本框架，dsh 的自进化输出只能作为「提案」进入我方管线
- **并发纪律**：多个并发任务不得共用一个 sdk runtime 进程（无法单独 kill 某一轮）
- dsh 原生支持把活转包给其他 CLI，这层嵌套**禁止**（违反两级承包：一单一 agent 一命）
- **环境注意**：本机到 registry.npmjs.org 链路实测严重退化，安装/升级 dsh 需走镜像或缓存（已验证镜像 tarball 与官方 shasum 一致）

### 5.5 验收口径

探针集在 claude/dsh/（可选）kimi-code 三适配器上全绿；同一单据可指定不同 adapter 执行且证据格式一致。

## 6. 唤起层扩展（Invocation，横切 L1）

唤起是"谁让 agent 醒过来干活"。六源矩阵：

| # | 唤起方式 | 现状 | 说明 |
|---|---|---|---|
| 1 | 状态唤起 | 已有 | state-diff 派单，10 分钟粒度（V4 实测：API 支撑 1 分钟级，提速只改调度） |
| 2 | 定时唤起 | 已有 | APScheduler 15 岗 |
| 3 | 事件唤起 | 新增 | GitHub webhook（web.py 路由+签名校验）、YouTrack 活动流轮询加速（无 webhook，404 实锤） |
| 4 | 人际唤起 | 明确化 | 制作人一句话 → 主 PM 落单 → 流入正常流；群聊唤起同此通道 |
| 5 | 接力唤起 | 新增（约束内） | worker 完成 → 发「请重估单 X」幂等提示 → daemon 仍按状态机决策；本机限定+wkey 签名+防抖（V6 论证通过：不破坏状态即控制面） |
| 6 | 续命唤起 | 已有 | resume-cmd / resume-terminal，断点续跑 |

**唤起装配清单**（每次唤起统一注入，可进化资产）：
- executor 配置（adapter+model+plugins，按 §5.2）
- **公司身份包**（§4.5：公司是谁/你在哪/你是谁/该干什么）
- 上下文包：单据全量（流转史/批注/冻结验收口径）+ 同类历史教训 + 知识库引用
- 资源配额：预算帽/看门狗参数**按单据等级挂载**（等级=爆炸半径语义的落点）
- 证据契约：REPORT 落盘格式与验收命令

制作人任意介入的语义不变：拖单即语义，daemon 自适应（kill/park/返工），事件源同样服从。

## 7. V6 · 全栈自进化（统一进化管线）

零件已有（evolve / orggov / sandbox-verify / signoff / 影子模式），V6 串成一条管线，
**所有可进化资产走同一条路**：

```
观测(metrics/巡检/外审) → 提案(自动起草内部改进单) → 沙箱验证 → 按等级批示
→ 灰度(shadow 并行记账) → 零分歧期满切权 → 复盘入案例库
```

**可进化资产清单化**（每类声明验证集与灰度期）：
prompt 模板（PROMPT_VERSION 已是雏形）｜ 公司身份包 ｜ 人事档案 schema ｜
workflow 状态机 ｜ schema ｜ org.yaml ｜ 适配器与插件 ｜ 报表定义 ｜ daemon 代码 ｜ 唤起装配参数
