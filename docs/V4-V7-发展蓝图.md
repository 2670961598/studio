## 1. 总原则（新增一条设计哲学）

在六条基本法之外，本蓝图引入一条贯穿全部版本的原则：

**可选项共存原则**：遇到两条都合理的路线，不做单选，做成可配置/可适配的并存项——
executor 可以多家并存、唤起方式可以多源并存、报表可以多种粒度并存。
选型权下放给单据级配置与调度策略，由运行数据（成功率/成本/时延）自然淘汰劣势项。
「能犹豫说明都有可取之处」——犹豫的终点是收编，不是取舍。

## 2. 终点（V∞）与验收口径

制作人只做两件事：**定方向（发 9 级单）**、**定口味（阅月报）**。

- 经营自治：三项目接单→拆单→排期→执行→验收→记账→复盘全闭环

- 资产自治：框架自身、GitHub 形象、文档站、游戏平台等周边全部纳管、保鲜有责
- 能力自治：除模型本身外，一切皆为可进化资产
- 制作人权力保留清单（永不委托）：宪章修改、9 级单、总预算、口味裁决

**终点验收口径**：制作人连续 30 天只看月报不做批示，三项目吞吐不降、成本不超、无 A 级事故。

## 5. V5 · 可插拔执行层（适配器协议）

### 5.1 适配器四原语

```python
class ExecutorAdapter(Protocol):
    def launch(task_brief, budget, watchdog, plugins) -> Handle
    def stream(handle) -> Iterator[Event]        # 心跳/进度/usage
    def result_stats(handle) -> {cost, tokens, duration_ms, turns}
    def kill(handle, grace) -> None
```

每个适配器自带**能力声明**：上下文规模、工具集、成本模型、权限模式、支持的插件清单。
现有 claude code 链路重写为第一个适配器（行为不变，纯重构，验证闸全流程走一遍）。

### 5.2 启动装配（每次派单可指定）

派单参数 = `adapter × model × plugins × 唤起方式`，单据级可配，缺省走调度策略。
插件（webbridge / kimi-cu / ifind / 自研）manifest 化，声明依赖与挂载点。

### 5.3 适配器自生产（招聘流程）

新 CLI 出现 → 自动开「适配器开发单」→ worker 读对方文档生成适配器 →
**标准探针任务集**（5–10 个固定任务：代码修改/调试/研究/长链路各一）沙箱跑分 →
达标注册，进调度矩阵参与竞争；连续劣化自动降权直至停派。**这就是"招聘-试用-转正-淘汰"。**

### 5.4 dsh 接入方案（第一个真实客户）——2026-10-14 已实测（V1 探针，沙箱 /tmp/dsh-probe）

dsh = DeepSeek Harness（官方仓 deepseek-ai/deepseek-harness，MIT，2026-08-13 开源，实测 249k stars 且当天仍有提交；npm 包 `@deepseek-ai/dsh`，实测 0.2.0-rc.2）。**注意甄别：网上大量镜像站（dshplugin.store、deepseek404.com 等）均非官方，接入决策只认 github.com / npmjs.com / deepseek.com 三个域。**

- **定位**：执行层新工种 + 自进化试验田；不替代任何现有层
- **实测接入面（两条都成立）**：
  - `dsh --profile headless "任务" --json`：一次性执行，stdout 出 NDJSON 事件流（session/status/text/final），`step_end` 事件带 `usage` token 计数；跑完自退
  - `dsh --profile sdk`：stdio JSON-RPC 常驻服务，`session.event` 已记录即推送
- **实测结论（四原语）**：launch ✅ / stream ✅ / result_stats ⚠️（tokens+耗时 ✅，**无原生成本字段，需 daemon 侧按价目表折算**）/ kill ⚠️（进程级 SIGTERM 可杀，但**协议层无单轮 cancel；被 SIGTERM 打断后退出码为 0、final 为空**——成功判定必须校验「存在 turn_end 且 reason=completed 且输出非空」，绝不能只看退出码）
- **无墙钟预算参数**：运行时长上限由调度器看门狗兜底（现有 wrap 机制可直接复用）
- **官方处于 developer preview，明示有 breaking changes：接入必须锁版本，升级走回归**
- **治理边界（红线级）**：
  - 生产泳道（games/core/studio）的 dsh 实例**禁用运行时自装插件**——实测 headless profile 默认已禁用 hmr/plugin-manager/tool-plugin-manager 三面，接入时再叠加 `--patch` 显式 `disabled: true` 双保险
  - 自修改能力仅在 explore 泳道与沙箱放开；验证出价值后按批示流转正
  - 进化审批权永远留在本框架，dsh 的自进化输出只能作为「提案」进入我方管线
- **并发纪律**：多个并发任务不得共用一个 sdk runtime 进程（无法单独 kill 某一轮）
- dsh 原生支持把活转包给其他 CLI，这层嵌套**禁止**（违反两级承包：一单一 agent 一命）
- **环境注意**：本机到 registry.npmjs.org 链路实测严重退化（packument 77.5s 且多数超时），安装/升级 dsh 需走镜像或缓存；已验证镜像 tarball 与官方 shasum 一致

### 5.5 验收口径

探针集在 claude/dsh/（可选）kimi-code 三适配器上全绿；同一单据可指定不同 adapter 执行且证据格式一致。

## 6. 唤起层扩展（Invocation，横切 L1）

唤起是"谁让 agent 醒过来干活"。现状只有两源：状态轮询唤起、定时岗唤起。扩展为六源矩阵：

| # | 唤起方式 | 现状 | 说明 |
|---|---|---|---|
| 1 | 状态唤起 | 已有 | state-diff 派单，10 分钟粒度 |
| 2 | 定时唤起 | 已有 | APScheduler 15 岗 |
| 3 | 事件唤起 | 新增 | GitHub webhook（issue/PR/push）、YouTrack 工作流事件；收编外部刺激为探索单/需求单 |
| 4 | 人际唤起 | 明确化 | 制作人一句话 → 主 PM 落单 → 流入正常流；群聊唤起同此通道 |
| 5 | 接力唤起 | 新增（约束内） | worker 完成 → 直接唤起下一环（收割/QA），把 10 分钟轮询粒度降到秒级；仍只能唤起"自己下一站"，不破坏状态即控制面 |
| 6 | 续命唤起 | 已有 | resume-cmd / resume-terminal，断点续跑 |

**唤起装配清单**（每次唤起统一注入，可进化资产）：
- executor 配置（adapter+model+plugins，按 §5.2）
- 上下文包：单据全量（流转史/批注/冻结验收口径）+ 角色档案（org_profile_block，修 pid 传递）+ 同类历史教训 + 知识库引用
- 资源配额：预算帽/看门狗参数**按单据等级挂载**（等级=爆炸半径语义的落点）
- 证据契约：REPORT 落盘格式与验收命令

制作人任意介入的语义不变：拖单即语义，daemon 自适应（kill/park/返工），事件源同样服从。

## 7. V6 · 全栈自进化（统一进化管线）

零件已有（evolve / orggov / sandbox-verify / signoff / 影子模式），V6 串成一条管线，
**所有可进化资产走同一条路**：

```
观测(metrics/巡检/外审) → 提案(自动起草内部改进单) → 沙箱验证 → 按等级批示
→ 灰度(shadow 并行记账) → 零分歧期满切权 → 复盘入案例库
```

**可进化资产清单化**（每类声明验证集与灰度期）：
prompt 模板（PROMPT_VERSION 已是雏形）｜ workflow 状态机 ｜ schema ｜ org.yaml ｜
适配器与插件 ｜ 报表定义 ｜ daemon 代码 ｜ 唤起装配参数

**模型的特殊位置**：模型不可被进化，但**模型选型可以被竞标**——同一探针集多模型跑分，
模型矩阵走进化流程。「除模型外全部自进化」由此闭环。

**管线健康自检（必须内置）**：每月自检"管线自己的盲区"——持续报错未升级、配置漂移、
文档-代码不一致（本次外审发现的三类盲区全部纳入自检清单）。月度外部审查保留为兜底，
直到内部自检连续三月证明可信。
