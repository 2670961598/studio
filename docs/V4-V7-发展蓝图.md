## 1. 总原则

**可选项共存原则**：遇到两条都合理的路线，不做单选，做成可配置/可适配的并存项。
选型权下放给单据级配置与调度策略，由运行数据自然淘汰劣势项。
「能犹豫说明都有可取之处」——犹豫的终点是收编，不是取舍。

**前沿校准（v1.3 新增）**：外部 8 路调研确认——一单一命、证据断言、断路器、状态外置
与业界最优实践同构（Cognition 单写入者、ERC-8004 验证登记、durable execution 文献）。
同时引入八条修正，已逐条落入对应章节（附 B 对照表）。

## 2. 终点（V∞）与验收口径

制作人只做两件事：**定方向（发 9 级单）**、**定口味（阅月报）**。

- 经营自治：三项目接单→拆单→排期→执行→验收→记账→复盘全闭环
- 组织自治：编制随业务量伸缩，人事全周期留痕，升级会签有数据可依
- 资产自治：框架自身、GitHub 形象、文档站、游戏平台等周边全部纳管、保鲜有责
- 能力自治：除模型本身外，一切皆为可进化资产
- 制作人权力保留清单（永不委托）：宪章修改、9 级单、总预算、口味裁决

**终点验收口径**：制作人连续 30 天只看月报不做批示，三项目吞吐不降、成本不超、无 A 级事故。

## 3. 五层模型

```
L5 进化层   观测→提案→沙箱→批示→灰度→切权→复盘   （零件已分别设计，V6 统一成管线）
L4 经营层   ├ 4a 框架监控面：机器的温度计（成功率/派出/闸门/会话回顾）
            └ 4b 公司面：老板的公司（组织/人事/财务/项目进度）
            底座：SQLite 台账库（V4 新建，见 §4.1）
L3 组织层   org 引擎·分权·联签·升级会签          （有章程，机构半就职）
L2 流程层   YouTrack 状态机·单据·知识库          （健康，不动）
L1 执行层   worker·适配器·唤起·泳道·证据闸       （健康，V5 解耦 CLI 硬绑定）
```

**框架监控与公司面的分野（制作人 2026-10-15）**：
框架监控回答「这台机器运转得好不好」；公司面回答「这家公司经营得怎么样」。
两面共用 SQLite 数据底座，但口径、受众、抽象层级不同，不得混为一谈。
公司面不只是看板，还是注入每个 agent 提示词的"身份与方向"（§4.5）。

## 4. V4 · 公司架构（一整个公司的架构）

### 4.1 数据底座：SQLite 台账库（底层重构，制作人已许可）

**三事实源边界（不越宪章 §12.5）：**

| 事实源 | 管什么 | V4 后的关系 |
|---|---|---|
| YouTrack | 流程流转：单据/状态/批示/知识库 | **不动**，仍是流程唯一事实源 |
| 公司目录（org-config.yaml / 部门 config / 人事档案） | 组织：编制/等级/部门/分权/人事 | **组织唯一事实源**；SQLite 只镜像只读 |
| **SQLite（store 包；库文件在存储目录，不入 git）** | **框架台账与公司数据**：事件/工时/成本/会话索引/人事变动/候选制品/报表快照 | **V4 新建**；产物本体（REPORT/stream/证据）仍是文件，库里只存路径索引与哈希 |

**为什么必须换**：JSONL 只能顺序扫，公司面要的是关系查询。实测体量（events 11k 行）
对 SQLite 是微型负载，WAL 单写多读足够；零依赖（运行时标准库自带）。

**核心表**：

```
events            事件账本（ULID/ts/pid/issue/event/actor/cost/tokens/duration）
work_records      工时单（done.json 索引化：工号/单号/泳道/分支/起止/成本/结果/session_id）
sessions          会话索引（单号/工号/归档路径/起止，支持回放定位）
people            个体（工号[永不变主键]/名称/login/等级/部门/岗位/汇报线/能力档/状态）
personnel_events  人事变动台账（append-only，见 §4.2）
departments       部门（镜像公司目录 org-config.yaml + 统计列）
ticket_mirror     YouTrack 只读镜像（单号/created/状态/部门/等级/派单人）
ledgers           双台账：task_ledger（事实/假设/计划）+ progress_ledger（进度/卡点/重规划）
candidates        进化候选制品（类型/版本/diff/blast_radius/验证结果/谱系父id，见 §7）
budgets           预算预留-结算台账（reserve/settle/refusal 节点）
reports           报表快照
schema_version    版本与 migration 记录
```

**事件与审计 schema 纪律（前沿采纳，附 B-4/4b）**：
- 事件字段命名向 OTel `gen_ai.*` 语义约定靠拢（可移植、后端可换），但只当对外契约，
  内部 schema 自主（该约定仍为 Development 级，会漂移）
- **结果体分离存储**：台账只存 status/duration/size/hash + 路径引用，大 payload 与
  prompt 内容单独存、短保留期——防篡改 hash 链需要干净输入，也防密钥灌进台账
- token bucket **互斥**（cache 读/写不得与 input 重叠，OpenAI/Anthropic 口径不同，
  重复计价是行业高发坑）
- 状态机做成对事件日志的 fold，不另存可变第二份状态

**纪律**：daemon 唯一写入者；migration 脚本化；每日快照（落存储目录，不入 git）；
**可从 JSONL + YouTrack 全量重建**，每季度恢复演习一次；存量回填
events.jsonl / runs.jsonl / done.json（1167 份）；JSONL 双写 30 天灰度后降级为导出格式。

### 4.2 人事：个体、岗位与人事变动台账（公司的人事部）

**工号制（9 级前置，V4 落地）**：工号 = 永不变稳定主键；名称/能力/绩效/状态全是附加层
（前沿同构：NANDA Lean Index + AgentFacts 分层，附 B-2）。worker 池从"匿名池"升级为
"编制池"：每次派工在 work_records 记工号+实例 id——实例一单一命可弃，**经验与成本累计到工号**。

**人事变动台账（personnel_events，append-only，每条必挂单据号）**：

| 变动类型 | 触发场景 |
|---|---|
| 入职 | 新角色设立、新 adapter 探针转正上岗（§5.3 招聘流程的终点） |
| 调岗 | 职责/泳道/汇报线变更 |
| 晋升/降级 | 等级变动，与升级链（宰相月度审查 → 会签 → 制作人终验）接轨；能力档（0-3 档，按近窗口实际行为自动归）升档/降档 |
| 部门调动 | 跨部门编制调整 |
| 停派/复派 | 连续劣化降权（§5.3 淘汰机制）、修复后复岗 |
| 退休下线 | 角色撤销、executor 退役（只改状态不删号，历史不悬空） |

每条记录：{时间, 工号, 类型, 前值, 新值, 单据号, 批准人}。
**公司的历史 = 人事变动台账 + 工时台账 + 成本台账**。

**绩效铁律（前沿实证，附 B-2/B-5）**：
- **绩效只认已验证交付证据**（完工单 + 证据哈希 + 验收者），**严禁 agent 自评与互评打分**——
  ERC-8004 实证自评/互评信誉 73-90% 为 Sybil 协同造假
- 能力用本体化技能 ID（内部工种映射表，可导出 OASF 格式），不用自由文本；
  能力声明必须带 `side_effects` 等级（写库/改单/对外发言），防派错工

**人事档案（每个体一份，库存结构化，页面是渲染产物）**：
- 事实段（人事整理岗每日机械归集，零 LLM）：工时、做过的功能（REPORT+git+单据）、
  单据与会话索引、表现画像（一次通过率/单件成本/耗时/活跃曲线）
- 自述段（个体本人每周写）：干了什么、卡在哪、下一步该接什么
- 用途：人事部分配参考；财务分摊成本；身份注入包（§4.5）取摘要

### 4.3 财务面

- **核心指标 = 每成功交付成本（cost per successful task）**，不是 cost per token
  （FinOps for AI 共识，附 B-7）；四级 rollup：人 → 部门 → 项目 → 公司
- **双账本**：实时估算账（worker 自报，供调度/熔断）+ 每日权威对账账（供应商 Usage/Cost API），
  按 request_id 对账，drift 告警；价目表体检查询"有 usage 零成本"防漏配
- **预算预留-结算制（reserve/settle，前沿采纳）**：派工时按最坏估算原子预留，
  完工按实测结算释放；超额在调用前拒绝并落 refusal 节点（记录"考虑过但未执行"）——
  替代简单的事后扣减，防多级委派下的扇出超支（行业 63 起超支事故的主因）
- 归因键在**适配器层统一注入**（工号/单号/父单号），不由 worker 自觉：
  claude 支持 `OTEL_RESOURCE_ATTRIBUTES` 与 `TRACEPARENT` 注入（附 B-3 实锤），其余 CLI 用环境变量约定
- 预算周期（周/月）与单项成本异常报警（单件成本离群告警）

### 4.4 监控两面（4a 框架监控 / 4b 公司面）

**4a 框架监控面**（机器的温度计）：执行健康（一次通过率，实测 78.5%）、派出面
（吞吐/泳道/卡单）、成本与超时、适应能力矩阵（V5 探针集）、上下文回顾（任意会话回放）。

**4b 公司面**（老板的公司），四个视图全部等级无关：
- **组织架构视图**：公司目录渲染（org-config.yaml + 部门 config + 人事档案）——个体/部门/等级/泳道/汇报线/在干什么单
- **人事名录**：people 表进档案页（§4.2）
- **财务面**：§4.3
- **项目进度面**：Epic→单据树、状态分布、需求吞吐、排期预测、待制作人批示积压单独成栏

**监控纪律（前沿采纳，附 B-1/B-8）**：
- **异源监控**：QA/监控执行体不得与 worker 同 CLI 同模型——生成者与验证者异源是
  Cognition 生产结论，同源自欺会塌缩（AI control 研究实测近零安全性）。这把外审 B1
  （QA 独立性）的修复与 V5 多适配器天然挂钩：验证岗固定用"另一家"
- **指标防通胀**：不把提交数/PR 数/DORA 绝对值当绩效（AI 实测 PR +98%、评审 +91%、
  交付持平）；看板必须含"证据可追溯率"与最差分位，不只报均值
- **审批界面展示原始证据**而非 agent 自述摘要（防自动化偏见）

呈现：面板新增 `/company` 页；框架监控留 `/` 与 `/board`。
月报改两册：技术月报（框架面）+ 经营月报（公司面）。

### 4.5 身份注入包（公司 → 提示词）

每个 worker 出工，提示词必带"公司包"：
1. **公司是谁**：使命与宪章摘要（六条基本法）、当前战役方向
2. **你在哪**：组织架构位置——部门、汇报线、泳道、公司等级
3. **你是谁**：工号、岗位职责、技能本体、人事档案摘要、署名协议
4. **该干什么**：本单任务书 + 验收口径 + 当前优先级
5. **执业边界与拒答权**（前沿采纳，附 B-6）：「我做不到 / 需要升级到人类」是一等公民
   动作且给正分——防止幻觉式自信被错误激励（生产实测：agent"宁愿编个合理假答案也不说做不到"）

实现：`org_profile_block` 升级为 `company_pack(pid, role)`，数据从 SQLite 秒查；
修复已知 pid 未传递问题。身份包为可进化资产，版本号随 PROMPT_VERSION 记账。

### 4.6 外部交互面（接口层，V7 的底座）

- **入口**：GitHub webhook（挂路由 + 签名校验 + 本机防护放行）、
  YouTrack 活动流轮询加速至 1 分钟级（实测 API 无压力）、群聊入口（已有）
- **出口**：GitHub（release/issue/README，V7 形象岗复用）、面板、通知
- **纪律**：一切外部刺激统一落成"探索单/需求单"再入流，不直接驱动 worker；
  出站内容过密钥扫描（红线）；**对外提交一律人审闸门**——curl/Ghostty 等社区
  对 AI 自动提交的零容忍是前车之鉴（附 B-1）

### 4.7 健壮性专项（V4 内建）

- **daemon 心跳事件**：零活动日与采集故障可区分（补零活动日口径）
- **持续报错升级电路**：同单同错误 N 连击自动开 bug 单（高频循环报警不再无声）
- **配置漂移看门狗**：公司目录配置 vs 代码能力、未提交改动、注释与值矛盾（外审盲区全覆盖）
- **崩溃注入回归集**（前沿采纳，附 B-4b）：LLM 响应后/外部调用成功后/写盘后/审批后/
  版本轮转时各 kill 一次——过不了就是在靠运气；恢复重放查 receipt 防重复执行
- **短时令牌**：工号关联的凭证按单签发、任务结束即吊销；agent 不以管理员运行，
  出站走白名单网关（前沿：工号=短期可撤销身份，附 B-8）
- **不可逆操作同步阻断**：删数据/改权限/对外发信/动钱 → 独立进程同步拦截；
  删数据与删备份禁用同一把钥匙（PocketOS 9 秒删库事故，附 B-8）
- **SQLite 快照+季度恢复演习**（§4.1）；**探针集回归**：adapter 升级/模型切换前必跑

### 4.8 V4 验收口径

1. SQLite 台账上线，全量重建演习一次通过（删库再生且数据一致）
2. 人事变动 100% 挂单留痕（抽查任一变动能答出"谁批的、依据哪单"）
3. `/company` 页回答制作人三连问：「这个人在干什么」「这个单是谁干的」「这个月哪个部门钱花哪了」
4. 持续报错升级电路演练一次（人为制造卡单 → 自动开 bug 单）
5. 排期预测与实际关单偏差 <50% 且逐月收敛
6. 崩溃注入回归集首次全绿（v1.3 新增）

## 5. V5 · 可插拔执行层（适配器协议）

### 5.1 适配器四原语

```typescript
interface ExecutorAdapter {
  launch(taskBrief, budget, watchdog, plugins): Promise<Handle>
  stream(handle): AsyncIterable<Event>              // 心跳/进度/usage
  resultStats(handle): Promise<{ cost, tokens, durationMs, turns }>
  kill(handle, graceMs): Promise<void>
}
```

每个适配器自带**能力声明**：上下文规模、工具集、成本模型、权限模式、副作用等级、插件清单。
既有 CLI 链路重写为第一个适配器（行为不变，纯重构，验证闸全流程走一遍）。

**公共需求（V2 实测）**：daemon 侧统一**价目表折算成本**（已前置到 V4 §4.3）；
预算硬帽为 claude 独有（`--max-budget-usd`），其余 executor 以墙钟看门狗+预留结算制为约束；
副作用统一 `prepare→execute→receipt` 三段（幂等键，恢复先查 receipt）。

### 5.2 启动装配（每次派单可指定）

派单参数 = `adapter × model × plugins × 唤起方式`，单据级可配，缺省走调度策略。
插件（webbridge / kimi-cu / ifind / 自研）manifest 化，声明依赖与挂载点。

### 5.3 适配器自生产（招聘流程）

新 CLI 出现 → 自动开「适配器开发单」→ worker 读对方文档生成适配器 →
**标准探针任务集**沙箱跑分 → 达标注册，进调度矩阵，**personnel_events 记"入职"**；
连续劣化降权直至停派（记"停派"）。

**探针集纪律（前沿采纳，附 B-6）**：
- **私有且与自进化目标物理隔离**：考题永不进任何 worker 上下文、永不喂给进化管线——
  同一题库既考试又当进化目标会"越优化越差"（Terminal-Bench 实证负迁移）
- 分两层：**能力探针**（定级与可接单域）+ **回归探针**（历史已通过任务子集，
  每次框架升级/自进化提交后重放）
- 判分确定性 oracle 优先（单测/环境状态），主观题才 rubric+judge（禁用同族模型自评）
- **降权只由错误率驱动**（不按延迟，防级联），保留 5% 影子流量防供应商静默漂移
- 竞标派工用**校准胜任度 − 成本**，禁用裸自报置信度（"赢家诅咒"有实证）；
  结算账本提供校准标签，按任务族分别校准

### 5.4 dsh 接入方案（第一个真实客户）——2026-10-14 已实测（V1 探针，沙箱 /tmp/dsh-probe）

dsh = DeepSeek Harness（官方仓 deepseek-ai/deepseek-harness，MIT，2026-08-13 开源，实测 249k stars 且当天仍有提交；npm 包 `@deepseek-ai/dsh`，实测 0.2.0-rc.2）。**注意甄别：网上大量镜像站均非官方，接入决策只认 github.com / npmjs.com / deepseek.com 三个域。**

- **定位**：执行层新工种 + 自进化试验田；不替代任何现有层
- **实测接入面（两条都成立）**：
  - `dsh --profile headless "任务" --json`：一次性执行，stdout 出 NDJSON 事件流，`step_end` 带 `usage` token 计数；跑完自退
  - `dsh --profile sdk`：stdio JSON-RPC 常驻服务，`session.event` 已记录即推送
- **实测结论（四原语）**：launch ✅ / stream ✅ / result_stats ⚠️（tokens+耗时 ✅，**无原生成本字段，需 daemon 侧按价目表折算**）/ kill ⚠️（进程级 SIGTERM 可杀，但**协议层无单轮 cancel；被 SIGTERM 打断后退出码为 0、final 为空**——成功判定必须校验「存在 turn_end 且 reason=completed 且输出非空」，绝不能只看退出码）
- **无墙钟预算参数**：运行时长上限由调度器看门狗兜底（看门狗兜底机制复用）
- **官方处于 developer preview，明示有 breaking changes：接入必须锁版本，升级走回归**
- **治理边界（红线级）**：
  - 生产泳道（games/core/studio）的 dsh 实例**禁用运行时自装插件**——实测 headless profile 默认已禁用 hmr/plugin-manager/tool-plugin-manager 三面，接入时再叠加 `--patch` 显式 `disabled: true` 双保险
  - 自修改能力仅在 explore 泳道与沙箱放开；验证出价值后按批示流转正
  - 进化审批权永远留在本框架，dsh 的自进化输出只能作为「提案」进入我方管线
- **并发纪律**：多个并发任务不得共用一个 sdk runtime 进程（无法单独 kill 某一轮）
- dsh 原生支持把活转包给其他 CLI，这层嵌套**禁止**（违反两级承包：一单一 agent 一命）
- **环境注意**：本机到 registry.npmjs.org 链路实测严重退化，安装/升级 dsh 需走镜像或缓存（已验证镜像 tarball 与官方 shasum 一致）

| # | 唤起方式 | 落地形态 | 说明 |
|---|---|---|---|

| 4 | 人际唤起 | 明确化 | 制作人一句话 → 主 PM 落单 → 流入正常流；群聊唤起同此通道 |

## 7. V6 · 全栈自进化（统一进化管线）

进化所需零件（沙箱验证 / 会签 / 影子模式等）已分别设计，V6 把它们串成一条管线，
**所有可进化资产走同一条路**：

```
观测(metrics/巡检/外审) → 提案(候选制品，带 diff+blast_radius+谱系) → 沙箱验证
→ 三态闸门(accept/reject/escalate，只有 escalate 惊动制作人)
→ 灰度(shadow 并行记账) → 零分歧期满切权 → 复盘入案例库
```

**进化治理（前沿采纳，附 B-5）**：
- **三态闸门**：accept / reject / escalate——全量审批必然崩溃（审批疲劳有实证），
  低风险自动、中风险值班签、高风险才到制作人
- **护栏物理外置**：任何约束自进化的规则不得放在 agent 能编辑的地方——
  老板层规则对优化器物理不可达（optimizer-optimizee 塌缩有论文实证）
- **产物一律候选制品**：版本号 + diff + blast radius + 验证结果 + **谱系父 id**——
  坏技能会跨代遗传（Lamarckian propagation），台账必须能回答"这技能从哪一代哪张单长出来的"
- **验证层级写进验收**：形式验证 > 执行测试 > 检索证据 > 自评；能用测试的绝不用自我评估
- **fail-closed**：无审批人时默认拒绝，不是超时放行
- **进化目标与探针集物理隔离**（§5.3）

**可进化资产清单化**（每类声明验证集与灰度期）：
prompt 模板（PROMPT_VERSION 已是雏形）｜ 公司身份包 ｜ 人事档案 schema ｜
workflow 状态机 ｜ schema ｜ 公司目录配置（org-config.yaml 等） ｜ 适配器与插件 ｜ 报表定义 ｜ daemon 代码 ｜ 唤起装配参数

**模型的特殊位置**：模型不可被进化，但**模型选型可以被竞标**（§5.3 校准竞标）。
「除模型外全部自进化」由此闭环。

**管线健康自检（必须内置）**：每月自检"管线自己的盲区"——持续报错未升级、配置漂移、
文档-代码不一致（外审三类盲区全部纳入）。月度外部审查保留为兜底，
直到内部自检连续三月证明可信。

## 10. 开发规范（公私边界与工程标准，制作人 2026-10-15 定调）

> 本节是横跨所有版本的工程纪律：以后的开发**以上传 GitHub 为目标**——仓即产品；
> 本地是我们的生产现场，内部数据永不出本机。

### 10.1 公私边界（第一原则）

- **GitHub 两仓（studio/games，public+MIT）= 对外产品**：上面的一切必须对"陌生用户"有意义
- **本地 = 自用生产现场**：运行数据、台账、证据、内部人事、凭证——永不出本机
- **判据一句话**：「这是产品的一部分，还是我们运营产生的数据？」前者上库，后者留本地
- 推论：别人部署本框架时，他们的运营数据同样留在他们本地——**边界纪律本身就是产品承诺**

**上库白名单（产品侧）**：框架代码（apps/、packages/）、schema 与模板（templates/）、
组织设计（公司目录模板/宪章/设计文档）、campaign spec、intel 调研、README/LICENSE、测试、
migration 脚本、探针集的**结构与定义**（具体题目本地，呼应附 B-6 私有原则）。

**本地黑名单（.gitignore 强制）**：运行日志·证据·worker 状态·锁·心跳·指标等全部
jsonl·digest·reports、campaigns state/snapshots、projects/（项目仓独立）、
.venv、**所有 *.sqlite 与 backups**、人事档案（公司目录内）、
凭证（~/.config/，永不入库）。

**现状审计（2026-10-15 实测）**：跟踪文件全部在产品侧，黑名单项零泄漏；
并已做过一次远端清洁（运营报告出库）。
**灰区默认问制作人**：如产品仓内驻留的内部 QA 档案——
暂定保留（质量档案对用户有参考价值），有异议再出库。

### 10.2 结构合理

- 仓 = 产品，目录即产品文档：apps/ packages/（引擎与库）、templates/（公司目录模板）、
  docs/（设计文档）、根目录（宪章/README/LICENSE）
- 模块单一职责（一包一职责）；新模块先进设计文档再写码
- **本地痕迹零硬编码**：仓库里不得出现本机绝对路径、本机 IP、内网地址、真实凭证——
  一切环境相关走 ~/.config/ 外部配置（把它从惯例升级为强制）

### 10.3 功能清晰

- 每个功能一张单、一个冻结验收命令、一份落盘证据（现有纪律延续）
- 注释写"为什么"不写"是什么"；README 与文档计数必须和实现一致（外审发现的漂移即反例）
- 对外功能（别人会用到的 API/CLI/配置项）必须有文档与示例；纯内部运维接口标注"内部"

### 10.4 开发与发布纪律

- 写码时就当写给陌生用户：配置外部化、错误信息可读、文档随码同改
- **push 前三查**：git status 无黑名单文件｜密钥扫描通过（红线）｜文档计数与实现一致
- 框架仓 master 即发布面，主 PM 日常同步；项目仓版本日批量授权（红线不变）
- release notes 从 git 历史生成（V7 形象岗职责）

### B-3 财务（→ §4.3）

- cost per successful task 取代 cost per token（FinOps for AI）
- 双账本：实时估算 + 每日权威对账（drift 告警）
- 预留-结算制预算（Pollard arXiv:2610.16145；Token Budgets 63 起超支事故，委派扇出是主因）
- 归因键适配器层注入；claude 支持 OTEL_RESOURCE_ATTRIBUTES/TRACEPARENT（官方文档实锤）
- token bucket 互斥，防缓存重复计价

### B-4 数据与持久执行（→ §4.1/§5.1）

- 事件 schema 向 OTel gen_ai.* 靠拢（仅对外契约，内部自主）
- 结果体分离存储（哈希+引用，Obot/Gryph 契约）
- 副作用 prepare→execute→receipt 三段 + 幂等键；恢复先查 receipt
- 审批绑工件哈希不绑"尝试"（Janus post-approval substitution，arXiv:2609.38266）
- 崩溃注入回归集（5 个 kill 点）；Safe to Resume 五类失效（arXiv:2608.29381）

### B-5 自进化治理（→ §7）

- 三态闸门 accept/reject/escalate（腾讯混元 L0-L4 可靠性分层）
- 护栏物理外置，防 optimizer-optimizee 塌缩（arXiv:2606.23075；实测 Hermes 攻击持久化 100%、扫描器只拦 2.5%）
- 候选制品 + 谱系追踪（防拉马克式遗传）
- 验证层级：形式>执行>检索>自评（1250 篇 RSI 综述，arXiv:2607.07663）
- fail-closed 默认值

### B-6 评测与招聘（→ §5.3/§4.5）

- 探针集私有+冻结注册表+与进化目标物理隔离（《Harness or Model?》arXiv:2609.11987；Terminal-Bench 负迁移 arXiv:2607.14004）
- 能力探针/回归探针两层；确定性 oracle 优先
- 竞标 = 校准胜任度 − 成本（Agora，arXiv:2607.09600）；禁裸置信度
- 降权只按错误率（Grafana Demoter 经验）；5% 影子流量
- 拒答权一等公民（AlphaEval 六种生产特有失败，含"虚假自信"）

### B-7 老板看板（→ §4.3/§4.4）

- 指标防通胀：PR +98% 评审 +91% 交付持平（arXiv:2605.01160）；METR RCT：实际慢 19% 主观觉快 20%——只信台账客观事件
- SPACE 五维框架可搬，活动量单维会误导（arXiv:2510.24265）
- 看板含证据可追溯率+最差分位；审批界面展示原始证据

### B-8 治理与安全（→ §4.7/§5.1）

- 预算 admission 四段闭环（Oracle 运行时护栏模板）
- 工号 = 短期可撤销身份，按单签发短时令牌
- 不可逆操作同步阻断+独立进程；删数据与删备份不同钥匙（PocketOS 9 秒删库）
- 失控事故共性：可观测≠可执行，刹车必须在运行时不在文档里

### 待核实标注（调研中标注的不确定性）

OTel GenAI semconv 成熟度级别说法不一；AutoGen 转维护模式为多方转述；ERC-8004 仍 draft；GB/Z 185-2026 发布日期有两种记载；SaferAI 对 RSP v3 的评分降为二手来源。以上均不影响已采纳模式（采纳项均有一手信源）。
