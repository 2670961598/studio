# 58 · 岗位组合（权责原子 → 岗位的组合规则与范式库）

> 性质：**需求层文档**（抽象与模型层，不含技术实现；与 docs/57、docs/59 同属
> 2026-10-23 制作人令的三件套）。上位=docs/57（权责原子总表）；下位=docs/55
> （岗位规范，schema 层，待本文过审后回流修订）。
> 回答的问题：**「所有可能的岗位」如何从权责原子拼出来、拼得对不对怎么判、
> 不同规模的公司怎么配。**

---

## 〇、结论先行

1. **岗位 = 权责原子的合法组合 + 参数。** 合法性判据=docs/57-§三八条
   （一事一裁/禁配表/证据闭环/限额参数化/可撤回/异质验证/组合算子/过度分离红线）；
   参数={职级、预算、幅度、节奏}。组合不合法=这个岗位不存在。
2. **先定族，再定岗。** 岗位设计的第一步不是写岗位说明书，而是声明这个岗位持有
   哪些原子族（决策/资源/执行/验证/人事/信息/风险/元规则/协作）中的哪些原子。
   部门名是标签，原子组合才是实质——两个公司可以都有「QA 部」，持有的原子完全不同。
3. **规模不增减原则，只增减持有者。** 三人公司与三千人公司的**原子表相同**；
   变的是「一岗持多少原子、多少岗合一、哪些外化」。最小组织真正不可省的只有两条：
   **具名责任人** + **执行与验收不同源**——其余制衡都可合法取消，但取消要用东西换
   （事后举证/外部锚/阈值双签）。

## 一、组合模型

```
岗位（Position） = {
  atoms:      权责原子集合（57-§二），满足 57-§三 组合规则,
  params:     { level（成熟度锚）, budget（帽）, span（幅度）, cadence（节奏窗） },
  interfaces: { reports_to, supervises, co_sign, veto }（57 原子的关系面投影）,
  holder:     任职者（工号）或 空编
}
```

四条组合定律：

1. **权责一体**：每个原子连权带责整取，不得劈开（57-§二注）。
2. **空编可见**：岗位无任职者=合法但告警（「先建岗再进人」与「先有人后定岗」都合法；
   有没有编制必须是显式状态）。
3. **岗位模板与任职实例二分**：岗位配置变更不得改写历史任职者的当时快照——
   「当时谁有什么权」必须可复算。
4. **参数不下沉**：职级/预算/幅度是参数不是原子；同一原子组合配不同参数=同族不同档
   （如「复核岗-L3」与「复核岗-L7」同构，差在限额与汇报深度）。

## 二、岗位类型 ↔ 原子族映射（对接 55-§二 六类型）

| 55 岗位类型 | 主原子族 | 必有原子 | 必无原子 |
|---|---|---|---|
| `execute` 执行岗 | C 执行 + I 协作 | C1、C6 | D4、同事项的 D1/D2/C3 |
| `coordinate` 协调岗 | C2 派工 + A5/A6 议程召集 + I1 建议 | C2、A5 | 业务终裁 A3、D4 |
| `govern` 治理岗 | D 验证 + A4 否决 + G 合规 | D1 或 D2、A4 | 被审业务的 C1/A2/H1 |
| `platform` 平台岗 | H1 标准 + D10 权威源 + C5 权限授予 | H1、C5 | C4 自用 |
| `intel` 情报岗 | A1 提议 + I1 建议 + F1 知情 | A1、F1 | C1 执行、A2 批准 |
| `watch` 巡检岗 | D5 监控 + D8 叫停 + I2 关卡 | D5、D8 | 一切写动作族（只读+告警） |

新类型只能在「原子族组合不进现有六类」时增设（概念准入闸同款纪律）。

## 三、标准岗位范式库（archetypes）

> 每个范式 = 原子组合 + 典型参数 + 关键禁配检查。这是公司模板的「零件盒」；
> 公司作者可以改参数、增删非必有原子，但不得破坏禁配。

### 3.1 治理层

| 范式 | 原子组合 | 关键禁配/说明 |
|---|---|---|
| **制作人（老板）** | A3 全域终裁、A10 剩余裁量、H6 修宪、E2 高管任免、保留事项清单的修改权 | 无禁配（终裁者）；但受章程与判据约束——**终裁者的制衡在 59-§四** |
| **宰相/协调总长** | C2 派工、A5 议程、A6 召集、I1 建议、D7 异议受理（流程性） | 禁 A3 业务终裁、禁 D4；「提议与督办」一体但永不终裁 |
| **审计负责人** | D4 独立审计、D6 调查、F1 知情、豁免权（不被被审方撤换） | 禁一切被审业务的设计/执行/批准；双线汇报（功能→制作人、行政→宰相） |

### 3.2 部门层

| 范式 | 原子组合 | 关键禁配/说明 |
|---|---|---|
| **部长** | A1 提案、A2 部门内批准（限额）、B4 预算执行、C2 部门派工、E1 提名、E3 初考 | 禁 D4、禁超限额 A2（超限升级）；派单律=其 A2 的默认来源 |
| **执行岗** | C1 执行、C6 执行自主、I2 自己环节的核查配合 | 禁同事项 D1/D2/C3；偏差必须上报不得自行修正 |
| **复核岗** | D1 复核 | **异源参数必填**（与被验方不同模型/上下文/数据源）；复核意见留痕 |
| **验收岗（QA）** | D2 测试验收、D8 叫停 | 用例事前定义；禁 C1 被验事项；开发自测不算验收 |
| **巡检岗** | D5 监控、D8 叫停、I2 关卡主持 | 只读+告警；写动作=岗位不合法（55-P-8） |
| **参谋岗** | I1 建议 | **无命令权**；代令时责任仍归指挥岗（建议单/决定单分型） |
| **情报岗** | A1 立项建议、I1 建议、F1 知情 | 无执行权；产出=提案与扫描报告 |
| **关卡岗** | I2 关卡主持 | 可由低阶岗兼任（WHO 核查表：主持权给最靠近事实的人）；四件套必须齐 |

### 3.3 资源与合规线

| 范式 | 原子组合 | 关键禁配/说明 |
|---|---|---|
| **财务负责人** | B2 预算批准、B3 限额设定、B12 定价政策、F2 报告 | 禁 B9 保管；P&L 不归其定 |
| **会计** | B10 记录、B1 预算编制 | 禁 B8/B9/B11（记账不碰钱不核对） |
| **出纳** | B8 付款、B9 保管、F5 凭证归档 | 禁 B10/B11；三单匹配为付款前提 |
| **对账岗** | B11 对账核对 | 独立于 B9/B10 持有者（小公司可由制作人自兼=外部锚变体） |
| **人事岗** | E 族制度面（E1 执行、E3 组织、E4 执行、E7 交接清单） | **决定权归委员会/制作人**；人事岗是程序持有者是事实持有者的分离 |
| **法务合规岗** | G2 合规判定、G3 放行、A4 否决（窄口径）、B5 合同审查 | 禁 A1 业务方案设计 |
| **风控岗** | G1 风险偏好建议、B3 风险限额、D5 监控、A4 风险否决 | 禁任何创收目标 |
| **安全岗** | C4 特权治理（非使用）、B3 安全基线、G3 安全放行、D8 停线 | 禁 C4 自用、禁 C5 自授 |

### 3.4 元治理线

| 范式 | 原子组合 | 关键禁配/说明 |
|---|---|---|
| **规范委员会** | H1 制度制修订、H3 组织定编、I4 合议 | 被约束者不得单方改（H2）；合议奇数+少数意见落盘 |
| **规则守护岗** | H2 规则自保护、D5 元监控 | 只管「改规则的规则」；无权干预期内容 |

## 四、规模变形（3 人 / 30 人 / 300 人怎么配）

**规模不变量**（任何规模都不可省的 12 条底线）：

1. 具名责任人（每件事有且只有一个最后签字者）
2. 执行 ≠ 验收（至少一次由非执行者读一遍）
3. 发起 ≠ 批准（钱/权限/发布，阈值以上必须第二者）
4. 事实与记录分离（做的人不记账，或账不可篡改）
5. 意图可见（每次授权带 why+边界+期限）
6. 越权可归因（签名/日志定位到岗）
7. 叫停权（任何在场者可叫停流程）
8. 纠错通道且不因纠错变差（上诉不加刑）
9. 利益冲突回避（不能自审自批；AI 版=同源回避）
10. 规则变更另有授权（改规则的权 ≠ 用规则的权）
11. 退出/替换机制（在任者可被移除，含创始人）
12. 外部锚（内部无法分离时：执行可外化，**验收/追责/终止权必留内部**）

**规模变形表**：

| 权责项 | 微（≤5 岗） | 小（≤30 岗） | 中（≤300 岗） | 变形机制 |
|---|---|---|---|---|
| 记录/付款 | 法定仍须分设 | 会计/出纳分设 | 财务部+预算岗 | 外化+补偿控制（流水直送老板、月度独立对账） |
| 复核 | 异源互看 | 专职复核岗 | 治理岗族 | 拆「技术复核」与「流程复核」 |
| 签字批准 | 老板一人（低阈值） | 额度分级 | 双签+合议 | 阈值表+双签+事后审计三重叠加 |
| 法务/审计 | 全外包 | 外部顾问+内部接口 | 法务岗+独立审计 | 执行外化，验收/审计/终止/数据取回权留内 |
| 决策 | 直觉 | 例会 | 委员会 | 人裁→规则裁→委员会裁，每级留兜底终裁 |
| 冲突解决 | 老板裁决 | 升级链 | 异议受理+仲裁 | 升级链必须有终点 |
| 监督 | 可无（合法） | 一名监事 | 审计委员会 | 从「人事监督」转向「证据监督」 |

**外化铁律**：可外化的是**执行**，不可外化的是**验收、追责、终止**。外包方是一个
接口，不是一个责任主体。

## 五、AI 语境的组合修正（人类机制直接照搬会失效的地方）

1. **「换个人」≠「换视角」**。人类复核的价值来自独立经验；同模型两个 agent 复核的
   误差相关性≈1。独立性必须重定义为：**不同模型 / 不同上下文 / 不同数据源 /
   不同时间 / 不同指标**——回避审查（57-E8）按此判定关联。
2. **核查表会退化成装饰**。WHO 的教训：只要求用核查表无效，关键是有一个具名者
   有权拦住流程。关卡原子必须四件套齐（持有者+动作+否决后果+证据）。
3. **权限渐变是主风险**。人类靠任期/轮换/审批摩擦；AI 组织这些摩擦天然消失，
   必须显式造：限额到期、例外计数、定期权限复核、按原子组合审计（防藩镇式累积）。
4. **责任稀释比错误本身更危险**。建议/会诊/参谋类原子的共同点是「建议可流动，
   责任锚不动」。每张单据必须能回答：这条建议最终由哪个岗位承接？答不出=未完成。
5. **并行独立再比对，不做串行评论**。连署的正确形态是并行独立生成后比对差异；
   「A 写完 B 在后面评论」会被锚定污染，等于没有独立（五花判事的正确打开方式）。
6. **复核不加刑**（57-I6）：复核结论不得降低被复核方的等级/预算（除新证据）——
   否则一切复核通道因恐惧空转。
7. **收入信号不进内容上下文**（编营分离的 AI 版）：计费/预算信号只能进台账与
   预算闸，不得进入生产提示词。

## 六、岗位生命周期（与人事族的接口）

```
设岗（H3 定编，说明理由与成本）
 → 提名（E1，依据+备选）
 → 任命（E2，程序+理由）
 → 在岗（考核 E3：证据+校准+公示+可申诉；指标来自台账，禁止自评）
 → 晋升/降档（E5/E6，标准前置公开）
 → 退役（E7：离岗回收清单逐项结清——凭证/派单边/订阅/在途单/外部连接）
```

两条特殊纪律：
- **绩效从台账复算，不自评**；评估看「这一支的后代工单表现」，不看单次离线分。
- **退休与上限**：长期无有效产出的岗位进入退役评审（数字劳工纪律：
  不用的岗不是资产，是负债）。
