## 〇、结论先行

1. **「定时+hook」不是量不够，是语义缺。** 唤起源分类学（10 类意图源）已宽过多数
   产品；缺的是槽位幂等、投递耐久、意图 TTL、折叠、节流、节奏窗、静默通道——本文 §二
   把这些定为规矩。
2. **框架的可信度 = 授权与验收的机制化程度。** 「机制而非纪律」目前有一半还是纪律：
   委派链、quorum、sponsor 吊销、验收器密封——本文 §三/§五 把它们定为规矩。
3. **四层分离是逻辑约束，不是物理搬家。** Company Spec / Institutional / Orchestration /
   Execution 的职责边界本文冻结；物理包结构不动（改包结构=20-§十五 分层宪法修订，
   另走提案）。

## 一、四层分离（逻辑分层，❄️）

| 层 | 回答什么 | 不许做什么 | 现有映射 |
|---|---|---|---|
| **Company Spec** | 公司声明什么（组织/岗位/章程/依赖） | 不存运行时状态；不引用运行时对象 | 公司 git 目录 + packages/company（校验/挂载） |
| **Institutional**（制度面） | 谁有权、谁负责、证据在哪、学过什么 | 不做调度决策；不直接唤起 executor | gateway（wkey）、store（台账）、company（人事）、prompt（L0-L5） |
| **Orchestration**（编排面） | 什么时候、按什么顺序、失败了怎么办 | 不判定授权（问制度面）；不碰 executor 内部 | engine（主循环/调度/意图/收割/预算/断路） |
| **Execution**（执行面） | 在哪跑、用什么工具、怎么隔离 | 不写状态（一切写回经制度面） | adapters、dsh-bridge、studio-tools |

约束（❄️）：
1. 跨层调用只许 Orchestration → Institutional / Execution；**Execution → Institutional
   只许经网关**（现状即如此，本文冻结为层规）。
2. Institutional 的规则（授权/验收/记忆治理）必须在 executor 可编辑面之外（宪法外置
   原则的重申与扩展）。
3. 四层是文档与评审用语；依赖方向仍以 `scripts/guards/boundary-rules.mjs` 为唯一
   机械源（20-§十五）。

## 二、唤醒语义规范（WAKE 组）

> 现状基线：docs/22 源注册表、35-§3 新鲜度窗、`engine/scheduler.ts`。
> 「源只产意图、意图进主循环、决策归纯函数」纪律不变（❄️，docs/22 既定）。

| 规则 | 内容 | 轨 | 现状差距 |
|---|---|---|---|
| WAKE-1 | **槽位幂等**：定时意图的 dedupKey = `job@计划槽位时刻`，不是触发时刻；同一槽位无论何时重放/补跑都是同一个键 | ❄️ | scheduler.ts:200 现用 poll 时刻，需修 |
| WAKE-2 | **投递耐久**：槽位推进（markRan）与意图落库必须原子；或接受 at-most-once 并凭 WAKE-1 保证重放不重复——选定后写成设计条文，**不许停留在「中间崩了静默丢槽」** | ❄️ | scheduler.ts:136→143 与 engine.ts:2302 内存队列之间有崩溃窗口 |
| WAKE-3 | **意图级 TTL**：新鲜度窗从 job 层推广到 intent 层；恢复后过期意图丢弃（落账留痕），不一次性炸出 | β | 现只有 job 级新鲜度窗 |
| WAKE-4 | **唤醒折叠**：同岗在途时，wake 作为追加指令并入当前任务书（第三种语义），不丢弃、不开第二 executor | β | 现只有丢弃/排队两态 |
| WAKE-5 | **意图节流顺序（冻结）**：rate limit → batch → debounce → singleton → concurrency；debounce/singleton 的 key 可配置（如 key=人、key=岗位） | β | 现只有总量闸（每拍/全局在途） |
| WAKE-6 | **节奏窗（提案式自唤醒）**：岗位可声明 pacing 上下界（55-§二 triggers 扩展位）；agent 运行中可提议 next_check，调度器 clamp 到窗内；**本次执行失败/超时/跳过则提案丢弃** | β | 无 |
| WAKE-7 | **静默通道**：唤醒不必须产出——NO_REPLY/no_change 是一等终态，落账不告警 | β | 无 |
| WAKE-8 | **唤醒隔离（硬约束）**：唤醒执行不得与长期记忆/公司记忆共享可变上下文；记忆只能经 L0-L5 预算通道注入（防心跳污染通路） | ❄️ | 现状天然满足（每单独立上下文），本文冻结为不可退让约束 |
| WAKE-9 | **cron 校验**：DOM 与 DOW 同时非通配的表达式在校验期拒收或强制显式确认（croner 的 OR 语义陷阱） | ❄️ | scheduler.ts:92 未拦 |
| WAKE-10 | **心跳不是特权**：周期检查类任务并入普通调度面，带 activeHours/idleOnly/skipIfEmpty 策略档；不另开心跳机制 | β | 无（现无心跳，将来也不许开特权通道） |

成本依据（❄️ 级判断的实证底座）：30 分钟全量上下文心跳 ≈ $4.8/天/岗，轻上下文
≈ $0.015/天（差三个数量级）；后台心跳污染共享记忆的实验证据（长期记忆污染率最高
91%）。**便宜的门 + 贵的执行**是铁律，反过来就是烧钱加污染。

## 三、授权与身份规范（AUTH 组）

> 现状基线：wkey 六动作白名单、派单律、批示流、人事同步器。已知缺口：
> 复查报告 B10（同进程替三个身份签字）、53-§2.5（无授权图/quorum）、42（env 透传）。

| 规则 | 内容 | 轨 |
|---|---|---|
| AUTH-1 | **委派不放大**：任何子授权 ⊆ 父授权；`delegation_parent` 必填，授权链可沿台账回溯到人 | ❄️ |
| AUTH-2 | **sponsor 离场即失效**：personnel_events 直连 ①凭证吊销 ②派单边关闭 ③在途单处置 ④离岗回收清单（凭证/token/派单边/订阅/在途单/外部连接逐项 reconcile 落账） | ❄️ |
| AUTH-3 | **quorum 语义**：多方批准必须 distinct identity + distinct session；签名 action-bound；fail-closed；批准窗超时**只升级不放行**；批准延迟落账（反橡皮图章信号） | ❄️原则 / β机制 |
| AUTH-4 | **wkey scope 按岗位细分**：默认不是六动作全集；按岗位 authority 面投影最小集 | β |
| AUTH-5 | **利益冲突**：不得自审自批；同一 executor 实例/同一进程不得充当 quorum 的两个签名方 | ❄️ |
| AUTH-6 | **凭据不落盘**：agent 进程的凭据按需注入、任期同 turn；长期方向=按 turn 解密注入（目标态；现状 env 白名单为过渡，42 红队缺口登记在案） | β |

授权图（Authority Graph）作为 Org 扩展面（53-§七 D-C）落地时，AUTH-1..6 是其不变量；
授权图字段形状以 55-§二 authority 面为准。

## 四、事件规范（EVT 组）

| 规则 | 内容 | 轨 |
|---|---|---|
| EVT-1 | **事件五要素**：类型 + schema + 版本 + 幂等键 + correlation/causation id；hook 是事件**源**，不是事件——源输出必须折算成事件才许进主循环 | ❄️形状 |
| EVT-2 | **落账即发布**：意图/事件先落台账（append-only），后被消费（outbox 语义）；不允许「先消费后补账」 | ❄️ |
| EVT-3 | **重放安全与死信可见**：消费端幂等（键=EVT-1 幂等键）；死信落台账可查可重放 | β |

与 WAKE 组的关系：定时源的事件幂等键=WAKE-1 槽位键；事件 TTL=WAKE-3。

## 五、变更（进化）规范（EVO 组）

> 现状基线：候选制品+谱系+三态闸门+沙箱+切权+灰度+复盘已实现，evolve-guard 为
> v0 观察模式（docs/38 自认：有轨道、无机车、无司机）。前沿硬数据的结论：
> **瓶颈不在提议器，在验收器**——naive「涨分就留」规则在噪声下产生 30-42% 错误提交；
> 被拒提案中 55% 是「修好 A 弄坏 B」。先把验收器建成，司机才有意义。

| 规则 | 内容 | 轨 |
|---|---|---|
| EVO-1 | **验收器=验证器，不是分类器/LLM judge**：判决依据=可执行证据 + 固定 harness + 密封用例；分类器式闸门有理论上界（无法兼有界风险与无界有益修改），LLM judge 只能做建议层 | ❄️ |
| EVO-2 | **评测集=供应链**：验收用例 agent 不可编写、不可查看、版本化+签名、与 agent 可编辑面物理隔离；投毒实验证实污染会沿谱系持久化，撤源不解毒 | ❄️ |
| EVO-3 | **试用态**：三态闸门外加「临时执行权」态——只在触发失败上验证修好、且保护用例集无回归，才转持久 | β |
| EVO-4 | **谱系评估看后代**：切权决策看候选制品名下后续 N 张工单的成功率/返工率，不看上线前离线分（Metaproductivity-Performance Mismatch） | β |
| EVO-5 | **灰度单位=新派工单**：新单拿新版、在途单钉旧版（与「不动在途单泳道」红线同构）；回滚必须含上下文/快照失效语义；不用流量百分比（样本量无统计功效） | ❄️原则 |
| EVO-6 | **技能/规则库有退休与上限**：结果驱动退休 + 活跃上限；只积累不淘汰的库是负债（Library Drift） | β |
| EVO-7 | **复盘四件套**：复盘产出=候选规则 + 触发用例 + 保护用例 + 可证伪预测；散文式复盘不许进配置面 | ❄️形状 |
| EVO-8 | **能力授予与内容审批分离**：「写技能库/改配置」是默认关闭的岗位能力开关（人授予）；内容走证据闸 + 版本钉 + 可撤销，不逐条人审 | ❄️原则 |
| EVO-9 | **审批风险分层**（适用域=公司内机器提案量场景；**框架本体开发仍走 20-§十三 全流程，本条不适用**）：低风险自动+留审计 / 中风险 24h 无异议自动过 / 高风险双人或制作人；批准延迟落账 | β |
| EVO-10 | **禁止全自动合并**：无任何有生产证据的系统支持；「提案权」与「批准权」不得合并于同一意志 | ❄️ |

## 六、记忆与技能治理规范（MEM 组）

> 现状基线：lessons 空（prompt-assembly.ts:21）、无 per-agent 记忆、无技能库

| 规则 | 内容 | 轨 |

## 七、不做什么（边界）

1. **不引 Temporal/Restate/Kafka 类服务端与消息总线**——与「daemon 唯一常驻 +
   SQLite 台账」形态冲突；借语义（槽位幂等/outbox/流控），不引引擎。
2. **不做通用 Actor 运行时重写**——借 mailbox/supervision/backpressure 概念，
   per-position inbox 先做逻辑投影，不换运行时。
3. **不把编排交给 LLM**（53-§5.6 重申）：LLM 判断放提案/建议层，不绕过状态机与预算闸。
4. **规范层不放流程图/步骤序列**（BPMN 教训）：框架层也不内置声明式流程引擎；
   长流程需求用「义务 + 事件 + 升级」组合表达。
5. **不做 backfill 自动补跑**（与 35-§3「不盲目补跑」纪律一致；catchup 只走人工入口）。
