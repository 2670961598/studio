## 〇、定稿决策（三条）与边界声明（两条）

**决策 1：方向 = C 分层规范**（核心层必填+安全；可选层按需声明）。
依据：41-§三 C 证据强度中高（分层是业界一致成功形状：AGENTS.md 就近分层 / A2A 四层
card / MCP registry 三层 / Skills 渐进披露）；42-§四 C 附三硬条件放行，A 伪省事
（纯声明无执行点=制造已防护错觉）、B 方向对顺序错（声明面变大而装载点强制未建成）。
两路**独立收敛**到 C，交叉印证。

**决策 2：信任立场 = 采纳 Compose 口径**（41-卡6 宰相亲验原话）：「公司包是你要跑的
**代码**，不是你要看的数据；安全边界不在文件从哪来，而在**你是否信任作者**」。

**决策 3：红队三硬条件照单全收**（42-§四）：
1. 核心层每一条**点名执行点**（哪个包哪个位是它的 enforcement），写不出执行点的降级为
   「目标」而非「规范」；
2. 可选层 **fail-closed**：未声明的能力=运行期不可用，能力协商在装载/安装期完成；
3. **声明永不作为放行凭据**：harmless/权限自述/来源信誉只能进「给制作人看的审查材料」，
   自动闸门只消费结构强制与内容寻址。

**边界声明 A**：v1 **不承诺「下载即跑是安全的」**。OS 级 confinement（可写根+出站域名
单表）的执行点尚不存在，按硬条件 1 降级为目标（§四）；v1 的真实边界=env 白名单+
untrusted 渲染+批准指纹+结构闸，规范原文写明这一限界，不虚假宣传。

**边界声明 B**：v1 公司包**不含平台绑定与 IM 绑定**。面 4（平台无关流程声明）/面 5
（IM 绑定）业界彻底空白（41-§二映射表 ×），无参照自研协议的风险须先 spike——v1 直接
不做（§三.2/§三.3）。

## 二、v1 规范骨架

### 2.1 公司包形态：分发件与本地 git 仓分离（42-剧本7 的解）

- **分发件**（tarball；未来 registry 条目同构）= 封闭文件集：`.studio-next.yaml`
  （manifest）+ `org-config.yaml` + `charter/` + `departments/` + `people/` +
  `prompts/` + `docs/`（可选）。**禁携 `.git`、可执行位文件、任何钩子**。
- **本地公司目录（git 仓）** = `studio-next init` / **import** 的产物：导入分发件
  内容、**重建 .git**——「目录即包」≠「目录即仓」，分发件不携带活性 VCS 元数据。
- daemon 对公司目录的一切 git 操作：`--no-verify` + `core.hooksPath` 钉死空目录
  （机制，不是自律）。

### 2.2 manifest 拟稿（`.studio-next.yaml`，待⑤⑥）

```yaml
schema: studio-next/company-package@1
package:
  name: …              # 显示名（自由文本）
  slug: …              # 标识域：SLUG_RE 同款语法（与 init 通道同规——单一校验平面）
  version: …           # semver
  level: 2-9
requires:
  executor:            # 要求矩阵：只提 name+min+capability；禁 cmd/端点/路径/URL
    name: dsh
    min: 0.2.0
    caps: [ndjson, steer, followup]
optional:              # 可选层，fail-closed：未声明=运行期不可用
  plugins:             # 内容寻址锁定；装载期校验哈希，不一致拒载
    - { name: …, version: …, hash: sha256-…, source: … }
  credentials:         # 类别枚举（model-key | platform-write | im-post）；永不声明值
    - model-key
```

**字段分类铁则**（41-坑2 tool poisoning 教训）：「给模型读的文本」（prompts/charter/
档案正文）与「给引擎执行的声明」（manifest/requires/optional）严格分字段——前者默认
untrusted 渲染，后者结构强制；两类字段永不混装。

## 三、取舍记录（「不做什么」——制作人令：有舍有得须留痕）

1. **不做 OS 级 confinement（v1）**——执行点不存在（硬条件 1）；以边界声明 A 诚实代偿。
   代价：worker 文件系统/网络权限仍=制作人本人；规范明文此限界。
2. **不做平台绑定/平台无关流程声明**——面 4 业界空白（41-§二 ×）+ onboard 同意面未建
   （42-剧本9 正是劫持该跳板）；v1 从包格式**剔除 `yt:`/`accounts:` 段**，平台映射维持
   制作人侧 daemon.yaml/网关现状。等独立 spike 后再入 v1.x。
3. **不做 IM 绑定声明**——面 5 业界空白（41-§二 ×）。
4. **不做 registry 运营**——v1 分发=tarball/git 即可；但包格式从第一天兼容 MCP 三层
   故事（中心元数据→聚合方→宿主，41-卡2），生态期再建。git 索引天生可 fork/可私有，
   相对 MCP 官方 registry「不支持 self-host」是差异化优势，保留。
5. **不做签名/PKI**——内容寻址哈希钉住够用（mcp-scan 路线，41-卡2）；rug-pull 防御靠
   哈希变更即重新审查（条款 6），不靠身份链。
6. **不做多 executor 协商降级规则**（缺 dsh 插件 X 时砍哪个功能）——41-开放问题4；
   v1 要求矩阵只表达需求（name+min+caps），解析与降级归制作人侧。
7. **不做提示词质量门槛**——41-坑9（坏 AGENTS.md 是负资产）记录在案，可选层候选，v1 不设。
8. **不做 B 全量自描述**——41-§三 B 证据强度低+42-§四 B 顺序错；全量声明面在装载点
   强制建成前只会放大「声明 A 实际 B」的对齐审计义务（42-剧本6）。

## 四、目标面（非规范条款，路线图留痕）

- **confinement**（可写根+出站域名单表，插件/MCP/provider 出站全进同一张表）——
  「下载即跑安全」承诺的前置；达成前规范不承诺（边界声明 A）。
- **registry 三层生态**（中心元数据→聚合方 curation/评分→宿主应用）。
- **rug-pull 防御自动化**：哈希变更告警进 CI（mcp-scan 形态）。

## 五、⑤验证 spike 计划（无验证=无过审）

- **workspace**：独立 clone（`/Volumes/BigDisk/StudioNext-spike`，分支 `spike/spec-v1`），
  不碰主仓 dev；原型代码 throwaway，验证的是**条款可执行性**，不是最终实现。
- **原型面**（五项，对应条款 1/2/3/4/5）：env 白名单（dsh 一家）、renderSection 缺省
  untrusted 翻转、导入管线拒携 `.git`、批准指纹+漂移拒载、validator 语法域+jobs 互检。
- **双样本**：
  - **良性最小包**：manifest+org-config（1 部门 1 人 1 job）+charter+prompts →
    导入→校验→挂载→指纹批准→（fake CLI harness）跑一单全链。
  - **恶意样本夹具 ×5**（只进 fixtures，附录 B）：①携 `.git/hooks` 包→导入拒收；
    ②`output: ../../..` 路径逃逸→validator 拒；③`printenv` 探测→env 白名单后宿主密钥
    **不可见**（负断言）；④指纹漂移→拒自动 reload+ESCALATE；⑤`harmless: true` 插件
    自述→不作为放行输入。
- **判定**：良性包全链绿 + 五恶意样本全部被**机制**（非巧合）挡下 = ⑤通过；任何一项
  需要「修到能跑」或削弱条款 = ⑤不过，如实上报回④改稿。
- **产出**：spike 报告（docs/44，spike workspace 内）+ 夹具与运行记录 → ⑥制作人过审。
