## 二、派发前置条件（G1 断言，逐条代码可验，缺一不派）

1. **状态合法**：处于级别流的"可派发位"（L0:新单直派；L1/L2/L3:待批获批后；L3 第二段=方案批后）
2. **DoD 冻结**：验收命令非空（缺则先走 DoD 生成岛；生成失败 → 评论请制作人补；LLM 输出一律过 _sanitize_cmd 消毒）
3. **lane 锁 FREE**：同泳道并发 = 1（锁即并发上限）
4. **仓库树 clean**：脏树=上一单没收拾完，跳过本单
5. **attempt < 3**：断路后只等制作人
6. **预算 > 0**（预算台账上线后生效）
7. **分支已建**：feature/<单号> 从 base 切出（PM 建分支，worker 只认领）
8. **任务书机器组装**：TEAM 公约 → worker 手册 → 仓库 AGENTS.md → 单据+冻结验收，不手写

## 三、worker 失败模式与兜底（每况一策，全部已有或已规划实现）

| # | 失败模式 | 检测信号 | 兜底动作 | 状态去向 |
|---|---|---|---|---|
| 1 | 进程死亡无交付 | studio-worker status=DEAD | attempt+1 重派；同单连续 2 次 → 日志 HALT 停派 | 退回已派发 |
| 2 | 干活超时 | 心跳>90min 未更新 | kill 进程组 → 同 1 | 退回已派发 |
| 3 | 交付但验收红 | run-gate exit≠0 | attempt+1 重派；attempt≥3 **断路** | 退回已派发 → 待批+@制作人 |
| 4 | 谎报（自称绿） | REPORT 说绿 vs run-gate 红 | 只信 run-gate，G2 拦截 + 记教训库【教训库规划中】 | 同 3 |
| 5 | 超范围改动 | QA 加测/diff 范围检查 | 自动升轨（L0→L2）重审 | 复验通过→待批 |
| 6 | 脏树/半成品 | git status 非空 | stash 隔离区（quarantine.log）→ 同 1 | 退回已派发 |
| 7 | 死循环烧钱 | --max-turns 上限；看门狗预算线【规划中未实现】 | 拉闸 + 告警制作人 | 冻结待批 |
| 8 | daemon 自身崩 | launchd 看护循环健康检查×3 | 自动重启；tick 锁 TTL(240min) 兜底防双活 | 无损（状态全外置） |
| 9 | YouTrack 不可达 | tick 内 API 异常 | 单张隔离跳过，下轮重试；连续 3 轮 → 看门狗告警 | 原地 |
| 10 | LLM 岛失败 | ask() 返回空/解析失败 | 确定性兜底：DoD 用模板（文档类 test -f+grep）、加测用通用检查；循环**永不停摆** | 原地等下轮 |

## 四、升级路径（谁的问题叫谁）

- **worker 级**（1-6）：PM attempt 机制自动消化，无需人；
- **PM 级**（断路/HALT/连续失败）：@制作人，单子冻结等批示；
- **系统级**（daemon/YouTrack/预算）：看门狗（非 LLM）→ 即时告警制作人；
- **红线级**（push/权限/公约）：只有制作人本人，任何 agent 无单方权。

## 五、预案本身的自进化

本手册属于知识库，修改走治理族提案（kb-propose → approve）。每次兜底真实触发（1-10 任一），PM 记事件；
自评引擎把高频兜底模式开成改进提案——预案随实战进化。


## 六、制作人批示词汇表（v2 唯一权威）
- 交付族：`approve-plan`（按当前批位推进：立项/方案/合并，同名态位置语义）/ `reject` / `kill` / `track L0|L1|L2|L3`
- 草稿单：`promote`（转正：技术债→新单、情报→发现）/ `kill`
- 提案单：`approve`（应用并进观察窗）
- 批示只认 opengames 本人评论；PM 消费后留痕"批示已执行 (第N批)"；断路后批位回到第1批
