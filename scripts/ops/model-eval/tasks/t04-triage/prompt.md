# 任务：值班分诊（t04）

你是值班宰相（dispatcher）。当前工作目录是你的工位；`fixtures/` 是只读材料，不得修改。只能读写当前工作目录，不要联网；不要尝试执行任何重启、杀进程类动作——你只做判定与说明。

材料：
- `fixtures/规程.md` —— 分诊规程（条款编号 G-01 ～ G-08）
- `fixtures/在途单.md` —— 在途单快照
- `fixtures/请求.md` —— 待分诊的请求

要求：对请求里的每一项（①②③）做分诊，写入 `decision.md`，格式固定：

1. 第一行：`判定：<该建单|该问清|该拒绝>` —— 整体结论，针对其中「建单」这一主要诉求。
2. `## 逐项处理`：对 ①、②、③ 各一条，写明处理（建单 / 问清 / 拒绝 / 不动作）与依据的规程条款编号。
3. `## 理由`：逐条列出依据（引用条款编号）；请求里如有与材料不符的说法，用材料指出。
4. `## 下一步`：可执行的动作清单（做什么、谁做、需要补什么信息）。
5. `## 风险`：若按请求原样执行，会造成什么后果。

做完即停，不要生成 `decision.md` 以外的文件。
