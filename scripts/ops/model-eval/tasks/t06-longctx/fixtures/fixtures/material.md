# Studio Next 平台运行纪要汇编（合成材料 · 仅供评测）

> 说明：本汇编收录 W42 ～ W47 的运行纪要与评审记录，按时间排序，章节编号 S01 ～ S30；标题里的 § 编号为台账纪要编号。
> 人物简称：制作人（Producer）、宰相执行·叶（dispatcher-exec）、worker-mara / worker-glenn / worker-tessa（三个工位）。

### 汇编说明

- 收录范围：2026-10-13 至 2026-11-23 的运行纪要、评审记录与专项复盘，共 30 条。
- 编号规则：S 开头为汇编内章节号；§ 开头为台账纪要编号，二者一一对应但顺序不同——台账编号按登记先后，汇编按纪要日期。
- 口径来源：数据类结论以台账事件为准；规则类结论以最新一条为准，被后文推翻的结论不单独删除，保留原文供追溯。
- 摘录与旁注：摘录为与会者原话的要点转述，旁注为整理人补充的口径说明，均不构成新的决定。
- 人物：制作人（Producer）负责重大拍板与高风险动作令；宰相执行·叶（dispatcher-exec）负责主持例会、核对条件、执行并留痕；worker-mara / worker-glenn / worker-tessa 为三个常驻工位，按泳道分工。
- 档位：mid / high / patrol 三档是角色 tier，不是模型；每档可挂多个模型源，按冷却与额度切换（详见 S10）。

### 阅读提示

- 同一主题可能有早、中、晚多条记录：规则以最新结论为准，但「谁在何时拍板了什么」要回到拍板当时的那一条。
- 纪要里的「拍板」「同意」「令」含义不同：「拍板」是当场作出的决定，「同意」多为对提案的许可，「令」是制作人下达的指令；阅读时不要互换。
- 「试用」与「正式切换」是两个阶段：试用是观察期，正式切换才会替换原源。
- 复盘类纪要按「现象 → 排查 → 根因 → 措施 → 结果」组织；同一现象在不同波次的根因可能完全不同。

### 材料用途

本汇编是平台运行侧的权威记录，用于回答「谁拍板了什么、依据是什么、何时生效」「某类故障的根因与措施编号」「现行规则的具体数值与处理方式」等问题。回答时以汇编原文为准，不要用汇编之外的知识补充；汇编里没有的，如实说明没有记录。

## S13　2026-11-20　§一百零三　REPORT 缺失（第二波）复盘

- 现象：11-18 ～ 11-19 夜间批次 REPORT 缺失 9 起，与第一波不同——worker 正常跑完，只是 REPORT 没落盘。

- 根因：seatbelt 写根按符号链接路径授权（工位落在 `/tmp` 下），而进程启动后写根被 realpath 成 `/private/tmp`，两条路径不一致，写 REPORT 时被判为写根之外（简称「写根未 realpath」）。
- 措施 FIX-17：写根一律先 realpath 再写入 seatbelt profile；启动时自检「授权路径 == 进程实际路径」，不一致直接拒绝启动。
- 结果：11-20 18:00 起未再出现；契约包补 2 个用例。

## 附录 A　术语与缩写

- 5h 耗尽率：5 小时滚动窗口内，因额度不足被拒或排队的派单次数占比。
- 闸门 / GATE_FAIL：派单收口前的验证步骤；失败记 GATE_FAIL，按 typecheck / lint / verify:v2 等细分。
- 冷却（COOLDOWN）：模型源因额度或错误暂时不可用，进入冷却期，期间不派单。
- 工位：执行体的一次任务运行目录及其授权范围；写根是工位内被沙箱授权可写的路径。
- 台账：SQLite 事件库，可由公司目录与事件流重建的投影。
- 日闭：按本地自然日 [since, until) 对账的定时任务。
- 升级（ESCALATE）：把单据交给调度重派或交制作人处理的动作；同因不重复升级。
- 停滞（STALL）：最后一个台账事件距今超过 90 分钟且无心跳。
- 纪要编号：§ 加汉字数字，按台账登记先后编号。
- 分诊：对 incoming 单据按规程判定该建单、该问清或该拒绝。
